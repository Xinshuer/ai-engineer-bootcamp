title: with_structured_output：直接拿到对象
--- body
第 12 天你手写过：`json_object` 模式 + 把字段说明写进 prompt + Pydantic 校验 + 失败再问。LangChain 一行：

```python
reviewer = model.with_structured_output(ClauseReview)
review = reviewer.invoke("Review clause 8.1: ...")   # 一个 ClauseReview 对象
```

它是怎么做到的？看请求体：ChatDeepSeek 默认把 `ClauseReview` 变成一个**工具**放进 `tools`，再用 `tool_choice` **强制**模型调用它；模型填的参数就是你要的字段，LangChain 再用 Pydantic 校验。所以类的 docstring 变成工具说明，`Field(description=...)` 变成字段说明，`Literal` 变成 `enum`，这些都是写给模型看的 prompt。

今天所有审查和工具的代码都会关掉思考模式，原因在第 4 张卡。
--- code

title: method、include_raw 和 None
--- body
- `method="json_mode"`：改用 `response_format: {"type": "json_object"}`（第 12 天的做法）。这时 prompt 里必须写上 "json" 并说明字段；模型在 JSON 前面多嘴（本页用 `[bad-json]` 模拟），会抛 `OutputParserException`
- `include_raw=True`：返回字典 `{"raw": AIMessage, "parsed": 对象或 None, "parsing_error": 异常或 None}`，失败时还能看到模型的原始回答、写进日志
- **坑**（本页的 langchain-core 1.6 是这样）：默认的工具方式下，模型给的参数是坏 JSON（本页用 `[bad-args]` 模拟）时，`invoke` **不抛异常，直接返回 `None`**。加了 `include_raw=True`，`parsed` 是 None，`parsing_error` **也是** None，坏参数躺在 `raw.invalid_tool_calls` 里

所以拿到结果先检查 None，不然下一行 `review.verdict` 就是 `AttributeError`。拿不到合格结果怎么办？和 `review.py` 一样：判 flag，交给人，绝不当成 accept。
--- code

title: @tool：把函数变成工具
--- body
`@tool` 装饰器把一个普通函数变成工具（一个 `StructuredTool` 对象）：

- 名字 = 函数名；说明 = **docstring**（没有 docstring 直接报 `ValueError`，因为模型只能靠说明决定用不用它）；参数的 schema 来自类型标注和默认值
- `convert_to_openai_tool(t)`：看模型收到的 JSON，和第 12 天 `tools.py` 的 `tool_specs()` 生成的是同一种东西
- `t.invoke({"topic": "payment"})`：先按 schema 校验参数，再调用函数；参数不对抛 pydantic 的 `ValidationError`

description 怎么写，第 12 天 `mark_for_review` 的教训还是一样：写清什么时候用、会发生什么、什么时候**不要**用。
--- code
from langchain_core.tools import tool
from langchain_core.utils.function_calling import convert_to_openai_tool
from pydantic import ValidationError

@tool
def lookup_playbook(topic: str, max_rules: int = 3) -> str:
    """Return the customer's playbook rules for one contract topic, e.g. liability_cap or payment."""
    return f"{max_rules} rules for {topic}"

print(type(lookup_playbook).__name__, "|", lookup_playbook.name)
print(lookup_playbook.description)
print(lookup_playbook.args)
print(convert_to_openai_tool(lookup_playbook)["function"]["parameters"])
print(lookup_playbook.invoke({"topic": "payment"}))
try:
    lookup_playbook.invoke({"topik": "payment"})
except ValidationError as e:
    print("ValidationError:", e.errors()[0]["loc"], e.errors()[0]["msg"])

try:
    @tool
    def get_clause(clause_id: str) -> str:
        return clause_id
except ValueError as e:
    print("ValueError:", e)

@@ concept
title: bind_tools 和 tool_calls
--- body
`model.bind_tools([工具, ...])` 返回一个「带着工具定义」的模型。模型想调工具时，回的 `AIMessage`：

- `.content` 通常是空字符串；`.tool_calls = [{"name", "args", "id", "type": "tool_call"}]`，`args` 已经是字典（LangChain 替你 `json.loads` 了）
- 执行：`工具.invoke(call)`，把**整个** call 传进去，得到一条 `ToolMessage`，`tool_call_id` 自动对上
- 下一次请求的 messages：……、那条 AIMessage、每个调用各一条 ToolMessage。少一条或者 id 对不上，真接口会返回 400（第 17 天的规则），本页的模拟服务器也一样

**思考模式和工具**：DeepSeek 的文档写明，思考模式下带 `tools` 的请求，之前每一条 assistant 消息的思考内容（`reasoning_content`）都必须在后面的请求里传回去，否则返回 400。ChatDeepSeek 不会把它传回去（本页用的 langchain-deepseek 1.1 是这样，以后的版本可能会改），所以思考开着的工具循环，第二次请求就是 400（本页的模拟服务器也一样，例子最后演示）。做工具循环和 Agent 时关掉思考：能跑、更快、也更便宜。`with_structured_output` 发的也是 tools，同样关掉：它只有一次请求，暂时碰不到这个 400，但以后改成多轮就会踩到，而且思考按输出价收钱。
--- code
import openai

messages = [HumanMessage("Is unlimited liability acceptable?")]
ai = llm.invoke(messages)
print("content:", repr(ai.content), "| finish:", ai.response_metadata["finish_reason"])
print("tool_calls:", ai.tool_calls)
print("tools sent:", [t["function"]["name"] for t in MOCK.calls[-1]["body"]["tools"]])

title: 手写工具循环
--- body
和第 17 天是同一个循环，只是消息换成了 LangChain 的类：

```python
for step in range(1, max_steps + 1):
    ai = llm.invoke(messages)
    messages.append(ai)
    if not ai.tool_calls:
        return ai.content
    for call in ai.tool_calls:
        messages.append(TOOLS[call["name"]].invoke(call))
```

两个要注意的地方：

- **坏参数**：模型给的参数不是合法 JSON 时，这个调用不在 `tool_calls` 里，而在 `ai.invalid_tool_calls` 里（`finish_reason` 仍然是 `tool_calls`）。上面的循环会以为模型说完了，返回一个空回答。正确做法：给每个坏调用也回一条错误的 ToolMessage，错误是写给模型看的（第 17 天，`review.py` 里的 `INVALID_ARGS`）
- **上限**：模型可能一直调工具（本页的 `[loop]`），所以一定要有 `max_steps`

第 31 天的 `create_agent` 和第 33 天用 LangGraph 搭的 Agent，里面跑的就是这个循环。
--- code
from langchain_core.messages import HumanMessage
from langchain_core.tools import tool
from langchain_deepseek import ChatDeepSeek

@tool
def lookup_playbook(topic: str) -> str:
    """Return the customer's playbook rule for one contract topic."""
    return f"rule for {topic}"

TOOLS = {"lookup_playbook": lookup_playbook}
llm = ChatDeepSeek(model="deepseek-flash", extra_body={"thinking": {"type": "disabled"}}).bind_tools(list(TOOLS.values()))

def naive_loop(question, max_steps=3):
    messages = [HumanMessage(question)]
    for step in range(1, max_steps + 1):
        ai = llm.invoke(messages)
        messages.append(ai)
        if not ai.tool_calls:
            return f"answer after {step} step(s): {ai.content!r}"
        for call in ai.tool_calls:
            messages.append(TOOLS[call["name"]].invoke(call))
    return f"stopped after {max_steps} steps"

print(naive_loop("Is unlimited liability acceptable?"))
print(naive_loop("Is unlimited liability acceptable? [loop]"))
print(naive_loop("Is unlimited liability acceptable? [bad-args]"))
print("  invalid_tool_calls:", [c["name"] for c in llm.invoke("Is unlimited liability acceptable? [bad-args]").invalid_tool_calls])

@@ concept
title: 容错：重试和备用模型
--- body
- **SDK 自带重试**：ChatDeepSeek 底下是 openai SDK，遇到 429、5xx、连不上时会自己重试，默认再试 2 次（一共 3 次），中间指数等待加随机抖动；`ChatDeepSeek(..., max_retries=5)` 可以调。本页不真的等，而是把每次等待记进 `MOCK.sleeps`（数值是随机的，只看个数）
- 重试用完了抛 openai 的异常：`openai.RateLimitError`（429）、`openai.InternalServerError`（500 及以上）、`openai.BadRequestError`（400，这是你的请求写错了，不会重试）。它们都是 `openai.APIStatusError` 的子类，有 `.status_code`。Traceback 里看到的类名是 langchain-openai（本页 1.6）再包一层的子类（比如 `OpenAIRateLimitError`、`OpenAIAPIError`），它们继承自这些 openai 异常，所以 `except openai.RateLimitError` 照样接得住
- **你自己的不稳定步骤**（比如调一个偶尔连不上的内部服务）：`RunnableLambda(fn).with_retry(stop_after_attempt=3, retry_if_exception_type=(ConnectionError,))`，只重试你列出来的异常。它默认在两次之间指数等待，测试里用 `wait_exponential_jitter=False` 不等
- **备用模型**：`primary.with_fallbacks([backup])`：primary 抛异常（它自己的重试用完以后）就换 backup，比如 flash → v4-pro。用 `exceptions_to_handle=(...)` 限定哪些错误才换：400 是你的 bug，换个模型只会把它藏起来
- 超时：`ChatDeepSeek(..., timeout=30)`
--- code
import openai
from langchain_core.runnables import RunnableLambda
from langchain_deepseek import ChatDeepSeek

OFF = {"thinking": {"type": "disabled"}}
flash = ChatDeepSeek(model="deepseek-flash", extra_body=OFF)

MOCK.fail_next(429, 2)
print("429 x2:", flash.invoke("hi").content, "| requests", len(MOCK.calls), "| waits", len(MOCK.sleeps))

MOCK.reset()
MOCK.fail_next(503, 3)
try:
    flash.invoke("hi")
except openai.InternalServerError as e:
    print("503 x3: gave up,", e.status_code, "| requests", len(MOCK.calls))

safe = flash.with_fallbacks(
    [ChatDeepSeek(model="deepseek-v4-pro", extra_body=OFF)],
    exceptions_to_handle=(openai.RateLimitError, openai.InternalServerError),
)
MOCK.reset()
MOCK.fail_next(503, 3)
print("fallback:", safe.invoke("hi").content, [c["body"]["model"] for c in MOCK.calls])
MOCK.reset()
MOCK.fail_next(400, 1)
try:
    safe.invoke("hi")
except openai.BadRequestError as e:
    print("400: no fallback,", e.status_code, [c["body"]["model"] for c in MOCK.calls])

attempts = []
def flaky_lookup(topic):
    attempts.append(topic)
    if len(attempts) < 3:
        raise ConnectionError("playbook service unreachable")
    return f"rule for {topic}"

lookup = RunnableLambda(flaky_lookup).with_retry(stop_after_attempt=3, retry_if_exception_type=(ConnectionError,), wait_exponential_jitter=False)
print("with_retry:", lookup.invoke("payment"), "after", len(attempts), "attempts")

@@ concept
title: 观测：回调
--- body
每次模型调用的前后，LangChain 都会通知**回调**（callback handler）。记 token、记耗时、把整条链上报给追踪平台，都是靠它。

- 统计用量：`with get_usage_metadata_callback() as cb:` 里面所有调用的 token，按模型名加在一起，看 `cb.usage_metadata`
- 自己写：继承 `BaseCallbackHandler`，实现 `on_chat_model_start(serialized, messages, **kwargs)`、`on_llm_end(response, **kwargs)`、`on_llm_error(error, **kwargs)`
- 坑：回调里抛出的异常默认**不会**让调用失败，LangChain 只打一行 `Error in ... callback` 的日志（`raise_error` 默认是 False）。回调写错了很容易没发现，测试时设 `handler.raise_error = True`
- 传给一次调用：`chain.invoke(x, config={"callbacks": [h], "tags": ["review"], "metadata": {"clause_id": "8.1"}})`。回调会沿着整条链传下去，tags 和 metadata 也会带到每一步（LangChain 自己还会加几个 tag，比如 `seq:step:2` 表示链里的第几步）

追踪平台就是这样接进来的：LangSmith 的追踪本身就是一个回调（`LangChainTracer`），设置环境变量 `LANGSMITH_TRACING=true` 和它的 API key 后，LangChain 会自动把它加上；Langfuse 也提供给 LangChain 用的回调（导入路径以它的文档为准）。Clause Check 没用 LangChain，所以 `tracing.py` 用的是 Langfuse 的 `@observe` 装饰器，没配 key 时它什么都不做。
--- code
from langchain_core.callbacks import BaseCallbackHandler, get_usage_metadata_callback
from langchain_core.output_parsers import StrOutputParser
from langchain_core.prompts import ChatPromptTemplate
from langchain_deepseek import ChatDeepSeek

model = ChatDeepSeek(model="deepseek-flash", extra_body={"thinking": {"type": "disabled"}})
chain = ChatPromptTemplate.from_messages([("user", "Review clause {clause_id}: {text}")]) | model | StrOutputParser()

with get_usage_metadata_callback() as cb:
    chain.invoke({"clause_id": "3.1", "text": "Fees are due in 30 days."})
    chain.invoke({"clause_id": "8.1", "text": "Liability is unlimited."})
print(cb.usage_metadata)

class PrintCalls(BaseCallbackHandler):
    def on_chat_model_start(self, serialized, messages, *, tags=None, metadata=None, **kwargs):
        print(f"  start: {len(messages[0])} message(s), tags={tags}, clause={metadata.get('clause_id')}")

    def on_llm_end(self, response, **kwargs):
        usage = response.generations[0][0].message.usage_metadata
        print(f"  end:   {usage['total_tokens']} tokens")

    def on_llm_error(self, error, **kwargs):
        print(f"  error: {error.status_code}")

config = {"callbacks": [PrintCalls()], "tags": ["review"], "metadata": {"clause_id": "3.1"}}
chain.invoke({"clause_id": "3.1", "text": "Fees are due."}, config=config)
MOCK.reset()
MOCK.fail_next(503, 3)
try:
    model.invoke("hi", config={"callbacks": [PrintCalls()], "metadata": {}})
except Exception:
    print(f"  (the SDK sent {len(MOCK.calls)} requests; the callback saw one call and one error)")

title: 成本：按用量算钱
--- body
DeepSeek 当前的价格（2026 年 9 月官方价格页，美元 / 百万 token）：`deepseek-flash` 高峰时段，输入命中缓存 0.006、没命中 0.30、输出 1.20；`deepseek-v4-pro` 分别是 0.044、1.32、3.96。低谷时段半价。高峰时段：周一到周五 UTC 01:00–04:00 和 06:00–10:00（中国法定节假日除外），其他时间都是低谷。

```
费用 = (cache_read × 命中价 + (input_tokens − cache_read) × 没命中价 + output_tokens × 输出价) / 1_000_000
```

- `input_tokens` **已经包括**命中缓存的部分，所以没命中的 = input − cache_read
- 思考的 token 算在 `output_tokens` 里，按**输出价**收费。一次审查思考几百个 token，比回答本身贵好几倍，这就是分类、审查要关掉思考的原因
- 价格变得很快：写进配置，报数字之前先看官方价格页（项目 `config.py` 里记的还是停用前 deepseek-chat 的价格）
--- code
from langchain_deepseek import ChatDeepSeek

PRICE = {"hit": 0.006, "miss": 0.30, "output": 1.20}   # deepseek-flash, peak, USD per 1M tokens

def cost(usage, peak=True):
    hit = usage["input_token_details"].get("cache_read", 0)
    miss = usage["input_tokens"] - hit
    usd = (hit * PRICE["hit"] + miss * PRICE["miss"] + usage["output_tokens"] * PRICE["output"]) / 1_000_000
    return usd if peak else usd / 2

SYSTEM = "You review contract clauses for the Customer against the playbook. " * 8
on = ChatDeepSeek(model="deepseek-flash")
off = ChatDeepSeek(model="deepseek-flash", extra_body={"thinking": {"type": "disabled"}})

def show(name, model):
    u = model.invoke([("system", SYSTEM), ("user", "Review clause 8.1: liability is unlimited.")]).usage_metadata
    print(f"{name}: input {u['input_tokens']} (cache {u['input_token_details']['cache_read']}), "
          f"output {u['output_tokens']} (reasoning {u['output_token_details'].get('reasoning', 0)}) "
          f"-> ${cost(u):.7f} peak, ${cost(u, peak=False):.7f} off-peak, ${1000 * cost(u):.4f} per 1000 clauses")

show("thinking on ", on)
MOCK.reset()                  # 清空模拟服务器记住的前缀，公平地比较
show("thinking off", off)
show("off + cache ", off)     # 同样的开头再来一次：命中缓存

from typing import Literal
from pydantic import BaseModel

class ClauseReview(BaseModel):
    """Review of one contract clause."""
    clause_id: str
    verdict: Literal["accept", "flag", "redline"]
    risk_level: Literal["low", "medium", "high"]
    rationale: str

FALLBACK = "Automatic review did not complete; needs human review."

def safe_review(model, clause_id, text):
    reviewer = model.with_structured_output(ClauseReview, include_raw=True)
    result = reviewer.invoke(f"Review clause {clause_id}: {text}")
    review = result["parsed"]
    if review is None:

    return review

from langchain_core.messages import ToolMessage

def run_tools(ai_message, tools):
    by_name = {t.name: t for t in tools}
    results = []
    for call in ai_message.tool_calls:
        tool = by_name.get(call["name"])
        if tool is None:
            results.append(ToolMessage(f"UNKNOWN_TOOL: {call['name']}", tool_call_id=call["id"], status="error"))
            continue
        try:
            results.append(tool.invoke(call))
        except Exception as e:
            results.append(ToolMessage(f"ERROR: {type(e).__name__}: {e}", tool_call_id=call["id"], status="error"))
    for bad in ai_message.invalid_tool_calls:
        results.append(ToolMessage("INVALID_ARGS: arguments are not valid JSON", tool_call_id=bad["id"], status="error"))
    return results

from langchain_core.callbacks import BaseCallbackHandler

class CallLog(BaseCallbackHandler):
    def __init__(self):
        super().__init__()
        self.calls = 0
        self.errors = 0
        self.tokens = 0
        self.clause_ids = []

    def on_chat_model_start(self, serialized, messages, **kwargs):
        self.calls += 1
        self.clause_ids.append((kwargs.get("metadata") or {}).get("clause_id"))

    def on_llm_end(self, response, **kwargs):
        usage = response.generations[0][0].message.usage_metadata or {}
        self.tokens += usage.get("total_tokens", 0)

    def on_llm_error(self, error, **kwargs):
        self.errors += 1

from typing import Literal
import openai
from pydantic import BaseModel

class Verdict(BaseModel):
    """Verdict for one contract clause."""
    clause_id: str
    verdict: Literal["accept", "flag", "redline"]
    risk_level: Literal["low", "medium", "high"]
    rationale: str

def review(model, clause_id, text):
    fallback = Verdict(clause_id=clause_id, verdict="flag", risk_level="medium", rationale="Automatic review did not complete.")
    reviewer = model.with_structured_output(Verdict, include_raw=True)
    messages = [("system", "You review contract clauses for the Customer."), ("user", f"Review clause {clause_id}: {text}")]
    try:
        result = reviewer.invoke(messages)
    except openai.APIStatusError:
        return fallback
    verdict = result["parsed"]
    if verdict is None:
        return fallback
    verdict.clause_id = clause_id
    return verdict

--- solution
from langchain_core.messages import HumanMessage, ToolMessage
from langchain_core.tools import tool

CLAUSES = {"12": "The limitations in Section 8 shall not apply to Customer.", "8.1": "Each party's liability is capped at the fees paid."}

@tool
def get_clause(clause_id: str) -> str:
    """Fetch the text of another clause of the same contract by its number, e.g. '12'."""
    return CLAUSES.get(clause_id, f"NOT_FOUND: clause {clause_id}")

def answer_with_tools(model, question, max_steps=3):
    llm = model.bind_tools([get_clause])
    messages = [HumanMessage(question)]
    called = []
    for step in range(1, max_steps + 1):
        ai = llm.invoke(messages)
        messages.append(ai)
        if not ai.tool_calls and not ai.invalid_tool_calls:
            return {"answer": ai.content, "steps": step, "called": called}
        for call in ai.tool_calls:
            messages.append(get_clause.invoke(call))
            called.append(f"get_clause:{call['args']['clause_id']}")
        for bad in ai.invalid_tool_calls:
            messages.append(ToolMessage("INVALID_ARGS: arguments are not valid JSON", tool_call_id=bad["id"], status="error"))
            called.append(f"{bad['name']}:INVALID_ARGS")
    return {"answer": None, "steps": max_steps, "called": called}

from langchain_core.callbacks import get_usage_metadata_callback

PRICES = {
    "deepseek-flash": {"hit": 0.006, "miss": 0.30, "output": 1.20},
    "deepseek-v4-pro": {"hit": 0.044, "miss": 1.32, "output": 3.96},
}

def usage_cost(usage_by_model, peak=True):
    total = 0.0
    for model, usage in usage_by_model.items():
        p = PRICES[model]
        hit = (usage.get("input_token_details") or {}).get("cache_read", 0)
        miss = usage["input_tokens"] - hit
        total += (hit * p["hit"] + miss * p["miss"] + usage["output_tokens"] * p["output"]) / 1_000_000
    if not peak:
        total /= 2
    return round(total, 8)

def run_with_cost(chain, inputs, peak=True):
    with get_usage_metadata_callback() as cb:
        results = chain.batch(inputs)
    return {"results": results, "usd": usage_cost(cb.usage_metadata, peak)}
