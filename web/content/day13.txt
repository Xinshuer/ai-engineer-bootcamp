title: 评测用例是数据，不是感觉
--- body
「我试了几条，看起来没问题」不是证据。评测用例把「什么算对」写成**数据**，任何人、任何时候都能重跑。

Clause Check 的 `evals/cases.json` 里每条用例有 `id`、`kind`、`clause` 和 `expect`：

- `kind`：`must_flag`（有风险，必须拦下）、`must_accept`（普通样板条款，必须放过）、`trap`（交叉引用陷阱）、`injection`（提示注入）
- `expect` 写**允许的答案集合** `verdict_in`，不是唯一答案：flag 和 redline 都算「拦下了」
- 正确答案来自**人的判断**，不是模型说的
- 线上每出一个错，先把它变成一条用例（`learn/04_failure_to_dataset.md`）

`harness.py` 的 `check()` 返回**失败原因的列表**，空列表就是通过。好处是失败时知道为什么失败。
--- code
CASES = [
    {"id": "unlimited-liability", "kind": "must_flag", "clause": "Customer's liability shall be unlimited.",
     "expect": {"verdict_in": ["flag", "redline"], "risk_in": ["high"]}},
    {"id": "payment-net-30", "kind": "must_accept", "clause": "Fees are payable within thirty (30) days.",
     "expect": {"verdict_in": ["accept"]}},
]

def check(case, result):
    fails = []
    e = case["expect"]
    if result["verdict"] not in e["verdict_in"]:
        fails.append(f"verdict {result['verdict']} not in {e['verdict_in']}")
    return fails

results = {
    "unlimited-liability": {"verdict": "accept", "risk_level": "low"},
    "payment-net-30": {"verdict": "accept", "risk_level": "low"},
}
for case in CASES:
    fails = check(case, results[case["id"]])
    print(f"{case['id']:<22} {'PASS' if not fails else 'FAIL'} {fails}")

@@ concept
title: 跑 N 次，看通过率
mock: yes
--- body
同一条用例，模型这次对、下次错。所以每条用例要跑 N 次，报**通过率**（通过次数 ÷ N），而不是「对」或「错」。

- N 至少 5：跑 1 次对了可能只是运气；5 次对 3 次（60%）说明这条不稳
- 回顾第 7 天：pass@k（k 次里至少对一次）很容易接近 100%；pass^k（k 次全对）才是无人值守要看的。`run_evals.py` 的表里就有 `pass^k` 一列
- 本页的模拟服务器对 AS IS 免责条款故意摇摆（约 60% 判 accept）。`MOCK.reset()` 会把它的随机种子复位，所以同样的代码每次跑出同样的数，测试才能写死期望值

`classify` 的请求和昨天一样带着 `"thinking": {"type": "disabled"}`：评测要把每条用例调很多次，判一条条款又用不着长推理，关掉思考模式更快、更便宜，`temperature` 也重新起作用。

下面的例子里，跑 1 次是 100%，跑多了才看出它其实不稳。
--- code
import json
import os
import requests

URL = "https://api.deepseek.com/v1/chat/completions"
HEADERS = {"Authorization": f"Bearer {os.getenv('DEEPSEEK_API_KEY')}"}

def classify(clause_text):
    body = {"model": "deepseek-flash", "messages": [{"role": "user", "content": clause_text}],
            "response_format": {"type": "json_object"}, "thinking": {"type": "disabled"}}
    content = requests.post(URL, headers=HEADERS, json=body).json()["choices"][0]["message"]["content"]
    return json.loads(content)

AS_IS = 'Review clause 7.2: THE SERVICE IS PROVIDED "AS IS" AND EACH PARTY DISCLAIMS ALL OTHER WARRANTIES.'
for n in [1, 5, 20]:
    MOCK.reset()
    verdicts = [classify(AS_IS)["verdict"] for _ in range(n)]
    print("runs =", n, " accept rate =", verdicts.count("accept") / n, " all passed:", all(v == "accept" for v in verdicts))

@@ concept
title: 混淆矩阵、精确率、召回率
--- body
把「这条有风险吗」当成是非题。真实答案来自用例（`must_flag` 是有风险），模型的答案是「标记了吗」（verdict 不是 accept）。四种组合：

- **TP**：有风险，标记了（抓对了）
- **FP**：没风险，却标记了（误报，律师白看一眼）
- **FN**：有风险，却放过了（漏报，最危险）
- **TN**：没风险，放过了

**精确率** precision = TP ÷ (TP + FP)：标记出来的里面，有多少是真问题。
**召回率** recall = TP ÷ (TP + FN)：真有风险的里面，抓住了多少。

合同审查里，漏掉一条无限责任条款（FN）比多标一条（FP）代价大得多，所以项目最看重**高风险召回率**（`harness.py` 的 `high_risk_recall`，`run_evals.py` 要求它至少 0.9）。分母可能是 0（一条风险用例都没有），要先判断，项目里这时返回 1.0。
--- code
truth = [True, True, True, False, False]     # 真有风险吗（来自用例）
flagged = [True, True, False, True, False]   # 模型标记了吗
pairs = list(zip(truth, flagged))
tp = sum(1 for t, f in pairs if t and f)
fp = sum(1 for t, f in pairs if not t and f)
fn = sum(1 for t, f in pairs if t and not f)
tn = sum(1 for t, f in pairs if not t and not f)
print("TP FP FN TN =", tp, fp, fn, tn)
print("precision =", round(tp / (tp + fp), 2))
print("recall    =", round(tp / (tp + fn), 2))

@@ concept
title: 函数是值：装饰器
--- body
函数可以当值传来传去（第 2 天的 `sorted(key=...)`，昨天的 `ask=call_model`），也可以**返回一个新函数**。

装饰器就是这样一个函数：收进一个函数，返回一个「包了一层」的新函数。新函数在调用前后做点事（计时、计数、记日志），中间照常调用原函数，并且**把结果 return 出去**。

```python
@logged
def section_of(clause_id): ...
# 完全等于：section_of = logged(section_of)
```

`*args, **kwargs`（第 8 天读过）让包装函数能接住任何参数，原样转交。`@functools.wraps(fn)` 把原函数的名字和文档复制到包装函数上，否则 `section_of.__name__` 会变成 `"wrapper"`，追踪里全是 wrapper。

`clausecheck/tracing.py` 的 `@observe` 就是装饰器：配了 Langfuse 密钥时用 Langfuse 的版本，每次调用记成一个 span；没配时退化成一个原样调用的包装，什么都不做。
--- code
import functools

def logged(fn):
    @functools.wraps(fn)
    def wrapper(*args, **kwargs):
        print("->", fn.__name__, args)
        result = fn(*args, **kwargs)
        print("<-", fn.__name__, result)
        return result
    return wrapper

@logged
def section_of(clause_id):
    return clause_id.split(".")[0]

print(section_of("8.1"))
print("name:", section_of.__name__)

@@ concept
title: 计时、假时钟、带参数的装饰器
--- body
`time.perf_counter()` 返回一个专门用来算时间差的秒数，前后各取一次相减：`ms = round((end - start) * 1000)`。一次计时记成一个 **span**，比如 `{"name": "review_clause", "ms": 250}`。Langfuse 里看到的就是一串 span。

真实时间每次都不一样，测试没法写死期望值。办法：**把时钟当参数传进来**，默认用 `time.perf_counter`，测试时换成一个假时钟，按顺序吐出事先准备好的时间。`iter(列表)` 把列表变成「一个一个往外取」的迭代器，`next(it)` 取下一个。

装饰器要带参数时（`@timed(clock=...)`，就像 `tracing.py` 的 `@observe(name="review_clause")`），要**多套一层**：`timed(clock)` 先返回一个装饰器，装饰器再返回包装函数。
--- code
import functools
import time

def fake_clock(times):
    it = iter(times)
    return lambda: next(it)

def measure(fn, clock=time.perf_counter):
    start = clock()
    result = fn()
    return result, round((clock() - start) * 1000)

print(measure(lambda: "flag", clock=fake_clock([10.0, 10.25])))
print("real clock is fast:", measure(lambda: "flag")[1] < 1000)

def tagged(label):                        # 第 1 层：收参数
    def decorator(fn):                    # 第 2 层：收函数
        @functools.wraps(fn)
        def wrapper(*args, **kwargs):     # 第 3 层：每次调用时运行
            print(f"[{label}] {fn.__name__}{args}")
            return fn(*args, **kwargs)
        return wrapper
    return decorator

@tagged("eval")
def section_of(clause_id):
    return clause_id.split(".")[0]

print(section_of("8.1"))

@@ concept
title: with 和上下文管理器
--- body
`with open(...) as f:` 保证文件用完一定关上，哪怕中间出错。你也可以自己写这种「进去时做一件事，出来时**一定**做另一件事」的东西：

```python
from contextlib import contextmanager

@contextmanager
def span(name):
    start = time.perf_counter()
    try:
        yield            # with 里面的代码在这里运行
    finally:
        record(name, start)   # 不管有没有出错都会执行
```

`yield` 把控制权交给 `with` 里面的代码；`finally` 保证出错时也记下这个 span。追踪最需要的恰恰是**出错**那次调用的记录。

经典错误：用 `except Exception:` 代替 `finally`。这样错误被吞掉了，调用方以为一切正常。
--- code
from contextlib import contextmanager

SPANS = []

@contextmanager
def span(name):
    ok = False
    try:
        yield
        ok = True
    finally:
        SPANS.append({"name": name, "ok": ok})

with span("split"):
    parts = "8.1 Cap\n8.2 Exclusions".split("\n")

try:
    with span("review"):
        raise RuntimeError("API error 503")
except RuntimeError as e:
    print("caught:", e)

for s in SPANS:
    print(s)

title: token、缓存命中率、延迟分位数
--- body
把每次调用的 `usage` 加起来，就是这次评测（或这份合同）的总账：

- **总 token** 和**缓存命中率** `hit ÷ (hit + miss)`：命中率低，说明请求开头有东西在变（昨天学的）
- **成本**：第 7 天的 `estimate_cost`；给客户报价时换算成「每 100 份合同多少钱」。开着思考模式时，推理 token 也算在 `completion_tokens` 里（其中推理占多少，看 `usage["completion_tokens_details"]["reasoning_tokens"]`），按输出价格收费
- **延迟不要只看平均**：一次 30 秒的卡顿会被一堆 1 秒的调用平均掉。要看 **p50**（一半的调用比它快）和 **p95**（95% 的调用比它快，代表「慢的那批」有多慢）

最简单的分位数算法（nearest-rank）：排好序，取第 `ceil(p ÷ 100 × n)` 个（从 1 开始数）。下面 10 个延迟里，p50 是第 5 个，p95 是第 10 个。
--- code
latencies = [1450, 820, 30000, 1010, 1200, 950, 1100, 2100, 1300, 1600]
ordered = sorted(latencies)
print("mean:", sum(latencies) / len(latencies))
print("p50: ", ordered[4])
print("p95: ", ordered[9])

usage = [
    {"prompt_cache_hit_tokens": 0, "prompt_cache_miss_tokens": 900},
    {"prompt_cache_hit_tokens": 832, "prompt_cache_miss_tokens": 70},
    {"prompt_cache_hit_tokens": 832, "prompt_cache_miss_tokens": 95},
]
hit = sum(u["prompt_cache_hit_tokens"] for u in usage)
miss = sum(u["prompt_cache_miss_tokens"] for u in usage)
print("cache hit ratio:", round(hit / (hit + miss), 2))

@@ concept
title: A/B 对比：一次只改一个东西
--- body
改了 prompt，怎么知道变好了？**同一批用例、同样的 N**，两个版本各跑一遍，逐条并排比。三条规矩（`learn/05_prompt_ab.md`）：

- **一次只改一个东西**，否则不知道是谁起的作用
- 先看高风险召回有没有掉，再看误报有没有少
- 总分变高也要逐条看：一条从 3/3 掉到 1/3 就是回归，要查

`run_evals.py` 用 f-string 把表格对齐：`{x:<10}` 左对齐占 10 格，`{x:>6}` 右对齐占 6 格，`{rate:.0%}` 把 0.8 显示成 `80%`，合起来就是 `{rate:>6.0%}`。
--- code
A = {"unlimited-liability": 1.0, "mutual-warranty-disclaimer": 0.4, "payment-net-30": 1.0}
B = {"unlimited-liability": 1.0, "mutual-warranty-disclaimer": 0.8, "payment-net-30": 0.6}
print(f"{'case':<28}{'v1':>6}{'v2':>6}")
for case_id in A:
    a, b = A[case_id], B[case_id]
    note = "  <- worse" if b < a else ""
    print(f"{case_id:<28}{a:>6.0%}{b:>6.0%}{note}")

from collections import Counter

verdicts = ["accept", "flag", "accept", "accept", "flag"]
counts = Counter(verdicts)
print(counts.most_common(1))
print(counts["accept"] / len(verdicts))

--- explain

--- solution
import json
import os
import requests

URL = "https://api.deepseek.com/v1/chat/completions"
HEADERS = {"Authorization": f"Bearer {os.getenv('DEEPSEEK_API_KEY')}"}

def classify(clause_text):
    body = {"model": "deepseek-flash", "messages": [{"role": "user", "content": clause_text}],
            "response_format": {"type": "json_object"}, "thinking": {"type": "disabled"}}
    content = requests.post(URL, headers=HEADERS, json=body).json()["choices"][0]["message"]["content"]
    return json.loads(content)

def check_case(case, result):
    fails = []
    e = case["expect"]
    if result["verdict"] not in e["verdict_in"]:
        fails.append(f"verdict {result['verdict']} not in {e['verdict_in']}")
    if "risk_in" in e and result["risk_level"] not in e["risk_in"]:
        fails.append(f"risk {result['risk_level']} not in {e['risk_in']}")
    return fails

def pass_rate(case, runs, review=classify):
    if runs < 1:
        raise ValueError("runs must be at least 1")
    passed = 0
    for _ in range(runs):
        if not check_case(case, review(case["clause"])):

import functools
import time

SPANS = []

def timed(clock=time.perf_counter):
    def decorator(fn):
        @functools.wraps(fn)
        def wrapper(*args, **kwargs):
            start = clock()
            try:
                result = fn(*args, **kwargs)
            except Exception as e:
                SPANS.append({"name": fn.__name__, "ms": round((clock() - start) * 1000), "error": type(e).__name__})
                raise
            SPANS.append({"name": fn.__name__, "ms": round((clock() - start) * 1000)})
            return result
        return wrapper
    return decorator

import time
from contextlib import contextmanager

STACK = []

@contextmanager
def span(name, spans, clock=time.perf_counter):
    parent = STACK[-1] if STACK else None
    STACK.append(name)
    start = clock()
    ok = False
    try:
        yield
        ok = True
    finally:
        STACK.pop()
        spans.append({"name": name, "parent": parent, "ms": round((clock() - start) * 1000), "ok": ok})

import math

def percentile(values, p):
    if not values or not 0 <= p <= 100:
        raise ValueError("need values and 0 <= p <= 100")
    ordered = sorted(values)
    rank = max(math.ceil(p / 100 * len(ordered)), 1)
    return ordered[rank - 1]

- 被装饰的函数抛出任何 `Exception`，就再调一次，一共最多调用 `times` 次

- `times` 次全失败：把**最后一次**的异常原样抛出

import functools

def retry(times):
    if times < 1:
        raise ValueError("times must be at least 1")
    def decorator(fn):
        @functools.wraps(fn)
        def wrapper(*args, **kwargs):
            last = None
            for _ in range(times):
                try:
                    return fn(*args, **kwargs)
                except Exception as e:
                    last = e
            raise last
        return wrapper
    return decorator

--- context
评测跑完，最后要给出一份简短的成绩单：四个格子各有几条，再加一行精确率和召回率，可以直接贴进周报，也能和上一次的成绩对比。
--- prompt
写 `report(cases, predictions)`：

- `cases`：`{"id": ..., "kind": ...}` 的列表；`kind` 是 `"must_accept"` 的算没风险，其他都算有风险
- `predictions`：`{用例 id: 判定}`；判定不是 `"accept"` 就算标记了；某条用例在 `predictions` 里**没有**，算没标记
- 返回字典，键是 `"TP"`、`"FP"`、`"FN"`、`"TN"`、`"precision"`、`"recall"`、`"line"`
- precision = TP ÷ (TP + FP)，recall = TP ÷ (TP + FN)，都用 `round(x, 2)`；分母为 0 时都返回 `1.0`
- `"line"` 是 `f"precision {precision:.2f}  recall {recall:.2f}"`（中间两个空格）
--- solution
def report(cases, predictions):
    tp = fp = fn = tn = 0
    for case in cases:
        risky = case["kind"] != "must_accept"
        flagged = predictions.get(case["id"], "accept") != "accept"
        if risky and flagged:
            tp += 1
        elif flagged:
            fp += 1
        elif risky:
            fn += 1
        else:
            tn += 1
    precision = round(tp / (tp + fp), 2) if tp + fp else 1.0
    recall = round(tp / (tp + fn), 2) if tp + fn else 1.0
    return {"TP": tp, "FP": fp, "FN": fn, "TN": tn, "precision": precision, "recall": recall,
            "line": f"precision {precision:.2f}  recall {recall:.2f}"}
