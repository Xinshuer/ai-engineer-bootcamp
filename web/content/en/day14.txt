@@ concept
title: Splitting up the project: five files, three kinds of data
--- body
A real project doesn't put all its code in one function. It splits the code by the rule "one file does one job". The mini version uses the same file names as Clause Check:

- `models.py`: what the data looks like (`Clause`, `Verdict`, `ClauseReview`)
- `split.py`: read the file and split it into clauses. Plain code, no model calls
- `review.py`: the **only** place that calls the model: send the request, validate, retry
- `pipeline.py`: connect the pieces above, summarize, write the report
- `cli.py`: parse the command-line arguments, call the pipeline, return the exit code

Data flows between the files like this: the full contract text `str` → `list[Clause]` → `list[ClauseReview]` → report `dict` → JSON file. **Use a dataclass for data you produce yourself** (light, no validation); **use Pydantic for data that comes from outside** (the model's answer can break the rules at any time, so it must be validated).
--- code
from dataclasses import dataclass, asdict
from typing import Literal
from pydantic import BaseModel

@dataclass
class Clause:              # produced by split.py: our own data, no validation needed
    id: str
    heading: str
    text: str

class Verdict(BaseModel):  # the model's answer: outside data, must be validated
    clause_id: str
    verdict: Literal["accept", "flag", "redline"]
    risk_level: Literal["low", "medium", "high"]
    topic: str
    rationale: str

@dataclass
class ClauseReview:        # produced by review.py, summarized by pipeline.py
    clause_id: str
    verdict: str
    risk: str
    tokens: int

c = Clause("8.1", "Cap on Liability", "Customer's liability shall be unlimited.")
raw = '{"clause_id": "8.1", "verdict": "redline", "risk_level": "high", "topic": "liability_cap", "rationale": "no cap"}'
v = Verdict.model_validate_json(raw)
r = ClauseReview(c.id, v.verdict, v.risk_level, 180)
print(c)
print(v.verdict, v.risk_level)
print(asdict(r))

@@ concept
title: Start small: get one clause working first
mock: yes
--- body
The approach most likely to fail: write all five files in one go, then run them and stare at a screen full of errors with no idea where to start.

The right order:

1. Hard-code **one** clause and take it all the way through "call the model → validate → print", and see the correct result with your own eyes
2. Once that works, switch to a loop and run three clauses
3. Then add one piece at a time: retry, summary, writing the report, command-line arguments

Run the code after every piece you add. Then, when something breaks, you only need to look at **the few lines you just added**. Today's P1–P7 follow exactly this order.

Every review request today carries Day 12's `"thinking": {"type": "disabled"}`: reviewing one clause at a time doesn't need long reasoning, so turning thinking mode off makes it faster and cheaper, and `temperature` works again.
--- code
import os
import requests
from typing import Literal
from pydantic import BaseModel

API_URL = "https://api.deepseek.com/v1/chat/completions"
HEADERS = {"Authorization": f"Bearer {os.getenv('DEEPSEEK_API_KEY')}"}

class Verdict(BaseModel):
    clause_id: str
    verdict: Literal["accept", "flag", "redline"]
    risk_level: Literal["low", "medium", "high"]

def review_one(clause_id, text):
    body = {
        "model": "deepseek-flash",
        "messages": [{"role": "user", "content": f"Review clause {clause_id}: {text}"}],
        "response_format": {"type": "json_object"},
        "thinking": {"type": "disabled"},
    }
    data = requests.post(API_URL, headers=HEADERS, json=body, timeout=60).json()
    return Verdict.model_validate_json(data["choices"][0]["message"]["content"])

# Step 1: hard-code one clause and see a result first
print(review_one("8.1", "Customer's liability shall be unlimited."))

# Step 2: once one clause works, switch to a loop
for cid, text in [("3.1", "Fees are payable within thirty days."), ("4.2", "Renews for twenty-four (24) months.")]:
    v = review_one(cid, text)
    print(cid, v.verdict, v.risk_level)

@@ concept
title: Validate at the door
--- body
Data enters the program through three doors: **files** (may not exist, may be empty), **the model's answer** (may not be JSON, may have invalid values) and **command-line arguments** (may be misspelled).

Check once at the door: if something is wrong, immediately raise an error that says clearly what (or have the model answer again). Data that made it through the door can be trusted, so the functions inside don't need `if` checks everywhere.

- Files: checked in `read_contract`, which raises `FileNotFoundError` / `ValueError`
- The model: `review_clause` validates with Pydantic; on failure it tells the model the error and has it answer again
- Arguments: argparse's `choices` checks them for you

A common mistake: passing the model's answer along without validating it, until `summarise` sorts and hits a `KeyError` on a `"HIGH"`. By then you are far away from where things actually went wrong.
--- code
import argparse
import json
from typing import Literal
from pydantic import BaseModel, ValidationError

class Verdict(BaseModel):
    verdict: Literal["accept", "flag", "redline"]
    risk_level: Literal["low", "medium", "high"]

RISK_RANK = {"high": 0, "medium": 1, "low": 2}
raw = '{"verdict": "flag", "risk_level": "HIGH"}'   # the model wrote it in uppercase

# No check at the door: the error shows up only when sorting, far from the cause
try:
    RISK_RANK[json.loads(raw)["risk_level"]]
except KeyError as e:
    print("found only in summarise:", repr(e))

# Check at the door: you know what's wrong as soon as the answer arrives
try:
    Verdict.model_validate_json(raw)
except ValidationError as e:
    print("found right away in review:", e.errors()[0]["loc"], e.errors()[0]["msg"])

# Command-line arguments: choices is the check at the door
parser = argparse.ArgumentParser(prog="minicheck")
parser.add_argument("--only-risk", choices=["low", "medium", "high"])
try:
    parser.parse_args(["--only-risk", "urgent"])
except SystemExit as e:
    print("argparse refused it, exit code", e.code)

--- prompt
Recap of Day 8 (dataclass, sorting by several keys): write the output. Notice the difference between sorting strings and sorting by number.
--- code
from dataclasses import dataclass

RISK_RANK = {"high": 0, "medium": 1, "low": 2}

@dataclass
class ClauseReview:
    clause_id: str
    verdict: str
    risk: str

reviews = [
    ClauseReview("10.1", "redline", "high"),
    ClauseReview("3.2", "flag", "medium"),
    ClauseReview("8.1", "redline", "high"),
    ClauseReview("3.1", "accept", "low"),
]
print(sorted(r.clause_id for r in reviews))
by_number = sorted(reviews, key=lambda r: tuple(int(x) for x in r.clause_id.split(".")))
print([r.clause_id for r in by_number])
urgent = sorted(reviews, key=lambda r: (RISK_RANK[r.risk], r.clause_id))
print([r.clause_id for r in urgent])
print(reviews[0])
--- explain
Strings are compared one character at a time, and `"1"` is smaller than `"8"`, so `"10.1"` comes before `"8.1"`. In the third line's sort key the clause number is still a string, so it falls into the same trap. Today's `summarise` compares clause numbers as integer tuples like `(10, 1)`. The last line is the `__repr__` that dataclass generates for you.

from pathlib import Path

def read_contract(path):
    p = Path(path)
    if not p.exists():
        raise FileNotFoundError(f"contract not found: {path}")
    text = p.read_text(encoding="utf-8")
    if not text.strip():
        raise ValueError(f"contract is empty: {path}")
    return text

import re
from dataclasses import dataclass

HEAD = re.compile(r"^(\d+(?:\.\d+)*)\.?\s+([A-Z].*)$")

@dataclass
class Clause:
    id: str
    heading: str
    text: str

def split_clauses(text):
    clauses = []
    current = None
    for line in text.split("\n"):
        m = HEAD.match(line.strip())
        if m:
            current = Clause(m.group(1), m.group(2), "")
            clauses.append(current)
        elif current is not None:
            current.text += line + "\n"
    for c in clauses:
        c.text = c.text.strip()
    return [c for c in clauses if c.text]

        resp = requests.post(API_URL, headers=headers, json=body, timeout=60)
        if resp.status_code == 200:
            return [[resp.json()]]

    body = {"model": "deepseek-flash", "messages": messages, "response_format": {"type": "json_object"},
            "thinking": {"type": "disabled"}}

        resp = requests.post(API_URL, headers=headers, json=body, timeout=60)
        if resp.status_code == 200:
            return resp.json()

            raise RuntimeError(f"API error {resp.status_code}")

    messages = [
        {"role": "system", "content": SYSTEM},
        {"role": "user", "content": f"Review clause {clause.id}: {clause.text}"},
    ]
    tokens = 0
    for _ in range(2):
        data = call(messages)
        tokens += data["usage"]["total_tokens"]
        content = data["choices"][0]["message"]["content"]
        try:
            v = Verdict.model_validate_json(content)
        except ValidationError as e:
            messages.append({"role": "assistant", "content": content})
            messages.append({"role": "user", "content": f"Invalid reply: {e.errors()[0]['msg']}. Reply with the JSON object only."})
            continue
        return ClauseReview(clause.id, v.verdict, v.risk_level, tokens)
    raise RuntimeError(f"clause {clause.id}: no valid JSON after 2 attempts")

from dataclasses import dataclass

RISK_RANK = {"high": 0, "medium": 1, "low": 2}

@dataclass
class ClauseReview:
    clause_id: str
    verdict: str
    risk: str
    tokens: int

def id_key(clause_id):
    return tuple(int(x) for x in clause_id.split("."))

def summarise(reviews):
    counts = {"accept": 0, "flag": 0, "redline": 0}
    for r in reviews:
        counts[r.verdict] += 1
    flagged = [r for r in reviews if r.verdict != "accept"]
    flagged.sort(key=lambda r: (RISK_RANK[r.risk], id_key(r.clause_id)))
    return {
        "clauses": len(reviews),
        "counts": counts,
        "needs_attention": [r.clause_id for r in flagged],
        "tokens": sum(r.tokens for r in reviews),
    }

from collections import defaultdict
from dataclasses import dataclass

RANK = {"high": 0, "medium": 1, "low": 2}

@dataclass
class Finding:
    clause_id: str
    rule_id: str
    severity: str

def id_key(clause_id):
    return tuple(int(x) for x in clause_id.split("."))

def triage(findings):
    by_clause = defaultdict(list)
    for f in findings:
        by_clause[f.clause_id].append(f)
    rows = []
    for cid, fs in by_clause.items():
        worst = min((f.severity for f in fs), key=lambda s: RANK[s])
        rows.append((cid, worst, sorted({f.rule_id for f in fs})))
    rows.sort(key=lambda r: (RANK[r[1]], id_key(r[0])))
    return rows

import json
from pathlib import Path

def append_run(history_path, run, keep=5):
    p = Path(history_path)
    p.parent.mkdir(parents=True, exist_ok=True)
    history = {"runs": []}
    if p.exists():
        try:
            history = json.loads(p.read_text(encoding="utf-8"))
        except json.JSONDecodeError:
            p.rename(p.with_name(p.name + ".bak"))
            history = {"runs": []}
    history["runs"] = (history["runs"] + [run])[-keep:]
    p.write_text(json.dumps(history, indent=2, ensure_ascii=False), encoding="utf-8")
    return history

title: Weekly exam 3: search by clause, with extra weight for headings
exam: yes
level: 3
cards: d11:Keyword search; d11:Chunking: by structure, by length, with overlap
--- context
A lawyer asks "what happens to the data after the contract ends?" The program first finds the few most relevant clauses among dozens, then hands them to the model for a close read. Narrowing it down first means the model reads less text: faster and cheaper.
--- prompt
A contract already comes cut into chunks: its clauses. Write `find_clauses(text, query, k)`:

1. **Chunking**: a line that matches `r"^(\d+(?:\.\d+)*)\.?\s+([A-Z].*)$"` after removing the whitespace at both ends is a clause heading; the lines below it, up to the next heading, are its body; skip headings with an empty body
2. **Words**: lowercase the text, then `re.findall(r"[a-z0-9]+", ...)`
3. **Score** = the number of **distinct** query words that appear in the body + 2 × the number that appear in the heading (the heading says best what the clause is about)
4. Keep only scores > 0; sort by score from high to low, and ties by clause number in numeric order; return a list of `(clause number, score)` tuples for the top `k`

Example: with the query `"effect of termination"`, the clause with the heading `11.2 Effect of Termination` and the body `Data is deleted after termination.` scores 1 + 2 × 3 = 7.
--- solution
import re

HEAD = re.compile(r"^(\d+(?:\.\d+)*)\.?\s+([A-Z].*)$")

def words(text):
    return set(re.findall(r"[a-z0-9]+", text.lower()))

def find_clauses(text, query, k):
    clauses = []
    for line in text.split("\n"):
        m = HEAD.match(line.strip())
        if m:
            clauses.append([m.group(1), m.group(2), []])
        elif clauses:
            clauses[-1][2].append(line)
    q = words(query)
    scored = []
    for cid, heading, lines in clauses:
        body = "\n".join(lines).strip()
        if not body:
            continue
        score = len(q & words(body)) + 2 * len(q & words(heading))
        if score > 0:
            scored.append((cid, score))
    scored.sort(key=lambda s: (-s[1], tuple(int(x) for x in s[0].split("."))))
    return scored[:k]

--- prompt

- At most 3 requests in total (a 429 and a failed validation each count as one); if it still hasn't succeeded, `raise RuntimeError`
--- solution
import os
from typing import Literal
import requests
from pydantic import BaseModel, ValidationError

URL = "https://api.deepseek.com/v1/chat/completions"

class Verdict(BaseModel):
    clause_id: str
    verdict: Literal["accept", "flag", "redline"]
    risk_level: Literal["low", "medium", "high"]

def review(clause_text):
    headers = {"Authorization": f"Bearer {os.getenv('DEEPSEEK_API_KEY')}"}
    messages = [{"role": "user", "content": clause_text}]
    for _ in range(3):
        body = {"model": "deepseek-flash", "messages": messages, "response_format": {"type": "json_object"},
                "thinking": {"type": "disabled"}}
        resp = requests.post(URL, headers=headers, json=body, timeout=60)
        if resp.status_code == 429:
            continue
        if resp.status_code != 200:
            raise RuntimeError(f"API error {resp.status_code}")
        content = resp.json()["choices"][0]["message"]["content"]
        try:
            return Verdict.model_validate_json(content)
        except ValidationError as e:
            messages.append({"role": "assistant", "content": content})
            messages.append({"role": "user", "content": f"Invalid: {e.errors()[0]['msg']}. Reply with the JSON object only."})
    raise RuntimeError("no valid verdict after 3 attempts")

- **flaky**: the ids of the cases whose runs did not all give the same verdict (any kind counts), in the order of `cases`, joined with `", "`; write `-` if there are none

def eval_line(cases, runs):
    hit = total = false_flags = accept_runs = 0
    flaky = []
    for case in cases:
        verdicts = runs.get(case["id"], [])
        if len(set(verdicts)) > 1:
            flaky.append(case["id"])
        for v in verdicts:
            if case["kind"] in ("must_flag", "trap"):
                total += 1
                if v != "accept":
                    hit += 1
            elif case["kind"] == "must_accept":
                accept_runs += 1
                if v != "accept":
                    false_flags += 1
    recall = hit / total if total else 1.0
    return f"high-risk recall {recall:.2f}  false flags {false_flags}/{accept_runs}  flaky: {', '.join(flaky) or '-'}"
