@@ concept
title: Tuples and unpacking
--- body
A tuple `("8.1", "flag")` is like a **small list you can't change**. Use it for "a fixed few things that always go together": a clause number and its verdict, a result and its reason.

- **Unpacking**: `cid, verdict = pair`; the number of variables on the left must match the length of the tuple
- A function that "returns two values" really returns one tuple: `return ok, reason`, and the caller writes `ok, reason = check(...)`
- `a, b = b, a` swaps two variables in one line
- You have been unpacking for a while already: in `for k, v in d.items():` each step gives you a `(key, value)` tuple

A common mistake is trying to change an element of a tuple: `pair[1] = "accept"` raises `TypeError`. To change it, build a new tuple.
--- code
pair = ("8.1", "flag")
cid, verdict = pair
print(cid, verdict, len(pair))

def check(verdict):
    if verdict in ("accept", "flag", "redline"):
        return True, ""
    return False, f"unknown verdict: {verdict}"

ok, reason = check("maybe")
print(ok, reason)
print(check("flag"))

first, second = "8.1", "3.1"
first, second = second, first
print(first, second)

try:
    pair[1] = "accept"
except TypeError as e:
    print("TypeError:", e)

@@ concept
title: enumerate and zip
--- body
- `enumerate(xs)` gives you an `(index, element)` pair each time; `enumerate(xs, 1)` starts counting at 1. Clause Check's `pipeline.py` has exactly `for i, clause in enumerate(clauses, 1):`, used to show "clause i of n". From now on you don't need `for i in range(len(xs))` any more
- `zip(a, b)` **pairs up two lists by position**: `zip(["8.1", "3.1"], ["flag", "accept"])` gives `("8.1", "flag")`, then `("3.1", "accept")`
- `dict(zip(ids, verdicts))` pairs them into a dictionary in one step

Trap: when the two lists have different lengths, `zip` **stops as soon as the shorter one runs out**. The extra items are silently dropped, with no error.
--- code
ids = ["8.1", "3.1", "10.1"]
verdicts = ["flag", "accept", "redline"]

for i, cid in enumerate(ids, 1):
    print(f"{i}/{len(ids)} reviewing {cid}")

for cid, v in zip(ids, verdicts):
    print(cid, "->", v)

print(dict(zip(ids, verdicts)))
print(list(zip(ids, ["flag"])))

@@ concept
title: The set type
--- body
A set `{"PB-01", "PB-03"}` is a collection of elements with **no duplicates and no order**. It is best at two things:

- **Removing duplicates**: `set(["PB-01", "PB-01", "PB-03"])` leaves just two; `s.add(x)` adds one element
- **Checking membership**: `"PB-03" in rules` is fast, however big the set is

Operations between sets match "rule checks" exactly:

- `required - cited`: required but not cited (which ones are missing)
- `required & cited`: in both
- `required | cited`: everything from both together

Two traps: an empty set is written `set()`, because `{}` is an empty **dictionary**; and a set has no order, so when you need stable output, turn it into a sorted list with `sorted(the_set)`.
--- code
required = {"PB-01", "PB-03", "PB-07"}
cited = set(["PB-03", "PB-03", "PB-09"])
print(len(cited))
print(sorted(required - cited))
print(sorted(required & cited))
print(sorted(required | cited))
print("PB-07" in required)

seen = set()
for rid in ["PB-02", "PB-01", "PB-02"]:
    seen.add(rid)
print(sorted(seen))
print(type(set()).__name__, type({}).__name__)

@@ concept
title: More on dictionaries: comprehensions, Counter, defaultdict
--- body
- **Dictionary comprehension**: `{r["id"]: r["verdict"] for r in reviews}`. It works like a list comprehension, only written as `key: value`
- **Counter**: a dictionary made for counting. `Counter(a_list)` does Day 2's counting loop in one line; `.most_common(2)` returns the two most common `(value, count)` pairs; looking up a missing key returns 0 instead of raising an error
- **defaultdict(list)**: when you look up a key that isn't there, it first puts an empty list there for you, so grouping no longer needs `if key not in groups`. `evals/run_evals.py` uses `defaultdict(list)` to collect the results of each test case

Both need an import first: `from collections import Counter, defaultdict`.

Trap: a defaultdict adds a missing key even when you only **read** it. Before you hand it to other code, turn it into a plain dictionary with `dict(groups)`.
--- code
from collections import Counter, defaultdict

reviews = [
    {"id": "3.1", "topic": "payment", "verdict": "accept"},
    {"id": "8.1", "topic": "liability_cap", "verdict": "flag"},
    {"id": "3.2", "topic": "payment", "verdict": "flag"},
]
print({r["id"]: r["verdict"] for r in reviews})

counts = Counter([r["verdict"] for r in reviews])
print(counts)
print(counts.most_common(1), counts["redline"])

groups = defaultdict(list)
for r in reviews:
    groups[r["topic"]].append(r["id"])
print(dict(groups))
print(groups["termination"], len(groups))

@@ concept
title: any and all
--- body
- `any(...)`: True if **at least one** is true. "Did any clause get a redline?"
- `all(...)`: True only if **all of them** are true. "Are all the verdicts valid?"

Inside the parentheses you usually write a **comprehension without the square brackets** (called a generator expression):

```python
any(r["verdict"] == "redline" for r in reviews)
```

It doesn't build a whole list first: it checks as it goes and stops as soon as it knows the answer. You can write the same thing inside `sum(...)`, `max(...)` and `Counter(...)`. `evals/harness.py` has the line `any(t.startswith(prefix) for t in ...)`.

Remember the edge cases: `any([])` is False, and `all([])` is **True** (there is no counterexample, so "all valid" holds). If an empty list means something went wrong in your program, check for it separately.
--- code
reviews = [{"id": "3.1", "verdict": "accept"}, {"id": "8.1", "verdict": "redline"}]
print(any(r["verdict"] == "redline" for r in reviews))
print(all(r["verdict"] in ("accept", "flag", "redline") for r in reviews))
print(sum(1 for r in reviews if r["verdict"] != "accept"))
print(any([]), all([]))

@@ concept
title: Sorting by several keys
--- body
The order a lawyer wants often has more than one condition: "by risk from high to low first, and by clause number when the risk is the same". The trick is to make `key` return a **tuple**. Python compares tuples item by item: the first items first, and only when those are equal, the second:

```python
RISK = {"high": 0, "medium": 1, "low": 2}
sorted(reviews, key=lambda r: (RISK[r["risk"]], r["id"]))
```

- `reverse=True` flips the whole order; to sort one item descending and another ascending, negate the number: `key=lambda r: (-r["tokens"], r["id"])`
- `max(xs, key=...)` finds the "largest" element, and `min` works the same way; add `default=None` when the list may be empty

The clause-number trap: strings are compared one character at a time, so `"10.1" < "8.1"` (because `"1" < "8"`). To sort by clause number, first turn it into a tuple of numbers: `"10.1"` → `(10, 1)`. That is exactly what `_sort_key` in Clause Check's `split.py` does.
--- code
RISK = {"high": 0, "medium": 1, "low": 2}
reviews = [
    {"id": "10.1", "risk": "high", "tokens": 900},
    {"id": "3.1", "risk": "low", "tokens": 300},
    {"id": "8.1", "risk": "high", "tokens": 1200},
]
print(sorted(["10.1", "8.1", "3.1"]))

def id_key(cid):
    return tuple(int(x) for x in cid.split("."))

print(id_key("10.1"), sorted(["10.1", "8.1", "3.1"], key=id_key))
for r in sorted(reviews, key=lambda r: (RISK[r["risk"]], id_key(r["id"]))):
    print(r["risk"], r["id"])
print(max(reviews, key=lambda r: r["tokens"])["id"])
print(max([], key=len, default=None))

@@ concept
title: dataclass: classes that only hold data
--- body
On Day 3, writing a class meant writing `__init__` by hand, one `self.x = x` line after another. When a class mostly holds data, `@dataclass` has Python write that for you:

```python
from dataclasses import dataclass, field

@dataclass
class Clause:
    id: str
    text: str
    risk: str = "low"
    tags: list[str] = field(default_factory=list)
```

You get these for free: `__init__` (`Clause("8.1", "...")`), readable printing `Clause(id='8.1', ...)`, and an `==` that compares field by field. You write methods as usual. `asdict(c)` turns it into a dictionary (handy for writing JSON).

- **Mutable** defaults such as lists and dictionaries must be written `field(default_factory=list)`, so every object gets its own new one; writing `= []` raises an error straight away. Plain functions have the same trap with `def f(tags=[])`; you'll meet it in the exercises
- A dataclass **does no validation**: `Clause(8.1, None)` is created without complaint
--- code
from dataclasses import dataclass, field, asdict

@dataclass
class Clause:
    id: str
    text: str
    risk: str = "low"
    tags: list[str] = field(default_factory=list)

    def is_high(self) -> bool:
        return self.risk == "high"

a = Clause("8.1", "Liability is unlimited.", "high")
b = Clause("3.1", "Fees are due in 30 days.")
print(a)
print(a.is_high(), b.is_high())
b.tags.append("payment")
print(b.tags, a.tags)
print(a == Clause("8.1", "Liability is unlimited.", "high"))
print(asdict(b))

@@ concept
title: *args, **kwargs, and keyword-only parameters
--- body
When you read other people's code (Clause Check included), you often see stars in front of parameters:

- In a definition, `def log(event, *args, **kwargs):` collects extra **positional arguments** into the tuple `args`, and extra **keyword arguments** into the dictionary `kwargs`
- In a call, `f(**d)` unpacks a dictionary into keyword arguments. Day 4's `tools[name](**args)` is exactly this; so is `Settings(**kw)` in `run_evals.py`; and `_create(self, **kwargs)` in `review.py` passes the arguments it receives on, unchanged, to `client.messages.create(**kwargs)`
- `def review(clause_id, *, strict=False):` has a lone `*` in the middle, which means the parameters after it **can only be passed by name**: `review("8.1", strict=True)` works, `review("8.1", True)` raises `TypeError`. That way, anyone reading the call sees at once what that `True` means

When you write your own functions and can list the parameters, don't use `**kwargs`: it lets misspelled parameter names slip through silently.
--- code
def log(event, *args, **kwargs):
    print(event, args, kwargs)

log("review")
log("review", "8.1", "flag", risk="high", ms=120)

def review(clause_id, *, strict=False):
    return f"{clause_id} strict={strict}"

options = {"strict": True}
print(review("8.1"), "|", review("8.1", **options))
try:
    review("8.1", True)
except TypeError as e:
    print("TypeError:", e)

def count_by_risk(reviews):

--- context
Suppose the model reviews a batch of clauses at once and returns a list of verdicts in order. If a single one is missing, every clause number after it is paired with the wrong verdict: the report pins a flag on the wrong clause, and nobody notices.
--- prompt
The model returned a list of verdicts in order, and they must be paired one to one with the clause numbers. Write `verdict_map(ids, verdicts)` that returns `{clause number: verdict}`.

`verdict_map(["8.1", "3.1"], ["flag", "accept"])` → `{"8.1": "flag", "3.1": "accept"}`

If the two lists have different lengths, something went wrong (a clause was skipped?). Then you must not silently drop data the way `zip` does; instead, `raise ValueError(f"length mismatch: {len(ids)} ids, {len(verdicts)} verdicts")`.

(Since Python 3.10, `zip(..., strict=True)` also raises an error when the lengths differ, but here you have to write the clear error message above yourself.)
--- starter
def verdict_map(ids, verdicts):
    return dict(zip(ids, verdicts))
--- solution
def verdict_map(ids, verdicts):
    if len(ids) != len(verdicts):
        raise ValueError(f"length mismatch: {len(ids)} ids, {len(verdicts)} verdicts")
    return dict(zip(ids, verdicts))
--- tests
expect("two clauses", lambda: verdict_map(["8.1", "3.1"], ["flag", "accept"]), {"8.1": "flag", "3.1": "accept"})
expect("empty", lambda: verdict_map([], []), {})
expect_raises("one verdict missing", lambda: verdict_map(["8.1", "3.1"], ["flag"]), ValueError)
def _message():
    try:
        verdict_map(["8.1"], ["flag", "accept"])
    except ValueError as e:
        return str(e)
expect("error message", _message, "length mismatch: 1 ids, 2 verdicts")
--- hints
- The starter code is already right when the lengths match. What's missing: raise an error when they differ.
- Before the `return`, add `if len(ids) != len(verdicts):` with `raise ValueError(...)` inside it.
