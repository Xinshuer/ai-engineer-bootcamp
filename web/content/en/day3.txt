title: import: use code someone else wrote
--- body
Python comes with many "standard library" modules. You `import` a module before you use it:

- `import json`, then write `json.loads(...)`
- `from pathlib import Path` takes just one name from the module; after that, write `Path(...)` directly

print(math.ceil(2.1))

@@ concept
title: JSON: the bridge between text and dictionaries
--- body
The model returns **text**; the program needs a **dictionary**. JSON is the format between the two.

- `json.loads(text)` → a dictionary or list (the s stands for string)
- `json.dumps(obj)` → text; add `ensure_ascii=False` to keep characters like é as they are instead of escaping them, and `indent=2` for tidy indentation

Remember the pairs: JSON's `true` / `false` / `null` are Python's `True` / `False` / `None`; JSON strings **must use double quotes**.
--- code
import json

raw = '{"clause_id": "8.1", "verdict": "flag", "ok": true, "note": null}'
data = json.loads(raw)
print(type(data), data["verdict"], data["ok"], data["note"])

back = json.dumps({"verdict": "accept", "high": False}, indent=2)
print(back)

@@ concept
title: try / except: catch the errors you expect
--- body
Some errors are not bugs: they come from **unreliable outside input**. The JSON the model returned is broken, or a field is missing from the dictionary. In those cases, catch the error with try/except and give a sensible result instead of letting the whole program crash.

```python
try:
    data = json.loads(raw)
except json.JSONDecodeError:
    data = None
```

- Name only the error types you **expect**. Don't write a bare `except:`: it hides real bugs too
- `except SomeError as e:` gives you the error object; `str(e)` is the error message
--- code
import json

for raw in ['{"verdict": "flag"}', "Sure! {bad json"]:
    try:
        data = json.loads(raw)
        print("ok:", data["verdict"])
    except json.JSONDecodeError as e:
        print("bad json:", e)

@@ concept
title: raise: report an error on purpose
--- body
When a function gets input it can't handle, don't quietly return a wrong value. It is better to **raise an error on purpose**:

```python
if risk not in ("low", "medium", "high"):
    raise ValueError(f"unknown risk: {risk}")
```

The caller can catch it with try/except. "Fail early and loudly" is much easier to debug than "quietly compute the wrong answer".
--- code
def parse_risk(text):
    risk = text.strip().lower()
    if risk not in ("low", "medium", "high"):
        raise ValueError(f"unknown risk: {text}")
    return risk

print(parse_risk(" HIGH "))
try:
    parse_risk("urgent")
except ValueError as e:
    print("caught:", e)

@@ concept
title: Reading a multi-level traceback
error_demo: yes
--- body
When a function calls another function, the error lists the **whole chain of calls**, from the outside in: the entry point is at the top, and **the line that actually failed is at the bottom**.

You read it the same way as before: first the error type on the last line, then the `File "main.py", line N, in function_name` right above it. That is where it happened. The levels further up tell you who called it.

Run the code below and find which line of which function fails.
--- code
def summarise(clauses):
    counts = {}
    for c in clauses:
        counts[c["verdict"]] += 1
    return counts

clauses = [{"verdict": "flag"}]
print(summarise(clauses))

@@ concept
title: Regex basics: find patterns in text
--- body
A regular expression (regex) describes what a piece of text looks like. The most common symbols:

- `\d` one digit, `\d+` one or more digits
- `\.` a literal dot (a `.` on its own means "any character")
- `( )` a group: take out only the part inside the parentheses
- `?` the thing before it is optional

`re.findall(pattern, text)` returns every match; `re.search` returns the first match (`None` if there is none), and `.group(1)` gives what the first pair of parentheses matched. Put `r` in front of the pattern string so backslashes stay as they are.
--- code
import re

text = "Subject to Section 12, see also Section 4.2. Pay within 30 days."
print(re.findall(r"\d+", text))
print(re.findall(r"Section (\d+(?:\.\d+)?)", text))
m = re.search(r"(\d+) days", text)
print(m.group(1) if m else None)

@@ concept
title: Classes: keep data and operations together
--- body
A class is a "type" you define yourself. A clause has a number, a heading and a text, plus a few operations that go with them. You can write it like this:

```python
class Clause:
    def __init__(self, clause_id, heading, text):
        self.clause_id = clause_id
        self.heading = heading
        self.text = text

    def is_title(self):
        return self.text.strip() == ""
```

- `__init__` runs automatically when an object is created and stores the data; `self` means "this object itself"
- `Clause("8.1", "Cap", "...")` creates an object; `c.heading` reads an attribute; `c.is_title()` calls a method
- The first parameter of a method is always `self`
--- code
class Clause:
    def __init__(self, clause_id, heading, text):
        self.clause_id = clause_id
        self.heading = heading
        self.text = text

    def is_title(self):
        return self.text.strip() == ""

    def label(self):
        return f"{self.clause_id} {self.heading}"

c = Clause("8.1", "Cap on Liability", "Each party's liability ...")
t = Clause("8", "Limitation of Liability", "")
print(c.label(), c.is_title())
print(t.label(), t.is_title())

@@ concept
title: Type hints: notes for people and tools
--- body
```python
def risk_score(risk: str) -> int:
```

This means "the parameter risk should be a string, and the function returns a whole number". Common forms: `list[str]`, `dict[str, int]`, `str | None` (may be None).

**Python does not check these hints when it runs**: pass the wrong type and it runs anyway. What they are good for: people reading the code see at a glance what to pass; the editor can give hints; and **Pydantic reads these hints to validate data** (tomorrow's topic). TypeScript, on the other hand, really checks them before the code runs (Day 5).
--- code
def risk_score(risk: str) -> int:
    scores: dict[str, int] = {"low": 1, "medium": 2, "high": 3}
    return scores.get(risk, 0)

def first_id(ids: list[str]) -> str | None:
    return ids[0] if ids else None

print(risk_score("high"), risk_score("urgent"))
print(first_id(["3.1", "8.1"]), first_id([]))

--- starter

--- solution
class VerdictTally:
    def __init__(self):
        self.counts = {}

    def add(self, verdict):
        self.counts[verdict] = self.counts.get(verdict, 0) + 1

    def count(self, verdict):
        return self.counts.get(verdict, 0)

    def most_common(self):
        best = None
        for v, n in self.counts.items():
            if best is None or n > self.counts[best]:
                best = v
        return best
--- tests
def _make(*vs):
    t = VerdictTally()
    for v in vs:
        t.add(v)
    return t

expect("empty returns None", lambda: VerdictTally().most_common(), None)
--- hints
- `add` and `count` are just the counting pattern; the dictionary is now `self.counts`.
- `most_common`: loop over `self.counts.items()` and remember the biggest one so far; replace it only when a count is "strictly greater", so a tie keeps the one that appeared first.

--- solution
import json

def parse_result(raw):
    try:
        return {"ok": True, "data": json.loads(raw)}
    except json.JSONDecodeError:
        return {"ok": False, "error": "invalid json"}

Write the class `Rule`: when created, it takes `rule_id`, `topic` and `severity` and stores them as attributes with the same names; the method `is_high()` returns `True` when `severity` is `"high"`; the method `summary()` returns a string like `"PB-01 (payment, high)"`.
--- solution
class Rule:
    def __init__(self, rule_id, topic, severity):
        self.rule_id = rule_id
        self.topic = topic
        self.severity = severity

    def is_high(self):
        return self.severity == "high"

    def summary(self):
        return f"{self.rule_id} ({self.topic}, {self.severity})"
--- tests
