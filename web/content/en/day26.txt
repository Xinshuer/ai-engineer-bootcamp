@@ concept
title: What the cloud is: rented computers, pay as you go
--- body
The cloud is **someone else's computers, rented to you through an API**: you don't buy servers; you call operations like `put_object` and `deploy`, and pay for what you use (how many GB you store, how many seconds you run, how many calls you make).

Three words you will see everywhere:

- **Project / account**: GCP calls it a project (for example `clausecheck-dev`), AWS calls it an account. Billing and permissions hang on it; development and production are usually two separate ones
- **Region**: where the data center is, for example GCP's `europe-north1` (Finland) and AWS's `eu-north-1` (Stockholm). You choose the region when you create a resource; it decides where the data is stored and processed, and compliance (for example "data stays in the EU") depends on it
- **Zone** (availability zone): several independent data centers inside one region; if one has a problem, the others keep running

The services of the two clouds match almost one to one (run the code below). The projects you work on later may use either one, and being able to say things like "GCS is GCP's S3" in an interview earns you points. Names change, so watch for that when you read: AWS App Runner, common in older material, has not accepted new customers since the end of April 2026, and AWS recommends moving to ECS; GCP's Vertex AI was renamed Gemini Enterprise Agent Platform in April 2026 (the API did not change, and docs and interviews still often call it Vertex AI).

@@ concept
title: Object storage: buckets, keys, and bytes
cloud: yes
--- body
**Files** such as contract PDFs and review reports go in object storage: S3 on AWS, Cloud Storage (GCS) on GCP.

- **Bucket**: a big container whose name is unique worldwide, for example `clausecheck-contracts`
- **Key**: the full name of an object, for example `contracts/1/103/original.pdf`. **There are no real folders**: `/` is just a character in the name, and "listing a folder" really means "listing the keys that start with this prefix"
- Object = bytes + metadata: `ContentType` (`application/json`, `application/pdf`) and key-value pairs you add yourself (Metadata; S3 **turns their key names into lowercase**)
- What you read back is **bytes**: in S3 it is `resp["Body"].read()`, and you need `.decode("utf-8")` to get text
- A listing returns at most 1000 keys at a time; for more, you **paginate** (fetch them page by page); when nothing matches, the S3 response doesn't even have a `Contents` key
- With versioning turned on, overwrites and deletes keep the old versions, so you can get back something you deleted by mistake

The boto3 / google-cloud on this page are simulated: the calls and the shape of what they return match the real SDKs (only the parts this course uses are implemented); in a real project you run `pip install boto3 google-cloud-storage` and set up credentials. The two buckets `clausecheck-contracts` and `clausecheck-reports` already exist.
--- code
import json
import boto3
from google.cloud import storage

report = {"contract_id": 103, "counts": {"redline": 2, "flag": 1}}

# AWS S3: one client; the method names are the API names, and every argument is passed by keyword
s3 = boto3.client("s3", region_name="eu-north-1")
s3.put_object(Bucket="clausecheck-reports", Key="reports/103.json",
              Body=json.dumps(report).encode("utf-8"),
              ContentType="application/json", Metadata={"Contract-Id": "103"})
resp = s3.get_object(Bucket="clausecheck-reports", Key="reports/103.json")
print(resp["ContentType"], resp["Metadata"])
print(json.loads(resp["Body"].read().decode("utf-8")))

# GCP Cloud Storage: client → bucket → blob (one object)
gcs = storage.Client()
blob = gcs.bucket("clausecheck-reports").blob("reports/103.json")
blob.upload_from_string(json.dumps(report), content_type="application/json")
print(blob.content_type, json.loads(blob.download_as_text()))

# a "folder" is just a prefix
page = s3.list_objects_v2(Bucket="clausecheck-reports", Prefix="reports/")
print([o["Key"] for o in page["Contents"]], page["IsTruncated"])
print([b.name for b in gcs.list_blobs("clausecheck-reports", prefix="reports/")])
empty = s3.list_objects_v2(Bucket="clausecheck-reports", Prefix="archive/")
print("Contents" in empty, empty.get("Contents", []))

title: Identity and credentials: who is calling
cloud: yes
--- body
Every API call has to answer "who are you?". In the cloud there are two kinds of identity:

- **People**: your own account, used when you develop on your own computer
- **Machines**: a **service account** on GCP, an **IAM role** on AWS. A Cloud Run service or a Lambda function runs with this identity built in, so the code contains no keys at all

The SDK looks for credentials automatically, in a fixed order (the credential chain), so the same code works unchanged on your computer and in production:

- AWS: environment variables (`AWS_ACCESS_KEY_ID` and so on) → the `~/.aws/` config on your computer (written by `aws configure` or `aws configure sso`) → the role the runtime environment provides
- GCP: **Application Default Credentials (ADC)**: the file that `GOOGLE_APPLICATION_CREDENTIALS` points to → the account you logged in with via `gcloud auth application-default login` on your computer → the service account attached to the runtime environment

**Never** write access keys or a service account's JSON key file into code, and never commit them to git.

One detail: `boto3.client(...)` doesn't check credentials. Only the **first real call** signs the request and raises `NoCredentialsError`; that is not a `ClientError`, so `except ClientError` won't catch it. Google's client looks for credentials as soon as it is created.
--- code
import boto3
import google.auth.exceptions
from botocore.exceptions import ClientError, NoCredentialsError
from google.cloud import storage

# CLOUD exists only in this page's simulation: pretend this computer has no credentials at all
CLOUD.aws_credentials = False
CLOUD.gcp_adc = False

s3 = boto3.client("s3", region_name="eu-north-1")
print("boto3 client created, no credentials checked yet")
try:
    s3.list_objects_v2(Bucket="clausecheck-contracts")
except ClientError as e:
    print("ClientError:", e)
except NoCredentialsError as e:
    print(type(e).__name__, "-", e)
    print("is it a ClientError?", isinstance(e, ClientError))

try:
    storage.Client()
except google.auth.exceptions.DefaultCredentialsError as e:
    print(type(e).__name__, "-", str(e).split(".")[0])

@@ concept
title: IAM: grant only what is needed
--- body
IAM decides "what this identity may do to which resource". The principle is **least privilege**: grant only the few actions the job needs, and only on the resources that need them.

Clause Check's review worker needs only this: read contracts in `clausecheck-contracts`, write reports to `clausecheck-reports`, read the DeepSeek API key. It doesn't need to delete contracts, and it doesn't need to touch any other bucket.

- AWS: attach a policy to the worker's role. `Action` lists specific actions (`s3:GetObject`), `Resource` lists specific ARNs (`arn:aws:s3:::clausecheck-contracts/*`)
- GCP: grant roles to the service account **on the bucket**, for example `roles/storage.objectViewer` on the contracts bucket, `roles/storage.objectCreator` on the reports bucket, and `roles/secretmanager.secretAccessor` on the secret. Note that `objectCreator` can only create new objects; it **cannot overwrite** existing ones. If reports have to be rewritten, switch to the broader `roles/storage.objectUser` (which can also delete)

When you see **403 / AccessDenied / PermissionDenied**: most likely the code isn't wrong; the identity is missing a permission. Three questions to ask: which identity made this call (`aws sts get-caller-identity`)? Which action is missing (the error message usually says)? Which resource was the permission granted on?

A trap: when S3 reads a key that **doesn't exist** and the identity doesn't have the `s3:ListBucket` permission, you get 403 AccessDenied, not 404 NoSuchKey.

Below is a **minimal** policy checker that helps you understand the shape of a policy. Real IAM also has Deny (an explicit deny always wins), conditions, and merging of several policies.
--- code
from fnmatch import fnmatch

WORKER_POLICY = {
    "Version": "2012-10-17",
    "Statement": [
        {"Effect": "Allow", "Action": ["s3:GetObject"], "Resource": ["arn:aws:s3:::clausecheck-contracts/*"]},
        {"Effect": "Allow", "Action": ["s3:PutObject"], "Resource": ["arn:aws:s3:::clausecheck-reports/*"]},
        {"Effect": "Allow", "Action": ["secretsmanager:GetSecretValue"],
         "Resource": ["arn:aws:secretsmanager:eu-north-1:123456789012:secret:clausecheck/deepseek-*"]},
    ],
}

def allowed(policy, action, resource):
    for st in policy["Statement"]:
        if st["Effect"] == "Allow" and action in st["Action"] and any(fnmatch(resource, r) for r in st["Resource"]):
            return True
    return False

checks = [
    ("s3:GetObject", "arn:aws:s3:::clausecheck-contracts/contracts/1/103/original.pdf"),
    ("s3:PutObject", "arn:aws:s3:::clausecheck-reports/reports/103.json"),
    ("s3:DeleteObject", "arn:aws:s3:::clausecheck-contracts/contracts/1/103/original.pdf"),
    ("s3:GetObject", "arn:aws:s3:::clausecheck-billing/invoices/2026-09.csv"),
]
for action, resource in checks:
    verdict = "ALLOW" if allowed(WORKER_POLICY, action, resource) else "DENY "
    print(verdict, action.ljust(16), resource.split(":::")[1])

@@ concept
title: Secret management: not in code, not in images
cloud: yes
--- body
When you develop on your own computer, API keys go in `.env` (Day 10). In production you don't do that: no secret may appear in the code repository, in a container image, or in the logs.

In production you use a **secret management service**: Secret Manager on GCP, Secrets Manager on AWS. Secrets are stored encrypted, IAM controls who can read them, reads can be recorded in audit logs (on AWS that is CloudTrail; on GCP you first have to turn on the "Data Access" audit logs for Secret Manager, which are off by default), and secrets can be **rotated** (swap in a new one and retire the old one).

- GCP: the name is `projects/<project>/secrets/<name>/versions/latest`; the `payload.data` you read back is **bytes**, so you need `.decode("utf-8")`
- AWS: `get_secret_value(SecretId=...)["SecretString"]` is a **string**; when the secret stores key-value pairs it is a piece of JSON, so you need `json.loads`
- Read it once when the process starts and **cache** it; don't read it on every request: every read adds latency, and reads are billed per call. The price: after a rotation you have to restart (or let the cache expire) before the new secret is used
- Another common approach: Cloud Run can inject a secret from Secret Manager directly as an environment variable, and the code keeps using `os.getenv` as before

When you print a secret, show only its first few characters; not a single complete secret should end up in the logs.
--- code
import json
import boto3
from google.cloud import secretmanager

gsm = secretmanager.SecretManagerServiceClient()
name = "projects/clausecheck-dev/secrets/deepseek-api-key/versions/latest"
resp = gsm.access_secret_version(name=name)
print(type(resp.payload.data).__name__, resp.payload.data.decode("utf-8")[:6] + "...")

asm = boto3.client("secretsmanager", region_name="eu-north-1")
secret = asm.get_secret_value(SecretId="clausecheck/deepseek")
print(type(secret["SecretString"]).__name__, secret["SecretString"][:14] + "...")
print(json.loads(secret["SecretString"])["api_key"][:6] + "...")

title: Errors and retries: retry only temporary errors
cloud: yes
--- body
Cloud API errors come in two kinds, and you handle them in completely different ways:

- **Temporary**: rate limits (429, `ThrottlingException`, S3's `SlowDown`) and server-side 5xx errors (`ServiceUnavailable`). Wait a little and try again, and it usually works
- **Permanent**: 404 not found, 403 no permission, 400 bad parameters. A hundred retries give the same result, so raise the error right away

The good news: the SDK retries temporary errors by itself. By default (legacy mode) boto3 tries 5 times in total, in standard mode 3 times; you can set this with `Config(retries={"mode": "standard", "total_max_attempts": 3})`. google-cloud-storage also retries reads. So when a rate-limit error reaches your code, it means "the SDK has already tried several times".

When you write retries yourself (for calls the SDK doesn't retry, or when a whole step has to start over): retry only temporary errors, use **exponential backoff** (0.5 s, 1 s, 2 s, …), multiply by **random jitter** (so that many clients don't all retry at the same instant), and set a limit. The operation you retry should ideally be **idempotent**: writing the same content to the same key again leaves the result unchanged.

The two clouds' errors look different: boto3 raises almost nothing but `ClientError`, and you look at `e.response["Error"]["Code"]`; Google has a different exception class for each status code (`NotFound`, `TooManyRequests`), and you look at the class or at `e.code`. Don't match on the text of the error message: it can change at any time.
--- code
import boto3
from botocore.config import Config
from botocore.exceptions import ClientError
from google.cloud import storage
from google.api_core.exceptions import NotFound

s3 = boto3.client("s3", region_name="eu-north-1")
CLOUD.fail_next("s3", "throttle", 2)            # simulation: the next two requests get rate-limited
resp = s3.list_objects_v2(Bucket="clausecheck-reports")
print("succeeded; the SDK retried", resp["ResponseMetadata"]["RetryAttempts"], "times behind the scenes")

no_retry = boto3.client("s3", region_name="eu-north-1", config=Config(retries={"total_max_attempts": 1}))
CLOUD.fail_next("s3", "throttle", 1)
try:
    no_retry.list_objects_v2(Bucket="clausecheck-reports")
except ClientError as e:
    print(e.response["Error"]["Code"], e.response["ResponseMetadata"]["HTTPStatusCode"], "-> transient, retry later")

try:
    s3.get_object(Bucket="clausecheck-reports", Key="reports/999.json")
except ClientError as e:
    print(e.response["Error"]["Code"], "-> permanent, do not retry")

gcs = storage.Client()
try:
    gcs.bucket("clausecheck-reports").blob("reports/999.json").download_as_text()
except NotFound as e:
    print(type(e).__name__, e.code, "-> permanent, do not retry")

@@ concept
title: Data residency: contracts stay in the EU
cloud: yes
--- body
Contracts contain names, email addresses and signatories: all of this is **personal data**. The EU's **GDPR**, in plain words: you need a legitimate reason to process personal data, you collect only what you need, and you protect it; moving it outside the EU needs extra legal safeguards. That is why customers often write "data may only be stored and processed in the EU" into their contracts. Rule **PB-03** (Data location and DPA) in the project's playbook reviews exactly this kind of clause, and of course Clause Check itself has to meet it too:

- Buckets, databases, logs and backups are all created in EU regions: AWS `eu-north-1` (Stockholm), GCP `europe-north1` (Finland)
- Sending contract text to a model is "processing" too: the model's inference also has to run in the EU (Bedrock and Vertex AI, tomorrow)
- Both clouds do **encryption at rest** by default, but encryption doesn't change which country the data is in

State the region when you create a bucket: to create an S3 bucket outside `us-east-1` you must pass `CreateBucketConfiguration={"LocationConstraint": region}`, or you get `IllegalLocationConstraintException`; when GCS's `create_bucket` is called without a `location`, the default is `US` (a multi-region in the United States).
--- code
import boto3
from botocore.exceptions import ClientError
from google.cloud import storage

s3 = boto3.client("s3", region_name="eu-north-1")
try:
    s3.create_bucket(Bucket="clausecheck-contracts-se")
except ClientError as e:
    print(e.response["Error"]["Code"])
s3.create_bucket(Bucket="clausecheck-contracts-se",
                 CreateBucketConfiguration={"LocationConstraint": "eu-north-1"})
print("S3 bucket created in", s3.meta.region_name)

gcs = storage.Client()
print(gcs.create_bucket("clausecheck-contracts-fi", location="europe-north1").location)
print(gcs.create_bucket("clausecheck-tmp").location, "<- no location given")

title: Cost and the command line
--- body
A cloud bill mainly comes from: compute (how many seconds things ran), storage (per GB per month), **egress** (data downloaded from the cloud to the outside world, charged per GB, a common source of surprise bills) and the number of API calls. For Clause Check, storing contracts costs almost nothing; most of the money goes to model tokens (run the estimate below).

- **Storage classes**: data you use often goes in Standard; old contracts that are rarely read can move automatically to cheap cold storage (S3 Glacier, GCS Coldline / Archive) through lifecycle rules, but getting them back costs extra
- **Budgets and alerts**: both clouds let you set a monthly budget and send you an email when you reach 50% and 90% of it. Set one up on the day you open the account. Note that a budget **only warns you; it doesn't stop your services**. For a hard cap you still need limits such as a maximum number of instances (tomorrow)
- Prices change often; the unit prices in the code are only examples to show the order of magnitude; the official pricing pages are what counts

Command lines show up everywhere in docs and interviews; being able to read them is enough:

```
gcloud auth list                          # which account is active now
gcloud auth application-default login     # log in for ADC on your computer
gcloud storage cp report.json gs://clausecheck-reports/reports/
aws sts get-caller-identity               # who am I now (the first step when you debug a 403)
aws s3 cp report.json s3://clausecheck-reports/reports/
aws s3 ls s3://clausecheck-reports/reports/
```
--- code
# example unit prices (USD), only to show the order of magnitude; the official pricing pages are what counts
STORAGE_PER_GB_MONTH = 0.02
EGRESS_PER_GB = 0.1
TOKENS_PER_CONTRACT = 150_000
USD_PER_MILLION_TOKENS = 0.5

def monthly_cost(contracts, mb_per_contract=2, downloads_per_contract=3):
    gb = contracts * mb_per_contract / 1024
    storage = gb * STORAGE_PER_GB_MONTH
    egress = gb * downloads_per_contract * EGRESS_PER_GB
    llm = contracts * TOKENS_PER_CONTRACT / 1_000_000 * USD_PER_MILLION_TOKENS
    return {"storage": round(storage, 4), "egress": round(egress, 4), "llm": round(llm, 2)}

for n in (100, 1000):
    print(n, "contracts/month:", monthly_cost(n))

A review of Day 25. The code below is meant to print `query failed` when the query goes wrong, but the table name `clausecheck.review` is missing an s (`client` is `bigquery.Client()`). What happens when it runs?
--- code
from google.api_core.exceptions import GoogleAPICallError

try:
    job = client.query("SELECT verdict FROM clausecheck.review")
except GoogleAPICallError:
    print("query failed")
rows = list(job.result())

- It prints `query failed`
- Nothing is printed: `client.query()` only submits a query job; the "table does not exist" error is raised only at `job.result()`, and that line is not inside the `try`, so the program crashes with `NotFound`

--- explain

type: code
title: The key for a contract
level: 2
cards: Object storage: buckets, keys, and bytes
--- context
Suppose Clause Check has moved to the cloud: contracts that customers upload go into object storage (the place in the cloud where files live), and each file is found by its name (its key). This function decides what each contract is called in the bucket. The file name was chosen by the user, so it can contain any character.
--- prompt
A contract's name (key) in the bucket must be **predictable**: with one prefix per customer, listing all of a customer's contracts or granting access for one customer only needs the prefix. Write `contract_key(customer_id, contract_id, filename)` that returns `contracts/<customer_id>/<contract_id>/<cleaned file name>`.

The file name comes from the user's upload and can't be used as it is (a `/` in it would become a fake "folder"). The cleaning rules:

- convert to lowercase
- replace each run of characters that are "not a–z, 0–9 or `.`" with **one** `-`
- remove `-` at both ends
- if the cleaned name is an empty string: `raise ValueError("empty filename")`

Example: `contract_key(2, 103, "Hospital Software License v2.PDF")` → `"contracts/2/103/hospital-software-license-v2.pdf"`
--- starter
import re

def contract_key(customer_id, contract_id, filename):
    return f"contracts/{customer_id}/{contract_id}/{filename}"
--- solution
import re

def contract_key(customer_id, contract_id, filename):
    name = re.sub(r"[^a-z0-9.]+", "-", filename.lower()).strip("-")
    if not name:
        raise ValueError("empty filename")
    return f"contracts/{customer_id}/{contract_id}/{name}"
--- tests
expect("the example from the prompt", lambda: contract_key(2, 103, "Hospital Software License v2.PDF"), "contracts/2/103/hospital-software-license-v2.pdf")
expect("brackets, a dash and spaces in a row become a single -", lambda: contract_key(1, 101, "Contract (final) — Nordlys AB.pdf"), "contracts/1/101/contract-final-nordlys-ab.pdf")
expect("/ must not become a folder", lambda: contract_key(1, 101, "../reports/x.json"), "contracts/1/101/..-reports-x.json")
expect("- at both ends is removed", lambda: contract_key(4, 108, "  NDA!  .txt"), "contracts/4/108/nda-.txt")
expect_raises("empty after cleaning", lambda: contract_key(1, 101, "???"), ValueError)
--- hints
- `re.sub(pattern, "-", text)` replaces every match with `-`. "Not one of these characters" is written `[^a-z0-9.]`, and a `+` after it means "a run of them".
- First `.lower()`, then replace, and finally `.strip("-")` to remove the `-` at both ends.

Write the output. Watch three things: what type `Body` gives you when you read it; the case of the metadata key names; where `ContentType` comes from.
--- code
import json
import boto3

s3 = boto3.client("s3", region_name="eu-north-1")
s3.put_object(
    Bucket="clausecheck-reports",
    Key="reports/103.json",
    Body=json.dumps({"contract_id": 103, "redlines": 2}),
    ContentType="application/json",
    Metadata={"Contract-Id": "103", "Prompt-Version": "v2"},

--- explain
`Body` is a stream, and `.read()` gives you **bytes** (it can be read only once); `json.loads` accepts bytes too, but to print it or work with it as a string, `.decode("utf-8")` it first. S3 stored the metadata key names in lowercase, so `.get("Contract-Id")` is `None`: in your code, always read them with lowercase names. `ContentType` is what you told S3 at upload time; without it, it is `binary/octet-stream`, and the browser doesn't know how to open the file.

--- context
The contract text a customer uploads has to be stored in S3. Next to the file you can also attach a few small labels (metadata) that record the contract number and the prompt version, so later you know which contract it is and which prompt version reviewed it without opening the file.
--- prompt
Write `upload_contract(s3, bucket, key, text, contract_id, prompt_version)`: upload the contract text to S3 and return the `ETag` that S3 gives back.

- For `Body`, use the UTF-8 encoded bytes `text.encode("utf-8")` (if you pass a str directly, boto3 also encodes it as UTF-8; writing it out means anyone reading the code sees at once what is stored)

def list_all_keys(s3, bucket, prefix, page_size=1000):
    keys = []
    kwargs = {"Bucket": bucket, "Prefix": prefix, "MaxKeys": page_size}
    while True:
        resp = s3.list_objects_v2(**kwargs)
        keys += [obj["Key"] for obj in resp.get("Contents", [])]

from botocore.exceptions import ClientError
from google.api_core.exceptions import TooManyRequests, ServiceUnavailable, InternalServerError

RETRYABLE_AWS_CODES = {"ThrottlingException", "SlowDown", "ServiceUnavailable", "InternalError"}

def is_retryable(error):
    if isinstance(error, ClientError):
        return error.response["Error"]["Code"] in RETRYABLE_AWS_CODES
    return isinstance(error, (TooManyRequests, ServiceUnavailable, InternalServerError))

def with_backoff(fn, sleep, attempts=4, base=0.5):
    for attempt in range(attempts):
        try:
            return fn()
        except Exception as e:
            if not is_retryable(e) or attempt == attempts - 1:
                raise
            sleep(base * 2 ** attempt)

from botocore.exceptions import ClientError

MAX_MINUTES = 7 * 24 * 60

def share_link(s3, bucket, key, minutes):
    if minutes < 1 or minutes > MAX_MINUTES:
        raise ValueError(f"minutes must be between 1 and {MAX_MINUTES}")
    try:
        s3.head_object(Bucket=bucket, Key=key)
    except ClientError as e:
        if e.response["Error"]["Code"] == "404":
            raise FileNotFoundError(key)
        raise
    return s3.generate_presigned_url("get_object", Params={"Bucket": bucket, "Key": key}, ExpiresIn=minutes * 60)

def archive_contracts(s3, customer_id, page_size=1000):
    src, dst = "clausecheck-contracts", "clausecheck-archive"
    kwargs = {"Bucket": src, "Prefix": f"contracts/{customer_id}/", "MaxKeys": page_size}
    keys = []
    while True:
        resp = s3.list_objects_v2(**kwargs)
        keys += [obj["Key"] for obj in resp.get("Contents", [])]
        if not resp.get("IsTruncated"):
            break
        kwargs["ContinuationToken"] = resp["NextContinuationToken"]
    for key in keys:
        obj = s3.get_object(Bucket=src, Key=key)
        s3.put_object(Bucket=dst, Key=key, Body=obj["Body"].read(), ContentType=obj["ContentType"])
        s3.delete_object(Bucket=src, Key=key)
    return keys

--- context
When many workers get rate-limited at the same time and all wait exactly as long before retrying, they all crash into the limit again at the same instant. If each worker's wait is a little random, the retries spread out.
--- prompt
Write `call_with_retry(fn, sleep, rand, attempts=5, base=0.2, cap=2.0)`:

- Call `fn()`, and return its result on success
- On failure, first decide whether it can be retried: a `botocore.exceptions.ClientError` whose error code is in `{"ThrottlingException", "SlowDown", "ServiceUnavailable"}`; or `TooManyRequests` or `ServiceUnavailable` from `google.api_core.exceptions`. Raise an error that can't be retried right away
- After failure number `i` (counting `i` from 0), wait `min(cap, base * 2 ** i) * rand()` seconds (exponential backoff + a cap + random jitter). `sleep(seconds)` and `rand()` (which returns a number between 0 and 1) are both passed in
- Call `fn` at most `attempts` times in total; when the last call fails, raise that error without waiting
--- solution
from botocore.exceptions import ClientError
from google.api_core.exceptions import TooManyRequests, ServiceUnavailable

AWS_RETRYABLE = {"ThrottlingException", "SlowDown", "ServiceUnavailable"}

def _retryable(e):
    if isinstance(e, ClientError):
        return e.response["Error"]["Code"] in AWS_RETRYABLE
    return isinstance(e, (TooManyRequests, ServiceUnavailable))

def call_with_retry(fn, sleep, rand, attempts=5, base=0.2, cap=2.0):
    for i in range(attempts):
        try:
            return fn()
        except Exception as e:
            if not _retryable(e) or i == attempts - 1:
                raise
            sleep(min(cap, base * 2 ** i) * rand())
