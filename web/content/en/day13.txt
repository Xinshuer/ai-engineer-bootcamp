@@ concept
title: Eval cases are data, not gut feeling
--- body
"I tried a few and they looked fine" is not evidence. Eval cases write down "what counts as right" as **data**, so anyone can rerun them at any time.

In Clause Check's `evals/cases.json`, each test case has an `id`, a `kind`, a `clause` and an `expect`:

- `kind`: `must_flag` (risky, must be stopped), `must_accept` (ordinary boilerplate, must be let through), `trap` (a cross-reference trap), `injection` (prompt injection)
- `expect` lists the **set of allowed answers** `verdict_in`, not one single answer: flag and redline both count as "stopped"
- The right answers come from **human judgment**, not from what the model says
- Every time something goes wrong in production, first turn it into a test case (bootcamp: `lessons/04_failure_to_dataset.md`)

`check()` in `harness.py` returns a **list of failure reasons**; an empty list means it passed. The benefit: when it fails, you know why.
--- code
CASES = [
    {"id": "unlimited-liability", "kind": "must_flag", "clause": "Customer's liability shall be unlimited.",
     "expect": {"verdict_in": ["flag", "redline"], "risk_in": ["high"]}},
    {"id": "payment-net-30", "kind": "must_accept", "clause": "Fees are payable within thirty (30) days.",
     "expect": {"verdict_in": ["accept"]}},
]

def check(case, result):
    fails = []
    e = case["expect"]
    if result["verdict"] not in e["verdict_in"]:
        fails.append(f"verdict {result['verdict']} not in {e['verdict_in']}")
    return fails

results = {
    "unlimited-liability": {"verdict": "accept", "risk_level": "low"},
    "payment-net-30": {"verdict": "accept", "risk_level": "low"},
}
for case in CASES:
    fails = check(case, results[case["id"]])
    print(f"{case['id']:<22} {'PASS' if not fails else 'FAIL'} {fails}")

@@ concept
title: Run N times, look at the pass rate
mock: yes
--- body
The same test case can be right this time and wrong the next. So you run each test case N times and report a **pass rate** (passes ÷ N), not just "right" or "wrong".

- N at least 5: one correct run may just be luck; 3 right out of 5 (60%) says this case is unstable
- Remember Day 7: pass@k (right at least once in k runs) easily gets close to 100%; pass^k (right all k times) is what counts when nobody is watching. The table from `run_evals.py` has a `pass^k` column
- The mock server on this page deliberately wavers on the AS IS disclaimer clause (about 60% accept). `MOCK.reset()` resets its random seed, so the same code gives the same numbers every run, and the tests can fix the expected values

As yesterday, the `classify` request carries `"thinking": {"type": "disabled"}`: evals call each test case many times, and judging one clause doesn't need long reasoning, so with thinking mode off it is faster and cheaper, and `temperature` works again.

In the example below, 1 run gives 100%; only more runs show that it is actually unstable.
--- code
import json
import os
import requests

URL = "https://api.deepseek.com/v1/chat/completions"
HEADERS = {"Authorization": f"Bearer {os.getenv('DEEPSEEK_API_KEY')}"}

def classify(clause_text):
    body = {"model": "deepseek-flash", "messages": [{"role": "user", "content": clause_text}],
            "response_format": {"type": "json_object"}, "thinking": {"type": "disabled"}}
    content = requests.post(URL, headers=HEADERS, json=body).json()["choices"][0]["message"]["content"]
    return json.loads(content)

AS_IS = 'Review clause 7.2: THE SERVICE IS PROVIDED "AS IS" AND EACH PARTY DISCLAIMS ALL OTHER WARRANTIES.'
for n in [1, 5, 20]:
    MOCK.reset()
    verdicts = [classify(AS_IS)["verdict"] for _ in range(n)]
    print("runs =", n, " accept rate =", verdicts.count("accept") / n, " all passed:", all(v == "accept" for v in verdicts))

@@ concept
title: Confusion matrix, precision, recall
--- body
Treat "is this clause risky?" as a yes/no question. The true answer comes from the test case (`must_flag` means risky); the model's answer is "did it flag it?" (the verdict is not accept). That gives four combinations:

- **TP**: risky, and flagged (caught correctly)
- **FP**: not risky, but flagged (a false alarm: the lawyer takes a look for nothing)
- **FN**: risky, but let through (a miss: the most dangerous one)
- **TN**: not risky, and let through

**Precision** = TP ÷ (TP + FP): of the clauses flagged, how many are real problems.
**Recall** = TP ÷ (TP + FN): of the clauses that really are risky, how many were caught.

In contract review, missing an unlimited-liability clause (FN) costs far more than flagging one clause too many (FP), so the project cares most about **high-risk recall** (`high_risk_recall` in `harness.py`; `run_evals.py` requires at least 0.9). The denominator can be 0 (no risky test cases at all), so check for that first; the project returns 1.0 in that case.
--- code
truth = [True, True, True, False, False]     # really risky? (from the test cases)
flagged = [True, True, False, True, False]   # did the model flag it?
pairs = list(zip(truth, flagged))
tp = sum(1 for t, f in pairs if t and f)
fp = sum(1 for t, f in pairs if not t and f)
fn = sum(1 for t, f in pairs if t and not f)
tn = sum(1 for t, f in pairs if not t and not f)
print("TP FP FN TN =", tp, fp, fn, tn)
print("precision =", round(tp / (tp + fp), 2))
print("recall    =", round(tp / (tp + fn), 2))

@@ concept
title: Functions are values: decorators
--- body
Functions can be passed around as values (Day 2's `sorted(key=...)`, yesterday's `ask=call_model`), and a function can also **return a new function**.

A decorator is exactly such a function: it takes a function in and returns a new function that "wraps" it. The new function does something before and after the call (timing, counting, logging), calls the original function in the middle as usual, and **returns its result**.

```python
@logged
def section_of(clause_id): ...
# exactly the same as: section_of = logged(section_of)
```

`*args, **kwargs` (from Day 8) let the wrapper accept any arguments and pass them on unchanged. `@functools.wraps(fn)` copies the original function's name and docstring onto the wrapper; otherwise `section_of.__name__` becomes `"wrapper"`, and your traces are full of wrapper.

`@observe` in `clausecheck/tracing.py` is a decorator: when Langfuse keys are configured it uses Langfuse's version and records each call as a span; when they are not, it falls back to a wrapper that just calls the function and does nothing else.
--- code
import functools

def logged(fn):
    @functools.wraps(fn)
    def wrapper(*args, **kwargs):
        print("->", fn.__name__, args)
        result = fn(*args, **kwargs)
        print("<-", fn.__name__, result)
        return result
    return wrapper

@logged
def section_of(clause_id):
    return clause_id.split(".")[0]

print(section_of("8.1"))
print("name:", section_of.__name__)

@@ concept
title: Timing, fake clocks, decorators with arguments
--- body
`time.perf_counter()` returns a number of seconds made for measuring time differences: read it once before and once after, and subtract: `ms = round((end - start) * 1000)`. One timing is recorded as a **span**, for example `{"name": "review_clause", "ms": 250}`. What you see in Langfuse is a series of spans.

Real time is different on every run, so a test can't fix the expected value. The fix: **pass the clock in as a parameter**. By default it is `time.perf_counter`; in tests you swap in a fake clock that hands out prepared times in order. `iter(list)` turns a list into an iterator that gives its items out "one at a time", and `next(it)` takes the next one.

When a decorator needs arguments (`@timed(clock=...)`, like `@observe(name="review_clause")` in `tracing.py`), you need **one more layer**: `timed(clock)` first returns a decorator, and the decorator returns the wrapper.
--- code
import functools
import time

def fake_clock(times):
    it = iter(times)
    return lambda: next(it)

def measure(fn, clock=time.perf_counter):
    start = clock()
    result = fn()
    return result, round((clock() - start) * 1000)

print(measure(lambda: "flag", clock=fake_clock([10.0, 10.25])))
print("real clock is fast:", measure(lambda: "flag")[1] < 1000)

def tagged(label):                        # layer 1: takes the arguments
    def decorator(fn):                    # layer 2: takes the function
        @functools.wraps(fn)
        def wrapper(*args, **kwargs):     # layer 3: runs on every call
            print(f"[{label}] {fn.__name__}{args}")
            return fn(*args, **kwargs)
        return wrapper
    return decorator

@tagged("eval")
def section_of(clause_id):
    return clause_id.split(".")[0]

print(section_of("8.1"))

@@ concept
title: with and context managers
--- body
`with open(...) as f:` makes sure the file is closed when you are done, even if an error happens in the middle. You can write this kind of thing yourself too: "do one thing on the way in, and **always** do another on the way out":

```python
from contextlib import contextmanager

@contextmanager
def span(name):
    start = time.perf_counter()
    try:
        yield            # the code inside the with runs here
    finally:
        record(name, start)   # runs whether or not there was an error
```

`yield` hands control to the code inside the `with`; `finally` makes sure the span is recorded even on an error. What tracing needs most is exactly the record of the call that **failed**.

A classic mistake: using `except Exception:` instead of `finally`. The error is swallowed, and the caller thinks everything went fine.
--- code
from contextlib import contextmanager

SPANS = []

@contextmanager
def span(name):
    ok = False
    try:
        yield
        ok = True
    finally:
        SPANS.append({"name": name, "ok": ok})

with span("split"):
    parts = "8.1 Cap\n8.2 Exclusions".split("\n")

try:
    with span("review"):
        raise RuntimeError("API error 503")
except RuntimeError as e:
    print("caught:", e)

for s in SPANS:
    print(s)

@@ concept
title: Tokens, cache hit rate, latency percentiles
--- body
Add up the `usage` of every call, and you have the full bill for this eval run (or this contract):

- **Total tokens** and the **cache hit rate** `hit ÷ (hit + miss)`: a low hit rate means something at the start of the request keeps changing (what you learned yesterday)
- **Cost**: Day 7's `estimate_cost`; when quoting a customer, convert it to "how much per 100 contracts". With thinking mode on, reasoning tokens are counted in `completion_tokens` too (how many of them are reasoning: see `usage["completion_tokens_details"]["reasoning_tokens"]`) and billed at the output price
- **Don't look only at the average latency**: one 30-second stall gets averaged away by a pile of 1-second calls. Look at **p50** (half of the calls are faster than this) and **p95** (95% of the calls are faster than this; it shows how slow "the slow ones" are)

The simplest percentile method (nearest-rank): sort the values and take item number `ceil(p ÷ 100 × n)` (counting from 1). For the 10 latencies below, p50 is item 5 and p95 is item 10.
--- code
latencies = [1450, 820, 30000, 1010, 1200, 950, 1100, 2100, 1300, 1600]
ordered = sorted(latencies)
print("mean:", sum(latencies) / len(latencies))
print("p50: ", ordered[4])
print("p95: ", ordered[9])

usage = [
    {"prompt_cache_hit_tokens": 0, "prompt_cache_miss_tokens": 900},
    {"prompt_cache_hit_tokens": 832, "prompt_cache_miss_tokens": 70},
    {"prompt_cache_hit_tokens": 832, "prompt_cache_miss_tokens": 95},
]
hit = sum(u["prompt_cache_hit_tokens"] for u in usage)
miss = sum(u["prompt_cache_miss_tokens"] for u in usage)
print("cache hit ratio:", round(hit / (hit + miss), 2))

@@ concept
title: A/B comparison: change one thing at a time
--- body
You changed the prompt. How do you know it got better? Run both versions on **the same test cases with the same N**, and compare them side by side, case by case. Three rules (bootcamp: `lessons/05_prompt_ab.md`):

- **Change only one thing at a time**, otherwise you can't tell which change made the difference
- First check whether high-risk recall dropped, then whether false alarms went down
- Even if the total score goes up, look case by case: one case dropping from 3/3 to 1/3 is a regression, and you have to look into it

`run_evals.py` lines up the table with f-strings: `{x:<10}` left-aligns in 10 characters, `{x:>6}` right-aligns in 6, `{rate:.0%}` shows 0.8 as `80%`; together that is `{rate:>6.0%}`.
--- code
A = {"unlimited-liability": 1.0, "mutual-warranty-disclaimer": 0.4, "payment-net-30": 1.0}
B = {"unlimited-liability": 1.0, "mutual-warranty-disclaimer": 0.8, "payment-net-30": 0.6}
print(f"{'case':<28}{'v1':>6}{'v2':>6}")
for case_id in A:
    a, b = A[case_id], B[case_id]
    note = "  <- worse" if b < a else ""
    print(f"{case_id:<28}{a:>6.0%}{b:>6.0%}{note}")

import json
import os
import requests

URL = "https://api.deepseek.com/v1/chat/completions"
HEADERS = {"Authorization": f"Bearer {os.getenv('DEEPSEEK_API_KEY')}"}

def classify(clause_text):
    body = {"model": "deepseek-flash", "messages": [{"role": "user", "content": clause_text}],
            "response_format": {"type": "json_object"}, "thinking": {"type": "disabled"}}
    content = requests.post(URL, headers=HEADERS, json=body).json()["choices"][0]["message"]["content"]
    return json.loads(content)

def check_case(case, result):
    fails = []
    e = case["expect"]
    if result["verdict"] not in e["verdict_in"]:
        fails.append(f"verdict {result['verdict']} not in {e['verdict_in']}")
    if "risk_in" in e and result["risk_level"] not in e["risk_in"]:
        fails.append(f"risk {result['risk_level']} not in {e['risk_in']}")
    return fails

def pass_rate(case, runs, review=classify):
    if runs < 1:
        raise ValueError("runs must be at least 1")
    passed = 0
    for _ in range(runs):
        if not check_case(case, review(case["clause"])):
            passed += 1
    return passed / runs

--- starter

--- solution
def confusion(cases, predictions):
    counts = {"TP": 0, "FP": 0, "FN": 0, "TN": 0}
    for case in cases:
        risky = case["kind"] != "must_accept"
        flagged = predictions[case["id"]] != "accept"
        if risky and flagged:
            counts["TP"] += 1
        elif not risky and flagged:
            counts["FP"] += 1
        elif risky and not flagged:
            counts["FN"] += 1
        else:
            counts["TN"] += 1
    return counts

import functools
import time

SPANS = []

def timed(clock=time.perf_counter):
    def decorator(fn):
        @functools.wraps(fn)
        def wrapper(*args, **kwargs):
            start = clock()
            try:

        return wrapper
    return decorator

KEYS = ["prompt_tokens", "completion_tokens", "prompt_cache_hit_tokens", "prompt_cache_miss_tokens"]

def evaluate(cases, predict, runs):
    if runs < 1:
        raise ValueError("runs must be at least 1")
    rates = {}
    for case in cases:
        passed = sum(1 for _ in range(runs) if predict(case["clause"]) in case["expect"]["verdict_in"])

    return rates

--- context
Calls to the model sometimes hit temporary failures, such as a network glitch or a server that is too busy, and trying again often works. Rather than writing the retry again in every function that calls the model, write it as a decorator and put it wherever it is needed.
--- prompt
Write the decorator with arguments `retry(times)`, used like this:

```python
@retry(3)
def call_model(text): ...
```

- If the decorated function raises any `Exception`, call it again, up to `times` calls in total
- As soon as one call succeeds, return that call's result
- If all `times` calls fail: re-raise the exception from the **last** call unchanged
- Use `functools.wraps` to keep the original function's name
- `times` less than 1: `raise ValueError` right at the `retry(0)` step
--- solution
import functools

def retry(times):
    if times < 1:
        raise ValueError("times must be at least 1")
    def decorator(fn):
        @functools.wraps(fn)
        def wrapper(*args, **kwargs):
            last = None
            for _ in range(times):
                try:
                    return fn(*args, **kwargs)
                except Exception as e:
                    last = e
            raise last
        return wrapper
    return decorator
--- tests
def flaky(fail_times):
    state = {"calls": 0}

        state["calls"] += 1
        if state["calls"] <= fail_times:
            raise ConnectionError(f"attempt {state['calls']} failed")
        return "flag"
    return call_model, state
def _ok_after_two():

    wrapped = retry(3)(fn)

--- prompt
Write `report(cases, predictions)`:

- `cases`: a list of `{"id": ..., "kind": ...}`; a `kind` of `"must_accept"` means not risky, everything else means risky
- `predictions`: `{case id: verdict}`; any verdict other than `"accept"` counts as flagged; a test case that is **missing** from `predictions` counts as not flagged
- Return a dictionary with the keys `"TP"`, `"FP"`, `"FN"`, `"TN"`, `"precision"`, `"recall"` and `"line"`
- precision = TP ÷ (TP + FP), recall = TP ÷ (TP + FN), both rounded with `round(x, 2)`; when a denominator is 0, return `1.0`
- `"line"` is `f"precision {precision:.2f}  recall {recall:.2f}"` (two spaces in the middle)
--- solution
def report(cases, predictions):
    tp = fp = fn = tn = 0
    for case in cases:
        risky = case["kind"] != "must_accept"
        flagged = predictions.get(case["id"], "accept") != "accept"
        if risky and flagged:
            tp += 1
        elif flagged:
            fp += 1
        elif risky:
            fn += 1
        else:
            tn += 1
    precision = round(tp / (tp + fp), 2) if tp + fp else 1.0
    recall = round(tp / (tp + fn), 2) if tp + fn else 1.0
    return {"TP": tp, "FP": fp, "FN": fn, "TN": tn, "precision": precision, "recall": recall,
            "line": f"precision {precision:.2f}  recall {recall:.2f}"}
