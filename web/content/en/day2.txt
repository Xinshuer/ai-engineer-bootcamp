@@ concept
title: for loops
--- body
`for variable in list:` takes the elements out of the list one at a time and runs the indented code below once for each.

`range(n)` produces the numbers 0 to n-1; `range(1, 4)` is 1, 2, 3 (the end is not included).

You can give the loop variable any name, but make it meaningful: when you loop over clauses, call it `clause` or `c`, not `x`.
--- code
ids = ["3.1", "4.2", "8.1"]
for cid in ids:
    print("reviewing", cid)

for i in range(3):
    print("attempt", i + 1)

@@ concept
title: Accumulating: set up before the loop, update inside it
--- body
Almost every count or total has the same shape:

1. **Before** the loop, set up a starting value (`0`, an empty list `[]`, an empty dictionary `{}`)
2. **Inside** the loop, update it
3. **After** the loop, return it

The most common bug: putting the starting value inside the loop, so it is reset on every pass.
--- code
lengths = [120, 45, 300]
total = 0
for n in lengths:
    total = total + n
print("total", total)

long_ones = []
for n in lengths:
    if n > 100:
        long_ones.append(n)
print(long_ones)

@@ concept
title: Dictionaries: look up values by name
--- body
A dictionary `{key: value, ...}` finds a value by its key, like looking something up in a table.

- `d["8.1"]` gets the value; a missing key raises `KeyError`
- `d.get("4.2")` returns `None` when the key is missing; `d.get("4.2", "unknown")` returns the default you give it
- `d["4.2"] = "low"` adds or changes a value
- `"3.1" in d` checks whether the key is there
- `for k, v in d.items():` loops over keys and values together

The JSON the model returns, the playbook rules, the counts: in Python they are all dictionaries.
--- code
risk = {"8.1": "high", "3.1": "low"}
print(risk["8.1"])
print(risk.get("4.2"), risk.get("4.2", "unknown"))
risk["4.2"] = "medium"
for cid, level in risk.items():
    print(cid, "->", level)

title: The standard way to count
--- body
Counting how many times each verdict appears is the most common operation in this project. The standard way:

```python
counts = {}

    counts[v] = counts.get(v, 0) + 1
```

`counts.get(v, 0)` means "how many we have counted so far, or 0 if we haven't seen it yet". Writing `counts[v] += 1` directly raises `KeyError` the first time a value shows up.

@@ concept
title: Functions: default arguments and early return
--- body
- **Default argument**: `def label(cid, prefix="Clause"):`; if the call leaves out `prefix`, the default is used
- **Early return**: as soon as you find the answer, `return` it and the function ends right there; if the loop finishes without finding it, `return None` at the end

The standard shape of "find one thing":

```python
def find(items, target):
    for x in items:
        if x == target:
            return x
    return None
```

Note that the last line, `return None`, lines up with `for`: it is not inside the loop.
--- code
def label(cid, prefix="Clause"):
    return f"{prefix} {cid}"

def first_high(clauses):
    for c in clauses:
        if c["risk"] == "high":
            return c["id"]
    return None

print(label("8.1"), label("8.1", "Section"))
print(first_high([{"id": "3.1", "risk": "low"}, {"id": "8.1", "risk": "high"}]))
print(first_high([]))

@@ concept
title: List comprehensions: filter and transform in one line
--- body
`[expression for variable in list if condition]` does the same as "set up an empty list → loop → append when the condition holds".

```python
ids = [c["id"] for c in clauses if c["risk"] == "high"]
```

Get comfortable with plain for loops first, then use comprehensions. The tests accept both; being able to read comprehensions is enough, and in an interview you can write either.
--- code
clauses = [
    {"id": "3.1", "risk": "low"},
    {"id": "8.1", "risk": "high"},
    {"id": "10.1", "risk": "high"},
]
print([c["id"] for c in clauses])
print([c["id"] for c in clauses if c["risk"] == "high"])
print([len(c["id"]) for c in clauses])

@@ concept
title: Sorting and while
--- body
**Sorting**: `sorted(list)` returns a new, sorted list. To sort by a field, use `key=`:

```python
RISK_ORDER = {"high": 0, "medium": 1, "low": 2}
sorted(clauses, key=lambda c: RISK_ORDER[c["risk"]])
```

`lambda c: ...` is a small function without a name: give it a clause and it returns the value to compare. `sorted` is stable: elements with the same comparison value keep their original order.

**while**: keeps looping as long as the condition is true. Use it when you don't know how many times you will loop, for example retrying when an API call fails. Always make sure something changes inside the loop, or it will loop forever (an infinite loop).
--- code
RISK_ORDER = {"high": 0, "medium": 1, "low": 2}
clauses = [{"id": "3.1", "risk": "low"}, {"id": "8.1", "risk": "high"}, {"id": "4.2", "risk": "medium"}]
for c in sorted(clauses, key=lambda c: RISK_ORDER[c["risk"]]):
    print(c["id"], c["risk"])

attempt = 1
while attempt <= 3:
    print("try", attempt)
    attempt = attempt + 1

@@ item d2-10
type: choice
title: print and return
level: 1
cards: d1:Functions: def and return; d1:How code runs: print and comments
--- context
The earlier exercise "Fix the bug: prints but doesn't return" went wrong because of exactly these two words. When beginners write counting functions, this is one of the most common misunderstandings.
--- prompt
Which statement about `print` and `return` is true?
--- options
- They are the same: both hand the result to the caller
- `return` hands the value to the caller and ends the function; `print` only shows it on the screen
- A function can use only one of them
- The function ends after `print`
answer: 2
--- explain
`return` is the function's way out: when you call `x = f()`, `x` gets the returned value, and the function ends as soon as it reaches return. `print` only affects the screen, not the value the program gets. Calling a function that has no return gives `None`.

- `[1, 2, 3, 4]`
- `[1, 2, 3]`
- `[0, 1, 2, 3]`
- `[2, 3, 4]`
answer: 2
--- explain
`range(start, end)` includes the start and does **not include** the end. It is the same rule as the slice `ids[1:4]`.

--- context
When you get a new contract, first skim its most frequent words: if fees and liability come up a lot, you already have a rough idea that the contract is mostly about money and liability.
--- prompt
Write `count_words(text)`: split the text on whitespace, convert everything to lowercase, count how many times each word appears, and return a dictionary.

`count_words("Fees and fees")` → `{"fees": 2, "and": 1}`
--- solution
def count_words(text):
    counts = {}
    for w in text.lower().split():
        counts[w] = counts.get(w, 0) + 1
    return counts
--- tests

title: Closed book: counts for three risk levels
exam: yes
level: 2
cards: The standard way to count; Dictionaries: look up values by name
--- context
In these exercises the report starts with a risk table that always has three cells: high, medium, low. The web page looks up the numbers by these three names, and if one cell is missing, the page breaks.
--- prompt
Write `risk_counts(clauses)`: return `{"high": count, "medium": count, "low": count}`. **All three keys must be there**; a level with no clauses gets 0; ignore any other risk values.
--- solution
def risk_counts(clauses):
    counts = {"high": 0, "medium": 0, "low": 0}
    for c in clauses:
        if c["risk"] in counts:
            counts[c["risk"]] += 1
    return counts
--- tests
expect("mixed", lambda: risk_counts([{"risk": "high"}, {"risk": "low"}, {"risk": "high"}]), {"high": 2, "medium": 0, "low": 1})
expect("empty list: all three keys are 0", lambda: risk_counts([]), {"high": 0, "medium": 0, "low": 0})
expect("ignores unknown values", lambda: risk_counts([{"risk": "urgent"}, {"risk": "medium"}]), {"high": 0, "medium": 1, "low": 0})
