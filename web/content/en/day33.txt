@@ concept
title: The agent graph: model ⇄ tools
--- body
On Day 17 you wrote the agent loop by hand, on Day 30 you wrote it again with LangChain messages, and on Day 31 `create_agent` did it for you. Today you build it yourself as a LangGraph graph: two nodes, three edges.

- The `model` node: calls the model once with `model.bind_tools(tools)` and returns `{"messages": [reply]}`
- The `tools` node: `ToolNode(tools)` runs **all** the tool_calls in the last AIMessage and returns one ToolMessage per call
- `add_conditional_edges("model", tools_condition)`: the last message has tool_calls → `"tools"`; no tool_calls → END
- `add_edge("tools", "model")`: sends the tool results back to the model. This edge is the "loop"

The graph that `create_agent` returns also calls its nodes `model` and `tools`. When all you need is a standard tool loop, that is enough; the benefit of building it yourself is that you can insert your own nodes in the middle (approval, logging, a budget check).

The model must have thinking turned off: `extra_body={"thinking": {"type": "disabled"}}`. Day 30 explained why: in thinking mode, a request with `tools` must send back the `reasoning_content` of every earlier assistant message, or DeepSeek returns 400. ChatDeepSeek does not send it back, so with thinking on, this graph breaks the rule on its second model call (this page's mock server answers 400). Turning it off is also faster, and you pay for fewer output tokens.
--- code
from langchain_core.tools import tool
from langchain_deepseek import ChatDeepSeek
from langgraph.graph import StateGraph, START, END, MessagesState
from langgraph.prebuilt import ToolNode, tools_condition

PLAYBOOK = {"liability_cap": "PB-01: cap at 12 months of fees", "payment": "PB-04: net 30 days is fine"}

@tool
def lookup_playbook(topic: str) -> str:
    """Look up the customer's playbook rule for a contract topic."""
    return PLAYBOOK.get(topic, "no rule for this topic")

tools = [lookup_playbook]
model = ChatDeepSeek(model="deepseek-flash", extra_body={"thinking": {"type": "disabled"}}).bind_tools(tools)

def call_model(state: MessagesState):
    return {"messages": [model.invoke(state["messages"])]}

g = StateGraph(MessagesState)
g.add_node("model", call_model)
g.add_node("tools", ToolNode(tools))
g.add_edge(START, "model")
g.add_conditional_edges("model", tools_condition)   # tool_calls → "tools", none → END
g.add_edge("tools", "model")                        # tool results go back to the model
app = g.compile()

out = app.invoke({"messages": [("user", "Review clause 8.1: Liability is unlimited.")]})
for m in out["messages"]:
    print(f"{type(m).__name__:<13}", m.content[:60])
print("tool call:", out["messages"][1].tool_calls[0]["args"])
print("model calls:", len(MOCK.calls), "| nodes:", list(app.get_graph().nodes))

@@ concept
title: ToolNode: errors are messages too
--- body
`ToolNode` does Day 30's `run_tools` for you: it runs each call and pairs each ToolMessage with its `tool_call_id`. When something goes wrong, there are two cases:

- **The model's mistake** (a tool name that doesn't exist, wrong arguments): it automatically becomes a ToolMessage with `status="error"`, which the model sees in the next round and can correct. This is what Day 17 meant by "errors are messages for the model"
- **Your own tool raises an exception** (for example the playbook has no such topic): by default it is **raised straight through**, the whole graph crashes, and all the review work already done on this contract is wasted. This is different from the `run_tools` you wrote on Day 30, which also returned a message on errors
- Add `handle_tool_errors=True`: the exception also becomes an error message, `"Error: KeyError('payment')\n Please fix your mistakes."`; you can also pass a string or a function and decide yourself what the model sees

Also, `ToolNode` only runs inside a graph: calling its `invoke` on its own raises an error.
--- code
from langchain_core.messages import AIMessage
from langchain_core.tools import tool
from langgraph.graph import StateGraph, START, END, MessagesState
from langgraph.prebuilt import ToolNode

PLAYBOOK = {"liability_cap": "PB-01: cap at 12 months of fees"}

@tool
def lookup_playbook(topic: str) -> str:
    """Look up the customer's playbook rule for a contract topic."""
    return PLAYBOOK[topic]          # raises KeyError when the topic is missing

def run_tools(node, call):
    g = StateGraph(MessagesState)
    g.add_node("tools", node)
    g.add_edge(START, "tools")
    g.add_edge("tools", END)
    out = g.compile().invoke({"messages": [AIMessage(content="", tool_calls=[call])]})
    return out["messages"][-1]

calls = {
    "ok": {"name": "lookup_playbook", "args": {"topic": "liability_cap"}, "id": "c1"},
    "wrong tool name": {"name": "lookup_rules", "args": {"topic": "liability_cap"}, "id": "c2"},
    "wrong argument name": {"name": "lookup_playbook", "args": {"topik": "payment"}, "id": "c3"},
}
for label, call in calls.items():
    msg = run_tools(ToolNode([lookup_playbook]), call)
    print(label, msg.status, "|", msg.content.splitlines()[0])

boom = {"name": "lookup_playbook", "args": {"topic": "payment"}, "id": "c4"}
try:
    run_tools(ToolNode([lookup_playbook]), boom)
except KeyError as e:
    print("the tool itself raised: the whole graph crashed", repr(e))
msg = run_tools(ToolNode([lookup_playbook], handle_tool_errors=True), boom)
print("handle_tool_errors=True:", msg.status, "|", msg.content.splitlines()[0])

@@ concept
title: recursion_limit: a cap on the loop
--- body
The model may keep calling tools and never give a final answer (in the mock, write `[loop]` in the question to simulate this). LangGraph uses `recursion_limit` to cap the number of **supersteps** (a superstep: the nodes that run together in one round count as one step).

- In LangGraph 1.2, the version on this page, the default is **10007**! Older versions and many tutorials say 25. If you don't set it, an endless loop calls the model thousands of times before it stops
- So pass it every time: `app.invoke(inputs, {"recursion_limit": 10})`
- Going over raises `GraphRecursionError` (`from langgraph.errors import GraphRecursionError`). Catch it and tell the user "no answer within the step limit", instead of letting the whole request fail with a 500
- The first step, which writes the input into the state (`__start__`), counts too: model → tools → model really takes 4 steps, so a limit of 3 raises an error and 4 passes (the example below, measured with this page's version). Don't set it right at the edge; leave some room

Compare with Day 17: the `max_steps` you wrote by hand is exactly this.
--- code
from langchain_core.tools import tool
from langchain_deepseek import ChatDeepSeek
from langgraph.errors import GraphRecursionError
from langgraph.graph import StateGraph, START, MessagesState
from langgraph.prebuilt import ToolNode, tools_condition

@tool
def lookup_playbook(topic: str) -> str:
    """Look up the customer's playbook rule for a contract topic."""
    return "PB-01: cap at 12 months of fees"

model = ChatDeepSeek(model="deepseek-flash", extra_body={"thinking": {"type": "disabled"}}).bind_tools([lookup_playbook])
g = StateGraph(MessagesState)
g.add_node("model", lambda state: {"messages": [model.invoke(state["messages"])]})
g.add_node("tools", ToolNode([lookup_playbook]))
g.add_edge(START, "model")
g.add_conditional_edges("model", tools_condition)
g.add_edge("tools", "model")
app = g.compile()

def run(question, limit):
    MOCK.reset()
    try:
        out = app.invoke({"messages": [("user", question)]}, {"recursion_limit": limit})
        return f"limit {limit}: ok after {len(MOCK.calls)} model call(s)"
    except GraphRecursionError:
        return f"limit {limit}: GraphRecursionError after {len(MOCK.calls)} model call(s)"

print(run("Review clause 8.1: Liability is unlimited.", 3))
print(run("Review clause 8.1: Liability is unlimited.", 4))
print(run("[loop] Review clause 8.1: Liability is unlimited.", 10))

@@ concept
title: Checkpointer and thread_id
--- body
Until now, every `invoke` started from nothing. Add a **checkpointer** when you compile, and the graph saves the state after every step, kept separately per `thread_id`:

```python
app = g.compile(checkpointer=InMemorySaver())
cfg = {"configurable": {"thread_id": "acme-msa"}}
app.invoke({"messages": [("user", "Review clause 8.1")]}, cfg)
app.invoke({"messages": [("user", "And clause 9.2?")]}, cfg)   # continues from the previous round
```

- Invoke again with the same `thread_id`: it first reads the last state, the new message is appended through `add_messages`, and the model sees the whole conversation
- A different `thread_id`: a fresh start
- A checkpointer but no thread_id (or a misspelled `threadId`): `ValueError`. Put it inside `"configurable"`, the way the docs and `graph.py` do
- `InMemorySaver` keeps everything in the process's memory, which is gone as soon as the process exits, so it is only for development and tests. It is your `run_id` + JSON file from Day 19
--- code
from langchain_deepseek import ChatDeepSeek
from langgraph.graph import StateGraph, START, END, MessagesState
from langgraph.checkpoint.memory import InMemorySaver

model = ChatDeepSeek(model="deepseek-flash", extra_body={"thinking": {"type": "disabled"}})

def chat(state: MessagesState):
    return {"messages": [model.invoke(state["messages"])]}

g = StateGraph(MessagesState)
g.add_node("chat", chat)
g.add_edge(START, "chat")
g.add_edge("chat", END)
app = g.compile(checkpointer=InMemorySaver())

acme = {"configurable": {"thread_id": "acme-msa"}}
globex = {"configurable": {"thread_id": "globex-msa"}}
app.invoke({"messages": [("user", "Review clause 8.1")]}, acme)
app.invoke({"messages": [("user", "And clause 9.2?")]}, acme)
app.invoke({"messages": [("user", "And clause 9.2?")]}, globex)
for call in MOCK.calls:
    print("model saw:", [m["role"] for m in call["body"]["messages"]])
try:
    app.invoke({"messages": [("user", "hi")]})
except ValueError as e:
    print("ValueError:", str(e)[:70])

@@ concept
title: Inspecting state: get_state and history
--- body
With checkpoints you can see the graph's state at every step. Debugging "what exactly did the agent see at step 2" depends on this:

- `snap = app.get_state(cfg)`: the latest checkpoint. `snap.values` is the state; `snap.next` is the nodes that run next (a tuple), and `()` means it has finished
- `app.get_state_history(cfg)`: all the checkpoints of this thread, **newest first**, one per superstep: `metadata["step"]` starts at -1 (input just received), then 0, 1, 2…
- A thread that doesn't exist: `values` is `{}`, `next` is `()`
- `snap.config` contains a `checkpoint_id` that is different on every run: don't print it or compare with it

The UI uses this to show progress, and the backend uses it to answer "which contracts are waiting for a person's approval" (the threads whose `next` is not empty).
--- code
from typing import TypedDict
from langgraph.graph import StateGraph, START, END
from langgraph.checkpoint.memory import InMemorySaver

class State(TypedDict, total=False):
    clause: str
    verdict: str
    report: str

def review(state: State):
    return {"verdict": "redline"}

def export(state: State):
    return {"report": f"{state['clause']}: {state['verdict']}"}

g = StateGraph(State)
g.add_node("review", review)
g.add_node("export", export)
g.add_edge(START, "review")
g.add_edge("review", "export")
g.add_edge("export", END)
app = g.compile(checkpointer=InMemorySaver())
cfg = {"configurable": {"thread_id": "t1"}}
app.invoke({"clause": "8.1"}, cfg)

snap = app.get_state(cfg)
print("next:", snap.next, "| values:", snap.values)
for s in app.get_state_history(cfg):          # newest first
    print("step", s.metadata["step"], "next", s.next, "keys", sorted(s.values))
print(app.get_state({"configurable": {"thread_id": "nobody"}}).values)

@@ concept
title: Changing state: update_state and time travel
--- body
On Day 19 you made the runner stop before a node and wait for a person's approval. Here is LangGraph's static way to do it, and how to change the state:

- `compile(..., interrupt_before=["export"])`: stops every time before reaching `export`. `invoke` returns the state so far, **without** an `__interrupt__` key; look at `get_state(cfg).next` instead
- A person makes a change: `app.update_state(cfg, {"verdict": "flag"})`. It works as if a node had returned this update (it still goes through the reducer), and it adds a new checkpoint
- Continue: `app.invoke(None, cfg)`. `None` means "no new input, carry on from where it stopped"
- **Time travel**: pick an old snapshot from the history, and `app.invoke(None, old_snapshot.config)` reruns from there; to change a value first, use `update_state(old_snapshot.config, {...})`, which returns a new config

The benefit: only the later steps rerun, the earlier review doesn't have to be redone, and you don't pay for the model a second time.
--- code
from typing import TypedDict
from langgraph.graph import StateGraph, START, END
from langgraph.checkpoint.memory import InMemorySaver

class State(TypedDict, total=False):
    clause: str
    verdict: str
    report: str

g = StateGraph(State)
g.add_node("review", lambda state: {"verdict": "redline"})
g.add_node("export", lambda state: {"report": f"{state['clause']}: {state['verdict']}"})
g.add_edge(START, "review")
g.add_edge("review", "export")
g.add_edge("export", END)
app = g.compile(checkpointer=InMemorySaver(), interrupt_before=["export"])
cfg = {"configurable": {"thread_id": "t2"}}

print(app.invoke({"clause": "8.1"}, cfg))          # stops before export
print("next:", app.get_state(cfg).next)
app.update_state(cfg, {"verdict": "flag"})          # the lawyer changes the verdict
print(app.invoke(None, cfg))                        # None = no new input, carry on

# Time travel: go back to the checkpoint "before export, before the verdict was changed" and rerun from there
old = [s for s in app.get_state_history(cfg) if s.next == ("export",)][-1]
print("old:", old.values)
print(app.invoke(None, old.config))

@@ concept
title: SqliteSaver: survives a process exit
--- body
`InMemorySaver` is gone as soon as the process exits. `clausecheck/graph.py` uses **SqliteSaver**: checkpoints are written to `data/checkpoints.sqlite`, and when the lawyer approves the next day, another process continues with the same `thread_id`.

```python
with SqliteSaver.from_conn_string("work/d33/cp.sqlite") as saver:
    app = build_graph(checkpointer=saver)
```

- The connection closes automatically when the `with` ends. Two `with` blocks are like two processes: in between, the graph in memory is completely gone, and only the file is left
- Another way to write it: `SqliteSaver(sqlite3.connect(path, check_same_thread=False))`. You **must** add `check_same_thread=False`: LangGraph writes checkpoints in a background thread, and without it, on your own computer you get `ProgrammingError: SQLite objects created in a thread can only be used in that same thread`. This page has only one thread, so you don't get the error here, which is all the more reason to remember it
- Production usually uses the Postgres checkpointer (a separate package). Same idea: the graph stays the same, only the checkpointer changes
--- code
import os
from typing import TypedDict
from langgraph.graph import StateGraph, START, END
from langgraph.checkpoint.sqlite import SqliteSaver

class State(TypedDict, total=False):
    clause: str
    verdict: str
    report: str

def build(checkpointer):
    g = StateGraph(State)
    g.add_node("review", lambda state: {"verdict": "redline"})
    g.add_node("export", lambda state: {"report": f"{state['clause']}: {state['verdict']}"})
    g.add_edge(START, "review")
    g.add_edge("review", "export")
    g.add_edge("export", END)
    return g.compile(checkpointer=checkpointer, interrupt_before=["export"])

os.makedirs("work/d33", exist_ok=True)
path = "work/d33/demo.sqlite"
if os.path.exists(path):
    os.remove(path)                                   # start from an empty file on every run
cfg = {"configurable": {"thread_id": "contract-42"}}

with SqliteSaver.from_conn_string(path) as saver:     # "process 1": review, stop before export
    print(build(saver).invoke({"clause": "8.1"}, cfg))

with SqliteSaver.from_conn_string(path) as saver:     # "process 2": the lawyer approves the next day
    app = build(saver)
    print("next:", app.get_state(cfg).next)
    print(app.invoke(None, cfg))
print("file kept:", os.path.exists(path))

@@ concept
title: Long-term memory: Store
--- body
The checkpointer is **short-term memory**: the state inside one thread (one conversation, one contract). Some things must be remembered across threads, for example "Acme accepts a 24-month liability cap", which is still needed next week when you review another Acme contract. That is **long-term memory**: the Store.

- `store.put(("prefs", "acme"), "liability_cap", {"cap": "24 months"})`: the namespace is a tuple, the key is a string, the value is a dict; putting the same key again overwrites it
- `store.get(ns, key)` returns an Item (use `.value`) or `None`; `store.search(("prefs",))` lists items by prefix, **at most 10 by default**; pass `limit=` for more
- Add a parameter `runtime: Runtime[Ctx]` to the node and use `runtime.store`; compile with `compile(store=store)`
- "Which customer is this" doesn't go in the state: declare it with `StateGraph(State, context_schema=Ctx)`, pass it in with `invoke(..., context=Ctx(customer="acme"))`, and read `runtime.context.customer` in the node

Also, a thread keeps growing, and every round sends the whole history to the model. Before calling the model, use `trim_messages(..., strategy="last", include_system=True, start_on="human")` to keep only the last few messages (the exercises use `token_counter=len`, which counts messages).
--- code
from dataclasses import dataclass
from typing import TypedDict
from langchain_core.messages import trim_messages
from langgraph.graph import StateGraph, START, END
from langgraph.runtime import Runtime
from langgraph.store.memory import InMemoryStore

@dataclass
class Ctx:
    customer: str

class State(TypedDict, total=False):
    clause: str
    rule: str

def load_rule(state: State, runtime: Runtime[Ctx]):
    item = runtime.store.get(("prefs", runtime.context.customer), "liability_cap")
    return {"rule": item.value["cap"] if item else "12 months (default)"}

store = InMemoryStore()
store.put(("prefs", "acme"), "liability_cap", {"cap": "24 months"})

g = StateGraph(State, context_schema=Ctx)
g.add_node("load_rule", load_rule)
g.add_edge(START, "load_rule")
g.add_edge("load_rule", END)
app = g.compile(store=store)
print(app.invoke({"clause": "8.1"}, context=Ctx(customer="acme")))
print(app.invoke({"clause": "8.1"}, context=Ctx(customer="globex")))
print([(item.namespace, item.key) for item in store.search(("prefs",))])

history = [("system", "You review contracts."), ("user", "Review clause 1"), ("assistant", "accept"),
           ("user", "Review clause 2"), ("assistant", "flag"), ("user", "Review clause 3")]
kept = trim_messages(history, max_tokens=4, token_counter=len, strategy="last", include_system=True, start_on="human")
print([m.content for m in kept])

--- prompt

--- code
import operator
from typing import Annotated
from langgraph.graph import StateGraph, START, END, MessagesState

class State(MessagesState):
    log: Annotated[list, operator.add]
    verdict: str

def review(state: State):
    return {"messages": [("assistant", "8.1 looks risky")], "log": ["review"], "verdict": "flag"}

def decide(state: State):
    n = len(state["messages"])
    return {"messages": [("assistant", f"final: redline after {n} messages")], "log": ["decide"], "verdict": "redline"}

g = StateGraph(State)
g.add_node("review", review)
g.add_node("decide", decide)
g.add_edge(START, "review")
g.add_edge("review", "decide")
g.add_edge("decide", END)
out = g.compile().invoke({"messages": [("user", "Review clause 8.1")], "log": ["start"], "verdict": ""})
for m in out["messages"]:
    print(type(m).__name__, "|", m.content)
print(out["log"], out["verdict"])
--- explain
The reducer of `messages` is `add_messages`: it appends, and it turns tuples like `("assistant", ...)` into AIMessages. `log` uses `operator.add`, so the three lists are joined together. `verdict` has no reducer, so the later write overwrites the earlier one. Today's agent graph is built on this: each node returns only its new messages, and `add_messages` takes care of appending them at the end.

from langchain_core.messages import AIMessage, HumanMessage
from langchain_core.tools import tool
from langgraph.graph import StateGraph, START, END, MessagesState
from langgraph.prebuilt import ToolNode, tools_condition

@tool
def lookup_playbook(topic: str) -> str:
    """Look up the customer's playbook rule for a contract topic."""
    return f"rule for {topic}"

call = {"name": "lookup_playbook", "args": {"topic": "payment"}, "id": "call_1"}
print(tools_condition({"messages": [HumanMessage("hi"), AIMessage("", tool_calls=[call])]}))
print(tools_condition({"messages": [AIMessage("", tool_calls=[call]), AIMessage("Done.")]}))

g = StateGraph(MessagesState)
g.add_node("tools", ToolNode([lookup_playbook]))
g.add_edge(START, "tools")
g.add_edge("tools", END)
two = [call, {"name": "lookup_playbook", "args": {"topic": "liability_cap"}, "id": "call_2"}]
out = g.compile().invoke({"messages": [AIMessage("", tool_calls=two)]})
print(len(out["messages"]))
for m in out["messages"][1:]:
    print(type(m).__name__, m.tool_call_id, m.content)
--- explain
`tools_condition` only looks at the **last** message: if it has tool_calls, go to `"tools"`; if not, it returns `"__end__"` (which is `END`). In the second call, the earlier message with tool_calls doesn't count. ToolNode runs every call in the last AIMessage, one ToolMessage per call, with matching `tool_call_id`s. That is exactly what your hand-written `run_tools` did on Day 30.

cards: The agent graph: model ⇄ tools
--- context
This is the skeleton of the review agent: the model reads the clause, calls tools like `lookup_playbook` when it needs to look up the company's review rules, and continues its judgment with the results until it reaches a conclusion. On Day 17 you wrote the same loop by hand.
--- prompt
Complete `build_agent(model, tools)`: the `model` node calls the model with the tools bound, the `tools` node runs the tools, after the model the graph branches on whether there are tool_calls, and after the tools it goes back to the model.
--- template
from langgraph.graph import StateGraph, START, END, MessagesState
from langgraph.prebuilt import ToolNode, tools_condition

def build_agent(model, tools):
    bound = model.bind_tools(tools)

    def call_model(state: MessagesState):
        return {"messages": [bound.invoke(state["messages"])]}

    g = StateGraph(MessagesState)
    g.add_node("model", call_model)
    g.add_node("tools", [[ToolNode(tools)]])
    g.add_edge(START, "model")
    g.add_conditional_edges("model", [[tools_condition]])
    g.add_edge([["tools"]], [["model"]])
    return g.compile()

from langchain_core.messages import SystemMessage
from langgraph.graph import StateGraph, START, END, MessagesState
from langgraph.prebuilt import ToolNode, tools_condition

def build_agent(model, tools, system_prompt):
    bound = model.bind_tools(tools)

    def call_model(state: MessagesState):
        messages = [SystemMessage(system_prompt)] + state["messages"]
        return {"messages": [bound.invoke(messages)]}

    g = StateGraph(MessagesState)
    g.add_node("model", call_model)
    g.add_node("tools", ToolNode(tools))
    g.add_edge(START, "model")
    g.add_conditional_edges("model", tools_condition)
    g.add_edge("tools", "model")
    return g.compile()

    topic: str
    rule: str

    store.put(("prefs", customer), topic, {"rule": rule})

    item = runtime.store.get(("prefs", runtime.context.customer), state["topic"])

--- solution
from langchain_core.messages import AIMessage
from langchain_deepseek import ChatDeepSeek
from langgraph.checkpoint.memory import InMemorySaver
from langgraph.errors import GraphRecursionError
from langgraph.graph import StateGraph, START, MessagesState
from langgraph.prebuilt import ToolNode, tools_condition

def review_agent(question, tools, limit=10):
    model = ChatDeepSeek(model="deepseek-flash", extra_body={"thinking": {"type": "disabled"}}).bind_tools(tools)

    def call_model(state: MessagesState):
        return {"messages": [model.invoke(state["messages"])]}

    g = StateGraph(MessagesState)
    g.add_node("model", call_model)
    g.add_node("tools", ToolNode(tools, handle_tool_errors=True))
    g.add_edge(START, "model")
    g.add_conditional_edges("model", tools_condition)
    g.add_edge("tools", "model")
    app = g.compile(checkpointer=InMemorySaver())
    cfg = {"configurable": {"thread_id": "exam"}}
    stopped = False
    try:
        app.invoke({"messages": [("user", question)]}, {**cfg, "recursion_limit": limit})
    except GraphRecursionError:
        stopped = True
    messages = app.get_state(cfg).values["messages"]
    used = [c["name"] for m in messages if isinstance(m, AIMessage) for c in m.tool_calls]
    answer = None if stopped else messages[-1].content
    return {"answer": answer, "tools_used": used, "stopped": stopped}

- Flow: run until it stops → read the `verdicts` at the stop → if there are valid changes, write the **merged, complete dict** with `update_state` → finish with `invoke(None, ...)`

--- solution
from typing import TypedDict
from langgraph.checkpoint.memory import InMemorySaver
from langgraph.graph import StateGraph, START, END

class State(TypedDict, total=False):
    clauses: list
    verdicts: dict
    report: list

def review(state: State):
    return {"verdicts": {c["id"]: ("redline" if "unlimited" in c["text"].lower() else "accept") for c in state["clauses"]}}

def export(state: State):
    return {"report": [f"{c['id']}: {state['verdicts'][c['id']]}" for c in state["clauses"]]}

def review_and_correct(clauses, corrections):
    g = StateGraph(State)
    g.add_node("review", review)
    g.add_node("export", export)
    g.add_edge(START, "review")
    g.add_edge("review", "export")
    g.add_edge("export", END)
    app = g.compile(checkpointer=InMemorySaver(), interrupt_before=["export"])
    cfg = {"configurable": {"thread_id": "review"}}
    app.invoke({"clauses": clauses}, cfg)
    before = app.get_state(cfg).values["verdicts"]
    valid = {k: v for k, v in corrections.items() if k in before}
    if valid:
        app.update_state(cfg, {"verdicts": {**before, **valid}})
    final = app.invoke(None, cfg)
    return {"before": before, "after": final["verdicts"], "report": final["report"]}

from dataclasses import dataclass
from langchain_core.messages import SystemMessage
from langgraph.checkpoint.memory import InMemorySaver
from langgraph.graph import StateGraph, START, END, MessagesState
from langgraph.runtime import Runtime

@dataclass
class Ctx:
    customer: str

def save_note(store, customer, key, text):
    store.put(("notes", customer), key, {"text": text})

def build_assistant(model, store):
    def answer(state: MessagesState, runtime: Runtime[Ctx]):
        items = sorted(runtime.store.search(("notes", runtime.context.customer), limit=100), key=lambda item: item.key)
        notes = "; ".join(item.value["text"] for item in items) or "none"
        reply = model.invoke([SystemMessage(f"Customer notes: {notes}")] + state["messages"])
        return {"messages": [reply]}

    g = StateGraph(MessagesState, context_schema=Ctx)
    g.add_node("answer", answer)
    g.add_edge(START, "answer")
    g.add_edge("answer", END)
    return g.compile(checkpointer=InMemorySaver(), store=store)
