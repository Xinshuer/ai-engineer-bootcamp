@@ concept
title: From Python to TypeScript
--- body
The ideas are almost the same; only the way you write them differs:

- Variables: `const x = 1` (won't change) / `let x = 1` (will change), never a bare `x = 1`
- Statements usually end with `;`, and blocks use `{ }` instead of indentation
- `print(...)` → `console.log(...)`
- f-string `f"{a}"` → template string `` `${a}` `` (backticks)
- `True` / `False` / `None` → `true` / `false` / `null`, `undefined`
- `and` / `or` / `not` → `&&` / `||` / `!`
- Equal is `===`, not equal is `!==`
- Comments: `#` → `//`

Run on your own computer: `npx tsx file.ts`; type check only: `npx tsc --noEmit`. This page does both.
--- code
const clauseId = "8.1";
let count = 3;
count = count + 1;
console.log(clauseId, count);
console.log(`Clause ${clauseId} has ${count} refs`);
console.log(count > 3 && clauseId.length > 0, !true);

@@ concept
title: Arrays, objects, and type
--- body
- Arrays: `const ids: string[] = ["3.1", "8.1"]`, then `ids.length`, `ids[0]`, `ids.push("12")`
- Objects (like Python dictionaries): `{ id: "8.1", risk: "high" }`; read a field with `c.id`

type Clause = { id: string; verdict: Verdict; risk: "low" | "medium" | "high" };

@@ concept
title: Functions and arrow functions
--- body
Annotate the types of the parameters and of the return value:

```ts
function describe(id: string, heading: string): string {
  return `${id} ${heading}`;
}
```

An arrow function is another way to write a function, common for short functions and callbacks:

```ts
const isHigh = (risk: string): boolean => risk === "high";
```

Default argument: `function label(id: string, prefix = "Clause")`. Optional parameter: `note?: string` (it may be undefined).
--- code
function describe(id: string, heading: string): string {
  return `${id} ${heading}`;
}
const isHigh = (risk: string): boolean => risk === "high";
function label(id: string, prefix = "Clause"): string {
  return `${prefix} ${id}`;
}
console.log(describe("8.1", "Cap on Liability"));
console.log(isHigh("high"), isHigh("low"));
console.log(label("8.1"), label("8.1", "Section"));

@@ concept
title: Array methods: map, filter, find
--- body
In TypeScript you rarely write "empty array → loop → push" by hand. You use array methods instead:

- `filter(c => condition)` keeps the elements that match, like the `if` in a comprehension
- `map(c => newValue)` turns each element into a new value, like the first part of a comprehension
- `find(c => condition)` finds the first match; if there is none, you get `undefined`
- `includes(x)`, `join(", ")`, `some(...)`, `every(...)`

You can chain them: `clauses.filter(c => c.risk === "high").map(c => c.id)`
--- code
type Clause = { id: string; risk: string };
const clauses: Clause[] = [
  { id: "3.1", risk: "low" },
  { id: "8.1", risk: "high" },
  { id: "10.1", risk: "high" },
];
console.log(clauses.filter((c) => c.risk === "high").map((c) => c.id));
console.log(clauses.find((c) => c.id === "8.1"));
console.log(clauses.find((c) => c.id === "99"));
console.log(clauses.map((c) => c.id).join(", "));

@@ concept
title: Record and counting
--- body
An object whose keys are strings and whose values are numbers is written `Record<string, number>`. It is Python's `dict[str, int]`.

The standard way to count:

```ts
const counts: Record<string, number> = {};
for (const v of verdicts) {
  counts[v] = (counts[v] ?? 0) + 1;
}
```

`a ?? b`: when a is `null` or `undefined`, use b. It plays the role of the default value in Python's `dict.get(key, 0)`.
--- code
const verdicts = ["accept", "flag", "accept", "redline"];
const counts: Record<string, number> = {};
for (const v of verdicts) {
  counts[v] = (counts[v] ?? 0) + 1;
}
console.log(counts);
console.log(Object.keys(counts), counts["flag"]);

@@ concept
title: Two sorting traps
--- body
1. **Without a compare function, `sort()` sorts as strings**: `[10, 9, 1].sort()` gives `[1, 10, 9]`
2. **`sort()` changes the original array**. If you don't want that, copy it first: `[...arr].sort(...)`

When the compare function returns a negative number, a goes first:

```ts
[...clauses].sort((a, b) => RISK_ORDER[a.risk] - RISK_ORDER[b.risk])
```

Like Python's `sorted`, JavaScript's sort is stable too.
--- code
const nums = [10, 9, 1];
console.log([...nums].sort());
console.log([...nums].sort((a, b) => a - b));
console.log(nums);
const RISK_ORDER: Record<string, number> = { high: 0, medium: 1, low: 2 };
const risks = ["low", "high", "medium", "high"];
console.log([...risks].sort((a, b) => RISK_ORDER[a] - RISK_ORDER[b]));

@@ item d5-14
type: choice
title: == and ===
level: 1
cards: From Python to TypeScript
--- context
Clause Check compares things everywhere: is the verdict `redline`, is the clause number `8.1`. JavaScript has two ways to write "equal", and in TypeScript you normally use only one of them.
--- prompt
Why is `===` recommended over `==` in TypeScript / JavaScript?
--- options
- `===` runs faster
- `==` converts types before comparing, so `"1" == 1` is true, which easily leads to surprises; `===` doesn't convert
- `==` has been removed
- They are exactly the same; it's only a matter of style
answer: 2
--- explain
`==` quietly converts types before comparing: `"1" == 1`, `0 == ""` and `null == undefined` are all true. `===` requires the same type and the same value, which behaves like Python's `==`. Always use `===` and `!==`.

The report in these exercises starts with a risk table that always has three cells: high, medium, low. The web page reads the numbers by these three names; if a cell is missing, the page can't show it.

Write `riskCounts(clauses)`: each element of `clauses` has `risk: string`. Return `{ high: count, medium: count, low: count }`; all three keys must be there, and any other value is ignored.
--- solution
function riskCounts(clauses: { risk: string }[]): Record<string, number> {
  const counts: Record<string, number> = { high: 0, medium: 0, low: 0 };
  for (const c of clauses) {
    if (c.risk in counts) {
      counts[c.risk] += 1;
    }
  }
  return counts;
}
