@@ concept
title: Reading and writing files: open, with, encoding
--- body
When a program ends, its variables are gone. To keep results (reports, logs), write them to a **file**:

```python
with open("notes.txt", "w", encoding="utf-8") as f:
    f.write("8.1 flag\n")
```

- When the `with` block ends, the file is closed for you, even if an error happens halfway. So always use `with`
- Modes: `"r"` read (the default), `"w"` write (**empties the file first**), `"a"` append to the end
- `f.read()` reads the whole file; `for line in f:` reads it line by line, and each line ends with `"\n"`
- **Always write `encoding="utf-8"`**. On Windows, if you leave it out, the default encoding is often not UTF-8, so text with Chinese, `§` or `ö` comes out garbled or raises `UnicodeDecodeError`. The project's `parse.py` writes it when it reads a contract
--- code
with open("d10_log.txt", "w", encoding="utf-8") as f:
    f.write("8.1 flag\n")
    f.write("3.1 accept\n")

with open("d10_log.txt", "a", encoding="utf-8") as f:
    f.write("4.2 redline\n")

with open("d10_log.txt", encoding="utf-8") as f:
    print(repr(f.read()))

with open("d10_log.txt", encoding="utf-8") as f:
    for n, line in enumerate(f, start=1):
        print(n, line.rstrip("\n"))

@@ concept
title: pathlib: paths are objects
--- body
Building paths from strings (`"data" + "/" + name`) is easy to get wrong. `pathlib.Path` turns a path into an object:

- `Path("data") / "sample_contract.txt"`: join paths with `/`. Write it this way on Windows too; printed, it becomes `data\sample_contract.txt`
- Take it apart: `.name` is the file name, `.stem` the name without the suffix, `.suffix` the suffix (the file extension), `.parent` the folder it is in
- `.with_suffix(".report.json")` swaps the suffix. When no `--out` is given, `cli.py` uses it to work out the report path
- `.exists()` tells you whether it exists; `.read_text(encoding="utf-8")` and `.write_text(text, encoding="utf-8")` read or write the whole file in one line, no `open` needed

This page runs on a Linux-style virtual disk in the browser, so paths print with `/`.
--- code
from pathlib import Path

p = Path("data") / "sample_contract.txt"
print(p, "|", p.name, "|", p.stem, "|", p.suffix, "|", p.parent)
print(p.with_suffix(".report.json"))
print(p.exists())

note = Path("d10_note.txt")
note.write_text("Clause 8.1 needs a lawyer.\n", encoding="utf-8")
print(note.exists(), repr(note.read_text(encoding="utf-8")))

@@ concept
title: Folders: mkdir, glob, and the current directory
--- body
- `folder.mkdir(parents=True, exist_ok=True)` creates a folder: `parents=True` also creates any missing folders above it, `exist_ok=True` means no error if it already exists. Before writing a file, create the folder it goes in: `path.parent.mkdir(...)`
- `folder.glob("*.json")` finds the matching files. The order is not guaranteed, so you almost always write `sorted(folder.glob("*.json"))`
- **Relative paths start from the current directory**: the folder you are in when you run the command, not the folder the .py file is in. `Path.cwd()` shows the current directory

That is why the project must be run from `G:\Contract Clause Reviewer` to find `data/sample_contract.txt`. In `config.py`, `ROOT = Path(__file__).resolve().parent.parent` works out the project's root folder from where the code file is, so paths are found correctly no matter where you run it from.
--- code
from pathlib import Path

folder = Path("work/d10/demo")
folder.mkdir(parents=True, exist_ok=True)
for name in ["b.json", "a.json", "notes.txt"]:
    (folder / name).write_text("{}", encoding="utf-8")

print(Path.cwd())
print([p.name for p in sorted(folder.glob("*.json"))])
print([p.name for p in sorted(folder.glob("*"))])

@@ concept
title: JSON files: load and dump
--- body
Day 3's `json.loads` / `json.dumps` work with **strings** (the s stands for string). For **files** there are two ways:

```python
with open(path, "w", encoding="utf-8") as f:
    json.dump(report, f, indent=2, ensure_ascii=False)   # write
with open(path, encoding="utf-8") as f:
    report = json.load(f)                                # read

report = json.loads(Path(path).read_text(encoding="utf-8"))  # how playbook.py does it
```

- `indent=2` makes it readable for people; `ensure_ascii=False` writes characters like `ö` and `§` as they are, instead of escapes like `\u00f6`
- The classic mistake: `json.dump(report, "out.json")`. The second argument must be an **open file**; passing a string raises `AttributeError: 'str' object has no attribute 'write'`
--- code
import json
from pathlib import Path

report = {"contract": "sample_contract", "counts": {"accept": 17, "redline": 11}, "note": "§ 8.2 Försäkring: a lawyer must check"}
path = Path("work/d10/demo/report.json")
path.parent.mkdir(parents=True, exist_ok=True)
with open(path, "w", encoding="utf-8") as f:
    json.dump(report, f, indent=2, ensure_ascii=False)

print(path.read_text(encoding="utf-8"))
with open(path, encoding="utf-8") as f:
    back = json.load(f)
print(back == report, back["counts"]["redline"])
print(json.dumps({"note": "Försäkring"}))

@@ concept
title: CSV: so lawyers can open it in Excel
--- body
Lawyers don't read JSON; they use Excel. CSV is "table text with commas between the values". The `csv` module handles the quotes, and the commas inside the text, for you:

- Write: `writer = csv.DictWriter(f, fieldnames=[column names...])`, first `writer.writeheader()` for the header row, then `writer.writerows(list_of_dicts)`
- Open the file with `newline=""`, or on Windows an extra blank line appears between rows
- Read: `csv.DictReader(f)`, where each row is a dictionary. **Every value you read back is a string**: you have to `int(...)` a `"340"` yourself
- For Excel to show characters like `ö` or Chinese correctly, use the encoding `"utf-8-sig"` (it adds a BOM mark at the start of the file); read with it too, or the first column name gets an invisible extra character in front
--- code
import csv
from pathlib import Path

rows = [
    {"clause_id": "8.1", "verdict": "redline", "tokens": 340, "rationale": "cap is not mutual, see 12"},
    {"clause_id": "3.1", "verdict": "accept", "tokens": 120, "rationale": "standard"},
]
path = Path("work/d10/demo/reviews.csv")
path.parent.mkdir(parents=True, exist_ok=True)
with open(path, "w", encoding="utf-8", newline="") as f:
    writer = csv.DictWriter(f, fieldnames=["clause_id", "verdict", "tokens", "rationale"])
    writer.writeheader()
    writer.writerows(rows)

print(path.read_text(encoding="utf-8"))
with open(path, encoding="utf-8", newline="") as f:
    back = list(csv.DictReader(f))
print(back[0])
print(back[0]["tokens"] + back[1]["tokens"], int(back[0]["tokens"]) + int(back[1]["tokens"]))

@@ concept
title: Command-line arguments: argparse
--- body
When you run `python -m clausecheck review data/sample_contract.txt --mode mock` in the terminal, all the program gets is a list of words: `["review", "data/sample_contract.txt", "--mode", "mock"]` (that is `sys.argv[1:]`). `argparse` turns them into arguments with names, types and checks:

```python
parser = argparse.ArgumentParser(prog="clausecheck")
parser.add_argument("path")                                  # positional argument: required
parser.add_argument("--out")                                 # optional; None if not given
parser.add_argument("--mode", choices=["mock", "deepseek"], default="mock")
parser.add_argument("--limit", type=int)                     # converted to int for you
parser.add_argument("--verbose", action="store_true")        # True if it is there
args = parser.parse_args(["data/c.txt", "--limit", "5"])
```

- Get the values with a dot: `args.path`, `args.limit`. A `-` in the name becomes `_`: `--only-risk` → `args.only_risk`
- When a value is invalid (not in `choices`, or `--limit abc`), argparse prints the usage and the reason, then exits with exit code 2
- The `-h` help text is generated for you
--- code
import argparse

parser = argparse.ArgumentParser(prog="clausecheck", description="Review a contract")
parser.add_argument("path", help="contract file (.txt or .pdf)")
parser.add_argument("--out", help="where to write the JSON report")
parser.add_argument("--mode", choices=["mock", "deepseek", "local"], default="mock")
parser.add_argument("--limit", type=int, help="review only the first N clauses")
parser.add_argument("--verbose", action="store_true")

args = parser.parse_args(["data/sample_contract.txt", "--limit", "5", "--verbose"])
print(args)
print(args.path, args.mode, args.limit + 1, args.verbose)

try:
    parser.parse_args(["-h"])
except SystemExit as e:
    print("exit code:", e.code)

@@ concept
title: main(argv), exit codes, and __name__
--- body
How the project does it (`clausecheck/cli.py` and `__main__.py`):

```python
def main(argv=None):
    args = build_parser().parse_args(argv)
    ...
    return 0

if __name__ == "__main__":
    raise SystemExit(main())
```

- `parse_args(argv)`: when `argv` is `None`, it reads the real command line; in tests you pass a list, `main(["c.txt", "--limit", "2"])`, with no terminal needed
- **Exit code**: `0` means success, `1` an error (for example, the file doesn't exist), and an argparse argument error is `2`. Scripts and CI use it to tell success from failure; in PowerShell you see it with `$LASTEXITCODE`. `raise SystemExit(main())` hands `main`'s return value to the system as the exit code
- `__name__`: it is `"__main__"` when you run this file directly, and the module name when another file `import`s it. That's why `from clausecheck.cli import main` in a test does not also run the program
- `python -m clausecheck` runs the package's `__main__.py`, which has just two lines: `from .cli import main` and `raise SystemExit(main())`

On this page `__name__` is also `"__main__"`, but there is no real command line, so the code below calls `main([...])` directly. If you write `raise SystemExit(main())` on this page, you'll see a usage error about a missing argument: there are no command-line arguments to read here, and that's expected.
--- code
import argparse
from pathlib import Path

def build_parser():
    p = argparse.ArgumentParser(prog="clausecheck")
    p.add_argument("path")
    return p

def main(argv=None):
    args = build_parser().parse_args(argv)
    path = Path(args.path)
    if not path.exists():
        print(f"error: {path} not found")
        return 1
    print(f"{path.name}: {len(path.read_text(encoding='utf-8'))} chars")
    return 0

demo = Path("work/d10/demo/c.txt")
demo.parent.mkdir(parents=True, exist_ok=True)
demo.write_text("8.1 Cap on Liability\nLiability is unlimited.\n", encoding="utf-8")
print("exit code:", main(["work/d10/demo/c.txt"]))
print("exit code:", main(["work/d10/demo/missing.txt"]))
try:
    main([])
except SystemExit as e:
    print("exit code:", e.code)
print(__name__)

@@ concept
title: Environment variables and configuration
--- body
Some settings shouldn't be hard-coded: API keys, the run mode, the maximum number of steps. They go in **environment variables**:

- Read: `os.getenv("CLAUSECHECK_MODE", "mock")` gives the default when the variable isn't set. **What you read is always a string**, so convert numbers yourself: `config.py` says `int(os.getenv("CLAUSECHECK_MAX_STEPS", "6"))`
- Set one temporarily in PowerShell: `$env:CLAUSECHECK_MODE="mock"`
- API keys go in the `.env` file in the project's root folder, and `load_dotenv()` from `python-dotenv` loads it into environment variables. `.env` is listed in `.gitignore`, so **keys never go into the code or into git**
- Priority: **command-line argument > environment variable > default**. `cmd_review` in `cli.py` first creates `Settings()` (which reads the environment variables), then overrides the mode if `--mode` was given on the command line
- When you write a function, pass the environment in as a parameter (an `env` dictionary), so tests don't have to change the global `os.environ`
--- code
import os

def resolve_steps(cli_value, env):
    if cli_value is not None:
        return cli_value
    return int(env.get("CLAUSECHECK_MAX_STEPS", "6"))

print(resolve_steps(None, {}))
print(resolve_steps(None, {"CLAUSECHECK_MAX_STEPS": "3"}))
print(resolve_steps(10, {"CLAUSECHECK_MAX_STEPS": "3"}))

os.environ["CLAUSECHECK_MODE"] = "deepseek"
print(os.getenv("CLAUSECHECK_MODE", "mock"), type(os.getenv("CLAUSECHECK_MODE")).__name__)
del os.environ["CLAUSECHECK_MODE"]
print(os.getenv("CLAUSECHECK_MODE", "mock"))

--- prompt

Example: when the file contains `"8.1 Cap\n\n   \nLiability is capped.\n"`, return `2`. The tests prepare their own files in `work/d10/lines/`.
--- starter

--- solution
def count_lines(path):
    count = 0
    with open(path, encoding="utf-8") as f:
        for line in f:
            if line.strip():
                count += 1
    return count

--- prompt
Following the project's `split.load_contract`, write `load_contract(path)`:

- the file doesn't exist: `raise FileNotFoundError(f"contract not found: {path}")`
- the file exists, but is empty once whitespace is removed: `raise ValueError(f"contract is empty: {file_name}")`, where the file name is `.name` (without the folder)
- otherwise, return the file's contents (`encoding="utf-8"`)

Python itself raises `FileNotFoundError` when a file doesn't exist, but its message is `[Errno 2] No such file or directory: ...`. **Check first, then raise an error a person understands at a glance**: that's a good habit when you write command-line tools.
--- starter
from pathlib import Path

def load_contract(path):
    path = Path(path)
    pass
--- solution
from pathlib import Path

def load_contract(path):
    path = Path(path)
    if not path.exists():
        raise FileNotFoundError(f"contract not found: {path}")
    text = path.read_text(encoding="utf-8")
    if not text.strip():
        raise ValueError(f"contract is empty: {path.name}")
    return text

Write `merge_reports(folder, out_path)`:

- `folder` holds some `*.json` reports, each like `{"contract": "alpha", "counts": {"accept": 3, "flag": 1}}`; ignore any other files in the folder
- add up the `counts` of all the reports per verdict, and write the result as a JSON file to `out_path` (indented by 2 spaces; create the parent folders if they don't exist), with this content:
  `{"files": number of reports, "contracts": [each report's contract, in file name order], "counts": {verdict: total}}`
- return the dictionary you wrote
- `folder` doesn't exist, or has no JSON in it: `files` is `0`, `contracts` and `counts` are empty, and the file is still written
--- solution
import json
from pathlib import Path

def merge_reports(folder, out_path):
    folder = Path(folder)
    paths = sorted(folder.glob("*.json")) if folder.exists() else []
    contracts = []
    counts = {}
    for p in paths:
        report = json.loads(p.read_text(encoding="utf-8"))
        contracts.append(report["contract"])
        for verdict, n in report["counts"].items():
            counts[verdict] = counts.get(verdict, 0) + n
    merged = {"files": len(paths), "contracts": contracts, "counts": counts}
    out = Path(out_path)
    out.parent.mkdir(parents=True, exist_ok=True)
    with open(out, "w", encoding="utf-8") as f:
        json.dump(merged, f, indent=2)
    return merged

Using argparse, write `main(argv=None)` for the command-line tool `count-verdicts` (`prog="count-verdicts"`):

- positional argument `path`: a CSV file with at least the two columns `clause_id` and `verdict`
- optional argument `--only`: must be `accept` / `flag` / `redline`; when it is invalid, argparse reports the error and exits (`SystemExit`)
- no `--only`: print one line `verdict: count` for each verdict, in alphabetical order of the verdicts, for example `accept: 2`
- `--only flag` given: print just one line, `flag: count` (if the file has no such verdict, print `flag: 0`)
- return `0` on success; when the file doesn't exist, print `error: file not found: <path>` and return `1`
--- solution
import argparse
import csv
from collections import Counter
from pathlib import Path

def main(argv=None):
    parser = argparse.ArgumentParser(prog="count-verdicts")
    parser.add_argument("path")
    parser.add_argument("--only", choices=["accept", "flag", "redline"])
    args = parser.parse_args(argv)
    path = Path(args.path)
    if not path.exists():
        print(f"error: file not found: {path}")
        return 1
    with open(path, encoding="utf-8", newline="") as f:
        counts = Counter(row["verdict"] for row in csv.DictReader(f))
    if args.only:
        print(f"{args.only}: {counts[args.only]}")
    else:
        for verdict in sorted(counts):
            print(f"{verdict}: {counts[verdict]}")
    return 0

- the top level must be a dictionary, and `"rules"` must be a list; otherwise `raise ValueError("playbook needs a 'rules' list")`
- every rule must have the three keys `id`, `topic` and `severity`, checked **in this order**; if one is missing, `raise ValueError(f"rule {i} is missing '{key}'")`, where `i` is the rule's index in the list (starting at 0)

import json
from pathlib import Path

REQUIRED = ("id", "topic", "severity")

def load_playbook(path):
    data = json.loads(Path(path).read_text(encoding="utf-8"))
    if not isinstance(data, dict) or not isinstance(data.get("rules"), list):
        raise ValueError("playbook needs a 'rules' list")
    by_topic = {}
    for i, rule in enumerate(data["rules"]):
        for key in REQUIRED:
            if key not in rule:
                raise ValueError(f"rule {i} is missing '{key}'")
        by_topic.setdefault(rule["topic"], []).append(rule["id"])
    return by_topic
