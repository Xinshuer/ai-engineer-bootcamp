@@ concept
title: Why we need retrieval (RAG)
--- body
The model has never seen this customer's playbook, and it has never seen this contract. When there is little material, you can put all of it into the prompt (in DeepSeek mode the project puts the whole contract into the system prompt; see `full_contract` in `config.py`). Once there is a lot, it gets expensive and slow, it can go over the context length, and unrelated content makes the model miss things.

**RAG** (Retrieval-Augmented Generation): **first find the few passages related to the question, put only those into the prompt, then let the model answer.**

Clause Check uses the simplest kind: the model first decides the clause's topic, then calls the tool `lookup_playbook(topic)`, and `playbook.py` returns only the few rules for that topic, not the whole playbook.

When you debug, remember what Day 7 said: **a retrieval error looks just like a reasoning error by the model.** First check that the passages sent to the model are the right ones.
--- code
PLAYBOOK = [
    {"id": "PB-01", "topic": "liability_cap", "text": "Liability is capped at 100% of the fees paid in the prior 12 months."},
    {"id": "PB-03", "topic": "auto_renewal", "text": "Renewal periods must not exceed 12 months."},
    {"id": "PB-05", "topic": "payment", "text": "Payment within 30 days; no suspension without notice."},
    {"id": "PB-07", "topic": "termination", "text": "Customer may terminate for convenience on 30 days' notice."},
]

def lookup_playbook(topic):
    return [r for r in PLAYBOOK if r["topic"] == topic]

clause = "This Agreement renews automatically for successive twenty-four (24) month periods."
rules = lookup_playbook("auto_renewal")
prompt = "Rules:\n" + "\n".join(f"[{r['id']}] {r['text']}" for r in rules) + "\n\nClause:\n" + clause
print(prompt)
print(f"\nretrieved {len(rules)} of {len(PLAYBOOK)} rules")

@@ concept
title: Cleaning text
--- body
Text extracted from a PDF is messy: extra spaces and line breaks, plus the header and footer that appear on every page (`CloudNotes Confidential`, `Page 3 of 12`). If you don't clean it, the footer gets mixed into the clause text, and it may even be retrieved as "relevant content".

- `re.sub(r"\s+", " ", text).strip()`: every run of whitespace (spaces, line breaks, tabs) becomes one space
- Removing headers and footers: go line by line and drop every line where the **whole line** matches a pattern like `page \d+ of \d+`. `re.fullmatch(pattern, text)` requires the whole text to match; a match in just part of it is not enough. The project's `_strip_repeated_lines` in `parse.py` is smarter: a line that repeats on most pages is treated as a header or footer and deleted
- **Lowercase only for comparing**: use `text.lower()` when you search; when you show text to the lawyer or quote it, use the original
--- code
import re

page = """CloudNotes Confidential
3.2   Late Payment
Overdue amounts accrue   interest at three percent
(3%) per month.
Page 3 of 12
"""
kept = []
for line in page.splitlines():
    s = line.strip()
    if re.fullmatch(r"page \d+ of \d+", s.lower()) or s == "CloudNotes Confidential":
        continue
    kept.append(line)
clean = re.sub(r"\s+", " ", " ".join(kept)).strip()
print(repr(clean))
print(clean.lower())
# a sentence in the body that mentions page: the whole line is not "page <number> of <number>", so no match (None), and it is not deleted
print(re.fullmatch(r"page \d+ of \d+", "see page 3 of the order form"))

@@ concept
title: Chunking: by structure, by length, with overlap
--- body
The unit of retrieval is called a **chunk**. How you cut the text decides what you can find:

- **By structure**: contracts come with numbered headings, so one clause is one chunk. That is what the project's `split.py` does (the top of the file says structure-aware chunking); each chunk carries its number, its heading and its cross-references
- **By length**: long text without structure is cut every `size` characters. Neighboring chunks **overlap** by `overlap` characters, so that a sentence cut right in half is not left incomplete on both sides. Each time, move forward by `step = size - overlap`
- Every chunk must carry an `id` and where it came from (for example its start position `start`); citing and debugging later both rely on it

The classic mistake: when `overlap >= size`, `step <= 0` and the loop never moves forward. So check the arguments first, and `raise ValueError` if they don't make sense.
--- code
text = "ABCDEFGHIJ"
size, overlap = 4, 1
step = size - overlap
start = 0
while True:
    print(" " * start + text[start:start + size], "start =", start)
    if start + size >= len(text):
        break
    start += step

@@ concept
title: Token estimates and budgets
--- body
Models charge by the **token**, and the context length is counted in tokens too. A token is a small piece cut out by the tokenizer; it is not a character, and not a word either. Before you write code, make a rough estimate:

- English: about **4 characters ≈ 1 token**
- Chinese: tokenizers differ a lot between models. OpenAI's older tokenizers often need 1–2 tokens per Chinese character; DeepSeek's docs give a rough conversion of about 0.6 tokens per Chinese character and about 0.3 tokens per English character (the official docs have the final word)
- For exact numbers, look at the `usage` the API returns (Day 4); estimates are only for planning

**Budget** = context length − system prompt and question − room left for the answer. Fill the remaining room chunk by chunk, from most relevant to least relevant, and skip what doesn't fit.
--- code
import math

def estimate_tokens(text):
    return math.ceil(len(text) / 4)

chunks = [
    {"id": "c3", "text": "Liability is capped at 100% of the fees paid in the prior 12 months."},
    {"id": "c7", "text": "Either party may terminate for material breach on thirty days' notice."},
    {"id": "c1", "text": "Definitions."},
]
context_window = 120
prompt_tokens = 60
answer_tokens = 30
budget = context_window - prompt_tokens - answer_tokens
print("budget:", budget)
for c in chunks:
    print(c["id"], len(c["text"]), "chars ->", estimate_tokens(c["text"]), "tokens")

@@ concept
title: Keyword search
--- body
The simplest kind of search: the more of the question's words appear in a chunk, the more relevant the chunk is.

1. Split into words (tokenize): `re.findall(r"[a-z0-9]+", text.lower())`
2. Remove the **stop words** (the, of, and: words that are everywhere and would only add noise)
3. Score: how many **different** words from the question appear in the chunk (set intersection, Day 8)
4. Sort by score from high to low and take the first k; drop chunks with a score of 0

Python's `sorted` is **stable**: elements with equal scores keep their original order, so sorting by `-score` alone is enough. The project's rule-based review (`rule_based_review` in `review.py`) picks the topic exactly this way: it counts how many times each topic's keywords hit in the clause.

The downside: it only matches the literal words. Ask about cancel and it won't find the clause that says terminate. This is called the **synonym problem**. BM25, which is common in production, is also a keyword method, just with a smarter score (rarer words score higher); the synonym problem is still there.
--- code
import re

STOP = {"the", "a", "an", "of", "to", "and", "or", "in", "on", "for", "is", "are", "be", "shall", "may", "we", "can", "this", "that"}

def tokenize(text):
    return [w for w in re.findall(r"[a-z0-9]+", text.lower()) if w not in STOP]

chunks = [
    {"id": "c1", "text": "Either party may terminate this Agreement for material breach."},
    {"id": "c2", "text": "Fees are payable within thirty (30) days of the invoice date."},
    {"id": "c3", "text": "Late fees accrue interest; Provider may suspend the Service."},
]
for q in ["When are fees payable?", "Can we cancel early?"]:
    words = set(tokenize(q))
    scores = {c["id"]: len(words & set(tokenize(c["text"]))) for c in chunks}
    print(q, tokenize(q), scores)

@@ concept
title: Vectors and cosine similarity
--- body
Another approach: turn each piece of text into a **vector** (a list of decimal numbers). Texts with similar meanings have vectors that point in similar **directions**. To compare two directions, use **cosine similarity**:

```python
dot = sum(x * y for x, y in zip(a, b))       # dot product
norm_a = math.sqrt(sum(x * x for x in a))    # the length of the vector
cos = dot / (norm_a * norm_b)
```

- 1: exactly the same direction; 0: unrelated; -1: opposite directions
- Only the direction counts, not the length: the cosine of `[1, 2]` and `[2, 4]` is 1
- Edge case: an all-zero vector has no direction. Its length is 0, and dividing by it directly raises `ZeroDivisionError`. By convention, return `0.0`
- Put the denominator in parentheses: `dot / norm_a * norm_b` divides first and then multiplies, and the wrong result raises no error
--- code
import math

a = [1.0, 2.0, 0.0]
b = [2.0, 4.0, 0.0]
c = [0.0, 0.0, 3.0]

dot_ab = sum(x * y for x, y in zip(a, b))
norm_a = math.sqrt(sum(x * x for x in a))
norm_b = math.sqrt(sum(x * x for x in b))
print(dot_ab, round(norm_a, 3), round(norm_b, 3))
print("cos(a, b) =", round(dot_ab / (norm_a * norm_b), 3))
print("wrong    =", round(dot_ab / norm_a * norm_b, 3))

dot_ac = sum(x * y for x, y in zip(a, c))
print("cos(a, c) =", dot_ac / (norm_a * math.sqrt(sum(x * x for x in c))))

@@ concept
title: The embeddings API
mock: yes
--- body
An **embedding model** turns a piece of text into a vector of fixed length, and texts with similar meanings point in similar directions. That is why asking about cancel can still find the clause that says terminate.

- Request: `POST https://api.openai.com/v1/embeddings`, header `Authorization: Bearer <OPENAI_API_KEY>`, body `{"model": "text-embedding-3-small", "input": [text1, text2, ...]}`
- Response: a `data` list; each item has `index` and `embedding`, and item i belongs to text i
- **DeepSeek has no embeddings API.** Common choices are OpenAI's `text-embedding-3-small` (1536 dimensions), or a local embedding model loaded in LM Studio (`http://127.0.0.1:1234/v1/embeddings`, same format)
- The mock API on this page has the same format as OpenAI's, but it is not a real model: it hashes the words (with stop words removed and a few groups of contract synonyms merged) into 256-dimensional vectors, so don't take its scores seriously
- Compute the documents' vectors **once and store them**; for each question, compute only the question's vector. Send a batch of texts in **one request**
--- code
import math
import os
import requests

EMBED_URL = "https://api.openai.com/v1/embeddings"
headers = {"Authorization": f"Bearer {os.getenv('OPENAI_API_KEY')}"}
texts = [
    "Can we cancel the contract early?",
    "Either party may terminate this Agreement for material breach.",
    "Fees are payable within thirty (30) days of the invoice date.",
]
data = requests.post(EMBED_URL, headers=headers, json={"model": "text-embedding-3-small", "input": texts}).json()
vectors = [d["embedding"] for d in sorted(data["data"], key=lambda d: d["index"])]
print(len(vectors), "vectors,", len(vectors[0]), "numbers each")
print("usage:", data["usage"])

def cosine(a, b):
    na = math.sqrt(sum(x * x for x in a))
    nb = math.sqrt(sum(y * y for y in b))
    if na == 0 or nb == 0:
        return 0.0
    return sum(x * y for x, y in zip(a, b)) / (na * nb)

print("question vs termination:", round(cosine(vectors[0], vectors[1]), 3))
print("question vs payment:    ", round(cosine(vectors[0], vectors[2]), 3))

@@ concept
title: Putting retrieved chunks into the prompt
--- body
Put the retrieved chunks into the prompt **with their ids**, and tell the model how to use them:

- **Answer only from the excerpts**: the model may not fill the gaps with "most contracts work like this"
- **Cite the ids**: when the answer contains `[c7]`, your code can check whether the excerpt it cites was really given to it, and whether the original text really says that (Day 19 writes this check)
- **Allow "I don't know"**: much safer than making up an answer
- Order: rules first, excerpts in the middle, the question last

The code below uses a triple-quoted f-string: inside triple quotes you can break lines directly, and `{...}` is still replaced.
--- code
import re

chunks = [
    {"id": "c3", "text": "Either party may terminate this Agreement for material breach."},
    {"id": "c7", "text": "Customer may terminate for convenience on 30 days' notice."},
]
question = "Can we cancel early?"
excerpts = "\n".join(f"[{c['id']}] {c['text']}" for c in chunks)
prompt = f"""Answer using ONLY the excerpts below.
After each claim, cite the excerpt id in brackets, e.g. [c2].
If the excerpts do not contain the answer, say: not found in the excerpts.

{excerpts}

Question: {question}"""
print(prompt)

answer = "Yes: the Customer may terminate for convenience on 30 days' notice [c7]."
print("\ncited:", re.findall(r"\[(c\d+)\]", answer))

Write `clean(text)` to clean one page of text extracted from a PDF:

--- solution
import re

FOOTER = re.compile(r"page \d+ of \d+")

def clean(text):
    kept = [line for line in text.splitlines() if not FOOTER.fullmatch(line.strip().lower())]
    return re.sub(r"\s+", " ", " ".join(kept)).strip()
--- tests

level: 2

--- context
The unit of retrieval is called a "chunk". Some material has no numbered headings to cut at, for example a very long negotiation email. It can only be cut by length into small chunks, which are then searched.
--- prompt
Write `chunk_fixed(text, size, overlap)`:

- The first chunk starts at position 0; each time, move forward by `step = size - overlap`
- Each chunk is `{"id": "c1", "start": start position, "text": text[start:start + size]}`; the ids start at `c1`
- Once a chunk reaches the end of the text (`start + size >= len(text)`), stop; don't cut another chunk
- If `text` is empty, return `[]`
- If the arguments don't make sense, `raise ValueError`: `size <= 0`, `overlap < 0`, `overlap >= size`

Example: `chunk_fixed("abcdefghij", 4, 1)` cuts three chunks, with the texts `"abcd"`, `"defg"`, `"ghij"`.
--- starter
def chunk_fixed(text, size, overlap):
    chunks = []
    return chunks
--- solution
def chunk_fixed(text, size, overlap):
    if size <= 0 or overlap < 0 or overlap >= size:
        raise ValueError(f"bad size/overlap: {size}/{overlap}")
    chunks = []
    if not text:
        return chunks
    step = size - overlap
    start = 0
    while True:
        chunks.append({"id": f"c{len(chunks) + 1}", "start": start, "text": text[start:start + size]})
        if start + size >= len(text):
            break
        start += step
    return chunks
--- tests
texts = lambda chunks: [c["text"] for c in chunks]
expect("overlap of 1 character", lambda: texts(chunk_fixed("abcdefghij", 4, 1)), ["abcd", "defg", "ghij"])
expect("the whole second chunk", lambda: chunk_fixed("abcdefghij", 4, 1)[1], {"id": "c2", "start": 3, "text": "defg"})
expect("no overlap, the last chunk is shorter", lambda: texts(chunk_fixed("abcdefghij", 4, 0)), ["abcd", "efgh", "ij"])
expect("text shorter than size", lambda: chunk_fixed("abc", 10, 2), [{"id": "c1", "start": 0, "text": "abc"}])
expect("empty text", lambda: chunk_fixed("", 4, 1), [])
expect_raises("overlap >= size", lambda: chunk_fixed("abcdef", 4, 4), ValueError)
expect_raises("size is 0", lambda: chunk_fixed("abcdef", 0, 0), ValueError)
--- hints
- Put the argument check first: `if size <= 0 or overlap < 0 or overlap >= size: raise ValueError(...)`.
- Use `while True:`: first cut a chunk and add it to the list, then if `start + size >= len(text)`, `break`; otherwise `start += size - overlap`.
- Work out the id before adding the chunk to the list: `f"c{len(chunks) + 1}"`.

title: How big should a chunk be?
level: 2
cards: Chunking: by structure, by length, with overlap
--- context
Chunk size is the first parameter you have to decide when you build retrieval, and interviews often ask about it.
--- prompt
In contract retrieval, what is the most likely problem with chunks that are **too big** (say 3000 characters each), and with chunks that are **too small** (say 50 characters each)?
--- options
- Too big: one chunk mixes several things, the relevant sentence is diluted by unrelated content, and putting it into the prompt costs a lot of tokens; too small: sentences are cut to pieces and a chunk on its own makes no sense (for example "Subject to Section 12" ends up in another chunk)

- Too big: nothing can be found; too small: every search hits exactly
answer: 1
--- explain
Chunk size is a trade-off between "precise" and "complete". Contracts have a numbered structure, so Clause Check simply uses "one clause, one chunk" (`split.py`): each chunk is naturally one complete thing, and it carries its cross-references too. Fixed length plus overlap is only for long text without structure. The exact size should be decided by comparing with evals (Day 13), not by guessing.

import re

import re

def estimate_tokens(text):
    cjk = len(re.findall(r"[\u4e00-\u9fff]", text))
    other = len(text) - cjk

import re

STOP = {"the", "a", "an", "of", "to", "and", "or", "in", "on", "for", "is", "are", "be", "shall", "may", "we", "can", "this", "that"}

def tokenize(text):

def keyword_score(query, text):
    return len(set(tokenize(query)) & set(tokenize(text)))

def top_k(query, chunks, k):
    scored = []
    for c in chunks:
        score = keyword_score(query, c["text"])
        if score > 0:
            scored.append((score, c["id"]))
    scored = sorted(scored, key=lambda pair: -pair[0])
    return [cid for score, cid in scored[:k]]

def dot(a, b):
    if len(a) != len(b):
        raise ValueError(f"vector lengths differ: {len(a)} vs {len(b)}")

    return [d["embedding"] for d in sorted(resp.json()["data"], key=lambda d: d["index"])]

def cosine(a, b):
    na = math.sqrt(sum(x * x for x in a))
    nb = math.sqrt(sum(y * y for y in b))
    if na == 0 or nb == 0:
        return 0.0
    return sum(x * y for x, y in zip(a, b)) / (na * nb)

def build_index(chunks, path):
    vectors = embed_texts([c["text"] for c in chunks])
    rows = [{"id": c["id"], "text": c["text"], "vector": v} for c, v in zip(chunks, vectors)]
    path = Path(path)
    path.parent.mkdir(parents=True, exist_ok=True)
    path.write_text(json.dumps(rows), encoding="utf-8")
    return len(rows)

def search(path, query, k):
    rows = json.loads(Path(path).read_text(encoding="utf-8"))
    q = embed_texts([query])[0]
    ranked = sorted(rows, key=lambda r: -cosine(q, r["vector"]))
    return [r["id"] for r in ranked[:k]]

--- context
Contracts come with numbered headings, so one clause is one chunk. This is the best way to cut a contract, and the real project's `split.py` cuts it this way too.
--- prompt
Write `chunk_by_heading(text)`, which cuts a contract into chunks at its numbered headings:

- **Heading line**: after removing the whitespace at both ends, it starts with a number (like `8`, `8.1`, `10.2.1`), followed by a space and a capital letter. You can check with `re.match(r"\d+(\.\d+)*\s+[A-Z]", line)`
- Each heading line starts a chunk, and the lines below it, up to the next heading, are its body; ignore anything before the first heading
- Join the body lines with spaces, merge runs of whitespace into one space, and remove the whitespace at both ends; **drop chunks with an empty body (just a section heading)**
- Return `[{"id": "c1", "heading": "8.1 Cap on Liability", "text": body}, ...]`: `id` numbers the kept chunks starting from `c1`, and `heading` is the whole heading line with the whitespace at both ends removed
--- solution
import re

HEAD = re.compile(r"\d+(\.\d+)*\s+[A-Z]")

def chunk_by_heading(text):
    blocks = []
    for line in text.splitlines():
        s = line.strip()
        if HEAD.match(s):
            blocks.append({"heading": s, "lines": []})
        elif blocks:
            blocks[-1]["lines"].append(s)
    chunks = []
    for b in blocks:
        body = re.sub(r"\s+", " ", " ".join(b["lines"])).strip()
        if body:
            chunks.append({"id": f"c{len(chunks) + 1}", "heading": b["heading"], "text": body})
    return chunks

import re

STOP = {"the", "a", "an", "of", "to", "and", "is", "are", "we", "can", "do"}

def tokenize(text):
    return {w for w in re.findall(r"[a-z0-9]+", text.lower()) if w not in STOP}

def retrieve(query, chunks, k):
    q = tokenize(query)
    scored = []
    for c in chunks:
        score = len(q & tokenize(c["text"]))
        if score > 0:
            scored.append((score, c["id"]))
    scored = sorted(scored, key=lambda pair: -pair[0])
    return [cid for score, cid in scored[:k]]

title: Closed book: search + budget + prompt
exam: yes
level: 3
cards: Putting retrieved chunks into the prompt; Token estimates and budgets; Keyword search
--- context
Everything the "ask the contract" tool prepares before it sends a request: from the lawyer's one-sentence question to the text actually sent to the model. When nothing is found, it is better to say so directly than to let the model answer out of thin air.
--- prompt
Write `answer_context(query, chunks, k, budget)`, which returns the prompt string to send to the model (each chunk is `{"id": ..., "text": ...}`):

1. **Search**: the query words = the words in the query that are **at least 4 characters long** (convert to lowercase, pull out the words with `re.findall(r"[a-z0-9]+", ...)`, remove duplicates). A chunk's score = how many query words appear among the words of the chunk's `text` (lowercased and split into words the same way). Drop scores of 0; sort from high to low, with ties keeping the original order, and take the first `k` chunks
2. **Fit the budget**: in the order from step 1, estimate `math.ceil(len(text) / 4)` tokens for each chunk; if adding a chunk would go over `budget`, skip it and go on to the next one
3. **Build the prompt**: the first line is `Answer using only these excerpts and cite their ids.`, then one line `[id] text` per chunk, and the last line is `Question: <query>`, joined with `"\n"`
4. If no chunk was picked, return `"No relevant excerpts found."`
--- solution
import math
import re

def _words(text):
    return set(re.findall(r"[a-z0-9]+", text.lower()))

def answer_context(query, chunks, k, budget):
    q = {w for w in _words(query) if len(w) >= 4}
    scored = []
    for c in chunks:
        score = len(q & _words(c["text"]))
        if score > 0:
            scored.append((score, c))
    ranked = [c for score, c in sorted(scored, key=lambda p: -p[0])][:k]
    picked = []
    used = 0
    for c in ranked:
        cost = math.ceil(len(c["text"]) / 4)
        if used + cost > budget:
            continue
        picked.append(c)
        used += cost
    if not picked:
        return "No relevant excerpts found."
    lines = ["Answer using only these excerpts and cite their ids."]
    lines += [f"[{c['id']}] {c['text']}" for c in picked]
    lines.append(f"Question: {query}")
    return "\n".join(lines)
