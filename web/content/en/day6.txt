@@ concept
title: async / await: wait for the network without freezing
--- body
Network requests take time. TypeScript uses a **Promise** to stand for "a result that arrives later":

```ts
async function ask(prompt: string): Promise<string> {
  const res = await fetch(URL, ...);   // waits here, then carries on once it arrives
  const data = await res.json();       // json() has to be awaited too
  return data.choices[0].message.content;
}
```

- Put `async` in front of the function and write the return type as `Promise<the real type>`
- Inside an async function, use `await` to wait until a Promise finishes
- **The most common bug: forgetting await**. You get a Promise that hasn't finished yet instead of the result
- Calling an async function needs `await` too: `const text = await ask("hi");`
--- code
function wait(ms: number): Promise<void> {
  return new Promise((resolve) => setTimeout(resolve, ms));
}

async function review(id: string): Promise<string> {
  console.log("start", id);
  await wait(10);
  return `done ${id}`;
}

async function main() {
  const r = await review("8.1");
  console.log(r);
  const p = review("4.2");
  console.log("without await:", p);
  console.log("after await:", await p);
}
main();

title: fetch: the requests.post of TypeScript
--- body
```ts
const res = await fetch("https://api.deepseek.com/v1/chat/completions", {
  method: "POST",
  headers: { Authorization: `Bearer ${process.env.DEEPSEEK_API_KEY}`, "Content-Type": "application/json" },

```

Three differences from Python: you must write `method: "POST"`; you `JSON.stringify` the request body yourself; `res.json()` needs await.

`process.env.DEEPSEEK_API_KEY` reads an environment variable, just like `os.getenv`. On this page it talks to a mock server; on your own computer it talks to the real one.

Thinking mode works as on Day 4: it is on by default, the reasoning is in `message.reasoning_content`, and thinking tokens are billed as output. Requests that review clauses add `thinking: { type: "disabled" }` to turn it off (faster, cheaper, and only then does `temperature` take effect).
--- code
async function main() {
  const res = await fetch("https://api.deepseek.com/v1/chat/completions", {
    method: "POST",
    headers: { Authorization: `Bearer ${process.env.DEEPSEEK_API_KEY}`, "Content-Type": "application/json" },
    body: JSON.stringify({ model: "deepseek-flash", messages: [{ role: "user", content: "Say hello" }] }),
  });
  console.log(res.status, res.ok);
  const data = await res.json();
  console.log(data.choices[0].message.content);
  console.log(data.usage.total_tokens, "reasoning:", data.usage.completion_tokens_details.reasoning_tokens);

  const off = await fetch("https://api.deepseek.com/v1/chat/completions", {
    method: "POST",
    headers: { Authorization: `Bearer ${process.env.DEEPSEEK_API_KEY}`, "Content-Type": "application/json" },
    body: JSON.stringify({ model: "deepseek-flash", messages: [{ role: "user", content: "Say hello" }], thinking: { type: "disabled" } }),
  });
  const offData = await off.json();
  // thinking off: no reasoning_content, and far fewer tokens (when it is off, completion_tokens_details may be missing, so don't read it directly)
  console.log(offData.usage.total_tokens);
}

@@ concept
title: try / catch / throw
--- body
```ts
try {
  const data = JSON.parse(raw);
} catch (e) {
  console.log("bad json:", e instanceof Error ? e.message : String(e));
}
```

- Python's `except` → `catch`; `raise ValueError("...")` → `throw new Error("...")`
- In TypeScript the `e` in `catch (e)` has the type `unknown` (anything can be thrown), so check `e instanceof Error` before you use it
- An error thrown inside an async function is caught by the caller's try/catch when the caller `await`s it
--- code
function parseRisk(text: string): string {
  const risk = text.trim().toLowerCase();
  if (!["low", "medium", "high"].includes(risk)) {
    throw new Error(`unknown risk: ${text}`);
  }
  return risk;
}
console.log(parseRisk(" HIGH "));
try {
  parseRisk("urgent");
} catch (e) {
  console.log("caught:", e instanceof Error ? e.message : String(e));
}
try {
  JSON.parse("{oops");
} catch (e) {
  console.log("bad json:", e instanceof Error ? e.name : "?");
}

@@ concept
title: Zod: the Pydantic of TypeScript
--- body
```ts
import { z } from "zod";

const VerdictSchema = z.object({
  clause_id: z.string(),
  verdict: z.enum(["accept", "flag", "redline"]),
  confidence: z.number().default(0.5),
});
```

- `z.enum([...])` is `Literal[...]`; `z.object({...})` is `BaseModel`
- `Schema.parse(data)`: returns the data if it is valid, otherwise **throws**
- `Schema.safeParse(data)`: doesn't throw; returns `{ success: true, data }` or `{ success: false, error }`, with the errors in `error.issues`
- Note that Zod validates **objects**: `JSON.parse` the model's text first
--- code
import { z } from "zod";

const VerdictSchema = z.object({
  clause_id: z.string(),
  verdict: z.enum(["accept", "flag", "redline"]),
  confidence: z.number().default(0.5),
});

console.log(VerdictSchema.parse({ clause_id: "8.1", verdict: "flag" }));
const bad = VerdictSchema.safeParse({ clause_id: "8.1", verdict: "HIGH" });
if (!bad.success) {
  console.log(bad.error.issues[0].path, bad.error.issues[0].message);
}

@@ concept
title: z.infer: one definition, two uses
--- body
A Pydantic class is itself a type. A Zod schema is a **value**; use `z.infer` to get a **type** from it:

```ts
type Verdict = z.infer<typeof VerdictSchema>;
// { clause_id: string; verdict: "accept" | "flag" | "redline"; confidence: number }
```

This way the runtime validation (the schema) and the compile-time type (the type) always agree, and you don't write them twice. In Clause Check, Pydantic also generates the JSON Schema the model sees: the same idea.
--- code
import { z } from "zod";

const VerdictSchema = z.object({
  clause_id: z.string(),
  verdict: z.enum(["accept", "flag", "redline"]),
});
type Verdict = z.infer<typeof VerdictSchema>;

function describe(v: Verdict): string {
  return `${v.clause_id}: ${v.verdict}`;
}
const v: Verdict = VerdictSchema.parse(JSON.parse('{"clause_id": "8.1", "verdict": "redline"}'));
console.log(describe(v));

title: Tool dispatch: a table from names to functions
--- body
The model says "call lookup_playbook with the arguments {"topic": "payment"}". The code has to find the function by its name:

```ts
const tools: Record<string, (args: any) => string> = {
  lookup_playbook: (args) => `rule for ${args.topic}`,
};
const result = tools[name](JSON.parse(argumentsText));
```

`Record<string, function type>` is the Python dictionary `{"name": function}`. `(args: any) => string` is a function type: it takes one argument and returns a string.
--- code

@@ concept
title: import / export and what Mastra looks like
--- body
In real projects the code is split across several files: one file has `export function classify(...)`, another has `import { classify } from "./review"`. On this page every exercise is a single file, but you will use `import { z } from "zod"`.

A Mastra tool definition has roughly this shape (a sketch; the official docs at mastra.ai have the exact syntax):

```ts
const lookupPlaybook = createTool({
  id: "lookup_playbook",
  description: "Return the customer's rule for one topic. Call before deciding.",
  inputSchema: z.object({ topic: z.enum(["payment", "liability_cap"]) }),
  execute: async (...) => { ... },
});
```

You can already read every part of it: Zod defines the arguments (like Pydantic), description says when to use the tool, and execute is an async function. Python's `@tool + Pydantic` and Mastra's `createTool + Zod` are the same concept. In an interview, say: "The concepts are the same. Everything I have done in Python has a counterpart in Mastra."
--- code
import { z } from "zod";

const ToolInput = z.object({ topic: z.enum(["payment", "liability_cap"]) });
type ToolInput = z.infer<typeof ToolInput>;

async function execute(input: ToolInput): Promise<string> {
  return `rule for ${input.topic}`;
}

async function main() {
  const raw = JSON.parse('{"topic": "payment"}');
  console.log(await execute(ToolInput.parse(raw)));
  console.log(ToolInput.safeParse({ topic: "gdpr" }).success);
}
main();

--- solution
const API_URL = "https://api.deepseek.com/v1/chat/completions";
const HEADERS = { Authorization: `Bearer ${process.env.DEEPSEEK_API_KEY}` };
const RETRYABLE = [429, 500, 503];

async function askWithRetry(prompt: string, maxAttempts = 3): Promise<string> {
  const body = JSON.stringify({ model: "deepseek-flash", messages: [{ role: "user", content: prompt }] });
  for (let attempt = 1; attempt <= maxAttempts; attempt++) {
    const res = await fetch(API_URL, { method: "POST", headers: HEADERS, body });
    if (res.status === 200) {
      const data = await res.json();
      return data.choices[0].message.content;
    }
    if (!RETRYABLE.includes(res.status)) {
      throw new Error(`not retryable: ${res.status}`);
    }
  }
  throw new Error(`gave up after ${maxAttempts} attempts`);
}
--- tests

  return [text, MOCK.calls.length];
}, ["Mock reply: hi", 3]);
expectAsync("always 503: throws after only 3 requests", async () => {
  MOCK.reset(); MOCK.failNext(503, 5);
  try { await askWithRetry("hi"); return "no error thrown"; } catch { return MOCK.calls.length; }
}, 3);

import { z } from "zod";

const VerdictSchema = z.object({
  clause_id: z.string(),
  verdict: z.enum(["accept", "flag", "redline"]),
});
type Verdict = z.infer<typeof VerdictSchema>;

function parseVerdict(raw: string): Verdict | string {
  let data: unknown;
  try {
    data = JSON.parse(raw);

    return "INVALID: bad json";

type ToolCall = { id: string; function: { name: string; arguments: string } };
type Tools = Record<string, (args: any) => string>;

function runToolCall(call: ToolCall, tools: Tools): string {
  const fn = tools[call.function.name];
  if (!fn) {

  }
  return fn(JSON.parse(call.function.arguments));
}

  const res = await fetch(API_URL, { method: "POST", headers: HEADERS, body: JSON.stringify({ model: "deepseek-flash", messages: [{ role: "user", content: text }], response_format: { type: "json_object" }, thinking: { type: "disabled" } }) });

async function passRate(text: string, expected: string, n: number): Promise<number> {
  let hits = 0;
  for (let i = 0; i < n; i++) {
    const v = await classify(text);
    if (v.verdict === expected) {
      hits += 1;
    }
  }
  return hits / n;
}

- Converts an object to JSON

--- explain
A Zod schema is a value at runtime and does the validation; `z.infer` derives a type from it at compile time. const RuleSchema = z.object({
  id: z.string(),
  topic: z.string(),
  severity: z.enum(["low", "medium", "high"]),
});
type Rule = z.infer<typeof RuleSchema>;

function loadRule(raw: string): Rule | null {
  try {

async function countTokens(prompts: string[]): Promise<number> {
