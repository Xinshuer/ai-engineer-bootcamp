@@ concept
title: interrupt(): stop and ask a person
--- body
Yesterday's `interrupt_before` can only stop in front of a node, and when it stops it doesn't say what the person should look at. `interrupt(payload)` stops **inside** a node and hands over "what the person needs to see" along with it:

```python
def approve(state):
    decision = interrupt({"question": "Apply these redlines?", "redlines": state["redlines"]})
    return {"approved": bool(decision)}
```

- The first time the run reaches this line, the graph stops, and the value `invoke` returns has an extra `"__interrupt__"` key. It is a list, and `[0].value` is the payload you passed in
- Once the person has decided: `app.invoke(Command(resume=True), cfg)`. This time `interrupt(...)` **returns** True, and the node carries on
- You must have a checkpointer and a thread_id. Without a checkpointer the graph still stops, but `Command(resume=...)` raises `RuntimeError` right away: this run can never be resumed
- Import both `interrupt` and `Command` from `langgraph.types`
--- code
from typing import TypedDict
from langgraph.graph import StateGraph, START, END
from langgraph.checkpoint.memory import InMemorySaver
from langgraph.types import interrupt, Command

class State(TypedDict, total=False):
    redlines: list[str]
    approved: bool
    exported: list[str]

def approve(state: State):
    decision = interrupt({"question": "Apply these redlines?", "redlines": state["redlines"]})
    return {"approved": bool(decision)}

def export(state: State):
    return {"exported": state["redlines"] if state["approved"] else []}

g = StateGraph(State)
g.add_node("approve", approve)
g.add_node("export", export)
g.add_edge(START, "approve")
g.add_edge("approve", "export")
g.add_edge("export", END)
app = g.compile(checkpointer=InMemorySaver())
cfg = {"configurable": {"thread_id": "msa-7"}}

result = app.invoke({"redlines": ["8.1", "12"]}, cfg)
print(sorted(result))                          # __interrupt__ is new
print(result["__interrupt__"][0].value)        # what the person gets to see
print("next:", app.get_state(cfg).next)
print(app.invoke(Command(resume=True), cfg))   # this time interrupt(...) returns True

no_saver = g.compile()                         # no checkpointer
print("__interrupt__" in no_saver.invoke({"redlines": ["8.1"]}, cfg))
try:
    no_saver.invoke(Command(resume=True), cfg)
except RuntimeError as e:
    print("RuntimeError:", e)

@@ concept
title: On resume, the node reruns from the top
--- body
The easiest trap to fall into: on resume, LangGraph does **not** carry on from the `interrupt()` line. It reruns the whole node **from its first line**, and when it reaches `interrupt()`, that call returns the resume value right away. (Your Day 19 runner did the same: the interrupted node ran once more.)

- So the code **before** `interrupt()` runs twice: sending a notification, charging money, writing to a database... all of it happens again
- Fix 1: put side effects in the **previous node**. That node has already finished and its checkpoint is saved, so it won't rerun
- Fix 2: put them **after** `interrupt()` (they run once, only after the answer has arrived)
- Fix 3: if they really must come before it, make them idempotent: the outbox from Day 17, "at-least-once + idempotency key" from Week 4
- Pure computation (for example working out the list waiting for approval from the state) can safely rerun. The `approve` in `graph.py` computes `pending` first, then calls `interrupt`
--- code
from typing import TypedDict
from langgraph.graph import StateGraph, START, END
from langgraph.checkpoint.memory import InMemorySaver
from langgraph.types import interrupt, Command

RUNS = []

class State(TypedDict, total=False):
    redlines: list[str]
    approved: bool

def approve(state: State):
    RUNS.append("before interrupt")              # runs again on resume
    decision = interrupt({"redlines": state["redlines"]})
    RUNS.append(f"after interrupt: {decision}")  # runs only once the answer has arrived
    return {"approved": decision}

g = StateGraph(State)
g.add_node("approve", approve)
g.add_edge(START, "approve")
g.add_edge("approve", END)
app = g.compile(checkpointer=InMemorySaver())
cfg = {"configurable": {"thread_id": "t1"}}

app.invoke({"redlines": ["8.1"]}, cfg)
print("paused :", RUNS)
app.invoke(Command(resume=True), cfg)
print("resumed:", RUNS)

@@ concept
title: Several ways to answer an approval
--- body
A real approval is more than "yes / no": a lawyer may want to remove one or two items before approving. The resume value can be anything a checkpoint can store, for example a dictionary:

```python
Command(resume={"action": "approve"})
Command(resume={"action": "reject"})
Command(resume={"action": "edit", "redlines": ["12"]})
```

- **Validate** the person's input too, just like you validate the model's output: if you don't recognize the answer, call `interrupt()` again and ask clearly. Don't guess. One node can call `interrupt()` several times; on resume, the answers are matched to the calls in order
- "Edit" needs limits: only allow removing items from the list waiting for approval, never sneaking in new clauses
- `interrupt_before` or `interrupt()`? The first is fixed at compile time and carries no explanation; if the person wants a change, the only way is `update_state`. The second lives inside the node and carries a payload, and the person's answer comes straight back into your code to be validated and carried out. Use `interrupt()` for approval flows; `interrupt_before` is better for stopping at every step while debugging
- Day 31's `HumanInTheLoopMiddleware` also calls `interrupt()` inside; its resume value is `{"decisions": [...]}`
--- code
from typing import TypedDict
from langgraph.graph import StateGraph, START, END
from langgraph.checkpoint.memory import InMemorySaver
from langgraph.types import interrupt, Command

class State(TypedDict, total=False):
    redlines: list[str]
    approved: bool

def approve(state: State):
    pending = state["redlines"]
    ask = {"question": "approve / reject / edit?", "redlines": pending}
    while True:
        decision = interrupt(ask)
        action = decision.get("action") if isinstance(decision, dict) else None
        if action == "approve":
            return {"approved": True}
        if action == "reject":
            return {"approved": False, "redlines": []}
        if action == "edit":
            keep = [r for r in pending if r in decision.get("redlines", [])]   # removing only
            return {"approved": True, "redlines": keep}
        ask = {"question": f"unknown answer {decision!r}; approve / reject / edit?", "redlines": pending}

g = StateGraph(State)
g.add_node("approve", approve)
g.add_edge(START, "approve")
g.add_edge("approve", END)
app = g.compile(checkpointer=InMemorySaver())
cfg = {"configurable": {"thread_id": "t1"}}

r = app.invoke({"redlines": ["8.1", "12"]}, cfg)
print(r["__interrupt__"][0].value["question"])
r = app.invoke(Command(resume="looks good"), cfg)          # an answer it can't understand: ask again
print(r["__interrupt__"][0].value["question"])
r = app.invoke(Command(resume={"action": "edit", "redlines": ["12", "99"]}), cfg)
print(r)

@@ concept
title: Command: update and jump from a node
--- body
Until now, edges have always decided "where to go next": a node returns an update, then a routing function looks at the state and decides the next step. `Command` lets a node say both things at once:

```python
def triage(state) -> Command[Literal["approve", "export"]]:
    if "redline" in state["verdicts"]:
        return Command(update={"status": "needs approval"}, goto="approve")
    return Command(update={"status": "clean"}, goto="export")
```

- The return type annotation `Command[Literal[...]]` tells the graph "which nodes it might go to": at compile time the graph checks that these names really are nodes, and `draw_mermaid()` also relies on it to draw the dotted edges. Without it the graph still runs; you just don't see these edges in the drawing
- But at run time the value of `goto` is not checked against the annotation: if `goto` has a wrong node name, there is no error, only a warning in the log, and the graph just stops (the same as a wrong routing function on Day 32). So every path needs a test
- When to use it: when the routing decision and the update you write are worked out together anyway (for example, an approval node decides from the person's answer whether to go to export or back to review); for ordinary branches, conditional edges are clearer
--- code
from typing import Literal, TypedDict
from langgraph.graph import StateGraph, START, END
from langgraph.types import Command

class State(TypedDict, total=False):
    verdicts: list[str]
    status: str

def triage(state: State) -> Command[Literal["approve", "export"]]:
    if "redline" in state["verdicts"]:
        return Command(update={"status": "needs approval"}, goto="approve")
    return Command(update={"status": "clean"}, goto="export")

def approve(state: State):
    return {"status": state["status"] + " -> approved"}

def export(state: State):
    return {"status": state["status"] + " -> exported"}

g = StateGraph(State)
g.add_node("triage", triage)
g.add_node("approve", approve)
g.add_node("export", export)
g.add_edge(START, "triage")          # no edge needed after triage: Command decides
g.add_edge("approve", "export")
g.add_edge("export", END)
app = g.compile()

print(app.invoke({"verdicts": ["accept", "redline"]})["status"])
print(app.invoke({"verdicts": ["accept"]})["status"])
print([line.strip() for line in app.get_graph().draw_mermaid().splitlines() if "-.->" in line])

@@ concept
title: Send: one branch per clause (map-reduce)
--- body
A contract has 30 clauses, and reviewing each one doesn't depend on the others, so it's a good fit for running in parallel. But the number of clauses is only known at run time, so you can't draw 30 edges in advance. `Send` solves this: the routing function of a conditional edge returns a list of `Send`s, and each `Send("review", {"clause": c})` starts one run of the `review` node, carrying **its own input**.

```python
def fan_out(state):
    return [Send("review", {"clause": c}) for c in state["clauses"]]
g.add_conditional_edges(START, fan_out, ["review"])
```

- `review` doesn't receive the whole state, only the dictionary from the Send (you can describe it with a separate `ClauseState`)
- The key where results are written back into the main state **must have a reducer** (`Annotated[list, operator.add]`); otherwise several branches writing one key in the same step raise `InvalidUpdateError`. The merge order = the order of the Sends
- Once all branches have finished, the edge `review → summarise` makes summarise run only **once**: that is the reduce
- On your computer, the branches really run in parallel in several threads; `config={"max_concurrency": 4}` limits how many run at the same time, so you don't hit the API's rate limit. This page has no threads, so they run one after another, with the same result
- When the clause list is empty, the routing function returns `[]` and none of the later nodes run; if you need them, return `"summarise"` to jump straight there (it must also be in the list in the third argument)
- When you just want to call the model several times at once and don't need a graph, Day 29's `reviewer.batch(prompts, config={"max_concurrency": 4})` is simpler. Send fits when each branch is already a step in the flow: the results get combined afterwards, you want to see progress, you want checkpoints
--- code
import operator
from typing import Annotated, Literal, TypedDict
from pydantic import BaseModel, Field
from langchain_deepseek import ChatDeepSeek
from langgraph.graph import StateGraph, START, END
from langgraph.types import Send

class ClauseReview(BaseModel):
    """Review of one contract clause."""
    clause_id: str = Field(description="the clause number, e.g. 8.1")
    verdict: Literal["accept", "flag", "redline"]

# with_structured_output sends tools (Day 30): following this week's rule, turn thinking off; classifying doesn't need long reasoning anyway, and it's faster and cheaper
reviewer =ChatDeepSeek(model="deepseek-flash", extra_body={"thinking": {"type": "disabled"}}).with_structured_output(ClauseReview)

class State(TypedDict, total=False):
    clauses: list[dict]
    reviews: Annotated[list[dict], operator.add]     # several branches write here: a reducer is required
    counts: dict

class ClauseState(TypedDict):
    clause: dict

def fan_out(state: State):
    return [Send("review", {"clause": c}) for c in state["clauses"]]

def review(state: ClauseState):
    c = state["clause"]
    result = reviewer.invoke(f"Review clause {c['id']}: {c['text']}")
    return {"reviews": [{"clause_id": c["id"], "verdict": result.verdict}]}

def summarise(state: State):
    counts = {"accept": 0, "flag": 0, "redline": 0}
    for r in state["reviews"]:
        counts[r["verdict"]] += 1
    return {"counts": counts}

g = StateGraph(State)
g.add_node("review", review)
g.add_node("summarise", summarise)
g.add_conditional_edges(START, fan_out, ["review"])
g.add_edge("review", "summarise")
g.add_edge("summarise", END)
app = g.compile()

clauses = [{"id": "8.1", "text": "Liability is unlimited."},
           {"id": "9.2", "text": "Fees may change without notice."},
           {"id": "3.1", "text": "Invoices are payable within 30 days."}]
out = app.invoke({"clauses": clauses}, {"max_concurrency": 4})
print([(r["clause_id"], r["verdict"]) for r in out["reviews"]])
print(out["counts"], "| model calls:", len(MOCK.calls))

@@ concept
title: Subgraphs: package a clause review for reuse
--- body
A compiled graph is itself a Runnable, so it can be used directly as a node of another graph: `parent.add_node("review", review_graph)`.

- Why: the steps for reviewing one clause (classify → judge) can be written and tested on their own, then reused in the flow for the whole contract. In Clause Check, the bounded tool loop in `review.py` is already a separate part, and when you rewrite it with LangGraph it makes a good subgraph
- Keys that **both** States have (for example `text`, `verdict`) pass in and out automatically; keys **private** to the subgraph (for example `topic`) don't show up in the parent graph's state
- When the two States are completely different: call `review_graph.invoke({...})` inside an ordinary node function and convert the input and output yourself (you can also call it this way inside a Send branch)
- `stream(..., subgraphs=True)` shows every step inside the subgraph. Its namespace has a random suffix (`review:<uuid>`), so don't print the whole thing
--- code
from typing import TypedDict
from langgraph.graph import StateGraph, START, END

class ClauseState(TypedDict, total=False):
    text: str
    topic: str        # only the subgraph has this
    verdict: str

def classify(state: ClauseState):
    return {"topic": "liability_cap" if "liab" in state["text"].lower() else "other"}

def judge(state: ClauseState):
    risky = state["topic"] == "liability_cap" and "unlimited" in state["text"].lower()
    return {"verdict": "redline" if risky else "accept"}

sub = StateGraph(ClauseState)
sub.add_node("classify", classify)
sub.add_node("judge", judge)
sub.add_edge(START, "classify")
sub.add_edge("classify", "judge")
sub.add_edge("judge", END)
review_graph = sub.compile()
print("alone :", review_graph.invoke({"text": "Liability is unlimited."}))

class ContractState(TypedDict, total=False):
    text: str
    verdict: str
    report: str

parent = StateGraph(ContractState)
parent.add_node("review", review_graph)       # a compiled subgraph used directly as a node
parent.add_node("report", lambda state: {"report": f"verdict={state['verdict']}"})
parent.add_edge(START, "review")
parent.add_edge("review", "report")
parent.add_edge("report", END)
app = parent.compile()
print("parent:", app.invoke({"text": "Liability is unlimited."}))
for namespace, update in app.stream({"text": "Liability is unlimited."}, stream_mode="updates", subgraphs=True):
    print("inside subgraph" if namespace else "parent         ", update)

@@ concept
title: Streaming: show progress in the UI
--- body
Reviewing a contract takes several minutes, and the UI can't stay blank all that time. The modes of `app.stream(...)`:

- `"updates"` (Day 32): each time a node finishes, you get the update it returned
- `"messages"`: the tokens of the model's output arrive a small piece at a time; each element is `(chunk, metadata)`, and `metadata["langgraph_node"]` says which node is talking. Inside the node you write `model.invoke(...)` as usual; LangGraph turns it into a streaming request automatically
- `"custom"`: inside a node, `writer = get_stream_writer()` (`from langgraph.config import get_stream_writer`), then `writer({"progress": "3/10"})` sends your own events
- Several at once: `stream_mode=["custom", "updates"]`; each element becomes `(mode, data)`

Same as Day 29's `chain.stream`: when thinking mode is on, the `content` of the thinking chunks is an empty string, so skip them before displaying. A real service pushes to the front end with `astream`; this page can't run asyncio, so it only uses the synchronous version.
--- code
from typing import TypedDict
from langchain_deepseek import ChatDeepSeek
from langgraph.config import get_stream_writer
from langgraph.graph import StateGraph, START, END

model = ChatDeepSeek(model="deepseek-flash", extra_body={"thinking": {"type": "disabled"}})

class State(TypedDict, total=False):
    clauses: dict
    verdicts: dict
    summary: str

def review_all(state: State):
    writer = get_stream_writer()
    verdicts = {}
    for i, (cid, text) in enumerate(state["clauses"].items(), start=1):
        verdicts[cid] = "redline" if "unlimited" in text else "accept"
        writer({"progress": f"{i}/{len(state['clauses'])}", "clause": cid})
    return {"verdicts": verdicts}

def summarise(state: State):
    return {"summary": model.invoke(f"Summarise {state['verdicts']}").content}

g = StateGraph(State)
g.add_node("review_all", review_all)
g.add_node("summarise", summarise)
g.add_edge(START, "review_all")
g.add_edge("review_all", "summarise")
g.add_edge("summarise", END)
app = g.compile()
inputs = {"clauses": {"8.1": "unlimited liability", "3.1": "net 30"}}

for mode, data in app.stream(inputs, stream_mode=["custom", "updates"]):
    print(mode, data)
pieces = [chunk.content for chunk, meta in app.stream(inputs, stream_mode="messages")
          if meta["langgraph_node"] == "summarise" and chunk.content]
print(pieces)

@@ concept
title: Reading graph.py
--- body
Match `clausecheck/graph.py` to today's concepts (the code below is its skeleton, with the review replaced by a fake):

- The `approve` node: first works out `pending` in code (pure computation, safe to rerun), then `interrupt({"question": ..., "redlines": pending})`, and returns `{"approved": bool(decision)}`
- `route` + `add_conditional_edges("summarise", route)`: go to approve only when there is a redline
- `run_graph`: `with SqliteSaver.from_conn_string(...)` → `invoke` → if the result has `__interrupt__`, hand the payload to `decide` (in the CLI it asks y/N) → `Command(resume=approved)`
- `pending_interrupt`: another process opens the same file, calls `get_state`, then looks for `interrupts` in `snap.tasks`, **looking only, never resuming**
- `resume`: another process continues with `Command(resume=approved)`
- After approval, it is the **code** in `export` that changes the files; the model takes no part: the person approved a definite list, and exactly that list must be carried out. Letting the model "interpret" the lawyer's decision once more could end up carrying out something else
- The `review` node is currently a for loop that reviews one clause at a time; today's `Send` can make it parallel (you'll do that on Day 35)
--- code
import os
from typing import TypedDict
from langgraph.checkpoint.sqlite import SqliteSaver
from langgraph.graph import StateGraph, START, END
from langgraph.types import Command, interrupt

class State(TypedDict, total=False):
    reviews: list[dict]
    approved: bool | None
    exported: list[str]

def approve(state: State):
    pending = [r["clause_id"] for r in state["reviews"] if r["verdict"] == "redline"]
    decision = interrupt({"question": "Apply these redlines to the exported copy?", "redlines": pending})
    return {"approved": bool(decision)}

def export(state: State):
    return {"exported": ["report.json", "report.redlined.txt"] if state.get("approved") else ["report.json"]}

def build_graph(checkpointer):
    g = StateGraph(State)
    g.add_node("approve", approve)
    g.add_node("export", export)
    g.add_edge(START, "approve")
    g.add_edge("approve", "export")
    g.add_edge("export", END)
    return g.compile(checkpointer=checkpointer)

def pending_interrupt(path, thread_id):
    with SqliteSaver.from_conn_string(path) as saver:
        snap = build_graph(saver).get_state({"configurable": {"thread_id": thread_id}})
        for task in snap.tasks:
            if task.interrupts:
                return task.interrupts[0].value
    return None

def resume(path, thread_id, approved):
    with SqliteSaver.from_conn_string(path) as saver:
        return build_graph(saver).invoke(Command(resume=approved), {"configurable": {"thread_id": thread_id}})

os.makedirs("work/d34", exist_ok=True)
path = "work/d34/graph.sqlite"
if os.path.exists(path):
    os.remove(path)
reviews = [{"clause_id": "8.1", "verdict": "redline"}, {"clause_id": "3.1", "verdict": "accept"}]
with SqliteSaver.from_conn_string(path) as saver:      # process 1: run until the interrupt, then exit
    first = build_graph(saver).invoke({"reviews": reviews}, {"configurable": {"thread_id": "demo-1"}})
print("paused:", "__interrupt__" in first)
print("process 2 sees:", pending_interrupt(path, "demo-1"))
print("process 3 resumes:", resume(path, "demo-1", True)["exported"])
print("after resume:", pending_interrupt(path, "demo-1"))

A review of yesterday's checkpoints: at a law firm there are often several contracts at once, all stopped before export and waiting for a lawyer to look, each contract in its own thread.

--- code
from typing import TypedDict
from langgraph.graph import StateGraph, START, END
from langgraph.checkpoint.memory import InMemorySaver

class State(TypedDict, total=False):
    clause: str
    verdict: str
    report: str

def review(state: State):
    return {"verdict": "redline" if "unlimited" in state["clause"] else "accept"}

def export(state: State):
    return {"report": f"{state['clause']} -> {state['verdict']}"}

g = StateGraph(State)
g.add_node("review", review)
g.add_node("export", export)
g.add_edge(START, "review")
g.add_edge("review", "export")
g.add_edge("export", END)
app = g.compile(checkpointer=InMemorySaver(), interrupt_before=["export"])
a = {"configurable": {"thread_id": "a"}}
b = {"configurable": {"thread_id": "b"}}
app.invoke({"clause": "8.1 unlimited"}, a)
app.invoke({"clause": "3.1 net 30"}, b)
app.update_state(a, {"verdict": "flag"})
print(app.get_state(a).next, app.get_state(b).next)
print(app.invoke(None, a)["report"])
print(app.get_state(b).values)
print([s.metadata["source"] for s in app.get_state_history(a)])
--- explain
Each thread has its own checkpoints, and they don't affect each other: `b` is still stopped before export, and no `report` has been produced. `update_state` leaves a checkpoint with source `"update"` in `a`'s history, and `invoke(None, a)` carries on from it. The history lists the newest first: export finished (loop) → a person changed the verdict (update) → review finished (loop) → start (loop) → input (input).

from typing import TypedDict
from langgraph.config import get_stream_writer
from langgraph.graph import StateGraph, START, END

    clauses: list[dict]
    verdicts: dict

    return "redline" if "unlimited" in text.lower() else "accept"

def review_all(state: State):
    writer = get_stream_writer()
    verdicts = {}
    total = len(state["clauses"])
    for i, c in enumerate(state["clauses"], start=1):
        verdicts[c["id"]] = judge(c["text"])
        writer({"done": i, "total": total, "clause_id": c["id"]})

            lines.append(f"{data['done']}/{data['total']} {data['clause_id']}")

import operator
from typing import Annotated, Literal, TypedDict
from pydantic import BaseModel
from langchain_deepseek import ChatDeepSeek
from langgraph.graph import StateGraph, START, END
from langgraph.types import Send

class ClauseReview(BaseModel):
    """Review of one contract clause."""
    clause_id: str
    verdict: Literal["accept", "flag", "redline"]
    risk_level: Literal["low", "medium", "high"]

class State(TypedDict, total=False):
    clauses: list[dict]
    reviews: Annotated[list[dict], operator.add]
    counts: dict
    high_risk: list[str]

def review_contract(clauses):
    reviewer = ChatDeepSeek(model="deepseek-flash", extra_body={"thinking": {"type": "disabled"}}).with_structured_output(ClauseReview)

    def fan_out(state: State):
        if not state["clauses"]:
            return "summarise"
        return [Send("review", {"clause": c}) for c in state["clauses"]]

    def review(state: dict):
        c = state["clause"]
        r = reviewer.invoke(f"Review clause {c['id']}: {c['text']}")
        return {"reviews": [{"clause_id": c["id"], "verdict": r.verdict, "risk_level": r.risk_level}]}

    def summarise(state: State):
        reviews = state.get("reviews", [])
        counts = {"accept": 0, "flag": 0, "redline": 0}
        for r in reviews:
            counts[r["verdict"]] += 1
        return {"counts": counts, "high_risk": [r["clause_id"] for r in reviews if r["risk_level"] == "high"]}

    g = StateGraph(State)
    g.add_node("review", review)
    g.add_node("summarise", summarise)
    g.add_conditional_edges(START, fan_out, ["review", "summarise"])
    g.add_edge("review", "summarise")
    g.add_edge("summarise", END)
    out = g.compile().invoke({"clauses": clauses})
    return {"reviews": out.get("reviews", []), "counts": out["counts"], "high_risk": out["high_risk"]}

from typing import TypedDict
from langgraph.checkpoint.memory import InMemorySaver
from langgraph.graph import StateGraph, START, END
from langgraph.types import Command, interrupt

class State(TypedDict, total=False):
    redlines: list[str]
    approved: bool
    exported: list[str]

def approval_flow(redlines, answer, notify):
    def notify_node(state: State):
        notify(f"{len(state['redlines'])} redline(s) waiting")
        return {}

    def approve(state: State):
        pending = state["redlines"]
        decision = interrupt({"redlines": pending})
        action = decision.get("action") if isinstance(decision, dict) else None
        if action == "approve":
            return {"approved": True}
        if action == "edit":
            return {"approved": True, "redlines": [r for r in pending if r in decision.get("redlines", [])]}
        return {"approved": False}

    def export(state: State):
        return {"exported": state["redlines"] if state["approved"] else []}

    g = StateGraph(State)
    g.add_node("notify", notify_node)
    g.add_node("approve", approve)
    g.add_node("export", export)
    g.add_edge(START, "notify")
    g.add_edge("notify", "approve")
    g.add_edge("approve", "export")
    g.add_edge("export", END)
    app = g.compile(checkpointer=InMemorySaver())
    cfg = {"configurable": {"thread_id": "exam"}}
    first = app.invoke({"redlines": redlines}, cfg)
    payload = first["__interrupt__"][0].value
    final = app.invoke(Command(resume=answer), cfg)
    return {"payload": payload, "exported": final["exported"]}

from typing import Literal, TypedDict
from langgraph.config import get_stream_writer
from langgraph.graph import StateGraph, START, END
from langgraph.types import Command

class State(TypedDict, total=False):
    clauses: list[dict]
    verdicts: dict
    status: str

def review_all(state: State):
    writer = get_stream_writer()
    verdicts = {}
    for c in state["clauses"]:
        verdicts[c["id"]] = "redline" if "unlimited" in c["text"].lower() else "accept"
        writer({"clause_id": c["id"], "verdict": verdicts[c["id"]]})
    return {"verdicts": verdicts}

def triage(state: State) -> Command[Literal["escalate", "done"]]:
    if "redline" in state["verdicts"].values():
        return Command(update={"status": "needs_approval"}, goto="escalate")
    return Command(update={"status": "clean"}, goto="done")

def escalate(state: State):
    return {"status": state["status"] + ": sent to legal"}

def done(state: State):
    return {}

def stream_triage(clauses):
    g = StateGraph(State)
    g.add_node("review_all", review_all)
    g.add_node("triage", triage)
    g.add_node("escalate", escalate)
    g.add_node("done", done)
    g.add_edge(START, "review_all")
    g.add_edge("review_all", "triage")
    g.add_edge("escalate", END)
    g.add_edge("done", END)
    app = g.compile()
    events, nodes, status = [], [], None
    for mode, data in app.stream({"clauses": clauses}, stream_mode=["custom", "updates"]):
        if mode == "custom":
            events.append(f"{data['clause_id']}={data['verdict']}")
        else:
            for node, update in data.items():
                nodes.append(node)
                if update and "status" in update:
                    status = update["status"]
    return {"events": events, "nodes": nodes, "status": status}
