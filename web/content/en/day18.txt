@@ concept
title: Workflow vs agent
--- body
Yesterday's agent let **the model decide** what to do next. Today's workflow lets **the code decide**: the steps and their order are written in advance.

Clause Check uses both, with a clear split. The comment at the top of `review.py` says: "The outer pipeline is a fixed workflow; *this* node is a small bounded agent". The outer steps `load → review → summarise → (approve) → export` always run in this order, so they are a workflow. Only "while reviewing this clause, should I go and read clause 12?" depends on the content, so only that is handed to an agent.

Rule of thumb: **if you know the steps in advance, write a workflow**. It is cheaper, more predictable and easier to test.

So why not just call a few functions in order? Why build a "graph"? The comments in `graph.py` answer that: the first need that really calls for a framework is "pause for a person to approve, then continue hours later from another process". Today you build up to that step by step.
--- code
const load = (text: string): string[] => text.split("\n");
const review = (clauses: string[]): string[] =>
  clauses.filter((c) => c.includes("unlimited")).map((c) => c.split(" ")[0]);
const summarise = (clauses: string[], redlines: string[]): string =>
  `${clauses.length} clauses, ${redlines.length} redline(s)`;

const text = "3.1 Fees are payable within thirty days.\n8.1 Liability shall be unlimited.\n12 Governing law is Sweden.";
const clauses = load(text);
const redlines = review(clauses);
console.log(summarise(clauses, redlines));
console.log(redlines.length > 0 ? "next: approve" : "next: export");

@@ concept
title: State: one object passed from start to end
--- body
All the nodes in a graph share **one state object**. Each node reads the state and returns **only the fields it changed**; the runner merges them in:

```ts
type Node = (s: State) => Partial<State>;   // Partial: Day 15
state = { ...state, ...node(state) };       // later values overwrite earlier ones
```

That is exactly how `graph.py` works: `summarise_node` returns only `{"summary": ...}`, and `approve` returns only `{"approved": ...}`.

**The classic mistake: changing `s` directly inside a node** (for example `s.redlines.push(...)`). The old state is quietly changed, so the "earlier state" you see in checkpoints, tests and debugging can no longer be trusted. A node only reads `s` and returns new values.
--- code
type State = { text: string; clauses: string[]; redlines: string[] };

const load = (s: State): Partial<State> => ({ clauses: s.text.split("\n") });
const review = (s: State): Partial<State> => ({
  redlines: s.clauses.filter((c) => c.includes("unlimited")).map((c) => c.split(" ")[0]),
});

let state: State = { text: "3.1 Fees within 30 days.\n8.1 Liability is unlimited.", clauses: [], redlines: [] };
const before = state;
state = { ...state, ...load(state) };
console.log(state.clauses.length);
state = { ...state, ...review(state) };
console.log(state.redlines);
console.log(before.clauses.length, before === state);

@@ concept
title: Edges and conditional routing
--- body
Nodes are connected by **edges**. An edge is either the fixed name of the next node, or a **routing function** that reads the state and returns the name of the next node. `"END"` means stop.

```ts
type Edge = string | ((s: State) => string);
const edges: Record<string, Edge> = {
  summarise: (s) => (s.redlines.length > 0 ? "approve" : "export"),
  export: "END",
};
```

The runner tells the two kinds of edge apart with `typeof edge === "function"` (type narrowing from Day 15). The `route` in `graph.py` is exactly the same: if there is a redline, go to `approve`; otherwise go straight to `export`.

A routing function only looks at the state and never calls the model, so it is deterministic and can be tested on its own.
--- code
type State = { redlines: string[] };
type Edge = string | ((s: State) => string);

const edges: Record<string, Edge> = {
  load: "review",
  review: "summarise",
  summarise: (s) => (s.redlines.length > 0 ? "approve" : "export"),
  approve: "export",
  export: "END",
};

function nextNode(node: string, state: State): string {
  const edge = edges[node];
  return typeof edge === "function" ? edge(state) : edge;
}

console.log(nextNode("load", { redlines: [] }));
console.log(nextNode("summarise", { redlines: ["8.1"] }));
console.log(nextNode("summarise", { redlines: [] }));
console.log(nextNode("export", { redlines: [] }));

@@ concept
title: The runner: from start to END
--- body
The runner is just a loop:

1. Keep going while the current node is not `"END"`
2. Find the node function (if it is missing, throw: usually a name in the edges is misspelled)
3. Run it, merge the state, and record the node name in `path`
4. Work out the next node from the edge

A graph can have **cycles** (for example "validation failed, go back and review again"), so, just like an agent, it needs a **step limit**. Past the limit it throws, and the error message includes the path taken, so when debugging you see at a glance where it goes in circles. In LangGraph this is `recursion_limit`.
--- code
type State = { text: string; redlines: string[]; exported: string };
type Node = (s: State) => Partial<State>;
type Edge = string | ((s: State) => string);
type Graph = { nodes: Record<string, Node>; edges: Record<string, Edge> };

function runGraph(graph: Graph, state: State, start: string, maxSteps = 10): { state: State; path: string[] } {
  let current = start;
  const path: string[] = [];
  while (current !== "END") {
    if (path.length >= maxSteps) throw new Error(`exceeded ${maxSteps} steps: ${path.join(" -> ")}`);
    const node = graph.nodes[current];
    if (!node) throw new Error(`unknown node: ${current}`);
    state = { ...state, ...node(state) };
    path.push(current);
    const edge = graph.edges[current];
    current = typeof edge === "function" ? edge(state) : edge;
  }
  return { state, path };
}

const graph: Graph = {
  nodes: {
    review: (s) => ({ redlines: s.text.split("\n").filter((l) => l.includes("unlimited")).map((l) => l.split(" ")[0]) }),
    approve: () => ({}),
    export: (s) => ({ exported: `${s.redlines.length} redline(s)` }),
  },
  edges: {
    review: (s) => (s.redlines.length > 0 ? "approve" : "export"),
    approve: "export",
    export: "END",
  },
};

const r1 = runGraph(graph, { text: "8.1 Liability is unlimited.\n3.1 Fees within 30 days.", redlines: [], exported: "" }, "review");
console.log(r1.path.join(" -> "), "|", r1.state.exported);
const r2 = runGraph(graph, { text: "3.1 Fees within 30 days.", redlines: [], exported: "" }, "review");
console.log(r2.path.join(" -> "), "|", r2.state.exported);
try {
  const broken: Graph = { nodes: graph.nodes, edges: { ...graph.edges, export: "review" } };
  runGraph(broken, { text: "3.1 Fees.", redlines: [], exported: "" }, "review", 5);
} catch (e) {
  console.log(e instanceof Error ? e.message : e);
}

@@ concept
title: Checkpoints: keep going after a crash
--- body
After each node finishes, save `{ next: <the next node>, state }` as JSON. If the program crashes, read the last checkpoint and continue from `next`; the nodes that already finished **don't run again**. Reviewing 30 clauses takes 30 model calls. If the disk fills up during export, you certainly don't want to pay for all of them again.

There are two more reasons: you may have to **wait a long time** (the lawyer approves tomorrow), and you may **continue in another process** (it starts on the command line and finishes in the web backend). `graph.py` uses `SqliteSaver` to store checkpoints in SQLite, with a `thread_id` to tell the runs apart.

**Requirement: the state must be plain JSON data**: strings, numbers, booleans, null, arrays, plain objects. A `Map`, `Set`, `Date`, class instance or `undefined` comes back changed after you save it and read it again. That is why the state in `graph.py` holds the dictionary from `contract.model_dump()`, and a node that needs it turns it back into an object with `Contract.model_validate(...)`.
--- code
type State = { clauses: string[]; verdicts: string[]; exported: string };
let modelCalls = 0;
let diskFull = true;

const nodes: Record<string, (s: State) => Partial<State>> = {
  review: (s) => {
    modelCalls += s.clauses.length;
    return { verdicts: s.clauses.map((c) => (c.includes("unlimited") ? "redline" : "accept")) };
  },
  export: (s) => {
    if (diskFull) throw new Error("disk full");
    return { exported: s.verdicts.join(",") };
  },
};
const edges: Record<string, string> = { review: "export", export: "END" };

function run(state: State, start: string, save: (text: string) => void): State {
  let current = start;
  while (current !== "END") {
    state = { ...state, ...nodes[current](state) };
    current = edges[current];
    save(JSON.stringify({ next: current, state }));
  }
  return state;
}

let saved = "";
try {
  run({ clauses: ["8.1 unlimited", "3.1 fees"], verdicts: [], exported: "" }, "review", (t) => { saved = t; });
} catch (e) {
  console.log("crashed:", e instanceof Error ? e.message : e);
}
console.log("checkpoint:", saved);

diskFull = false;
const cp = JSON.parse(saved);
const final = run(cp.state, cp.next, (t) => { saved = t; });
console.log("exported:", final.exported, "| model calls:", modelCalls);

@@ concept
title: Interrupt and resume: stop and wait for a person
--- body
A node that needs a person's decision (for example "apply these redlines to the exported file?") returns an `interrupt` field while no decision has been made yet:

```ts
type Update = Partial<State> & { interrupt?: string };
approve: (s) => (s.approved === null ? { interrupt: "Apply 2 redline(s)?" } : {}),
```

When the runner sees `interrupt`, it stops and returns the question and a checkpoint. **`next` records the current node** (`approve`), and then the program can simply exit. Once the lawyer replies, write the decision into the state (`approved: true`) and continue from the checkpoint: `approve` runs again, sees the decision this time and lets it through, and `export` does what was decided.

In `graph.py` this is `decision = interrupt({...})`, followed later by `Command(resume=True)` to continue. LangGraph also runs the `approve` node again from the start. One sentence in the comments matters a lot: "The approved decision is executed by code - the model does not get to re-decide".
--- code
type State = { redlines: string[]; approved: boolean | null; exported: string };
type Update = Partial<State> & { interrupt?: string };

const nodes: Record<string, (s: State) => Update> = {
  approve: (s) => (s.approved === null ? { interrupt: `Apply ${s.redlines.length} redline(s)?` } : {}),
  export: (s) => ({ exported: s.approved ? "with redlines" : "without redlines" }),
};
const edges: Record<string, string> = { approve: "export", export: "END" };

function run(state: State, start: string): string {
  let current = start;
  while (current !== "END") {
    const out = nodes[current](state);
    if (out.interrupt) {
      console.log("paused:", out.interrupt);
      return JSON.stringify({ next: current, state });
    }
    state = { ...state, ...out };
    current = edges[current];
  }
  console.log("done:", state.exported);
  return "";
}

const checkpoint = run({ redlines: ["8.1", "12"], approved: null, exported: "" }, "approve");
console.log("saved:", checkpoint);
// hours later, maybe in another process: the lawyer clicks "approve"
const cp = JSON.parse(checkpoint);
run({ ...cp.state, approved: true }, cp.next);

@@ concept
title: Parallelism: Promise.all and a concurrency limit
--- body
Reviewing 300 clauses one by one is too slow. `Promise.all(items.map(fn))` runs them at the same time, and **the results come back in input order** (no matter which finishes first).

But send all 300 requests at once and you may hit the provider's rate limit and get a 429. (DeepSeek counts how many requests your whole account has running at the same time; OpenAI counts requests and tokens per minute; each provider's docs give the actual limits.) So you **limit concurrency**. The simplest way is batches: run N at a time, and start the next batch only when the whole batch has finished:

```ts
for (let i = 0; i < items.length; i += limit) {
  const batch = items.slice(i, i + limit);
  results.push(...(await Promise.all(batch.map(fn))));
}
```

`clausecheck/pipeline.py` currently reviews clauses one at a time, in order; this is how you would change it to go faster. The classic mistake: calling `results.push(...)` as each task finishes. Then the order is "whoever finishes first comes first".
--- code
// a few awaits simulate "reviewing takes time"; different clauses take different amounts of time
async function takeTime(n: number): Promise<void> {
  for (let i = 0; i < n; i++) await null;
}
let active = 0;
let maxActive = 0;
const finished: string[] = [];

async function review(id: string, cost: number): Promise<string> {
  active += 1;
  maxActive = Math.max(maxActive, active);
  await takeTime(cost);
  active -= 1;
  finished.push(id);
  return `${id}:done`;
}

async function main() {
  const jobs = [["8.1", 30], ["3.1", 5], ["12", 15], ["4.2", 10]] as const;
  const all = await Promise.all(jobs.map(([id, cost]) => review(id, cost)));
  console.log("finished in order:", finished.join(" "));
  console.log("results:", all.join(" "), "| max at once:", maxActive);

  maxActive = 0;
  const out: string[] = [];
  for (let i = 0; i < jobs.length; i += 2) {
    const batch = jobs.slice(i, i + 2);
    out.push(...(await Promise.all(batch.map(([id, cost]) => review(id, cost)))));
  }
  console.log("batches of 2:", out.join(" "), "| max at once:", maxActive);
}
main();

title: Framework comparison: LangGraph and Mastra workflows
--- body
Every part you wrote today can be found in `graph.py` (LangGraph, Python):

- `StateGraph(State)`: `State` is a TypedDict, i.e. your state type
- `g.add_node("review", review)`: your `nodes` table
- `g.add_edge("load", "review")`, `g.add_edge(START, "load")`: fixed edges and the starting point
- `g.add_conditional_edges("summarise", route)`: your routing-function edges
- `g.compile(checkpointer=saver)` + `thread_id`: save a checkpoint after every step
- `interrupt(...)` and `Command(resume=...)`: your `interrupt` field and resuming

Mastra workflows use the same ideas (a sketch; check the mastra.ai docs for the exact syntax): `createStep` defines a step (its input and output are described with Zod too), `createWorkflow(...)` chains steps with `.then()`, there are also branches and parallel steps, and it ends with `.commit()`. A step can suspend and later resume to continue.

In an interview: "I have hand-written a graph runner, checkpoints, and interrupt and resume, so to me the LangGraph and Mastra APIs are just new names."

--- context
In today's graph runner, each node hands back only the fields it changed, and the runner merges them into the whole state. The merging is all done with object spread, so first get its rules clear.
--- prompt
A recap of the object spread `...` from Days 5 and 15. The runner relies on it to merge state. Write the output.
--- code
type Review = { id: string; verdict: string; risk?: string };

const base: Review = { id: "8.1", verdict: "accept", risk: "low" };
const update: Partial<Review> = { verdict: "flag" };
const a = { ...base, ...update };
const b = { ...update, ...base };
const c = { ...base, risk: undefined };
console.log(a.verdict, b.verdict);
console.log(c);
console.log(base.verdict);
--- explain
When spreading, **later values overwrite earlier ones**, so `a` is flag, while in `b` the `base` comes last and sets it back to accept. An `undefined` you write out explicitly also overwrites the old value: a node should not return fields it didn't change, and certainly not return `undefined`. Spreading creates a new object and `base` itself is unchanged. That is the basis of "a node doesn't change the old state".

@@ item d18-02
type: code
title: Recap: merging state
level: 2
cards: State: one object passed from start to end
--- context
Each node in the graph hands back a small update when it finishes. For most fields the new value simply replaces the old one, but a field like the run log gets a few lines added by every node, and earlier entries must not be lost. The old state must also stay exactly as it was: checkpoints and debugging depend on it.
--- prompt
Write `mergeState(state, update)` that returns the merged **new** state:

- Plain fields: whatever is in `update` overwrites what is in `state`
- The `log` field is the exception: it is not overwritten; `update.log` is **appended** after `state.log` (if `update` has no `log`, keep it as it is)
- Don't change the `state` that was passed in

Example: `mergeState({ stage: "load", redlines: 0, log: ["a"] }, { stage: "review", log: ["b"] })` → `{ stage: "review", redlines: 0, log: ["a", "b"] }`. In LangGraph, a field that is "appended to, not overwritten" like this is called a reducer.
--- starter
type State = { stage: string; redlines: number; log: string[] };

function mergeState(state: State, update: Partial<State>): State {
  return { ...state, ...update };
}
--- solution
type State = { stage: string; redlines: number; log: string[] };

function mergeState(state: State, update: Partial<State>): State {
  return { ...state, ...update, log: [...state.log, ...(update.log ?? [])] };
}
--- tests
const S: State = { stage: "load", redlines: 0, log: ["loaded 3 clauses"] };
expect("overwrites plain fields and appends to log", () => mergeState(S, { stage: "review", redlines: 2, log: ["reviewed 3"] }), { stage: "review", redlines: 2, log: ["loaded 3 clauses", "reviewed 3"] });
expect("no log: kept as it was", () => mergeState(S, { stage: "export" }).log, ["loaded 3 clauses"]);
expect("the original state is not changed", () => {
  mergeState(S, { log: ["x"] });
  return S.log;
}, ["loaded 3 clauses"]);
expect("empty update", () => mergeState(S, {}), S);
--- hints
- Start with `{ ...state, ...update }`, then write a separate `log: ...` at the end. It overwrites the log that the spread put in before it.
- A new array: `[...state.log, ...(update.log ?? [])]`. Don't use `push`: that would change the original array.

type State = { redlines: number };

--- solution
type State = { text: string; redlines: string[]; approved: boolean; exported: string };
type Node = (s: State) => Partial<State>;
type Edge = string | ((s: State) => string);
type Graph = { nodes: Record<string, Node>; edges: Record<string, Edge> };

function nextNode(edges: Record<string, Edge>, node: string, state: State): string {
  const edge = edges[node];
  if (edge === undefined) {
    throw new Error(`no edge from ${node}`);
  }
  return typeof edge === "function" ? edge(state) : edge;
}

function runGraph(graph: Graph, state: State, start: string, maxSteps = 10): { state: State; path: string[] } {
  const path: string[] = [];
  let current = start;
  while (current !== "END") {
    if (path.length >= maxSteps) {
      throw new Error(`exceeded ${maxSteps} steps: ${path.join(" -> ")}`);
    }
    const node = graph.nodes[current];
    if (!node) {
      throw new Error(`unknown node: ${current}`);
    }
    state = { ...state, ...node(state) };
    path.push(current);
    current = nextNode(graph.edges, current, state);
  }
  return { state, path };
}

function nextNode(edges: Record<string, Edge>, node: string, state: State): string {
  const edge = edges[node];
  if (edge === undefined) {
    throw new Error(`no edge from ${node}`);
  }
  return typeof edge === "function" ? edge(state) : edge;

function run(graph: Graph, state: State, start: string, save: (text: string) => void): { state: State; path: string[] } {
  let current = start;
  const path: string[] = [];
  while (current !== "END") {
    const node = graph.nodes[current];
    if (!node) {
      throw new Error(`unknown node: ${current}`);
    }
    state = { ...state, ...node(state) };
    path.push(current);
    current = nextNode(graph.edges, current, state);
    const cp: Checkpoint = { next: current, state };
    save(JSON.stringify(cp));
  }
  return { state, path };
}

  const cp: Checkpoint = JSON.parse(saved);
  return run(graph, cp.state, cp.next, save);

  const results: R[] = [];
  for (let i = 0; i < items.length; i += limit) {

type Node = (s: State) => State;
type Edge = string | ((s: State) => string);
type Graph = { nodes: Record<string, Node>; edges: Record<string, Edge> };

function runGraph(graph: Graph, state: State, start: string, maxSteps: number): { state: State; path: string[] } {
  let current = start;
  const path: string[] = [];
  while (current !== "END") {
    if (path.length >= maxSteps) {
      throw new Error(`exceeded ${maxSteps} steps: ${path.join(" -> ")}`);
    }
    const node = graph.nodes[current];
    if (!node) {
      throw new Error(`unknown node: ${current}`);
    }
    state = { ...state, ...node(state) };
    path.push(current);
    const edge = graph.edges[current];
    if (edge === undefined) {
      throw new Error(`no edge from ${current}`);
    }
    current = typeof edge === "function" ? edge(state) : edge;
  }
  return { state, path };
}

type State = Record<string, any>;
type Node = (s: State) => State;
type Edge = string | ((s: State) => string);
type Graph = { nodes: Record<string, Node>; edges: Record<string, Edge> };
type RunResult =
  | { status: "done"; state: State; path: string[] }
  | { status: "interrupted"; question: string; checkpoint: string };

function run(graph: Graph, state: State, start: string): RunResult {
  let current = start;
  const path: string[] = [];
  while (current !== "END") {
    const out = graph.nodes[current](state);
    if (out.interrupt) {
      return { status: "interrupted", question: out.interrupt, checkpoint: JSON.stringify({ next: current, state }) };
    }
    state = { ...state, ...out };
    path.push(current);
    const edge = graph.edges[current];
    current = typeof edge === "function" ? edge(state) : edge;
  }
  return { status: "done", state, path };
}

function resume(graph: Graph, checkpoint: string, decision: State): RunResult {
  const cp = JSON.parse(checkpoint);
  return run(graph, { ...cp.state, ...decision }, cp.next);
}
--- tests
const G: Graph = {
  nodes: {
    summarise: (s) => ({ redlines: s.verdicts.filter((v: string) => v === "redline").length }),
    approve: (s) => (s.approved === null ? { interrupt: `Apply ${s.redlines} redline(s)?` } : {}),
    export: (s) => ({ exported: s.approved ? "applied" : "not applied" }),
  },
  edges: { summarise: (s) => (s.redlines > 0 ? "approve" : "export"), approve: "export", export: "END" },
};
const RISKY = { verdicts: ["redline", "accept", "redline"], approved: null };
expect("pauses and asks", () => {
  const r = run(G, RISKY, "summarise");
  return r.status === "interrupted" ? [r.question, JSON.parse(r.checkpoint).next] : r.status;
}, ["Apply 2 redline(s)?", "approve"]);
expect("resumes after approval", () => {
  const r = run(G, RISKY, "summarise");
  if (r.status !== "interrupted") return r.status;
  const done = resume(G, r.checkpoint, { approved: true });
  return done.status === "done" ? [done.path, done.state.exported] : done.status;
}, [["approve", "export"], "applied"]);
expect("no redlines: finishes directly", () => {
  const r = run(G, { verdicts: ["accept"], approved: null }, "summarise");
  return r.status === "done" ? r.path : r.status;
}, ["summarise", "export"]);
