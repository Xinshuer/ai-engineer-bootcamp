@@ concept
title: Document: a chunk with its source
--- body
On Day 11 you wrote chunks as dictionaries `{"id": "c1", "text": "..."}`. LangChain's retrieval parts (splitters, vector stores, retrievers) all take in and give back `Document`s:

- `page_content`: the chunk text; this is what goes to the embeddings and into the prompt
- `metadata`: any dictionary; it holds the **source**: `clause_id`, `heading`, the `source` file name, `topic`… It comes back unchanged with every search result, and citations and filtering both depend on it

Contracts have numbers, so the best way to cut them is still the "one chunk per clause" of `split.py`: a regex finds the heading lines, and the text between two heading lines is the body. The regex below follows the same idea as `CLAUSE_HEAD` in `split.py`.

Classic mistake: storing only the text and no metadata. The search finds the chunk but can't say which clause it is, and the citations from Day 19 no longer work.
--- code
import re
from langchain_core.documents import Document

CONTRACT = """3.1 Invoicing
Fees are invoiced annually and are payable within thirty (30) days of the invoice date.
8.1 Cap on Liability
Each party's aggregate liability shall not exceed the Fees paid in the twelve (12) months before the claim.
11.1 Termination by Provider
Provider may terminate this Agreement for convenience upon ten (10) days' written notice."""

HEAD = re.compile(r"^(\d+(?:\.\d+)*)\s+([A-Z][^\n]{0,80})$", re.M)
heads = list(HEAD.finditer(CONTRACT))
docs = []
for i, h in enumerate(heads):
    end = heads[i + 1].start() if i + 1 < len(heads) else len(CONTRACT)
    body = CONTRACT[h.end():end].strip()
    docs.append(Document(page_content=body, metadata={"clause_id": h.group(1), "heading": h.group(2), "source": "sample_contract.txt"}))

for d in docs:
    print(d.metadata["clause_id"], "|", d.metadata["heading"], "|", d.page_content[:40])
print(repr(docs[0]))

@@ concept
title: Splitters: by length or by structure
--- body
`RecursiveCharacterTextSplitter` is LangChain's most used splitter, a stronger version of `chunk_fixed` from Day 11:

- `chunk_size`: the most characters a chunk may have; `chunk_overlap`: how many characters two neighboring chunks share
- `separators`: the separators to try, in order; the default is `["\n\n", "\n", " ", ""]`. It first cuts at blank lines; if a piece is still too long, at line breaks, then at spaces… and at the end it **merges** small pieces back into chunks close to `chunk_size`
- `add_start_index=True`: each chunk's metadata records where the chunk starts in the original text
- `create_documents(texts, metadatas=[...])` produces Documents directly, and the metadata is copied into every chunk

It only cares about length and knows nothing about clauses: below, the heading and the body of 8.1 end up apart, and the body is cut in the middle. So contracts with numbers are cut by clause (previous card); this splitter is only for long text with no structure (emails, meeting notes).

Parameter checks: a `chunk_overlap` larger than `chunk_size` raises `ValueError` right away; when the two are **equal** there is no error, but each chunk moves forward only a tiny step (about one word), producing a pile of nearly identical chunks. Your `chunk_fixed` from Day 11 is stricter: it raises an error when `overlap >= size`.
--- code
from langchain_text_splitters import RecursiveCharacterTextSplitter

text = ("8.1 Cap on Liability\nEach party's aggregate liability shall not exceed the Fees paid in the twelve (12) months before the claim.\n\n"
        "8.2 Indirect Damages\nNeither party is liable for indirect or consequential damages.")

splitter = RecursiveCharacterTextSplitter(chunk_size=80, chunk_overlap=20, add_start_index=True)
for d in splitter.create_documents([text], metadatas=[{"source": "msa.txt"}]):
    print(d.metadata["start_index"], repr(d.page_content))

same = RecursiveCharacterTextSplitter(chunk_size=80, chunk_overlap=80)
print(len(same.split_text(text)), "chunks when chunk_overlap == chunk_size")

@@ concept
title: Vector stores: compute vectors once, search many times
--- body
On Day 11 you did this by hand: send the chunks to the embeddings API, get vectors back and store them (`embed_texts`); when a question comes, turn it into a vector too and take the top k by cosine similarity. LangChain packs these steps into two objects:

- `OpenAIEmbeddings(model="text-embedding-3-small")`: calls the OpenAI-format `/v1/embeddings`. DeepSeek has no embeddings API; on this page it is a mock service with the same format (a bag of words plus synonyms, so asking about cancel finds terminate)
- `InMemoryVectorStore(embeddings)`: a vector store kept in memory. `add_documents(docs)` computes all the vectors in one request; `similarity_search(q, k=2)` returns the k most similar Documents; `similarity_search_with_score` returns the cosine scores with them; `filter=lambda doc: ...` filters by metadata first, then ranks

The ids that `add_documents` returns are random uuids; the clause number is in the metadata. Switch to a real vector store (pgvector, Chroma…) and these method names mostly stay the same. That is what a framework gives you.

Below, look at the second result, 8.3, for the question about canceling the contract: its score is very low, and it really has nothing to do with the question. The embedding on this page is a mock (bag of words + hashing, very rough), so it has more false hits like this than a real model; but a real model is the same in one way: vector search **always** returns k results, even when the last few are irrelevant. So don't set k too large, and filter by metadata whenever you can.

Look at the request body: `input` is a list of numbers. By default `OpenAIEmbeddings` first turns the text into token ids with tiktoken and sends those. A comment in the source code says that many non-OpenAI services (it names OpenRouter, Ollama, vLLM) need `check_embedding_ctx_length=False`, so the text is sent as is.
--- code
from langchain_core.documents import Document
from langchain_core.vectorstores import InMemoryVectorStore
from langchain_openai import OpenAIEmbeddings

CLAUSES = [
    ("3.1", "payment", "Fees are invoiced annually and are payable within thirty (30) days of the invoice date."),
    ("8.1", "liability_cap", "Each party's aggregate liability shall not exceed the Fees paid in the twelve (12) months before the claim."),
    ("8.3", "liability_cap", "Customer's liability for breach of Section 6 shall be unlimited."),
    ("11.1", "termination", "Provider may terminate this Agreement for convenience upon ten (10) days' written notice."),
]
docs = [Document(page_content=text, metadata={"clause_id": cid, "topic": topic}) for cid, topic, text in CLAUSES]

store = InMemoryVectorStore(OpenAIEmbeddings(model="text-embedding-3-small"))
ids = store.add_documents(docs)
print(len(ids), "documents,", len(MOCK.calls), "embeddings request")

for doc, score in store.similarity_search_with_score("Can the provider cancel the contract?", k=2):
    print(doc.metadata["clause_id"], round(score, 2))

only_caps = store.similarity_search("liability", k=2, filter=lambda d: d.metadata["topic"] == "liability_cap")
print("filtered:", [d.metadata["clause_id"] for d in only_caps])
body = MOCK.calls[-1]["body"]
print(body["model"], "| input for 'liability':", body["input"])

@@ concept
title: Retriever and RAG chains
--- body
`store.as_retriever(search_kwargs={"k": 2})` wraps the vector store in a **Runnable**: `retriever.invoke("question")` returns a list of Documents. So it can go into a `|` pipe together with a prompt and a model (LCEL from Day 29). The most common RAG chain:

```python
chain = (
    {"context": retriever | format_docs, "question": RunnablePassthrough()}
    | prompt | model | StrOutputParser()
)
```

- The dictionary at the start receives the same question and sends it two ways: `context` goes "search → join into text", `question` is passed through unchanged, and together they make `{"context": ..., "question": ...}` for the prompt
- `format_docs` is an ordinary function you write yourself: it puts `[clause number]` in front of each chunk, just like the numbered chunks from Day 19

This chain puts out only a string, so **the sources are lost**. To return `sources` as well, plain Python is clearest: call `docs = retriever.invoke(q)` once, and use the same docs both to build the prompt and to get the clause numbers.

Classic mistake: writing `as_retriever(k=2)`. That argument is **silently ignored**: no error, no warning, and you still get the default 4 results.
--- code
from langchain_core.documents import Document
from langchain_core.vectorstores import InMemoryVectorStore
from langchain_openai import OpenAIEmbeddings
from langchain_core.prompts import ChatPromptTemplate
from langchain_core.runnables import RunnablePassthrough
from langchain_core.output_parsers import StrOutputParser
from langchain_deepseek import ChatDeepSeek

docs = [
    Document(page_content="Fees are invoiced annually and are payable within thirty (30) days of the invoice date.", metadata={"clause_id": "3.1"}),
    Document(page_content="Provider may terminate this Agreement for convenience upon ten (10) days' written notice.", metadata={"clause_id": "11.1"}),
    Document(page_content="Customer Data may be stored and processed in any country.", metadata={"clause_id": "10.1"}),
]
store = InMemoryVectorStore(OpenAIEmbeddings(model="text-embedding-3-small"))
store.add_documents(docs)
retriever = store.as_retriever(search_kwargs={"k": 2})

def format_docs(docs):
    return "\n".join(f"[{d.metadata['clause_id']}] {d.page_content}" for d in docs)

prompt = ChatPromptTemplate.from_messages([
    ("system", "Answer only from the sources. Cite clause ids like [3.1]."),
    ("user", "Question: {question}\n\nSources:\n{context}"),
])
model = ChatDeepSeek(model="deepseek-flash", extra_body={"thinking": {"type": "disabled"}})
chain = {"context": retriever | format_docs, "question": RunnablePassthrough()} | prompt | model | StrOutputParser()

print(chain.invoke("When is the invoice due?"))
print("--- what the model received:")
print(MOCK.calls[-1]["body"]["messages"][1]["content"])

@@ concept
title: create_agent: a ready-made tool loop
--- body
On Day 17 (TypeScript) and yesterday (LangChain messages) you wrote an agent loop with a limit by hand: call the model → if there are `tool_calls`, run them and add the results back as tool messages → call the model again → stop when there are no `tool_calls`. In LangChain 1.x it is one line:

```python
agent = create_agent(model, tools=[lookup_playbook], system_prompt="...")
result = agent.invoke({"messages": [("user", "...")]})
```

- Input and output are both `{"messages": [...]}`. `system_prompt` is put first every time the model is called, but it is not in the returned messages
- Reading the trace: `HumanMessage → AIMessage(tool_calls) → ToolMessage → AIMessage` (the final answer)
- What you get back is a **compiled LangGraph graph**: the nodes `model` and `tools`, and `get_graph().draw_mermaid()` can draw it (solid lines are fixed edges, dotted lines are conditional edges). Tomorrow you build a graph like this yourself
- Step limit: `agent.invoke(..., {"recursion_limit": 10})`; going over it raises `GraphRecursionError`. In this version the default limit is 10007 (many older tutorials say 25), so not setting it is almost the same as having no limit

Why an agent's model must have thinking turned off (`extra_body={"thinking": {"type": "disabled"}}`): the DeepSeek docs say that in thinking mode, whenever the request includes tools, the `reasoning_content` of every earlier assistant message must be sent back unchanged, or the API returns 400; but LangChain's ChatDeepSeek drops it when it turns messages into a request. So with thinking on, the agent's second model call breaks this rule (this page's mock server answers 400, as the docs say; a test of the real API in 2026-09 showed it does not reject it for now, but you can't count on it never checking). Also, one task calls the model several times, the thinking of every call is billed as output tokens, and it is slower.
--- code
from langchain_core.tools import tool
from langchain_deepseek import ChatDeepSeek
from langchain.agents import create_agent

RULES = {"liability_cap": "PB-01: cap at 12 months of fees; never unlimited."}

@tool
def lookup_playbook(topic: str) -> str:
    """Return the customer's playbook rule for a contract topic."""
    return RULES.get(topic, "no rule for this topic")

model = ChatDeepSeek(model="deepseek-flash", extra_body={"thinking": {"type": "disabled"}})
agent = create_agent(model, tools=[lookup_playbook], system_prompt="Check the playbook before you answer.")
result = agent.invoke({"messages": [("user", "Clause 8.1 caps liability at 12 months of fees. Is that ok?")]})

for m in result["messages"]:
    print(f"{type(m).__name__:<13}", m.content[:50] or m.tool_calls[0]["name"])
print(type(agent).__name__, list(agent.get_graph().nodes))
first = MOCK.calls[0]["body"]
print([m["role"] for m in first["messages"]], first["thinking"])
print([line.strip() for line in agent.get_graph().draw_mermaid().splitlines() if "->" in line])

try:   # the same agent, only with thinking left on
    create_agent(ChatDeepSeek(model="deepseek-flash"), tools=[lookup_playbook]).invoke({"messages": [("user", "Is clause 8.1 ok?")]})
except Exception as e:
    print("thinking on:", type(e).__name__, e.status_code)

@@ concept
title: response_format: a structured final answer
--- body
What an agent says at the end is free text, which is hard for a program to use. `response_format` makes it hand in a Pydantic object at the end, which lands in the result's `structured_response`.

For DeepSeek, write it as `ToolStrategy(ClauseReview)`:

- It adds `ClauseReview` to the tools as **one more tool**, and sets `tool_choice: "required"` (the model must call a tool in every round). After looking up the playbook, the model "calls" ClauseReview, and the arguments are the answer; LangChain validates them and puts them in `structured_response`. The trace gets one more AIMessage + ToolMessage pair (`Returning structured response: ...`)
- When the arguments fail validation, by default it writes the error into a ToolMessage and sends it back so the model can hand it in again (just like Day 17's "errors are messages for the model"). If the model keeps getting it wrong, it keeps retrying, so you need `recursion_limit` here too
- When you write just `response_format=ClauseReview`, LangChain picks a strategy automatically from the model's profile data: in this version (langchain 1.4 + langchain-deepseek 1.1) the profile says deepseek-flash supports structured output, so it picks ProviderStrategy and sends `response_format: {"type": "json_schema", ...}`. But in the DeepSeek docs, JSON Output has only one kind, `json_object`, and this page's mock server answers json_schema with 400

A framework's "automatic" sometimes guesses wrong, and it changes from version to version. When something goes wrong, first look at what `MOCK.calls[-1]["body"]` actually sent; in a real project that means the request log or the trace.
--- code
from typing import Literal
from pydantic import BaseModel, Field
from langchain_core.tools import tool
from langchain_deepseek import ChatDeepSeek
from langchain.agents import create_agent
from langchain.agents.structured_output import ToolStrategy

class ClauseReview(BaseModel):
    """The final review of one clause."""
    clause_id: str = Field(description="the clause number, e.g. 8.1")
    verdict: Literal["accept", "flag", "redline"]
    risk_level: Literal["low", "medium", "high"]

@tool
def lookup_playbook(topic: str) -> str:
    """Return the customer's playbook rule for a contract topic."""
    return "PB-01: cap at 12 months of fees; never unlimited."

model = ChatDeepSeek(model="deepseek-flash", extra_body={"thinking": {"type": "disabled"}})
agent = create_agent(model, tools=[lookup_playbook], response_format=ToolStrategy(ClauseReview))
result = agent.invoke({"messages": [("user", "Review clause 8.3: Customer's liability shall be unlimited.")]})

print(repr(result["structured_response"]))
print([type(m).__name__ for m in result["messages"]])
print(result["messages"][-1].content)
body = MOCK.calls[-1]["body"]
print([t["function"]["name"] for t in body["tools"]], body["tool_choice"])

@@ concept
title: Middleware: step in before and after calls
--- body
In 1.x, `create_agent` customizes the loop with **middleware**: hooks that run "before and after calling the model" and "before and after calling a tool". A few ready-made ones:

- `HumanInTheLoopMiddleware(interrupt_on={"send_redline": True})`: when the model wants to call `send_redline`, the graph stops first (interrupt) and waits for a person to approve / edit / reject / respond. It needs a `checkpointer` (where the state is kept while it is stopped), every call carries the same `thread_id`, and `Command(resume={"decisions": [{"type": "approve"}]})` continues it. This is the approval gate from Day 17; Day 34 covers interrupt in detail
- `ModelCallLimitMiddleware(run_limit=5)`, `ToolCallLimitMiddleware(...)`: limits on the number of calls
- `ModelRetryMiddleware`, `ModelFallbackMiddleware`, `SummarizationMiddleware`, `PIIMiddleware`: retries, switching to a fallback model, compressing a long history, masking personal information

Every layer you add is one more layer to check when something goes wrong. First ask: can plain code do this? When you do use one, read its constructor arguments in the source code; the way older tutorials write it has often changed.
--- code
from langchain_core.tools import tool
from langchain_deepseek import ChatDeepSeek
from langchain.agents import create_agent
from langchain.agents.middleware import HumanInTheLoopMiddleware
from langgraph.checkpoint.memory import InMemorySaver
from langgraph.types import Command

SENT = []

@tool
def send_redline(clause_id: str) -> str:
    """Email the proposed redline for one clause to the counterparty."""
    SENT.append(clause_id)
    return f"redline for {clause_id} sent"

model = ChatDeepSeek(model="deepseek-flash", extra_body={"thinking": {"type": "disabled"}})
agent = create_agent(model, tools=[send_redline], checkpointer=InMemorySaver(),
                     middleware=[HumanInTheLoopMiddleware(interrupt_on={"send_redline": True})])
cfg = {"configurable": {"thread_id": "review-42"}}

result = agent.invoke({"messages": [("user", "Send the redline for clause 8.3")]}, cfg)
request = result["__interrupt__"][0].value["action_requests"][0]
print("paused:", request["name"], request["args"], "| sent so far:", SENT)

result = agent.invoke(Command(resume={"decisions": [{"type": "approve"}]}), cfg)
print("after approve:", SENT, "|", result["messages"][-1].content)

@@ concept
title: Which one to use when
--- body
A common interview question: a fixed chain, create_agent, or writing LangGraph yourself: how do you choose?

- **Fixed chain** (`prompt | model | parser`, or the RAG chain above): the steps are known in advance. Cheapest, most predictable, easiest to test. "Always fetch the playbook rule for the topic before reviewing a clause" is written straight into the code
- **create_agent**: whether to look something up, what, and how many times depends on the content (8.1 says subject to Section 12, so the model has to go and read clause 12 itself). The cost: more calls, a path that may be different every time, so you need a limit and have to read the trace
- **Writing LangGraph yourself**: the flow itself has branches, parallel steps, pauses to wait for a person, resuming from a checkpoint

Clause Check's own choice: the bounded tool loop in `review.py` is hand-written (≤ 6 steps), the outer `pipeline.py` is plain Python, and only the approval flow uses LangGraph (the README gives the reason: the first requirement that really needed a framework was "stop and wait for a person to approve, then continue hours later from another process").

A one-sentence answer: "Hard-code whatever you can; use an agent only when the model really needs to decide for itself; bring in a graph framework only when the flow has to pause, resume or run in parallel." Below, for the same question, the fixed chain calls the model once and the agent calls it twice.
--- code
from langchain_core.tools import tool
from langchain_core.prompts import ChatPromptTemplate
from langchain_core.output_parsers import StrOutputParser
from langchain_deepseek import ChatDeepSeek
from langchain.agents import create_agent

RULES = {"payment": "PB-04: net 30 is fine."}

@tool
def lookup_playbook(topic: str) -> str:
    """Return the customer's playbook rule for a contract topic."""
    return RULES.get(topic, "no rule for this topic")

model = ChatDeepSeek(model="deepseek-flash", extra_body={"thinking": {"type": "disabled"}})
question = "Clause 3.1: fees are payable within 30 days. Is that ok?"

MOCK.reset()
prompt = ChatPromptTemplate.from_messages([("system", "Playbook rule: {rule}"), ("user", "{question}")])
(prompt | model | StrOutputParser()).invoke({"rule": RULES["payment"], "question": question})
print("fixed chain:", len(MOCK.calls), "model call(s)")

MOCK.reset()
create_agent(model, tools=[lookup_playbook]).invoke({"messages": [("user", question)]})
print("agent:      ", len(MOCK.calls), "model call(s)")

from typing import Literal
from pydantic import BaseModel, Field
from langchain_deepseek import ChatDeepSeek

class ClauseReview(BaseModel):
    """Review of one contract clause."""
    clause_id: str = Field(description="the clause number, e.g. 8.1")
    verdict: Literal["accept", "flag", "redline"]
    risk_level: Literal["low", "medium", "high"]

MODEL = ChatDeepSeek(model="deepseek-flash", extra_body={"thinking": {"type": "disabled"}})

def review(text):
    result = MODEL.with_structured_output(ClauseReview).invoke(text)
    if result is None:
        return ClauseReview(clause_id="unknown", verdict="flag", risk_level="medium")
    return result

from langchain_core.tools import tool
from langchain_deepseek import ChatDeepSeek

--- explain
When the model wants to call a tool, `content` is an empty string, and what it wants done is in `tool_calls`: `name`, `args` (already a dictionary), `id`. title: How the splitter cuts
level: 2
cards: Splitters: by length or by structure
--- context
To answer questions about a contract, the long text first has to be cut into small chunks, so they can be stored in a vector store and searched. LangChain comes with a splitter that cuts by length; first see exactly how it cuts some contract text.
--- prompt
Write the output. Remember the card: it first cuts at `"\n\n"`; if a piece is longer than `chunk_size`, it cuts that piece at `"\n"`; at the end it merges neighboring small pieces, as long as the merged piece (counting the separator between them) is no longer than `chunk_size`. `start_index` counts from 0.
--- code
from langchain_text_splitters import RecursiveCharacterTextSplitter

text = "3.1 Invoicing\nFees are payable within thirty days.\n\n3.2 Late Payment\nInterest accrues at 3% per month."
splitter = RecursiveCharacterTextSplitter(chunk_size=40, chunk_overlap=0, add_start_index=True)
docs = splitter.create_documents([text])
print(len(docs))
for d in docs:
    print(d.metadata["start_index"], repr(d.page_content))
--- explain

import re
from langchain_core.documents import Document

HEAD = re.compile(r"^(\d+(?:\.\d+)*)\s+([A-Z][^\n]{0,80})$", re.M)

CONTRACT = """3.1 Invoicing
Fees are invoiced annually and are payable within thirty (30) days of the invoice date.
8.1 Cap on Liability
Each party's aggregate liability shall not exceed the Fees paid
in the twelve (12) months before the claim.
11.1 Termination by Provider
Provider may terminate this Agreement upon ten (10) days' notice."""

def split_contract(text, source):
    heads = list(HEAD.finditer(text))
    if not heads:
        raise ValueError("no numbered clauses")
    docs = []
    for i, h in enumerate(heads):
        end = heads[i + 1].start() if i + 1 < len(heads) else len(text)
        body = text[h.end():end].strip()
        docs.append(Document(page_content=body, metadata={"clause_id": h.group(1), "heading": h.group(2), "source": source}))
    return docs

from langchain_core.vectorstores import InMemoryVectorStore
from langchain_openai import OpenAIEmbeddings

    ("3.1", "payment", "Fees are invoiced annually and are payable within thirty (30) days of the invoice date."),
    ("4.2", "auto_renewal", "This Agreement renews automatically for successive periods of twenty-four (24) months."),
    ("8.1", "liability_cap", "Each party's aggregate liability shall not exceed the Fees paid in the twelve (12) months before the claim."),
    ("8.3", "liability_cap", "Customer's liability for breach of Section 6 shall be unlimited."),
    ("10.1", "data_processing", "Customer Data may be stored and processed in any country."),
    ("11.1", "termination", "Provider may terminate this Agreement for convenience upon ten (10) days' written notice."),
]
DOCS = [Document(page_content=text, metadata={"clause_id": cid, "topic": topic}) for cid, topic, text in CLAUSES]

def build_store(docs):
    store = InMemoryVectorStore(OpenAIEmbeddings(model="text-embedding-3-small"))
    store.add_documents(docs)
    return store

def search_ids(store, query, k=2, topic=None):
    if topic is None:
        hits = store.similarity_search(query, k=k)
    else:
        hits = store.similarity_search(query, k=k, filter=lambda d: d.metadata["topic"] == topic)
    return [d.metadata["clause_id"] for d in hits]

from langchain_core.tools import tool
from langchain_deepseek import ChatDeepSeek
from langchain.agents import create_agent
from langchain.agents.middleware import HumanInTheLoopMiddleware
from langgraph.checkpoint.memory import InMemorySaver
from langgraph.types import Command

SENT = []

@tool
def send_redline(clause_id: str) -> str:
    """Email the proposed redline for one clause to the counterparty."""
    SENT.append(clause_id)
    return f"redline for {clause_id} sent"

AGENT = create_agent(
    ChatDeepSeek(model="deepseek-flash", extra_body={"thinking": {"type": "disabled"}}),
    tools=[send_redline],
    middleware=[HumanInTheLoopMiddleware(interrupt_on={"send_redline": True})],
    checkpointer=InMemorySaver(),
)

def start(question, thread_id):
    config = {"configurable": {"thread_id": thread_id}}
    result = AGENT.invoke({"messages": [("user", question)]}, config)
    if "__interrupt__" not in result:
        return []
    requests = result["__interrupt__"][0].value["action_requests"]
    return [(r["name"], r["args"]) for r in requests]

def finish(thread_id, approve):
    config = {"configurable": {"thread_id": thread_id}}
    if approve:
        decision = {"type": "approve"}
    else:
        decision = {"type": "reject", "message": "Rejected by the reviewer."}
    result = AGENT.invoke(Command(resume={"decisions": [decision]}), config)
    return result["messages"][-1].content

- Put all the Documents into an `InMemoryVectorStore` in one go (`from langchain_core.vectorstores import InMemoryVectorStore`), with embeddings from `OpenAIEmbeddings(model="text-embedding-3-small")` (`from langchain_openai import OpenAIEmbeddings`), and return the store

import re
from langchain_core.documents import Document
from langchain_core.vectorstores import InMemoryVectorStore
from langchain_openai import OpenAIEmbeddings

HEAD = re.compile(r"^(\d+(?:\.\d+)*)\s+([A-Z][^\n]{0,80})$", re.M)

def index_contract(text):
    heads = list(HEAD.finditer(text))
    if not heads:
        raise ValueError("no numbered clauses")
    docs = []
    for i, h in enumerate(heads):
        end = heads[i + 1].start() if i + 1 < len(heads) else len(text)
        docs.append(Document(page_content=text[h.end():end].strip(), metadata={"clause_id": h.group(1)}))
    store = InMemoryVectorStore(OpenAIEmbeddings(model="text-embedding-3-small"))
    store.add_documents(docs)
    return store

def find(store, question, k=2):
    return [d.metadata["clause_id"] for d in store.similarity_search(question, k=k)]

from langchain_core.prompts import ChatPromptTemplate
from langchain_core.output_parsers import StrOutputParser

PROMPT = ChatPromptTemplate.from_messages([
    ("system", "Answer only from the sources and cite clause ids."),
    ("user", "Question: {question}\nSources:\n{context}"),
])

def rag(question, retriever, model):
    docs = retriever.invoke(question)
    if not docs:
        return {"answer": "I could not find this in the contract.", "sources": []}
    context = "\n".join(f"[{d.metadata['clause_id']}] {d.page_content}" for d in docs)
    answer = (PROMPT | model | StrOutputParser()).invoke({"question": question, "context": context})
    return {"answer": answer, "sources": [d.metadata["clause_id"] for d in docs]}

from langchain.agents import create_agent
from langchain.agents.structured_output import ToolStrategy
from langgraph.errors import GraphRecursionError

def agent_review(text):
    agent = create_agent(MODEL, tools=[lookup_playbook, get_clause], system_prompt="Review the clause against the playbook.",
                         response_format=ToolStrategy(ClauseReview))
    try:
        result = agent.invoke({"messages": [("user", text)]}, {"recursion_limit": 8})
    except GraphRecursionError:
        return {"verdict": "flag", "risk_level": "medium", "tools": []}
    tools = []
    for m in result["messages"]:
        for call in getattr(m, "tool_calls", None) or []:
            if call["name"] != "ClauseReview":
                tools.append(call["name"])
    review = result["structured_response"]
    return {"verdict": review.verdict, "risk_level": review.risk_level, "tools": tools}
