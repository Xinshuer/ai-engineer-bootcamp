title: Architecture: from upload to dashboard
cloud: yes
--- body
The goal: a user uploads a contract and gets a response right away; the review runs slowly in the background and retries by itself when it fails; the results can be viewed with SQL. The matching AWS services are in parentheses:

```
user uploads a .txt
  → GCS bucket clausecheck-contracts              (S3)
  → "object created" event → on_upload creates a job (S3 event notification → Lambda)
    (on GCP, on_upload can be a small Cloud Run service triggered by Eventarc)
  → Pub/Sub topic contract-uploaded               (SQS)
  → Cloud Run worker: download, split, call the model per clause (Lambda / ECS)
  → BigQuery table clausecheck.reviews             (Redshift / Athena)
    + the report in GCS bucket clausecheck-reports (S3)
  → dashboard SQL: latest verdicts, cost, failure rate
```

The bucket, the worker and BigQuery all sit in an EU region (`europe-north1` Finland / `eu-north-1` Stockholm); each component has its own service account with only the permissions it needs; the DeepSeek API key is in Secret Manager. **Watch the model step**: when you call DeepSeek, the clause text is sent to servers outside the EU. For real customers' contracts, either switch to a managed model in an EU region (Day 27: Bedrock's `eu.` inference profiles, Gemini on Vertex AI), or first confirm that the contract and the data processing agreement allow it. Interviewers are very likely to ask about this.

**The boto3 / google-cloud on this page are mocks**: the calls and the structures they return match the real SDKs (only the parts the course uses are implemented); in a real project you `pip install` them and set up credentials.

A classic mistake: reviewing the whole contract synchronously inside the upload's HTTP request. One clause takes 2–3 seconds, so 30 clauses take a minute or two; the user sits waiting, and the gateway may time out first; and when the service restarts, that contract is lost. The code below walks through the first two steps.
--- code
import json

print("uploaded:", blob.name, "generation =", blob.generation)

# Step 2: the upload event becomes a job, published to the queue; the worker takes it from the queue later
job = {"key": f"gs://{blob.bucket.name}/{blob.name}#{blob.generation}", "contract_id": 111}
publisher = pubsub_v1.PublisherClient()
topic = publisher.topic_path("clausecheck-dev", "contract-uploaded")
message_id = publisher.publish(topic, json.dumps(job).encode("utf-8"), contract_id="111").result()
print("published job:", job["key"], "message_id =", message_id)

for step, gcp, aws in [("storage", "Cloud Storage", "S3"), ("queue", "Pub/Sub", "SQS / SNS"),

                       ("secrets", "Secret Manager", "Secrets Manager"), ("logs", "Cloud Logging", "CloudWatch")]:

@@ concept
title: Every step can fail: at-least-once and idempotency
cloud: yes
--- body
In the cloud, nothing is guaranteed to work the first time. Step by step, here is how each one fails and how you recover:

- **Publishing the job**: `publish()` returns a future right away; a server error is raised in `future.result()`
- **Delivery**: Pub/Sub push subscriptions and SQS standard queues are both **at-least-once**. With a push subscription, only a success status code such as 200 or 204 from the worker counts as an acknowledgment; if the worker returns 500, doesn't answer within the subscription's acknowledgment deadline (ack deadline: 10 seconds by default, at most 600 seconds), or crashes, the message is delivered again a little later. So **the same job may be processed twice**
- **A single clause fails** (model 429, broken JSON): record one error row; it doesn't bring down the whole contract
- **Permanent errors** (a broken message, a contract with no clauses): redelivery won't fix them → log it and return 204 to acknowledge it. **Other errors** (BigQuery temporarily unavailable, rate limits, errors you can't classify): raise → return 500 → redelivery; give the subscription a dead-letter topic, and messages that reach the delivery limit (5 by default) move there, so they aren't redelivered forever
- **Idempotency**: first check whether the report exists, and skip if it does; write the report **last**, and create it only if it doesn't exist yet (`if_generation_match=0`). The report is the "done" marker

The price: if the worker crashes after writing to BigQuery but before writing the report, redelivery adds duplicate rows to the table. That's why the dashboard always takes the latest row per `(contract_id, clause_id)`.

Push or pull: with push, Pub/Sub POSTs the message to Cloud Run, and the service can scale to 0 when there are no messages, which is the least work; but every request must be answered within the ack deadline. With pull, the worker fetches and acknowledges messages itself, which suits very long jobs and cases where you need to control concurrency (SQS is pull).
--- code
import json
from google.cloud import storage
from google.api_core.exceptions import PreconditionFailed

reports = storage.Client().bucket("clausecheck-reports")

def finish(job, report):
    blob = reports.blob(f"reports/{job['contract_id']}/{job['generation']}.json")
    if blob.exists():
        return "duplicate: skipped"
    # ... downloading, reviewing and writing to BigQuery go here ...
    blob.upload_from_string(json.dumps(report), content_type="application/json", if_generation_match=0)
    return "done"

job = {"contract_id": 111, "generation": "1790000000000001"}
print(finish(job, {"redline": 1}))   # first delivery
print(finish(job, {"redline": 1}))   # the same message delivered again

# Two workers get the same job at the same time: both passed the exists() check, but only one "create if it doesn't exist" can succeed
try:
    reports.blob("reports/111/1790000000000001.json").upload_from_string("{}", if_generation_match=0)
except PreconditionFailed as e:
    print("second write rejected:", e.code)

title: Cost estimate: where the money goes
dataset: clausecheck
--- body
Interviewers often ask "how much does this cost per month?". How to answer: **use data you measured yourself, split the cost by usage, and say where each unit price comes from**.

- **Model**: each clause's input tokens (and how many of them hit the cache) + output tokens, times the unit prices. The sample database's `cost_usd` uses DeepSeek's **peak prices**; the official pricing page is what counts (2026-09): `deepseek-flash` costs $0.30 per million input tokens, $0.006 for cache hits and $1.20 for output; the larger model `deepseek-v4-pro` costs 1.32 / 0.044 / 3.96. Peak hours are weekdays UTC 01:00–04:00 and 06:00–10:00; all other hours are half price. `PRICES` in the project's `config.py` holds exactly these peak prices (2026-09). Watch how it is looked up: a model that isn't in the table gets a unit price of 0, and then the cost estimate in the report is 0, so when you switch models, add their prices to the table first
- **Thinking mode**: DeepSeek thinks before it answers by default, and thinking tokens are billed as **output**. Giving a verdict on one clause doesn't need long reasoning, so the worker's requests include `"thinking": {"type": "disabled"}`: faster and cheaper, and `temperature` works again (it has no effect in thinking mode). The sample database's output tokens are the amounts with thinking off; with thinking on, every clause adds a stretch of reasoning output tokens, and the model bill goes up quite a bit
- **BigQuery**: on-demand queries are billed by bytes scanned, about $6.25 / TiB, with the first 1 TiB each month free; even a small table is billed at a minimum of 10 MB (check the official pricing page). Streaming inserts are billed separately by volume, almost zero at this scale
- **Storage, Pub/Sub, Cloud Run**: at this scale, basically inside the free tier or a few cents (check the official pricing page)

Conclusion first: **the model is almost the whole bill**. The code below works it out straight from the sample database. Watch the last line: if the dashboard refreshes too often and there is no free tier, the dashboard alone costs nearly as much as the model does for 100 contracts.
--- code
conn = fresh_db()   # the sample database this page provides (the same one as Days 22–25)

--- context
In today's Clause Check in the cloud, an uploaded contract means publishing a job to Pub/Sub, and the dashboard queries BigQuery. Once you know which line an error comes out of, you know which line to put inside a `try` to catch it.
--- prompt
Recap of Days 25 and 27. `sql` has a misspelled column name, and `topic_path` points to a topic that doesn't exist. On which lines are these two errors raised?
--- code
job = client.query(sql, job_config=cfg)          # A
rows = list(job.result())                        # B
future = publisher.publish(topic_path, data)     # C
message_id = future.result()                     # D
--- options
- A and C: the call fails the moment you make it
- B and D: the error is raised only when you get the result
- A and D: SQL is checked when it's submitted; publishing waits for the result
- Neither raises: you have to check the return value yourself
answer: 2
--- explain
`client.query()` only creates a query job; the SQL error is raised in `job.result()` (a dry run is the exception: it fails right at `query()`). `publish()` returns a future immediately, and the NotFound for the missing topic is raised in `future.result()`. So the try/except has to wrap B and D. The fourth option describes a different function: `insert_rows_json` **doesn't raise** on bad rows; it returns a list of errors instead, and today's worker has to check it itself.

Recap of Day 23 (LEFT JOIN, JOIN fan-out). The query below tries to list the number of contracts and reviews for **every customer**, but it has two bugs: customers without contracts disappear, and the contract count is wrong (exactly the same as the review count). Run it, compare it with the expected result, and fix it.

Return three columns: `name`, `contracts` (number of contracts), `reviews` (number of reviews), ordered by `reviews` from most to fewest, and by `name` when they tie.
--- starter
SELECT cu.name, COUNT(co.id) AS contracts, COUNT(r.id) AS reviews
FROM customers AS cu
JOIN contracts AS co ON co.customer_id = cu.id
JOIN reviews AS r ON r.contract_id = co.id
GROUP BY cu.id, cu.name
ORDER BY reviews DESC, cu.name
--- solution
SELECT cu.name, COUNT(DISTINCT co.id) AS contracts, COUNT(r.id) AS reviews
FROM customers AS cu
LEFT JOIN contracts AS co ON co.customer_id = cu.id
LEFT JOIN reviews AS r ON r.contract_id = co.id
GROUP BY cu.id, cu.name
ORDER BY reviews DESC, cu.name
--- hints
- "Customers without contracts must be listed too" → both JOINs must become LEFT JOIN.
- Once a contract is joined to reviews, it turns into many rows (JOIN fan-out), and `COUNT(co.id)` counts rows. To count "how many different contracts", write `COUNT(DISTINCT co.id)`.
- `COUNT(r.id)` doesn't count NULL, so both columns are 0 for Amsterdam Data BV.

from google.cloud import storage

BUCKET = "clausecheck-contracts"

def upload_contract(client, customer_id, contract_id, filename, text):
    if not filename.endswith(".txt"):
        raise ValueError("only .txt contracts")
    name = f"contracts/{customer_id}/{contract_id}/{filename}"
    blob = client.bucket(BUCKET).blob(name)
    blob.metadata = {"customer_id": str(customer_id), "contract_id": str(contract_id)}
    blob.upload_from_string(text, content_type="text/plain; charset=utf-8")
    return {"bucket": BUCKET, "name": name, "generation": blob.generation}

import json
from google.cloud import pubsub_v1

def job_key(bucket, name, generation):
    return f"gs://{bucket}/{name}#{generation}"

def on_upload(event, publisher, topic_path):
    name = event["name"]
    if not name.startswith("contracts/"):
        return None
    job = {
        "key": job_key(event["bucket"], name, event["generation"]),
        "bucket": event["bucket"],
        "name": name,
        "generation": event["generation"],
        "contract_id": int(event["metadata"]["contract_id"]),
    }
    future = publisher.publish(topic_path, json.dumps(job).encode("utf-8"), contract_id=str(job["contract_id"]))
    return future.result()

import base64
import json

REQUIRED = ("key", "bucket", "name", "generation", "contract_id")

def decode_push(envelope):
    try:
        data = envelope["message"]["data"]
        job = json.loads(base64.b64decode(data).decode("utf-8"))
    except (KeyError, TypeError, ValueError) as e:
        raise ValueError(f"bad message: {e}") from e
    if not isinstance(job, dict) or any(k not in job for k in REQUIRED):
        raise ValueError("bad message: missing fields")
    return job

--- context
Instances in the cloud can be stopped at any moment, for example when a request times out. Interviewers love to ask: if the work is cut off halfway through, what does running it again leave behind?
--- prompt
The worker has written a contract's 3 rows to BigQuery, and before it gets to write the report, Cloud Run stops it (for example, because the request timed out). Pub/Sub didn't get a success status code, and a little later it delivers the same message again. What happens?
--- options
- Nothing: Pub/Sub guarantees that each message is delivered exactly once
- The new worker finds that the report doesn't exist yet, so it does everything again from the start: the model is called again, BigQuery gets 3 duplicate rows for this contract, and this time the report is written. That's why the dashboard has to take the latest row per (contract_id, clause_id) instead of simply counting all rows
- The new worker finds rows for this contract already in BigQuery, so it skips the job
- BigQuery rejects the 3 rows because of duplicate primary keys, so the table has no duplicates
answer: 2
--- explain
Push subscriptions and SQS standard queues are both "at least once" (in Pub/Sub, only pull subscriptions can turn on "exactly once" delivery; and even with it on, a worker that crashes halfway through still has to redo the work, so you still need idempotency). Our "done" marker is the report, and it is written last, so if any earlier step didn't finish, redelivery does everything again from the start: better duplicated than lost, and the duplicate rows are removed in the query (the first P5 exercise). BigQuery doesn't enforce primary keys (NOT ENFORCED), and the insertId deduplication of streaming inserts is only "best effort". The other way round, writing the report before BigQuery, is worse: if the report is written and BigQuery then fails, redelivery sees that the report exists and skips the job, and those rows are lost forever. Also, a push request must return within the subscription's acknowledgment deadline (ack deadline): only 10 seconds by default, at most 600 seconds (check the official docs). For long contracts, raise the deadline or switch to pull; otherwise Pub/Sub treats the job as failed and delivers it again before processing is even finished.

  SELECT contract_id, clause_id, verdict, error,
         ROW_NUMBER() OVER (PARTITION BY contract_id, clause_id ORDER BY created_at DESC) AS rn

       COUNT(*) AS clauses,
       COUNTIF(verdict IN ('flag', 'redline')) AS needs_human,

from dataclasses import dataclass

MB = 1024 ** 2
TIB = 1024 ** 4
# Example unit prices; check the official pricing pages before you quote them. The model prices are deepseek-flash peak prices (2026-09), half price off-peak
PRICES = {
    "input_per_m": 0.30,       # model input (cache miss), USD per million tokens
    "cache_hit_per_m": 0.006,  # model input (cache hit)
    "output_per_m": 1.20,      # model output (thinking-mode tokens count as output too)
    "bq_per_tib": 6.25,        # BigQuery on-demand queries, USD / TiB
    "bq_free_tib": 1.0,        # free query volume per month
    "gcs_per_gb_month": 0.02,  # storage, approximate
}

@dataclass
class Workload:
    contracts: int                 # contracts per month
    clauses_per_contract: float = 6.5
    prompt_tokens: int = 2200      # input tokens per clause
    completion_tokens: int = 175   # output tokens per clause
    cache_hit_ratio: float = 0.56  # share of the input that hits the cache
    dashboard_queries: int = 2880  # dashboard queries per month (one every 15 minutes)
    tables_per_query: int = 2
    stored_gb: float = 1.0         # contracts and reports in the buckets

def estimate_monthly_cost(w, prices=PRICES):
    clauses = w.contracts * w.clauses_per_contract
    hit = w.prompt_tokens * w.cache_hit_ratio
    miss = w.prompt_tokens - hit
    per_clause = (miss * prices["input_per_m"] + hit * prices["cache_hit_per_m"]
                  + w.completion_tokens * prices["output_per_m"]) / 1_000_000
    llm = clauses * per_clause
    tib = w.dashboard_queries * w.tables_per_query * 10 * MB / TIB
    bq = max(0.0, tib - prices["bq_free_tib"]) * prices["bq_per_tib"]
    storage = w.stored_gb * prices["gcs_per_gb_month"]
    return {"llm_usd": round(llm, 2), "bigquery_usd": round(bq, 2), "storage_usd": round(storage, 2),
            "total_usd": round(llm + bq + storage, 2)}

import json
from botocore.exceptions import ClientError

BUCKET = "clausecheck-reports"

def report_key(contract_id, generation):
    return f"reports/{contract_id}/{generation}.json"

def store_report(s3, contract_id, generation, report):
    try:
        s3.put_object(Bucket=BUCKET, Key=report_key(contract_id, generation), Body=json.dumps(report).encode("utf-8"),
                      ContentType="application/json", Metadata={"contract-id": str(contract_id)}, IfNoneMatch="*")
    except ClientError as e:
        if e.response["Error"]["Code"] == "PreconditionFailed":
            return "duplicate"
        raise
    return "stored"

def load_report(s3, contract_id, generation):
    try:
        resp = s3.get_object(Bucket=BUCKET, Key=report_key(contract_id, generation))
    except ClientError as e:
        if e.response["Error"]["Code"] == "NoSuchKey":
            return None
        raise
    return json.loads(resp["Body"].read().decode("utf-8"))

- Keep calling `sqs.receive_message(QueueUrl=queue_url, MaxNumberOfMessages=10)` until a call receives no messages (real SQS uses short polling by default, which now and then returns nothing even though messages are still there; in production, add `WaitTimeSeconds=20` for long polling. For this problem, either way is fine)
- The message body is JSON: `{"key": ..., "clause_id": ..., "text": ...}`
- If `key` is already in the set `done`: it's a duplicate delivery; delete the message right away, without calling the model
- Otherwise call Bedrock: `bedrock.converse(modelId=MODEL_ID, system=[{"text": SYSTEM}], messages=[{"role": "user", "content": [{"text": f"Review clause {clause_id}: {text}"}]}], inferenceConfig={"maxTokens": 200, "temperature": 0})`. The answer text is in `resp["output"]["message"]["content"][0]["text"]`; it's JSON containing `verdict` and `risk_level`
- Success: add `{"clause_id": ..., "verdict": ..., "risk_level": ...}` to the results, add `key` to `done`, **then** delete the message (with the `ReceiptHandle` from this receive)
- Bedrock raises `botocore.exceptions.ClientError` (the SDK's own retries are used up): don't delete the message, go on to the next one; it comes back after the visibility timeout

Copy these two constants into your code exactly as they are:

```python
MODEL_ID = "eu.amazon.nova-lite-v1:0"   # example: an EU cross-Region inference profile; check the Bedrock console
SYSTEM = 'You review one contract clause. Reply with JSON only: {"verdict": "accept|flag|redline", "risk_level": "low|medium|high"}'
```
--- solution
import json
from botocore.exceptions import ClientError

MODEL_ID = "eu.amazon.nova-lite-v1:0"   # example: an EU cross-Region inference profile; check the Bedrock console
SYSTEM = 'You review one contract clause. Reply with JSON only: {"verdict": "accept|flag|redline", "risk_level": "low|medium|high"}'

def review(bedrock, clause_id, text):
    resp = bedrock.converse(
        modelId=MODEL_ID,
        system=[{"text": SYSTEM}],
        messages=[{"role": "user", "content": [{"text": f"Review clause {clause_id}: {text}"}]}],
        inferenceConfig={"maxTokens": 200, "temperature": 0},
    )
    return json.loads(resp["output"]["message"]["content"][0]["text"])

def drain(sqs, queue_url, bedrock, done):
    results = []
    while True:
        messages = sqs.receive_message(QueueUrl=queue_url, MaxNumberOfMessages=10).get("Messages", [])
        if not messages:
            return results
        for msg in messages:
            job = json.loads(msg["Body"])
            if job["key"] not in done:
                try:
                    v = review(bedrock, job["clause_id"], job["text"])
                except ClientError:
                    continue
                results.append({"clause_id": job["clause_id"], "verdict": v["verdict"], "risk_level": v["risk_level"]})
                done.add(job["key"])
            sqs.delete_message(QueueUrl=queue_url, ReceiptHandle=msg["ReceiptHandle"])

import json
import boto3
sqs = boto3.client("sqs", region_name="eu-north-1")
br = boto3.client("bedrock-runtime", region_name="eu-north-1")
def queue(name, jobs):
    url = sqs.create_queue(QueueName=name)["QueueUrl"]
    for key, cid, text in jobs:
        sqs.send_message(QueueUrl=url, MessageBody=json.dumps({"key": key, "clause_id": cid, "text": text}))
    return url
def model_calls():
    return sum(1 for c in CLOUD.calls if c[0] == "bedrock.converse")
def _normal():
    url = queue("q-normal", [("k1", "8.1", "Liability shall be unlimited."),
                             ("k2", "3.5", "Provider may suspend the Service without notice."),
                             ("k1", "8.1", "Liability shall be unlimited.")])
    done = set()
    before = model_calls()
    res = drain(sqs, url, br, done)
    CLOUD.advance(31)
    return [res, sorted(done), model_calls() - before, sqs.receive_message(QueueUrl=url).get("Messages", [])]
expect("processes, deduplicates, deletes", _normal, [[{"clause_id": "8.1", "verdict": "redline", "risk_level": "high"},
                                   {"clause_id": "3.5", "verdict": "flag", "risk_level": "medium"}], ["k1", "k2"], 2, []])
def _seen():
    url = queue("q-seen", [("k9", "3.1", "Fees are payable within thirty days.")])
    before = model_calls()
    res = drain(sqs, url, br, {"k9"})
    CLOUD.advance(31)
    return [res, model_calls() - before, sqs.receive_message(QueueUrl=url).get("Messages", [])]
expect("a key done before: no model call, deleted right away", _seen, [[], 0, []])
def _throttled():
    url = queue("q-throttle", [("k3", "4.2", "Fees are payable within thirty days.")])
    CLOUD.fail_next("bedrock-runtime", "throttle", 5)
    done = set()
    first = drain(sqs, url, br, done)
    CLOUD.advance(31)
    second = drain(sqs, url, br, done)
    return [first, second]
expect("Bedrock keeps throttling: leave the message for now, process it after the visibility timeout", _throttled, [[], [{"clause_id": "4.2", "verdict": "accept", "risk_level": "low"}]])
def _many():
    url = queue("q-many", [(f"m{i}", f"{i}.1", "Fees are payable within thirty days.") for i in range(1, 13)])
    return len(drain(sqs, url, br, set()))
expect("12 messages: at most 10 per receive, so you have to loop", _many, 12)
