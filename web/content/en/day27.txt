title: From script to service: statelessness, environment variables, health checks
--- body
So far, Clause Check has mostly been a command-line tool: you run it in a terminal, it reviews one contract and exits. For people at a law firm to use it on a web page, it has to become a **service**: always online, taking requests over HTTP. The project already has one: `clausecheck/api.py` is a FastAPI app; `GET /health` answers "I'm still alive", and `POST /review` takes an uploaded contract and returns the report as JSON.

Before a service goes to the cloud, it has to meet three conditions:

- **Stateless**: the cloud runs several copies (instances) at once, and it can shut one down and swap in a new one at any time. So requests can't pass things to each other through memory: whatever must be remembered goes into a bucket, a database or a queue
- **Configuration comes from environment variables**: `Settings` in `config.py` reads everything with `os.getenv`; the `load_dotenv` it calls does nothing when it can't find `.env`, so the same code reads `.env` on your computer and the environment variables set by the platform in the cloud. The model name is configuration too: `config.py` uses `deepseek-flash` by default; to switch to `deepseek-v4-pro` when you deploy, set the environment variable `CLAUSECHECK_DEEPSEEK_MODEL`, with no code change (if you change the model, `PRICES` must have its unit prices; see the cost card on Day 28)
- **Health checks**: the platform regularly calls an address like `/health`, and unhealthy instances get replaced

The code below simulates two instances, to show why "keeping it in memory" goes wrong in the cloud.
--- code
class Instance:
    """One copy of the service. The cloud may run several and replace them at any time."""

    def __init__(self, name):
        self.name = name
        self.reviewed = []                       # in memory: gone when the instance goes away

    def handle(self, contract_id, store):
        self.reviewed.append(contract_id)
        store.setdefault("reviewed", []).append(contract_id)   # shared: a bucket or a database
        return f"{self.name} reviewed {contract_id}"

store = {}
a, b = Instance("instance-a"), Instance("instance-b")
print(a.handle(101, store))
print(b.handle(102, store))
print(a.handle(103, store))
print("instance-a remembers:", a.reviewed)
print("instance-b remembers:", b.reviewed)
a = Instance("instance-a2")                      # the platform replaced instance-a
print("after the restart:", a.reviewed)
print("the shared store:", store["reviewed"])

title: Docker: images, containers, and layer caching
--- body
A cloud platform doesn't care which language you use. What it wants is a **container image**: your code, Python and the dependency packages packed into one bundle that runs the same on any machine (the "but it works on my computer" problem goes away).

- **Image**: the packed bundle, read-only; **container**: one running instance of an image
- **Dockerfile**: the list of packing steps. Each step produces a **layer**. When you rebuild, layers that haven't changed come straight from the cache; once one layer changes, **every layer after it is rebuilt**

Clause Check's Dockerfile looks roughly like this:

```
FROM python:3.12-slim
ENV PYTHONUNBUFFERED=1
WORKDIR /app
COPY requirements.txt .
RUN pip install --no-cache-dir -r requirements.txt
COPY . .
CMD exec uvicorn clausecheck.api:app --host 0.0.0.0 --port ${PORT:-8080}
```

- Copy only `requirements.txt` first and install the dependencies, **then** copy the code: most of the time you only change code, so the dependency layer keeps coming from the cache (run the code below to compare)
- `--host 0.0.0.0`: by default uvicorn listens only on `127.0.0.1`, which can't be reached from outside the container. `${PORT:-8080}`: use the port the platform gives, or 8080 if there is none. `exec` lets uvicorn receive the platform's stop signal directly
- `PYTHONUNBUFFERED=1`: logs from `print` come out right away instead of waiting in a buffer
- `.dockerignore` lists the files that stay out of the image: `.env` (secrets), `.git`, reports and caches
- On your computer: `docker build -t clausecheck-api .`, then `docker run -p 8080:8080 -e PORT=8080 clausecheck-api`
--- code
def rebuild(steps, changed):
    """Docker re-runs the first step whose inputs changed, and every step after it."""
    out, dirty = [], False
    for step, inputs in steps:
        dirty = dirty or any(f in changed for f in inputs)
        out.append(("REBUILD " if dirty else "cached  ") + step)
    return out

CODE = ["requirements.txt", "clausecheck/api.py", "clausecheck/review.py"]
GOOD = [
    ("FROM python:3.12-slim", []),
    ("COPY requirements.txt .", ["requirements.txt"]),
    ("RUN pip install -r requirements.txt   (~2 min)", []),
    ("COPY . .", CODE),
]
BAD = [
    ("FROM python:3.12-slim", []),
    ("COPY . .", CODE),
    ("RUN pip install -r requirements.txt   (~2 min)", []),
]
for name, steps in [("good order", GOOD), ("bad order", BAD)]:
    print(f"{name}, you edited review.py:")
    for line in rebuild(steps, {"clausecheck/review.py"}):
        print("  " + line)

title: Cloud Run: run your container, scale with requests
--- body
**Cloud Run** (GCP) runs your container image and handles HTTPS, machines and scaling for you. On AWS, the counterpart for running containers is ECS on Fargate (App Runner, common in older material, stopped accepting new customers at the end of April 2026, and AWS recommends moving to ECS Express Mode); Lambda is a different approach (next card). You only have to follow one rule: **listen on the port given by the environment variable `PORT`** (8080 by default), on the address `0.0.0.0`.

- **Scaling**: with no requests it can scale down to 0 instances (costing nothing); with more requests it adds instances automatically. `--max-instances` sets a ceiling, so a traffic spike doesn't turn into a bill spike
- **Concurrency**: one instance handles several requests at the same time (80 by default with 1 vCPU, and up to 1000). LLM calls spend most of their time waiting on the network, so high concurrency pays off
- **Cold start**: going from 0 to the first running instance makes the first requests wait a few extra seconds (longer when importing big packages like langgraph). `--min-instances 1` keeps one instance always on, at the cost of always paying for it
- **Request timeout**: 5 minutes by default, up to 60 minutes (the numbers when this lesson was written; the official docs have the final word)
- With the default settings, **CPU is given only while a request is being handled**: work that keeps running in the background after the response is sent can't be relied on

You only need to be able to read the deploy command (`--set-secrets` injects secrets from Secret Manager as environment variables):

```
gcloud run deploy clausecheck-api --source . --region europe-north1 \
  --service-account clausecheck-api@clausecheck-dev.iam.gserviceaccount.com \
  --set-secrets DEEPSEEK_API_KEY=deepseek-api-key:latest \
  --max-instances 5 --no-allow-unauthenticated
```
--- code
import math
import os

port = int(os.environ.get("PORT", "8080"))
print(f"uvicorn clausecheck.api:app --host 0.0.0.0 --port {port}")

def instances_needed(requests_per_second, seconds_per_request, concurrency=80):
    in_flight = requests_per_second * seconds_per_request     # requests being handled at the same moment
    return math.ceil(in_flight / concurrency)

print(instances_needed(2, 6))                    # 2 clause reviews per second, 6 s each (mostly waiting for the LLM)
print(instances_needed(50, 6))
print(instances_needed(50, 6, concurrency=1))    # one request per instance: many more instances

title: AWS Lambda: one event, one function call
--- body
**Lambda** doesn't run an always-on service. It runs **a function**: an event comes in, and the function is called once. The Python entry point looks like this:

```python
def lambda_handler(event, context):
    return {"statusCode": 200, "headers": {"Content-Type": "application/json"}, "body": json.dumps({...})}
```

- `event` is a dictionary whose shape depends on the service that triggered it: an S3 upload, an SQS message, an HTTP request forwarded by API Gateway…
- The event from API Gateway (the proxy integration of a REST API) has `httpMethod`, `path`, `headers` and `body`. **`body` is a string** (or possibly `None`), and you `json.loads` it yourself; when `isBase64Encoded` is true, you base64-decode it first. The newer event format of HTTP APIs uses different field names; check the docs
- The `body` in the return value **must be a string too**: `json.dumps(...)`, not a dictionary
- The timeout is 3 seconds by default and 15 minutes at most; you pay per call and per run time (multiplied by the memory size); it has cold starts too
- HTTP requests through API Gateway have their own limit: a REST API waits at most **29 seconds** by default (check the official docs). So the HTTP entry point only does fast things and hands slow work to a queue (next card)
- Code at the top level of the module (imports, creating clients, reading secrets) runs only once per instance, and later calls reuse it: keep clients and caches outside the function

In TypeScript (the Node.js runtime) it is written `export const handler = async (event) => { ... }` and returns an object of the same shape.
--- code
import json

def lambda_handler(event, context):
    body = json.loads(event.get("body") or "{}")
    clause_id = body.get("clause_id", "unknown")
    return {
        "statusCode": 200,
        "headers": {"Content-Type": "application/json"},
        "body": json.dumps({"clause_id": clause_id, "verdict": "flag"}),
    }

event = {
    "httpMethod": "POST",
    "path": "/review",
    "headers": {"Content-Type": "application/json"},
    "body": '{"clause_id": "8.1", "text": "Liability is unlimited."}',
    "isBase64Encoded": False,
}
resp = lambda_handler(event, None)
print(resp["statusCode"], type(resp["body"]).__name__)
print(resp["body"])
print(json.loads(resp["body"])["verdict"])

title: Events and queues: at-least-once delivery
cloud: yes
--- body
Reviewing a contract takes several minutes, so the upload request can't be kept waiting. The usual approach is to **hand the work to a queue**:

The contract is uploaded to a bucket → the bucket sends an "object created" **event** → the event becomes a **message** in a queue → a **worker** takes the message, runs the review and writes the report

- AWS: S3 event notification → SQS queue → a worker in Lambda or in a container
- GCP: GCS notification → Pub/Sub topic (or Eventarc) → a worker on Cloud Run

A queue (and S3 event notifications themselves) guarantees **at-least-once** delivery: the same message may arrive **more than once**, and SQS standard queues don't guarantee the order either. When an SQS message is taken, it first goes "invisible" for a while (the visibility timeout, 30 seconds by default); once the worker has processed it successfully, it **deletes** it (Pub/Sub calls this an ack). If it isn't deleted, it reappears when the time is up and goes to the next worker. That is a free automatic retry, but it also means:

- **Delete only after processing succeeds**. Delete first and process second, and if the worker crashes, the message is lost
- The worker must be **idempotent** (Day 17): record finished work under a fixed key (for example `job_id`), and skip a message that comes again
- A message that keeps failing can't be retried forever: set a maximum receive count, and past it the message moves to a **dead-letter queue** (DLQ) for a person to look at
- `receive_message` uses **short polling** by default: it returns right away and may come back empty even when the queue has messages. Workers usually add `WaitTimeSeconds=20` (**long polling**: wait up to 20 seconds, and return as soon as there is a message), which means fewer empty responses and lower cost

The boto3 / google-cloud on this page are simulated: the calls and the response shapes match the real SDKs (only the parts the course uses are implemented); in a real project, `pip install` them and set up credentials. `CLOUD.advance(seconds)` exists only in the simulation; it moves the simulated clock forward.
--- code
import json
import boto3

sqs = boto3.client("sqs", region_name="eu-north-1")
url = sqs.create_queue(QueueName="review-jobs")["QueueUrl"]
for cid in (103, 104):
    sqs.send_message(QueueUrl=url, MessageBody=json.dumps({"job_id": f"review-{cid}", "contract_id": cid}))

got = sqs.receive_message(QueueUrl=url, MaxNumberOfMessages=10, WaitTimeSeconds=20).get("Messages", [])
print("received:", [json.loads(m["Body"])["job_id"] for m in got])
sqs.delete_message(QueueUrl=url, ReceiptHandle=got[0]["ReceiptHandle"])   # 103 done; the worker crashed on 104
print("right away:", sqs.receive_message(QueueUrl=url).get("Messages", []))

CLOUD.advance(31)                                # simulation: 31 seconds pass, the visibility timeout is over
again = sqs.receive_message(QueueUrl=url, MessageSystemAttributeNames=["ApproximateReceiveCount"]).get("Messages", [])
for m in again:
    print("again:", json.loads(m["Body"])["job_id"], "receive count", m["Attributes"]["ApproximateReceiveCount"])

title: Managed models: Bedrock and Vertex AI
cloud: yes
--- body
Right now Clause Check calls DeepSeek directly. Many companies (especially with sensitive data like contracts) prefer a **managed model** inside their own cloud: **Bedrock** on AWS, **Vertex AI** (Gemini) on GCP. The reasons: the data stays in their own cloud account and in the regions they chose; IAM controls who can call which model, so there is no separate API key to look after; billing, logs and monitoring are all in one place.

The routine is the same as on Day 4: send messages, ask for JSON, validate, retry, record tokens.

- Bedrock's `converse` is one unified chat interface; to switch models you only change `modelId`. Each message's `content` is a **list of blocks** `[{"text": ...}]`; the system prompt goes separately in `system=[{"text": ...}]`, not in a system message; parameters go in `inferenceConfig` (camelCase: `maxTokens`). The answer is in `resp["output"]["message"]["content"]`, and a `stopReason` of `"max_tokens"` means it was cut off
- Newer models often have to be called with the ID of an **inference profile**: for example, an ID starting with `eu.` routes only between EU regions; one starting with `global.` may send the request to any region in the world, so don't use it for contract data
- google-genai: `genai.Client(vertexai=True, project=..., location=...)`. Without `location` the default is `global`; to process in the EU, name an EU region explicitly (which models are available in which regions: check the Vertex AI docs). Its errors are its own `google.genai.errors.APIError` (`e.code` is 429, 503…), and it **doesn't retry by default**
- Names change: in April 2026 Vertex AI was renamed Gemini Enterprise Agent Platform (the API didn't change; the docs for newer google-genai versions write `enterprise=True`, and `vertexai=True` still works). Model IDs go out of date too: `eu.amazon.nova-lite-v1:0` and `gemini-2.5-flash` below are only examples (Google has already announced retirement dates in 2026 for the gemini-2.5 series). Before you write code, look up the names you can use today in the model lists of the Bedrock console and the Google Cloud console, and put them in configuration instead of hard-coding them

Bedrock and Gemini on this page are simulated: when the request mentions JSON, they give a verdict with keyword rules similar to the simulated DeepSeek (for example `unlimited` → redline / high).
--- code
import json
import boto3
from google import genai
from google.genai import types

SYSTEM = "You review contract clauses. Reply with JSON: clause_id, verdict, risk_level."
CLAUSE = "Review clause 8.1: Liability of the Customer is unlimited."

bedrock = boto3.client("bedrock-runtime", region_name="eu-north-1")
resp = bedrock.converse(
    modelId="eu.amazon.nova-lite-v1:0",
    system=[{"text": SYSTEM}],
    messages=[{"role": "user", "content": [{"text": CLAUSE}]}],
    inferenceConfig={"maxTokens": 300, "temperature": 0},
)
print(resp["stopReason"], resp["usage"])
print(json.loads(resp["output"]["message"]["content"][0]["text"]))

gemini = genai.Client(vertexai=True, project="clausecheck-dev", location="europe-north1")
r = gemini.models.generate_content(
    model="gemini-2.5-flash",
    contents=CLAUSE,
    config=types.GenerateContentConfig(system_instruction=SYSTEM, response_mime_type="application/json", temperature=0),
)
print(r.usage_metadata.prompt_token_count, r.usage_metadata.candidates_token_count)
print(json.loads(r.text))

title: Structured logs and alerts
--- body
In production, nobody watches the terminal. The service writes its logs to **standard output**, and the platform collects them automatically: Cloud Run's go to Cloud Logging, Lambda's go to CloudWatch Logs.

Logs should be **one JSON object per line** (structured logs), not a quick `print("done 8.1")`: only then can you query and count by field, for example "how many ERRORs in the past hour" or "what is the average latency of the v2 prompt".

- Every line carries `severity` (INFO / WARNING / ERROR) and `message`, plus the fields you need for debugging: `trace_id`, `contract_id`, `clause_id`, `tokens`, `latency_ms`
- Cloud Logging recognizes `severity` and `message` in the JSON and uses them as the entry's level and text; CloudWatch Logs Insights can query by JSON field too
- `json.dumps(..., sort_keys=True)` fixes the field order: tidy for people to read, and easy to compare
- **Don't** log full contract text, personal data or secrets: logs are kept for a long time, and many people can read them

Once you have logs, set up **alerts**: notify a person when the error rate, the p95 latency or the daily token spend goes over a threshold.
--- code
import json

def log(severity, message, **fields):
    print(json.dumps({"severity": severity, "message": message, **fields}, sort_keys=True))

log("INFO", "clause reviewed", trace_id="t-7f3a", contract_id=103, clause_id="8.1", verdict="redline", tokens=2205, latency_ms=3563)
log("ERROR", "model call failed", trace_id="t-9c1d", contract_id=109, clause_id="8.1", error="ThrottlingException")

lines = [
    '{"severity": "INFO", "latency_ms": 1296}',
    '{"severity": "ERROR", "latency_ms": 30000}',
    '{"severity": "INFO", "latency_ms": 3563}',
    '{"severity": "INFO", "latency_ms": 2149}',
]
records = [json.loads(line) for line in lines]
errors = sum(1 for r in records if r["severity"] == "ERROR")
print(f"error rate {errors / len(records):.0%}, slowest {max(r['latency_ms'] for r in records)} ms")

title: Launch checklist and rollback
--- body
Go through this list before you launch. When an interviewer asks "how would you deploy it?", answer in this order too:

1. **Secrets** are not in the code or the image; they come from Secret Manager / Secrets Manager
2. The **runtime identity** is a dedicated service account / role with least privilege (Day 26)
3. The **region** is in the EU: the service, the buckets, the logs and the model calls all are
4. **Limits**: maximum number of instances, step and token limits per clause (Day 17), budget alerts
5. **Observability**: structured logs, alerts on error rate and latency, tracing (Langfuse)
6. **Rollback**: every Cloud Run deploy creates a new **revision**. You can first send 10% of the traffic to the new revision to try it, and if something goes wrong, switch back to the old one without rebuilding (`gcloud run services update-traffic`); Lambda does the same with versions plus aliases. Give the image a fixed tag, not `latest`
7. **Health check**: `/health` answers

Explaining an architecture in two minutes: what it does → how requests flow (upload → queue → worker → report) → where the data lives and who can access it → what happens on failure (retries, idempotency, dead-letter queue) → what it costs and where the limits are.
--- code
def route(traffic):
    return ", ".join(f"{rev}: {pct}%" for rev, pct in traffic.items())

traffic = {"clausecheck-api-00012": 100}
print("before:  ", route(traffic))
traffic = {"clausecheck-api-00012": 90, "clausecheck-api-00013": 10}   # canary: 10% try the new revision
print("canary:  ", route(traffic))

error_rate = {"clausecheck-api-00012": 0.004, "clausecheck-api-00013": 0.09}   # from the structured logs
if error_rate["clausecheck-api-00013"] > 2 * error_rate["clausecheck-api-00012"]:
    traffic = {"clausecheck-api-00012": 100}   # roll back: no rebuild, just move the traffic
    print("rollback:", route(traffic))

messages = [
    {"job_id": "review-103", "clause": "8.1"},
    {"job_id": "review-104", "clause": "3.1"},
    {"job_id": "review-103", "clause": "8.1"},

--- explain

import json

def review_clause(clause_id, text):
    """The real one calls the LLM. Tests pass their own."""
    return {"clause_id": clause_id, "verdict": "flag", "risk_level": "medium"}

def respond(status, payload):
    return {"statusCode": status, "headers": {"Content-Type": "application/json"}, "body": json.dumps(payload)}

def lambda_handler(event, context, review=review_clause):
    try:
        data = json.loads(event.get("body") or "")
    except json.JSONDecodeError:
        return respond(400, {"error": "body must be a JSON object"})
    if not isinstance(data, dict):
        return respond(400, {"error": "body must be a JSON object"})
    text = data.get("text")
    if not isinstance(text, str) or not text.strip():
        return respond(400, {"error": "text is required"})
    return respond(200, review(data.get("clause_id", "unknown"), text))

def parse_s3_event(event):

import json

def process_batch(sqs, queue_url, handle, seen):
    counts = {"done": 0, "skipped": 0, "failed": 0}
    resp = sqs.receive_message(QueueUrl=queue_url, MaxNumberOfMessages=10)
    for msg in resp.get("Messages", []):
        job = json.loads(msg["Body"])
        if job["job_id"] in seen:
            sqs.delete_message(QueueUrl=queue_url, ReceiptHandle=msg["ReceiptHandle"])
            counts["skipped"] += 1
            continue
        try:
            handle(job)
        except Exception:
            counts["failed"] += 1
            continue
        seen.add(job["job_id"])
        sqs.delete_message(QueueUrl=queue_url, ReceiptHandle=msg["ReceiptHandle"])
        counts["done"] += 1
    return counts

import json
from google.genai import types, errors

SYSTEM = "You review contract clauses against a playbook. Reply with JSON: clause_id, verdict, risk_level."

def review_with_gemini(client, clause_id, text, sleep, model="gemini-2.5-flash"):
    config = types.GenerateContentConfig(system_instruction=SYSTEM, response_mime_type="application/json", temperature=0)
    for attempt in range(3):
        try:
            response = client.models.generate_content(model=model, contents=f"Review clause {clause_id}: {text}", config=config)
            break
        except errors.APIError as e:
            if e.code not in (429, 503) or attempt == 2:
                raise
            sleep(attempt + 1)
    if response.text is None:
        raise ValueError("empty response")
    data = json.loads(response.text)
    usage = response.usage_metadata
    return {"clause_id": data["clause_id"], "verdict": data["verdict"], "risk_level": data["risk_level"],
            "tokens": usage.prompt_token_count + usage.candidates_token_count}

- Put it in Cloud Run, raise the request timeout to 60 minutes, and have the front end keep waiting
- After the upload, send a message to a queue; a worker (Cloud Run or Lambda, either works) handles one contract or a few clauses at a time and writes progress and results to a database or bucket; the front end checks the progress

The second works but is fragile. The fourth: with Cloud Run's default settings, an instance gets almost no CPU after it returns the response, and the instance can be reclaimed at any time, so the work in the background thread is silently lost.

import { z } from "zod";

type ApiEvent = { httpMethod: string; path: string; headers: Record<string, string>; body: string | null; isBase64Encoded: boolean };
type ApiResult = { statusCode: number; headers: Record<string, string>; body: string };

const ReviewRequest = z.object({
  clause_id: z.string().default("unknown"),
  text: z.string().min(1),
});

function reviewClause(text: string): "accept" | "flag" | "redline" {
  return /unlimited/i.test(text) ? "redline" : "accept";
}

function respond(statusCode: number, payload: unknown): ApiResult {
  return { statusCode, headers: { "Content-Type": "application/json" }, body: JSON.stringify(payload) };
}

export const handler = async (event: ApiEvent): Promise<ApiResult> => {
  if (event.httpMethod !== "POST") {
    return respond(405, { error: "method not allowed" });
  }
  if (event.body === null) {
    return respond(400, { error: "body must be JSON" });
  }
  let raw: unknown;
  try {
    raw = JSON.parse(event.body);
  } catch {
    return respond(400, { error: "body must be JSON" });
  }
  const r = ReviewRequest.safeParse(raw);
  if (!r.success) {
    return respond(400, { error: "invalid request" });
  }
  return respond(200, { clause_id: r.data.clause_id, verdict: reviewClause(r.data.text) });
};

import base64
import json

def review_clause(clause_id, text):
    return {"clause_id": clause_id, "verdict": "accept"}

def respond(status, payload):
    return {"statusCode": status, "headers": {"Content-Type": "application/json"}, "body": json.dumps(payload)}

def lambda_handler(event, context, review=review_clause):
    if event.get("path") != "/review":
        return respond(404, {"error": "not found"})
    if event.get("httpMethod") != "POST":
        return respond(405, {"error": "method not allowed"})
    body = event.get("body")
    if body is not None and event.get("isBase64Encoded"):
        body = base64.b64decode(body).decode("utf-8")
    try:
        data = json.loads(body or "")
    except json.JSONDecodeError:
        return respond(400, {"error": "body must be a JSON object"})
    if not isinstance(data, dict):
        return respond(400, {"error": "body must be a JSON object"})
    text = data.get("text")
    clause_id = data.get("clause_id", "unknown")
    if not isinstance(text, str) or not text.strip() or not isinstance(clause_id, str):
        return respond(400, {"error": "invalid request"})
    try:
        result = review(clause_id, text)
    except Exception:
        return respond(502, {"error": "review failed"})
    return respond(200, result)

  2. The message's `msg["Attributes"]["ApproximateReceiveCount"]` (note: a **string**), converted to an integer, is greater than 3: this is a "poison message" that keeps failing; append the raw `Body` to the list `dead` (a simulated dead-letter queue), delete the message and don't process it

import json

def drain(sqs, queue_url, handle, done, dead):
    finished = []
    for _ in range(10):
        resp = sqs.receive_message(QueueUrl=queue_url, MaxNumberOfMessages=10, WaitTimeSeconds=20,
                                   MessageSystemAttributeNames=["ApproximateReceiveCount"])
        messages = resp.get("Messages", [])
        if not messages:
            break
        for msg in messages:
            job = json.loads(msg["Body"])
            receipt = msg["ReceiptHandle"]
            if job["job_id"] in done:
                sqs.delete_message(QueueUrl=queue_url, ReceiptHandle=receipt)
                continue
            if int(msg["Attributes"]["ApproximateReceiveCount"]) > 3:
                dead.append(msg["Body"])
                sqs.delete_message(QueueUrl=queue_url, ReceiptHandle=receipt)
                continue
            try:
                handle(job)
            except Exception:
                continue
            done.add(job["job_id"])
            sqs.delete_message(QueueUrl=queue_url, ReceiptHandle=receipt)
            finished.append(job["job_id"])
    return finished

import json
from botocore.exceptions import ClientError

RETRY_CODES = ("ThrottlingException", "ServiceUnavailableException")
VERDICTS = ("accept", "flag", "redline")

def review_clause_bedrock(client, clause_id, text, sleep):
    for i in range(4):
        try:
            resp = client.converse(
                modelId="eu.amazon.nova-lite-v1:0",
                system=[{"text": "Reply with JSON only: clause_id, verdict, risk_level."}],
                messages=[{"role": "user", "content": [{"text": f"Review clause {clause_id}: {text}"}]}],
                inferenceConfig={"maxTokens": 200, "temperature": 0},
            )
            break
        except ClientError as e:
            if e.response["Error"]["Code"] not in RETRY_CODES or i == 3:
                raise
            sleep(2 ** i)
    fallback = {"clause_id": clause_id, "verdict": "flag", "risk_level": "medium", "fallback": True}
    if resp["stopReason"] == "max_tokens":
        return fallback
    try:
        data = json.loads(resp["output"]["message"]["content"][0]["text"])
    except json.JSONDecodeError:
        return fallback
    if data.get("verdict") not in VERDICTS:
        return fallback
    return {"clause_id": clause_id, "verdict": data["verdict"], "risk_level": data.get("risk_level"), "fallback": False}
