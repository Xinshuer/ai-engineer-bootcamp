@@ concept
title: with_structured_output: get an object back directly
--- body
On Day 12 you did this by hand: `json_object` mode + field descriptions written into the prompt + Pydantic validation + ask again on failure. In LangChain it is one line:

```python
reviewer = model.with_structured_output(ClauseReview)
review = reviewer.invoke("Review clause 8.1: ...")   # a ClauseReview object
```

How does it do that? Look at the request body: by default ChatDeepSeek turns `ClauseReview` into a **tool**, puts it in `tools`, and uses `tool_choice` to **force** the model to call it; the arguments the model fills in are the fields you want, and LangChain then validates them with Pydantic. So the class docstring becomes the tool description, `Field(description=...)` becomes the field description, and `Literal` becomes `enum`: all of these are prompt text written for the model.

All of today's review and tool code turns thinking mode off; the reason is in card 4.
--- code
from typing import Literal
from pydantic import BaseModel, Field
from langchain_deepseek import ChatDeepSeek

class ClauseReview(BaseModel):
    """Review of one contract clause against the customer's playbook."""
    clause_id: str = Field(description="Clause number, e.g. 8.1")
    verdict: Literal["accept", "flag", "redline"]
    risk_level: Literal["low", "medium", "high"]
    rationale: str = Field(description="One sentence that quotes the clause")

model = ChatDeepSeek(model="deepseek-flash", extra_body={"thinking": {"type": "disabled"}})
reviewer = model.with_structured_output(ClauseReview)
review = reviewer.invoke("Review clause 8.1: Customer's liability shall be unlimited.")

print(review.rationale)

@@ concept
title: method, include_raw, and None
--- body
- `method="json_mode"`: uses `response_format: {"type": "json_object"}` instead (Day 12's approach). Then the prompt must contain the word "json" and describe the fields; if the model adds chatter before the JSON (this page simulates that with `[bad-json]`), it raises `OutputParserException`
- `include_raw=True`: returns a dict `{"raw": AIMessage, "parsed": object or None, "parsing_error": exception or None}`, so on failure you can still see the model's raw answer and write it to the log
- **Pitfall** (true for this page's langchain-core 1.6): with the default tool method, when the model's arguments are broken JSON (this page simulates that with `[bad-args]`), `invoke` **does not raise; it just returns `None`**. With `include_raw=True`, `parsed` is None and `parsing_error` is **also** None; the broken arguments sit in `raw.invalid_tool_calls`

So check the result for None first, or the very next line, `review.verdict`, is an `AttributeError`. What if you can't get a valid result? The same as `review.py`: verdict flag, hand it to a person, never treat it as accept.
--- code
from typing import Literal
from pydantic import BaseModel
from langchain_deepseek import ChatDeepSeek

class ClauseReview(BaseModel):
    """Review of one contract clause."""
    clause_id: str
    verdict: Literal["accept", "flag", "redline"]
    risk_level: Literal["low", "medium", "high"]

model = ChatDeepSeek(model="deepseek-flash", extra_body={"thinking": {"type": "disabled"}})

json_mode = model.with_structured_output(ClauseReview, method="json_mode")
print("json_mode:", json_mode.invoke("Review clause 10.1: data may go to any country. Reply in JSON."))
print("  request:", MOCK.calls[-1]["body"]["response_format"])

raw = model.with_structured_output(ClauseReview, include_raw=True)
ok = raw.invoke("Review clause 3.1: Fees are due in 30 days.")
print("include_raw:", sorted(ok), "| parsed:", ok["parsed"])

bad = raw.invoke("Review clause 3.1 [bad-args]: Fees are due in 30 days.")
print("bad args: parsed =", bad["parsed"], "| parsing_error =", bad["parsing_error"])
print("  tool_calls:", bad["raw"].tool_calls, "| invalid:", len(bad["raw"].invalid_tool_calls))
print("without include_raw:", model.with_structured_output(ClauseReview).invoke("Review clause 3.1 [bad-args]: Fees."))

@@ concept
title: @tool: turn a function into a tool
--- body
The `@tool` decorator turns an ordinary function into a tool (a `StructuredTool` object):

- name = the function name; description = the **docstring** (a function without a docstring raises `ValueError` right away, because the description is all the model has to decide whether to use the tool); the parameter schema comes from the type annotations and default values
- `convert_to_openai_tool(t)`: shows the JSON the model receives, the same kind of thing that `tool_specs()` in Day 12's `tools.py` generates
- `t.invoke({"topic": "payment"})`: validates the arguments against the schema first, then calls the function; wrong arguments raise pydantic's `ValidationError`

How to write the description is the same lesson as Day 12's `mark_for_review`: say clearly when to use it, what happens, and when **not** to use it.
--- code
from langchain_core.tools import tool
from langchain_core.utils.function_calling import convert_to_openai_tool
from pydantic import ValidationError

@tool
def lookup_playbook(topic: str, max_rules: int = 3) -> str:
    """Return the customer's playbook rules for one contract topic, e.g. liability_cap or payment."""
    return f"{max_rules} rules for {topic}"

print(type(lookup_playbook).__name__, "|", lookup_playbook.name)
print(lookup_playbook.description)
print(lookup_playbook.args)
print(convert_to_openai_tool(lookup_playbook)["function"]["parameters"])
print(lookup_playbook.invoke({"topic": "payment"}))
try:
    lookup_playbook.invoke({"topik": "payment"})
except ValidationError as e:
    print("ValidationError:", e.errors()[0]["loc"], e.errors()[0]["msg"])

try:
    @tool
    def get_clause(clause_id: str) -> str:
        return clause_id
except ValueError as e:
    print("ValueError:", e)

@@ concept
title: bind_tools and tool_calls
--- body
`model.bind_tools([tool, ...])` returns a model that "carries the tool definitions". When the model wants to call a tool, the `AIMessage` it returns has:

- `.content`, usually an empty string; `.tool_calls = [{"name", "args", "id", "type": "tool_call"}]`, where `args` is already a dict (LangChain did the `json.loads` for you)
- To run it: `tool.invoke(call)`, passing in the **whole** call, gives you a `ToolMessage` whose `tool_call_id` already matches
- The messages of the next request: …, that AIMessage, then one ToolMessage per call. If one is missing or an id doesn't match, the real API returns 400 (Day 17's rule), and so does this page's mock server

**Thinking mode and tools**: DeepSeek's docs say that for requests with `tools` in thinking mode, the thinking content (`reasoning_content`) of every earlier assistant message must be sent back in later requests, or the API returns 400. ChatDeepSeek does not send it back (true for the langchain-deepseek 1.1 on this page; later versions may change this), so a tool loop with thinking on breaks this rule on its second request. Tested in 2026-09, the real API does not reject it yet, but the docs say so, and the API could start checking at any time; this page's mock server follows the docs and returns 400 (shown at the end of the example). Turn thinking off for tool loops and agents: it works, it's faster, and it's cheaper. `with_structured_output` also sends tools, so turn it off there too: it makes only one request, so it can't hit this 400 for now, but it will once you make it multi-turn, and thinking is billed at the output price.
--- code
import openai
from langchain_core.messages import HumanMessage
from langchain_core.tools import tool
from langchain_deepseek import ChatDeepSeek

@tool
def lookup_playbook(topic: str) -> str:
    """Return the customer's playbook rule for one contract topic."""
    return f"rule for {topic}: cap at 12 months of fees"

model = ChatDeepSeek(model="deepseek-flash", extra_body={"thinking": {"type": "disabled"}})
llm = model.bind_tools([lookup_playbook])

messages = [HumanMessage("Is unlimited liability acceptable?")]
ai = llm.invoke(messages)
print("content:", repr(ai.content), "| finish:", ai.response_metadata["finish_reason"])
print("tool_calls:", ai.tool_calls)
print("tools sent:", [t["function"]["name"] for t in MOCK.calls[-1]["body"]["tools"]])

tool_msg = lookup_playbook.invoke(ai.tool_calls[0])
print(type(tool_msg).__name__, "|", tool_msg.tool_call_id, "|", tool_msg.content)

messages += [ai, tool_msg]
final = llm.invoke(messages)
print("final:", final.content)
print("roles sent:", [m["role"] for m in MOCK.calls[-1]["body"]["messages"]])

thinking_llm = ChatDeepSeek(model="deepseek-flash").bind_tools([lookup_playbook])   # thinking on
first = thinking_llm.invoke(messages[:1])
try:
    thinking_llm.invoke([messages[0], first, lookup_playbook.invoke(first.tool_calls[0])])
except openai.BadRequestError as e:
    print("thinking on, 2nd request:", e.status_code, e.body["message"][:70])

@@ concept
title: Writing the tool loop yourself
--- body
It is the same loop as Day 17; only the messages are now LangChain classes:

```python
for step in range(1, max_steps + 1):
    ai = llm.invoke(messages)
    messages.append(ai)
    if not ai.tool_calls:
        return ai.content
    for call in ai.tool_calls:
        messages.append(TOOLS[call["name"]].invoke(call))
```

Two things to watch:

- **Broken arguments**: when the model's arguments are not valid JSON, that call is not in `tool_calls` but in `ai.invalid_tool_calls` (and `finish_reason` is still `tool_calls`). The loop above would think the model is done and return an empty answer. The right way: reply to every broken call with an error ToolMessage too; the error is written for the model (Day 17, `INVALID_ARGS` in `review.py`)
- **Limit**: the model may keep calling tools forever (this page's `[loop]`), so you always need `max_steps`

Day 31's `create_agent` and the agent you build with LangGraph on Day 33 run exactly this loop inside.
--- code
from langchain_core.messages import HumanMessage
from langchain_core.tools import tool
from langchain_deepseek import ChatDeepSeek

@tool
def lookup_playbook(topic: str) -> str:
    """Return the customer's playbook rule for one contract topic."""
    return f"rule for {topic}"

TOOLS = {"lookup_playbook": lookup_playbook}
llm = ChatDeepSeek(model="deepseek-flash", extra_body={"thinking": {"type": "disabled"}}).bind_tools(list(TOOLS.values()))

def naive_loop(question, max_steps=3):
    messages = [HumanMessage(question)]
    for step in range(1, max_steps + 1):
        ai = llm.invoke(messages)
        messages.append(ai)
        if not ai.tool_calls:
            return f"answer after {step} step(s): {ai.content!r}"
        for call in ai.tool_calls:
            messages.append(TOOLS[call["name"]].invoke(call))
    return f"stopped after {max_steps} steps"

print(naive_loop("Is unlimited liability acceptable?"))
print(naive_loop("Is unlimited liability acceptable? [loop]"))
print(naive_loop("Is unlimited liability acceptable? [bad-args]"))
print("  invalid_tool_calls:", [c["name"] for c in llm.invoke("Is unlimited liability acceptable? [bad-args]").invalid_tool_calls])

@@ concept
title: Fault tolerance: retries and fallback models
--- body
- **The SDK's built-in retries**: under ChatDeepSeek is the openai SDK, which retries on its own on 429, 5xx and connection failures: by default 2 more times (3 in total), with exponentially growing waits plus random jitter in between; you can change it with `ChatDeepSeek(..., max_retries=5)`. This page doesn't really wait; it records each wait in `MOCK.sleeps` (the values are random, only count them)
- When the retries run out, it raises an openai exception: `openai.RateLimitError` (429), `openai.InternalServerError` (500 and above), `openai.BadRequestError` (400: your request is wrong, so it is not retried). They are all subclasses of `openai.APIStatusError` and have `.status_code`. The class names you see in a traceback are subclasses that langchain-openai (1.6 on this page) wraps around them (for example `OpenAIRateLimitError`, `OpenAIAPIError`); they inherit from these openai exceptions, so `except openai.RateLimitError` still catches them
- **Your own unreliable steps** (for example calling an internal service that sometimes can't be reached): `RunnableLambda(fn).with_retry(stop_after_attempt=3, retry_if_exception_type=(ConnectionError,))` retries only the exceptions you list. By default it waits exponentially longer between attempts; in tests, use `wait_exponential_jitter=False` so it doesn't wait
- **Fallback model**: `primary.with_fallbacks([backup])`: when primary raises (after its own retries run out), it switches to backup, for example flash → v4-pro. Use `exceptions_to_handle=(...)` to limit which errors cause a switch: a 400 is your bug, and switching models would only hide it
- Timeout: `ChatDeepSeek(..., timeout=30)`
--- code
import openai
from langchain_core.runnables import RunnableLambda
from langchain_deepseek import ChatDeepSeek

OFF = {"thinking": {"type": "disabled"}}
flash = ChatDeepSeek(model="deepseek-flash", extra_body=OFF)

MOCK.fail_next(429, 2)
print("429 x2:", flash.invoke("hi").content, "| requests", len(MOCK.calls), "| waits", len(MOCK.sleeps))

MOCK.reset()
MOCK.fail_next(503, 3)
try:
    flash.invoke("hi")
except openai.InternalServerError as e:
    print("503 x3: gave up,", e.status_code, "| requests", len(MOCK.calls))

safe = flash.with_fallbacks(
    [ChatDeepSeek(model="deepseek-v4-pro", extra_body=OFF)],
    exceptions_to_handle=(openai.RateLimitError, openai.InternalServerError),
)
MOCK.reset()
MOCK.fail_next(503, 3)
print("fallback:", safe.invoke("hi").content, [c["body"]["model"] for c in MOCK.calls])
MOCK.reset()
MOCK.fail_next(400, 1)
try:
    safe.invoke("hi")
except openai.BadRequestError as e:
    print("400: no fallback,", e.status_code, [c["body"]["model"] for c in MOCK.calls])

attempts = []
def flaky_lookup(topic):
    attempts.append(topic)
    if len(attempts) < 3:
        raise ConnectionError("playbook service unreachable")
    return f"rule for {topic}"

lookup = RunnableLambda(flaky_lookup).with_retry(stop_after_attempt=3, retry_if_exception_type=(ConnectionError,), wait_exponential_jitter=False)
print("with_retry:", lookup.invoke("payment"), "after", len(attempts), "attempts")

@@ concept
title: Observability: callbacks
--- body
Before and after every model call, LangChain notifies the **callbacks** (callback handlers). Counting tokens, timing calls, and reporting a whole chain to a tracing platform all work through them.

- Counting usage: inside `with get_usage_metadata_callback() as cb:`, the tokens of all calls are added up per model name; look at `cb.usage_metadata`
- Writing your own: subclass `BaseCallbackHandler` and implement `on_chat_model_start(serialized, messages, **kwargs)`, `on_llm_end(response, **kwargs)`, `on_llm_error(error, **kwargs)`
- Pitfall: by default, an exception raised inside a callback does **not** make the call fail; LangChain only logs one line, `Error in ... callback` (`raise_error` defaults to False). A buggy callback easily goes unnoticed, so in tests set `handler.raise_error = True`
- Passing them to one call: `chain.invoke(x, config={"callbacks": [h], "tags": ["review"], "metadata": {"clause_id": "8.1"}})`. Callbacks are passed down the whole chain, and tags and metadata reach every step too (LangChain also adds a few tags of its own, for example `seq:step:2`, which says which step of the chain this is)

This is how tracing platforms plug in: LangSmith tracing is itself a callback (`LangChainTracer`); once you set the environment variable `LANGSMITH_TRACING=true` and its API key, LangChain adds it automatically. Langfuse also provides a callback for LangChain (check its docs for the import path). Clause Check doesn't use LangChain, so `tracing.py` uses Langfuse's `@observe` decorator, which does nothing when no key is configured.
--- code
from langchain_core.callbacks import BaseCallbackHandler, get_usage_metadata_callback
from langchain_core.output_parsers import StrOutputParser
from langchain_core.prompts import ChatPromptTemplate
from langchain_deepseek import ChatDeepSeek

model = ChatDeepSeek(model="deepseek-flash", extra_body={"thinking": {"type": "disabled"}})
chain = ChatPromptTemplate.from_messages([("user", "Review clause {clause_id}: {text}")]) | model | StrOutputParser()

with get_usage_metadata_callback() as cb:
    chain.invoke({"clause_id": "3.1", "text": "Fees are due in 30 days."})
    chain.invoke({"clause_id": "8.1", "text": "Liability is unlimited."})
print(cb.usage_metadata)

class PrintCalls(BaseCallbackHandler):
    def on_chat_model_start(self, serialized, messages, *, tags=None, metadata=None, **kwargs):
        print(f"  start: {len(messages[0])} message(s), tags={tags}, clause={metadata.get('clause_id')}")

    def on_llm_end(self, response, **kwargs):
        usage = response.generations[0][0].message.usage_metadata
        print(f"  end:   {usage['total_tokens']} tokens")

    def on_llm_error(self, error, **kwargs):
        print(f"  error: {error.status_code}")

config = {"callbacks": [PrintCalls()], "tags": ["review"], "metadata": {"clause_id": "3.1"}}
chain.invoke({"clause_id": "3.1", "text": "Fees are due."}, config=config)
MOCK.reset()
MOCK.fail_next(503, 3)
try:
    model.invoke("hi", config={"callbacks": [PrintCalls()], "metadata": {}})
except Exception:
    print(f"  (the SDK sent {len(MOCK.calls)} requests; the callback saw one call and one error)")

@@ concept
title: Cost: calculate it from usage
--- body
DeepSeek's current prices (official pricing page, September 2026, USD per million tokens): `deepseek-flash` at peak hours: input with a cache hit 0.006, cache miss 0.30, output 1.20; `deepseek-v4-pro`: 0.044, 1.32 and 3.96. Off-peak hours are half price. Peak hours: Monday to Friday, UTC 01:00–04:00 and 06:00–10:00 (except Chinese public holidays); every other time is off-peak.

```
cost = (cache_read × hit price + (input_tokens − cache_read) × miss price + output_tokens × output price) / 1_000_000
```

- `input_tokens` **already includes** the cache-hit part, so the misses = input − cache_read
- Thinking tokens count as `output_tokens` and are billed at the **output price**. A review thinks for a few hundred tokens, which costs several times more than the answer itself; this is why classification and review turn thinking off
- Prices change fast: put them in config, and check the official pricing page before you quote a number (`PRICES` in the project's `config.py` holds the 2026-09 peak prices; update it when DeepSeek changes its prices)
--- code
from langchain_deepseek import ChatDeepSeek

PRICE = {"hit": 0.006, "miss": 0.30, "output": 1.20}   # deepseek-flash, peak, USD per 1M tokens

def cost(usage, peak=True):
    hit = usage["input_token_details"].get("cache_read", 0)
    miss = usage["input_tokens"] - hit
    usd = (hit * PRICE["hit"] + miss * PRICE["miss"] + usage["output_tokens"] * PRICE["output"]) / 1_000_000
    return usd if peak else usd / 2

SYSTEM = "You review contract clauses for the Customer against the playbook. " * 8
on = ChatDeepSeek(model="deepseek-flash")
off = ChatDeepSeek(model="deepseek-flash", extra_body={"thinking": {"type": "disabled"}})

def show(name, model):
    u = model.invoke([("system", SYSTEM), ("user", "Review clause 8.1: liability is unlimited.")]).usage_metadata
    print(f"{name}: input {u['input_tokens']} (cache {u['input_token_details']['cache_read']}), "
          f"output {u['output_tokens']} (reasoning {u['output_token_details'].get('reasoning', 0)}) "
          f"-> ${cost(u):.7f} peak, ${cost(u, peak=False):.7f} off-peak, ${1000 * cost(u):.4f} per 1000 clauses")

show("thinking on ", on)
MOCK.reset()                  # clear the prefixes the mock server remembers, for a fair comparison
show("thinking off", off)
show("off + cache ", off)     # the same beginning once more: a cache hit

from typing import Literal
from pydantic import BaseModel, Field
from langchain_deepseek import ChatDeepSeek

class RiskOnly(BaseModel):
    """Risk of one clause."""
    risk_level: Literal["low", "medium", "high"]
    reason: str = Field(description="Why, in one sentence")

model = ChatDeepSeek(model="deepseek-flash", extra_body={"thinking": {"type": "disabled"}})
result = model.with_structured_output(RiskOnly).invoke("Clause 4.2 renews for twenty-four months.")
body = MOCK.calls[-1]["body"]
fn = body["tools"][0]["function"]
print(fn["name"], "|", fn["description"])
print(fn["parameters"]["properties"]["risk_level"])
print(fn["parameters"]["required"])
print(body["tool_choice"])
print(type(result).__name__, result.risk_level, "|", result.reason)
--- explain
The tool name is the class name, and the description is the docstring; `Literal` becomes `enum`; neither field has a default value, so both are in `required`. `tool_choice` asks for this function by name, so the model can neither skip the call nor call something else. The fields' `description` is sent to the model too; it just isn't printed here. Writing it clearly matters as much as writing a clear tool description.

--- starter
from typing import Literal
from pydantic import BaseModel, Field

from typing import Literal
from pydantic import BaseModel

class ClauseReview(BaseModel):
    """Review of one contract clause."""
    clause_id: str
    verdict: Literal["accept", "flag", "redline"]
    risk_level: Literal["low", "medium", "high"]
    rationale: str

FALLBACK = "Automatic review did not complete; needs human review."

def safe_review(model, clause_id, text):
    reviewer = model.with_structured_output(ClauseReview, include_raw=True)
    result = reviewer.invoke(f"Review clause {clause_id}: {text}")
    review = result["parsed"]

    return review

from langchain_core.messages import ToolMessage

def run_tools(ai_message, tools):
    by_name = {t.name: t for t in tools}
    results = []
    for call in ai_message.tool_calls:
        tool = by_name.get(call["name"])
        if tool is None:
            results.append(ToolMessage(f"UNKNOWN_TOOL: {call['name']}", tool_call_id=call["id"], status="error"))
            continue
        try:
            results.append(tool.invoke(call))
        except Exception as e:
            results.append(ToolMessage(f"ERROR: {type(e).__name__}: {e}", tool_call_id=call["id"], status="error"))
    for bad in ai_message.invalid_tool_calls:
        results.append(ToolMessage("INVALID_ARGS: arguments are not valid JSON", tool_call_id=bad["id"], status="error"))
    return results

    messages = [HumanMessage(question)]

from langchain_core.callbacks import BaseCallbackHandler

class CallLog(BaseCallbackHandler):
    def __init__(self):
        super().__init__()
        self.calls = 0
        self.errors = 0
        self.tokens = 0
        self.clause_ids = []

    def on_chat_model_start(self, serialized, messages, **kwargs):
        self.calls += 1
        self.clause_ids.append((kwargs.get("metadata") or {}).get("clause_id"))

    def on_llm_end(self, response, **kwargs):
        usage = response.generations[0][0].message.usage_metadata or {}
        self.tokens += usage.get("total_tokens", 0)

    def on_llm_error(self, error, **kwargs):
        self.errors += 1

PRICES = {
    "deepseek-flash": {"hit": 0.006, "miss": 0.30, "output": 1.20},
    "deepseek-v4-pro": {"hit": 0.044, "miss": 1.32, "output": 3.96},
}

def cost_of(usage, model="deepseek-flash", peak=True):
    if not usage:
        return 0.0
    p = PRICES[model]
    hit = (usage.get("input_token_details") or {}).get("cache_read", 0)
    miss = usage["input_tokens"] - hit
    usd = (hit * p["hit"] + miss * p["miss"] + usage["output_tokens"] * p["output"]) / 1_000_000
    if not peak:
        usd /= 2
    return round(usd, 8)

Input: 1500 × 0.006 + 500 × 0.30 = 159; output: (60 + 900) × 1.20 = 1152, of which thinking is 900 × 1.20 = 1080. 1080 / 1311 ≈ 82%. Thinking is billed at the **output price**, and output costs 4 times as much as input with a cache miss and 200 times as much as input with a cache hit. For a decision like "accept / flag / redline", turning thinking off usually saves most of the cost and is faster too; but first use evals (Day 13) to confirm that accuracy didn't drop once it's off.

--- context
This is the complete LangChain version of "review one clause". A contract has dozens of clauses; whether the model answers badly or the service keeps failing, this clause must not disappear from the report, and it must certainly not be counted as passed.
--- prompt
Define the Pydantic model `Verdict`, whose class docstring is `"Verdict for one contract clause."`, with the fields `clause_id` (a string), `verdict` (only `accept` / `flag` / `redline`), `risk_level` (only `low` / `medium` / `high`) and `rationale` (a string).

Write `review(model, clause_id, text)`:

- Use `model.with_structured_output(Verdict, include_raw=True)` and send two messages: system `"You review contract clauses for the Customer."`, user `f"Review clause {clause_id}: {text}"`
- You got an object: set its `clause_id` to the `clause_id` passed in, and return it
- You got no object (`parsed` is None), or the call raises `openai.APIStatusError` (a 429 / 5xx and so on, after the retries run out): return `Verdict(clause_id=clause_id, verdict="flag", risk_level="medium", rationale="Automatic review did not complete.")`

Imports: `import openai`, `from pydantic import BaseModel`, `from typing import Literal`.
--- solution
from typing import Literal
import openai
from pydantic import BaseModel

class Verdict(BaseModel):
    """Verdict for one contract clause."""
    clause_id: str
    verdict: Literal["accept", "flag", "redline"]
    risk_level: Literal["low", "medium", "high"]
    rationale: str

def review(model, clause_id, text):
    fallback = Verdict(clause_id=clause_id, verdict="flag", risk_level="medium", rationale="Automatic review did not complete.")
    reviewer = model.with_structured_output(Verdict, include_raw=True)
    messages = [("system", "You review contract clauses for the Customer."), ("user", f"Review clause {clause_id}: {text}")]
    try:
        result = reviewer.invoke(messages)
    except openai.APIStatusError:
        return fallback
    verdict = result["parsed"]
    if verdict is None:
        return fallback
    verdict.clause_id = clause_id
    return verdict

--- context
Clauses often say things like "subject to clause 12", and a review that reads only this one clause gets it wrong. This small agent lets the model decide for itself whether to fetch other clauses, and answer after reading them.
--- prompt
`CLAUSES = {"12": "The limitations in Section 8 shall not apply to Customer.", "8.1": "Each party's liability is capped at the fees paid."}`

1. Use `@tool` to write `get_clause(clause_id: str) -> str`, with the docstring `"Fetch the text of another clause of the same contract by its number, e.g. '12'."`; take the text from `CLAUSES`, and if it isn't there, return `f"NOT_FOUND: clause {clause_id}"`
2. Write `answer_with_tools(model, question, max_steps=3)`:
   - `llm = model.bind_tools([get_clause])`; messages start with `HumanMessage(question)`
   - Each step makes one request and appends the answer to messages; if the answer has **neither** `tool_calls` **nor** `invalid_tool_calls`: return `{"answer": answer text, "steps": number of requests so far, "called": called}`
   - Otherwise, for each call in `tool_calls`: append the message from `get_clause.invoke(call)` to messages, and record `"get_clause:" + the clause_id in this call's arguments` in `called`
   - For each broken call in `invalid_tool_calls` (arguments that are not valid JSON): append `ToolMessage("INVALID_ARGS: arguments are not valid JSON", tool_call_id=its "id", status="error")`, and record `its "name" + ":INVALID_ARGS"` in `called` (the same as `review.py`)
   - Still no answer after `max_steps` requests: `{"answer": None, "steps": max_steps, "called": called}`

Imports: `HumanMessage` and `ToolMessage` from `langchain_core.messages`, `tool` from `langchain_core.tools`.
--- solution
from langchain_core.messages import HumanMessage, ToolMessage
from langchain_core.tools import tool

CLAUSES = {"12": "The limitations in Section 8 shall not apply to Customer.", "8.1": "Each party's liability is capped at the fees paid."}

@tool
def get_clause(clause_id: str) -> str:
    """Fetch the text of another clause of the same contract by its number, e.g. '12'."""
    return CLAUSES.get(clause_id, f"NOT_FOUND: clause {clause_id}")

def answer_with_tools(model, question, max_steps=3):
    llm = model.bind_tools([get_clause])
    messages = [HumanMessage(question)]
    called = []
    for step in range(1, max_steps + 1):
        ai = llm.invoke(messages)
        messages.append(ai)
        if not ai.tool_calls and not ai.invalid_tool_calls:
            return {"answer": ai.content, "steps": step, "called": called}
        for call in ai.tool_calls:
            messages.append(get_clause.invoke(call))
            called.append(f"get_clause:{call['args']['clause_id']}")
        for bad in ai.invalid_tool_calls:
            messages.append(ToolMessage("INVALID_ARGS: arguments are not valid JSON", tool_call_id=bad["id"], status="error"))
            called.append(f"{bad['name']}:INVALID_ARGS")
    return {"answer": None, "steps": max_steps, "called": called}

    "deepseek-flash": {"hit": 0.006, "miss": 0.30, "output": 1.20},

1. Write `usage_cost(usage_by_model, peak=True)`: `usage_by_model` has the same shape as `cb.usage_metadata` (model name → usage dict). 2. Write `run_with_cost(chain, inputs, peak=True)`: inside `get_usage_metadata_callback()`, run everything with `chain.batch(inputs)`, and return `{"results": list of results, "usd": usage_cost(...)}`

Imports: `from langchain_core.callbacks import get_usage_metadata_callback`.
--- solution
from langchain_core.callbacks import get_usage_metadata_callback

PRICES = {
    "deepseek-flash": {"hit": 0.006, "miss": 0.30, "output": 1.20},
    "deepseek-v4-pro": {"hit": 0.044, "miss": 1.32, "output": 3.96},
}

def usage_cost(usage_by_model, peak=True):
    total = 0.0
    for model, usage in usage_by_model.items():
        p = PRICES[model]
        hit = (usage.get("input_token_details") or {}).get("cache_read", 0)
        miss = usage["input_tokens"] - hit
        total += (hit * p["hit"] + miss * p["miss"] + usage["output_tokens"] * p["output"]) / 1_000_000
    if not peak:
        total /= 2
    return round(total, 8)

def run_with_cost(chain, inputs, peak=True):
    with get_usage_metadata_callback() as cb:
        results = chain.batch(inputs)
    return {"results": results, "usd": usage_cost(cb.usage_metadata, peak)}
