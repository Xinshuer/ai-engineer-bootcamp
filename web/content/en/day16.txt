@@ concept
title: class basics
--- body
You wrote classes in Python on Day 3. TypeScript maps onto them almost one to one:

- `__init__` → `constructor`, `self` → `this`. Inside a method you **must** write `this.xxx` to read a field
- Fields need a declared type: `counts: Record<string, number> = {};`
- Creating an object needs `new`: `const c = new VerdictCounter();`

Put `private readonly` or `readonly` in front of a constructor parameter and it automatically becomes a field (a **parameter property**). You'll see this a lot in SDK source code:

```ts
class Client {
  constructor(private readonly apiKey: string, readonly model = "deepseek-flash") {}
}
```

The classic mistake: forgetting `this.` inside a method. TypeScript reports `Cannot find name 'counts'`.
--- code
class VerdictCounter {
  counts: Record<string, number> = {};

  add(verdict: string): void {
    this.counts[verdict] = (this.counts[verdict] ?? 0) + 1;
  }

  total(): number {
    return Object.values(this.counts).reduce((sum, n) => sum + n, 0);
  }
}

class Client {
  constructor(private readonly apiKey: string, readonly model = "deepseek-flash") {}

  describe(): string {
    return `${this.model} with key ${this.apiKey.slice(0, 3)}...`;
  }
}

const counter = new VerdictCounter();
for (const v of ["flag", "accept", "flag"]) {
  counter.add(v);
}
console.log(counter.counts, counter.total());
console.log(new Client("sk-123456").describe());

@@ concept
title: Private state and getters
--- body
A class earns its keep by **guarding a rule**, for example "the tokens used must not go over the budget". If anyone can change `used` directly, the rule can't be kept.

- `#used = 0`: a truly private field. Code outside the class can neither read nor write it, and it isn't visible at runtime either (it's not in `Object.keys` or `JSON.stringify`)
- `private used = 0`: only blocked at **compile time**; at runtime it is still an ordinary field
- getter: `get remaining(): number { ... }`. Outside code uses it like a field, `budget.remaining` (no parentheses), and can read it but not change it

Use `#` in new code; in SDK source code you'll see both. Change state only through methods: the method checks first, then changes.
--- code
class TokenBudget {
  #used = 0;
  constructor(readonly limit: number) {}

  get used(): number {
    return this.#used;
  }
  get remaining(): number {
    return this.limit - this.#used;
  }
  spend(n: number): boolean {
    if (n > this.remaining) {
      return false;
    }
    this.#used += n;
    return true;
  }
}

const budget = new TokenBudget(1000);
console.log(budget.spend(600), budget.spend(600), budget.remaining);
console.log(Object.keys(budget), JSON.stringify(budget));
// budget.remaining = 5; // uncomment to try it: there is only a getter, so you can't assign

@@ concept
title: static and factory methods
--- body
A `static` method belongs to **the class itself**. You call it as `ClassName.method()`, without creating an object with new first. Its most common use is a **factory method**: it creates an object from outside data, and validates the data before creating it.

```ts
const pb = Playbook.fromJSON(JSON.parse(text)); // throws if the data is bad
```

The benefit: the constructor only ever receives data that has already passed, so bad data is stopped at the door, with a clear error. In Clause Check, `Playbook.load(path)` in `clausecheck/playbook.py` is the Python version of a factory method (`@classmethod`): it first validates every rule with Pydantic, then creates the Playbook.

`static` can also be a constant: `static readonly VERSION = "2026-09";`
--- code
interface Rule {
  id: string;
  topic: string;
}

class Playbook {
  static readonly VERSION = "2026-09";

  constructor(readonly rules: Rule[]) {}

  static fromJSON(raw: unknown): Playbook {
    if (typeof raw !== "object" || raw === null || !("rules" in raw) || !Array.isArray(raw.rules)) {
      throw new Error("playbook JSON needs a 'rules' array");
    }
    return new Playbook(raw.rules);
  }

  topics(): string[] {
    return this.rules.map((r) => r.topic);
  }
}

const pb = Playbook.fromJSON(JSON.parse('{"rules": [{"id": "PB-01", "topic": "liability_cap"}]}'));
console.log(pb.topics(), Playbook.VERSION);
try {
  Playbook.fromJSON({ items: [] });
} catch (e) {
  console.log(e instanceof Error ? e.message : e);
}

@@ concept
title: Custom errors and instanceof
--- body
A call to an API can fail in many ways: 429 rate limit (wait and try again), 401 wrong key (retrying won't help), 500 server error. The caller has to **handle each one differently**, so give each kind of failure its own error class:

```ts
class ApiError extends Error {
  constructor(message: string, readonly status: number) {
    super(message);          // must call the parent class's constructor first
    this.name = "ApiError";  // the name shown in the error
  }
}
```

Tell them apart with `instanceof`, and **check the subclass first** (a RateLimitError is also an ApiError). An error you don't recognize must be passed on with `throw e`; don't swallow it. In TypeScript the e in `catch (e)` is `unknown`, and an `instanceof` check narrows it at the same time.

Clause Check's `review.py` catches the Anthropic SDK's `RateLimitError` and `APIStatusError` by type in exactly this way.
--- code
class ApiError extends Error {
  constructor(message: string, readonly status: number) {
    super(message);
    this.name = "ApiError";
  }
}
class RateLimitError extends ApiError {
  constructor(message = "rate limited") {
    super(message, 429);
    this.name = "RateLimitError";
  }
}

function handle(e: unknown): string {
  if (e instanceof RateLimitError) {
    return `wait and retry (${e.status})`;
  }
  if (e instanceof ApiError) {
    return `give up: ${e.name} ${e.status} ${e.message}`;
  }
  throw e;
}

console.log(handle(new RateLimitError()));
console.log(handle(new ApiError("bad key", 401)));
const err = new RateLimitError();
console.log(err instanceof RateLimitError, err instanceof ApiError, err instanceof Error);
try {
  handle(new TypeError("x is undefined"));
} catch (e) {
  console.log("re-thrown:", e instanceof TypeError);
}

@@ concept
title: Result: failure is a return value too
--- body
throw is for the **unexpected**: a bug in the program, missing configuration, situations where the program can't go on. But some failures are **expected**: the model now and then returns bad JSON, and 3 out of 200 clauses fail to parse. Then it's better to treat the failure as an ordinary return value:

```ts
type Result<T> = { ok: true; value: T } | { ok: false; error: string };
```

It's the discriminated union you learned yesterday: you can read `r.value` only after `if (r.ok)`. The benefits: the function signature tells the caller directly "this can fail", so the caller **can't forget** to handle it; and in a batch, one failure doesn't stop the whole batch.

Zod's `safeParse` returns `{ success: true, data } | { success: false, error }`: the same design. Clause Check's `review.py` catches the errors the SDK throws and returns them as `Step(stop="error", error=...)`: the same idea.
--- code
type Result<T> = { ok: true; value: T } | { ok: false; error: string };

function parseScore(raw: string): Result<number> {
  const n = Number(raw);
  if (raw.trim() === "" || Number.isNaN(n)) {
    return { ok: false, error: `not a number: ${JSON.stringify(raw)}` };
  }
  return { ok: true, value: n };
}

for (const raw of ["0.8", "high", ""]) {
  const r = parseScore(raw);
  if (r.ok) {
    console.log("score", r.value * 100);
  } else {
    console.log("skip:", r.error);
  }
}

@@ concept
title: Dependency injection: pass the outside world in
--- body
If a class calls `fetch` or `Date.now()` directly, its tests have to really go online and really wait. **Dependency injection** means: pass these dependencies in as constructor parameters, with a real default value; in tests, pass in a fake one:

```ts
new DeepSeekClient(key);                  // production: uses the real fetch
new DeepSeekClient("sk-test", fakeFetch); // test: no network, fixed result
```

This is also "composition over inheritance": the client **has** a fetch function instead of **inheriting from** some HTTP base class, so swapping it out doesn't affect any other code. On Day 13 you gave `measure` a fake clock, `clock=fake_clock(...)`: the same idea. In Clause Check's `review.py`, the review loop `model_review(backend, ...)` only calls a few methods such as `backend.step(...)`, so the backend passed in can be the Anthropic backend or the DeepSeek backend.
--- code
type Clock = () => number;

class Stopwatch {
  #start: number;
  constructor(private readonly now: Clock = () => Date.now()) {
    this.#start = now();
  }
  elapsedMs(): number {
    return this.now() - this.#start;
  }
}

// a fake clock for tests: every call moves it 250 milliseconds forward
let fakeTime = 1000;
const fakeClock: Clock = () => {
  fakeTime += 250;
  return fakeTime;
};
const sw = new Stopwatch(fakeClock);
console.log(sw.elapsedMs(), sw.elapsedMs());

const real = new Stopwatch();
console.log(real.elapsedMs() >= 0);

@@ concept
title: Modules: one file, one job
--- body
Real projects split files by responsibility, and each file does one job:

- `types.ts`: types and error classes (`Verdict`, `Result`, `ApiError`)
- `client.ts`: `DeepSeekClient`, which only handles HTTP
- `review.ts`: the review logic, which depends only on types and the "client interface"
- `main.ts`: puts them together

How to write it: `export class DeepSeekClient { ... }`, and in another file `import { DeepSeekClient } from "./client";`; to import only types, write `import type { Verdict } from "./types";`. `class X implements ModelClient` makes the compiler check that the class really has the methods the interface requires.

The rule: dependencies point in one direction only (main → review → client → types); **files must not import each other**. A circular dependency causes strange bugs such as "it's still undefined when you use it". Each exercise on this page has only one file; today's local task splits one up for real.
--- code
// ---- types.ts ----
type Verdict = "accept" | "flag" | "redline";
interface ClauseReview {
  id: string;
  verdict: Verdict;
}

// ---- client.ts ---- (only handles "how to ask the model")
interface ModelClient {
  judge(text: string): Verdict;
}
class KeywordClient implements ModelClient {
  judge(text: string): Verdict {
    return text.includes("unlimited") ? "redline" : "accept";
  }
}

// ---- review.ts ---- (depends only on the ModelClient interface, doesn't care which class it is)
function reviewAll(client: ModelClient, clauses: { id: string; text: string }[]): ClauseReview[] {
  return clauses.map((c) => ({ id: c.id, verdict: client.judge(c.text) }));
}

// ---- main.ts ---- (puts it together)
const reviews = reviewAll(new KeywordClient(), [
  { id: "3.1", text: "Fees are due in 30 days." },
  { id: "8.1", text: "Liability is unlimited." },
]);
console.log(reviews.map((r) => `${r.id}: ${r.verdict}`).join(", "));

@@ concept
title: Map and Set
--- body
On Day 5 you used `Record<string, T>` as a dictionary. `Map` is a container made for "key → value", and it fits better when:

- keys are added and removed often, and you need `.size`
- keys are not strings (numbers, objects)
- keys come from outside data: on a plain object, keys such as `"constructor"` collide with built-in properties; on a Map they don't

```ts
const byId = new Map<string, Rule>();
byId.set("PB-01", rule);
byId.get("PB-01"); // Rule | undefined: remember it may not be there
byId.has("PB-02");
for (const [id, rule] of byId) { ... }
const seen = new Map([["8.1", "redline"]]); // you can also build it in one go from an array of [key, value] pairs
```

`Set` is "a collection without duplicates": `new Set(ids)` removes duplicates, `.has(x)` checks very fast, `.add(x)` adds, and `[...set]` turns it back into an array. Map and Set both loop in **insertion order**.
--- code
interface Rule {
  id: string;
  topic: string;
}
const rules: Rule[] = [
  { id: "PB-01", topic: "liability_cap" },
  { id: "PB-02", topic: "auto_renewal" },
  { id: "PB-07", topic: "liability_cap" },
];
const byId = new Map<string, Rule>();
for (const r of rules) {
  byId.set(r.id, r);
}
console.log(byId.size, byId.has("PB-02"), byId.get("PB-99"));
console.log(byId.get("PB-07")?.topic);

const topics = new Set(rules.map((r) => r.topic));
console.log(topics.size, [...topics]);

const verdicts = new Map([["8.1", "redline"], ["3.1", "accept"]]);
console.log(verdicts.get("8.1"), [...verdicts.keys()]);

const plain: Record<string, number> = {};
console.log("constructor" in plain, new Map<string, number>().has("constructor"));

--- prompt
A review of Day 15. `Step` is the three possible kinds of one model reply (the same as `Step.stop` in `review.py`). Write `finalText(steps)`, which looks at each step in order:

- on an `error`: return `"failed: " + error` right away
- on an `end`: remember its `text` (a later end overwrites an earlier one)
- when all steps are done: return the last text remembered; if there was no end at all, return `"(no answer)"`

Example: `[{ stop: "tool_use", tool: "lookup_playbook" }, { stop: "end", text: "flag" }]` → `"flag"`.
--- starter
type Step =
  | { stop: "end"; text: string }
  | { stop: "tool_use"; tool: string }
  | { stop: "error"; error: string };

function finalText(steps: Step[]): string {
  return "(no answer)";
}
--- solution
type Step =
  | { stop: "end"; text: string }
  | { stop: "tool_use"; tool: string }
  | { stop: "error"; error: string };

function finalText(steps: Step[]): string {
  let answer = "(no answer)";
  for (const s of steps) {
    if (s.stop === "error") {
      return `failed: ${s.error}`;
    }
    if (s.stop === "end") {
      answer = s.text;
    }
  }
  return answer;
}
--- tests
expect("answer after a tool call", () => finalText([{ stop: "tool_use", tool: "lookup_playbook" }, { stop: "end", text: "flag" }]), "flag");
expect("error along the way", () => finalText([{ stop: "tool_use", tool: "get_clause" }, { stop: "error", error: "http 429" }, { stop: "end", text: "accept" }]), "failed: http 429");
expect("a later end overwrites an earlier one", () => finalText([{ stop: "end", text: "a" }, { stop: "end", text: "b" }]), "b");
expect("empty", () => finalText([]), "(no answer)");
--- hints
- Only after narrowing with `if (s.stop === "error")` can you read `s.error`.
- Use a variable `let answer = "(no answer)";` to remember the text of the last end, and return it after the loop.

--- context
The report summary counts how many clauses got each verdict, and evals count which failure is most common. Python has a ready-made `Counter`; TypeScript doesn't, so write a small class yourself.
--- prompt
Write `class Counter`:

- `add(key)`: add 1 to this key's count
- `get(key)`: return the count; a key never seen returns 0
- `top(n)`: return the n keys with the highest counts; on a tie, the key that appeared first comes first

Example: after adding `flag, accept, flag, redline, flag, accept` in that order, `top(2)` → `["flag", "accept"]`.
--- starter
class Counter {
  counts: Record<string, number> = {};

  add(key: string): void {}

  get(key: string): number {
    return 0;
  }

  top(n: number): string[] {
    return [];
  }
}
--- solution
class Counter {
  counts: Record<string, number> = {};

  add(key: string): void {
    this.counts[key] = (this.counts[key] ?? 0) + 1;
  }

  get(key: string): number {
    return this.counts[key] ?? 0;
  }

  top(n: number): string[] {
    return Object.keys(this.counts)
      .sort((a, b) => this.counts[b] - this.counts[a])
      .slice(0, n);
  }
}
--- tests
const c = new Counter();
for (const v of ["flag", "accept", "flag", "redline", "flag", "accept"]) {
  c.add(v);
}
expect("get", () => c.get("flag"), 3);
expect("a key never seen", () => c.get("maybe"), 0);
expect("top 2", () => c.top(2), ["flag", "accept"]);
expect("n larger than the number of keys", () => c.top(10), ["flag", "accept", "redline"]);
expect("each object counts on its own", () => { const a = new Counter(); a.add("x"); return new Counter().get("x"); }, 0);
--- hints
- Inside a method, reading or writing the field always means `this.counts`.
- `top`: sort `Object.keys(this.counts)` by count from high to low (sort is stable, so keys with the same count keep the order they first appeared in), then `slice(0, n)`.

class Playbook:
    def __init__(self, rules: list[Rule]):
        self.rules = rules
        self._by_topic: dict[str, list[Rule]] = {}
        for r in rules:
            self._by_topic.setdefault(r.topic, []).append(r)

    @property
    def topics(self) -> list[str]:
        return sorted(self._by_topic)

    def for_topic(self, topic: str) -> list[Rule]:
        return list(self._by_topic.get(topic, []))

    def get(self, rule_id: str) -> Rule | None:
        return next((r for r in self.rules if r.id == rule_id), None)

--- solution
interface Rule {
  id: string;
  topic: string;
  severity: "low" | "medium" | "high";
}

class Playbook {
  readonly rules: Rule[];
  #byTopic: Record<string, Rule[]> = {};

  constructor(rules: Rule[]) {
    this.rules = rules;
    for (const r of rules) {
      if (this.#byTopic[r.topic] === undefined) {
        this.#byTopic[r.topic] = [];
      }
      this.#byTopic[r.topic].push(r);
    }
  }

  get topics(): string[] {
    return Object.keys(this.#byTopic).sort();
  }

  forTopic(topic: string): Rule[] {
    return [...(this.#byTopic[topic] ?? [])];
  }

  get(ruleId: string): Rule | undefined {
    return this.rules.find((r) => r.id === ruleId);
  }
}

class BudgetExceededError extends Error {
  constructor(message: string) {
    super(message);
    this.name = "BudgetExceededError";
  }
}

class TokenBudget {
  #used = 0;

  constructor(readonly limit: number) {}

  get used(): number {
    return this.#used;
  }

  get remaining(): number {
    return this.limit - this.#used;
  }

  spend(n: number): void {
    if (n < 0) {
      throw new Error(`cannot spend a negative amount: ${n}`);
    }
    if (n > this.remaining) {
      throw new BudgetExceededError(`need ${n} tokens, only ${this.remaining} left`);
    }
    this.#used += n;
  }
}

class PlaybookError extends Error {
  constructor(message: string) {
    super(message);
    this.name = "PlaybookError";
  }

interface Rule {
  id: string;
  topic: string;
}

function isRule(x: unknown): x is Rule {
  return typeof x === "object" && x !== null && "id" in x && typeof x.id === "string" && "topic" in x && typeof x.topic === "string";
}

class Playbook {
  constructor(readonly rules: Rule[]) {}

  static fromJSON(raw: unknown): Playbook {
    if (typeof raw !== "object" || raw === null || !("rules" in raw) || !Array.isArray(raw.rules)) {
      throw new PlaybookError("missing rules array");
    }
    const items: unknown[] = raw.rules;
    const rules: Rule[] = [];
    for (let i = 0; i < items.length; i++) {
      const item = items[i];
      if (!isRule(item)) {
        throw new PlaybookError(`bad rule at index ${i}`);
      }
      if (rules.some((r) => r.id === item.id)) {
        throw new PlaybookError(`duplicate rule id ${item.id}`);
      }
      rules.push(item);
    }
    return new Playbook(rules);
  }

  rulesFor(topic: string): string[] {
    return this.rules.filter((r) => r.topic === topic).map((r) => r.id);

    try {
      return await fn();

      lastError = e;
    }
  }

interface Rule {
  id: string;
  topic: string;
}

class RuleIndex {
  #byId = new Map<string, Rule>();

  add(rule: Rule): void {
    if (this.#byId.has(rule.id)) {
      throw new Error(`duplicate rule id ${rule.id}`);
    }
    this.#byId.set(rule.id, rule);
  }

  find(id: string): Rule | undefined {
    return this.#byId.get(id);
  }

  get size(): number {
    return this.#byId.size;
  }

  topics(): string[] {
    const unique = new Set<string>();
    for (const rule of this.#byId.values()) {
      unique.add(rule.topic);
    }
    return [...unique].sort();
  }
}

--- prompt
Write `class RateLimiter`: allow at most `max` calls in any `windowMs` consecutive milliseconds.

- Constructor: `constructor(max: number, windowMs: number, now: () => number = () => Date.now())`
- `tryAcquire(): boolean`: if the recent window (the timestamps `s` with `now() - s < windowMs`) already holds `max` successful calls, return `false` (and don't record this one); otherwise record the time of this call and return `true`
- getter `remaining`: how many more calls the current window allows (used as `limiter.remaining`, no parentheses)
--- solution
class RateLimiter {
  #stamps: number[] = [];

  constructor(
    private readonly max: number,
    private readonly windowMs: number,
    private readonly now: () => number = () => Date.now(),
  ) {}

  private prune(): void {
    const t = this.now();
    this.#stamps = this.#stamps.filter((s) => t - s < this.windowMs);
  }

  tryAcquire(): boolean {
    this.prune();
    if (this.#stamps.length >= this.max) {
      return false;
    }
    this.#stamps.push(this.now());
    return true;
  }

  get remaining(): number {
    this.prune();
    return this.max - this.#stamps.length;
  }
}

--- solution
type Result<T> = { ok: true; value: T } | { ok: false; error: string };

interface Verdict {
  clause_id: string;
  verdict: "accept" | "flag" | "redline";
}

const VERDICTS = ["accept", "flag", "redline"];

function isVerdict(x: unknown): x is Verdict {
  return (
    typeof x === "object" &&
    x !== null &&
    "clause_id" in x &&
    typeof x.clause_id === "string" &&
    "verdict" in x &&
    typeof x.verdict === "string" &&
    VERDICTS.includes(x.verdict)
  );
}

function parseOne(raw: string): Result<Verdict> {
  let data: unknown;
  try {
    data = JSON.parse(raw);
  } catch {
    return { ok: false, error: "bad json" };
  }
  if (!isVerdict(data)) {
    return { ok: false, error: "bad shape" };
  }
  return { ok: true, value: data };
}

function parseAll(raws: string[]): { verdicts: Verdict[]; errors: string[] } {
  const verdicts: Verdict[] = [];
  const errors: string[] = [];
  raws.forEach((raw, i) => {
    const r = parseOne(raw);
    if (r.ok) {
      verdicts.push(r.value);
    } else {
      errors.push(`#${i}: ${r.error}`);
    }
  });
  return { verdicts, errors };
}
