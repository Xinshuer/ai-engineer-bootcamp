@@ concept
title: Graph runner (Python version)
--- body
On Day 18 you wrote a graph runner in TypeScript. Clause Check's `graph.py` is written in Python, so today you write it again in Python. Three things:

- `nodes`: name → function. A node gets the whole state and returns only **the keys it changed** (a small dictionary)
- `edges`: name → the name of the next node (a string), or a **routing function** that looks at the state and decides where to go
- The runner: begin at the start node, then run the node → merge → find the next one, until `"END"`

Merge with `{**state, **update}`: later keys overwrite earlier ones, and you get a **new dictionary**; the original stays unchanged. The classic mistake is writing it backwards, `{**update, **state}`, so the old values overwrite the new ones.

`callable(x)` checks whether x can be called like a function; use it to tell a fixed edge from a routing function. Below, two steps are taken by hand; in the exercises you'll turn this into a loop.
--- code
def load(state):
    return {"clauses": ["3.1", "8.1", "10.1"]}

def review(state):
    verdicts = {"3.1": "accept", "8.1": "redline", "10.1": "redline"}
    return {"reviews": [verdicts[c] for c in state["clauses"]]}

def route(state):
    return "approve" if "redline" in state["reviews"] else "export"

nodes = {"load": load, "review": review}
edges = {"load": "review", "review": route}

state = {"contract_path": "data/sample_contract.txt"}
node = "load"
for _ in range(2):
    update = nodes[node](state)
    state = {**state, **update}
    edge = edges[node]
    nxt = edge(state) if callable(edge) else edge
    print(f"{node:<7} -> {nxt:<8} changed {sorted(update)}")
    node = nxt
print(state)

@@ concept
title: TypedDict: types for dictionary state
--- body
The `State` in `graph.py` is neither a dataclass nor Pydantic. It is a `TypedDict`:

```python
class State(TypedDict, total=False):
    contract_path: str
    reviews: list[dict]
    approved: bool | None
```

- At runtime it **is just a plain dict**: `state["reviews"]`, `state.get("approved")` and `{**state, **update}` work as usual
- The type hints are only for the editor (Pylance in VS Code) and mypy: a misspelled key or a wrong type gets a red underline, but there is **no error** at runtime
- `total=False`: any key may be missing for now. The graph's state fills up step by step; at first it holds only `contract_path`
- Why not Pydantic? A graph framework merges the state and saves it as checkpoints all the time, and a dict is the simplest thing for that. What really needs strict validation is **the model's output**, and that is where Pydantic goes
--- code
from typing import TypedDict

class State(TypedDict, total=False):
    contract_path: str
    reviews: list[dict]
    approved: bool | None

s: State = {"contract_path": "data/sample_contract.txt"}
s["approved"] = None
print(type(s).__name__, s)
s["reviews"] = "oops"   # the editor underlines this in red, but nothing stops it at runtime
print(s["reviews"])
print(sorted(State.__optional_keys__))   # total=False: every key is optional

@@ concept
title: Checkpoint files
--- body
Reviewing one contract takes several minutes. It may crash halfway, or it may wait a whole day for a lawyer to approve. A **checkpoint** means that every time a node finishes, you save "where to go next + the current state":

```python
{"next": "summarise", "state": {...}}
```

To resume, read the file and carry on from `next`. Nodes that are done don't run again, so you don't pay for the same model calls twice.

- Path: `Path("work/checkpoints") / f"{run_id}.json"`; call `mkdir(parents=True, exist_ok=True)` first
- The state may only hold things JSON can store (strings, numbers, lists, dictionaries, True/False/None). That is why `graph.py` stores `r.model_dump()` and not the Pydantic object
- Order matters: **work out the next node first, then save**. If you save the node that just ran, it runs again when you resume

On this page, files live on a virtual disk in your browser; they stay there until you reload the page.
--- code
import json
from pathlib import Path

folder = Path("work/d19/demo")
folder.mkdir(parents=True, exist_ok=True)
path = folder / "run-1.json"

saved = {"next": "summarise", "state": {"contract_path": "a.txt", "reviews": ["accept", "redline"], "approved": None}}
path.write_text(json.dumps(saved, indent=2), encoding="utf-8")

loaded = json.loads(path.read_text(encoding="utf-8"))
print(path.name, path.exists())
print(loaded["next"], loaded["state"]["reviews"], loaded["state"]["approved"])
print(loaded == saved)

@@ concept
title: Answers with citations
--- body
A RAG answer must be **verifiable**: every sentence says where it comes from. Three steps:

1. In the prompt, give each chunk an id, `[c1] ...`, `[c2] ...`, and ask the model to "answer only from these chunks, and mark the source of every sentence like [c1]"
2. Pull the citations out of the answer: `re.findall(r"\[(c\d+)\]", answer)`
3. Check: every citation must be an id **retrieved this time**; an answer with no citations at all counts as having no support ("unsupported")

Square brackets have a special meaning in regular expressions, so write them as `\[` and `\]`. Mind the `+` in `\d+`: without it, `[c10]` won't match.
--- code
import re

chunks = [
    {"id": "c1", "text": "Either party may terminate for convenience upon sixty (60) days' notice."},
    {"id": "c2", "text": "Fees are payable within thirty (30) days of the invoice date."},
]
lines = [f"[{c['id']}] {c['text']}" for c in chunks]
prompt = "Answer only from the sources. Cite like [c1].\n\n" + "\n".join(lines) + "\n\nQuestion: How long is the notice period?"
print(prompt)
print("---")
answer = "Sixty days' notice is required [c1]. See also [c7]."
cited = re.findall(r"\[(c\d+)\]", answer)
allowed = {c["id"] for c in chunks}
print("cited:", cited)
print("unknown:", [c for c in cited if c not in allowed])

@@ concept
title: Groundedness: is the quoted text real?
--- body
Even when every citation id is right, the "original text" inside the quotes may still be made up by the model. The groundedness check: every passage the answer puts in quotes must **really appear in the chunk it cites**.

- Normalize before comparing: collapse all whitespace into single spaces and make everything lowercase (`" ".join(s.split()).lower()`); otherwise line breaks and capital letters cause false alarms
- Models often output curly quotes `“…”`; recognize them together with straight quotes `"…"`
- This is a very cheap automatic eval (Day 13): no extra model call, just code, so it can run on every answer

It catches "made-up quotes", but not "the quote is real, yet the conclusion drawn from it is wrong".
--- code
import re

def norm(s):
    return " ".join(s.split()).lower()

chunk = "Provider may  terminate this Agreement\nfor convenience upon thirty (30) days' notice."
answer = 'The clause says “Provider may terminate this Agreement for convenience” [c3], and "without any notice" [c3].'
quotes = re.findall(r'["“]([^"”]+)["”]', answer)
for q in quotes:
    print(repr(q), "->", norm(q) in norm(chunk))

@@ concept
title: Dependency injection makes RAG testable
mock: yes
--- body
When you test a RAG flow, what you want to test is **your code** (retrieval, building the prompt, checking citations), not the model's mood today. The trick: pass "call the model" in as a parameter:

```python
def answer(question, chunks, llm):   # llm: any function that takes a string and returns a string
    return llm(build_prompt(question, chunks))
```

- In tests, pass a fake `llm`: it returns a fixed string, costs nothing, needs no network, gives the same result every time, and can even record the prompts it receives so you can check them
- In production, pass the real one: a function that calls DeepSeek
- Injecting the clock on Day 13 and `fetchFn` on Day 16 are the same idea: **things that change are passed in from outside**
--- code
import os
import requests

def build_prompt(question, chunks):
    return "\n".join(f"[{c['id']}] {c['text']}" for c in chunks) + f"\n\nQuestion: {question}"

def answer(question, chunks, llm):
    return llm(build_prompt(question, chunks))

def deepseek_llm(prompt):
    body = {"model": "deepseek-flash", "messages": [{"role": "user", "content": prompt}]}
    headers = {"Authorization": f"Bearer {os.getenv('DEEPSEEK_API_KEY')}"}
    data = requests.post("https://api.deepseek.com/v1/chat/completions", headers=headers, json=body).json()
    # thinking mode is on by default: the answer is in content, the thinking in reasoning_content (we only need the answer here)
    return data["choices"][0]["message"]["content"]

seen = []
def fake_llm(prompt):
    seen.append(prompt)
    return "Sixty days' notice [c1]."

chunks = [{"id": "c1", "text": "Either party may terminate upon sixty days' notice."}]
print(answer("Notice period?", chunks, fake_llm))
print(len(seen), "prompt(s), first line:", seen[0].splitlines()[0])
reply = answer("Notice period?", chunks, deepseek_llm)   # on this page it is a mock server: it only repeats the start of the prompt
print(reply.splitlines()[0])

--- solution
import re

def tokenize(text):
    return re.findall(r"[a-z0-9]+", text.lower())

def top_k(query, chunks, k):
    words = set(tokenize(query))
    scored = []
    for c in chunks:
        score = len(words & set(tokenize(c["text"])))
        if score > 0:
            scored.append((score, c))
    scored.sort(key=lambda pair: -pair[0])
    return [c for _, c in scored[:k]]
--- tests
CHUNKS = [
    {"id": "c1", "text": "Either party may terminate this Agreement upon sixty days' notice."},
    {"id": "c2", "text": "Fees are payable within thirty days of the invoice date."},
    {"id": "c3", "text": "Customer may terminate for material breach after thirty days."},
]
ids = lambda result: [c["id"] for c in result]
expect("the most relevant one", lambda: ids(top_k("fees payable", CHUNKS, 1)), ["c2"])
expect("higher scores first, ties keep their original order", lambda: ids(top_k("terminate after thirty days", CHUNKS, 3)), ["c3", "c1", "c2"])
expect("chunks that score 0 are left out", lambda: ids(top_k("invoice", CHUNKS, 5)), ["c2"])
expect("nothing relevant", lambda: top_k("gdpr", CHUNKS, 2), [])
expect("returns the chunk dictionaries", lambda: top_k("invoice", CHUNKS, 1), [CHUNKS[1]])
--- hints
- Make a set of the query's words, `set(tokenize(query))`, and a set of the chunk's words too; the length of their intersection `&` is the score.
- First collect `(score, chunk)` pairs, then `sort(key=lambda pair: -pair[0])`. Python's sort is stable, so ties keep their original order automatically.
- Finally take the first k: `[c for _, c in scored[:k]]`.

--- context
The state in `graph.py` is a dictionary. Each node hands back only the few keys it changed, and they get merged in. On Day 18 you did the same thing in TypeScript; here is how it looks in Python.
--- prompt
Write the output. On Day 18 you merged state in TypeScript with `{ ...state, ...update }`; in Python it is `{**state, **update}`. Watch which one comes last, and what a TypedDict really is at runtime.
--- code
from typing import TypedDict

class State(TypedDict, total=False):
    clauses: list[str]
    redlines: int
    approved: bool | None

state: State = {"clauses": ["3.1", "8.1"], "redlines": 0}
update = {"redlines": 2, "approved": None}
new = {**state, **update}
print(new)
print(state)
wrong = {**update, **state}
print(wrong["redlines"])
print(type(new).__name__)
--- explain
`{**a, **b}` puts in a's keys first, then overwrites them with b's, giving a new dictionary; `state` itself doesn't change. Written backwards (`{**update, **state}`), the old `redlines: 0` overwrites the new value, a bug that is very hard to spot in a graph runner. A TypedDict is only a type for the editor; at runtime it is a `dict`.

    if node not in edges:
        raise [[ValueError]](f"no edge from {node!r}")

The real project's `graph.py` is written in Python, so write the Day 18 runner again in Python. Once you have written it, you can match LangGraph's code to it line by line.
--- prompt
Write `run_graph(nodes, edges, state, start, max_steps=20)` that returns `(final state, path)`:

1. Begin at `start`; stop when the current node is `"END"`
2. Run the node, `update = nodes[node](state)`, and merge into a **new dictionary**, `state = {**state, **update}` (don't change the dictionary that was passed in)
3. Add the node's name to `path`, and find the next one with `next_node`
4. If `max_steps` nodes have already run and END still hasn't been reached: `raise RuntimeError` (this prevents an endless loop when the graph has a cycle)
5. If the node isn't in `nodes`: `raise ValueError`

Example: three nodes in a row → `({...}, ["load", "review", "export"])`
--- starter

--- solution
def next_node(edges, node, state):
    if node not in edges:
        raise ValueError(f"no edge from {node!r}")
    edge = edges[node]
    return edge(state) if callable(edge) else edge

def run_graph(nodes, edges, state, start, max_steps=20):
    path = []
    node = start
    while node != "END":
        if len(path) >= max_steps:
            raise RuntimeError(f"stopped after {max_steps} steps")
        if node not in nodes:
            raise ValueError(f"unknown node {node!r}")
        update = nodes[node](state)
        state = {**state, **update}
        path.append(node)
        node = next_node(edges, node, state)
    return state, path
--- tests

--- hints
- Skeleton: `while node != "END":`, and in the loop body, in this order: check the limit → check that the node exists → run it → merge → record the path → find the next one.

- Use `state = {**state, **update}`, not `state.update(update)`: the latter changes the caller's dictionary.

type: predict
title: Which way does the graph go?
level: 2
cards: Graph runner (Python version)
--- context
The model's first output was broken, so the graph loops back and has it review again. Loops like this, "go back and redo it", are common in review flows. You need to read the path a graph took to find out why it ran one step too many or too few.
--- prompt
Write the output. The first time `review` runs, the model's output is broken, and the routing sends it back to itself to review once more.
--- code
def next_node(edges, node, state):
    edge = edges[node]
    return edge(state) if callable(edge) else edge

def review(state):
    tries = state.get("tries", 0) + 1
    return {"tries": tries, "ok": tries >= 2}

nodes = {
    "load": lambda s: {"clauses": 3},
    "review": review,
    "summarise": lambda s: {"redlines": 0},
    "export": lambda s: {"exported": True},
}
edges = {
    "load": "review",
    "review": lambda s: "summarise" if s["ok"] else "review",
    "summarise": lambda s: "approve" if s["redlines"] > 0 else "export",
    "export": "END",
}
state, node, path = {}, "load", []
while node != "END":
    state = {**state, **nodes[node](state)}
    path.append(node)
    node = next_node(edges, node, state)
print(" -> ".join(path))
print(state["tries"], state["ok"], "approve" in path)
--- explain
A routing function can point back to its own node: that is how you write a retry in a graph. The first time, `tries` is 1 and `ok` is False, so it goes back to `review`; only the second time does it move on. There is no redline, so `approve` is skipped. Because edges can form a cycle, a runner must have `max_steps`.

--- context

A routing function only looks at the state and never calls the model, so it can be tested on its own. Reviewing again can't go on forever: every round costs money.
--- prompt
Write `route_after_review(state)`, checking in this order:

1. `state["errors"]` is not empty (some clauses weren't reviewed) and `state.get("retries", 0) < 2` → `"review"` (review again)
2. There are still errors, but it has already retried 2 times → `"human"` (hand it to a person)
3. Some entry in `state["reviews"]` has `verdict` `"redline"` → `"approve"`
4. Otherwise → `"export"`

--- starter
def route_after_review(state):
    return "export"
--- solution
def route_after_review(state):
    if state["errors"]:
        if state.get("retries", 0) < 2:
            return "review"
        return "human"
    if any(r["verdict"] == "redline" for r in state["reviews"]):
        return "approve"
    return "export"
--- tests

def next_node(edges, node, state):
    edge = edges[node]
    return edge(state) if callable(edge) else edge

def run(nodes, edges, state, start):
    node = start
    path = []
    while node != "END":
        update = nodes[node](state)
        if "__interrupt__" in update:
            return {"status": "interrupted", "next": node, "state": state, "question": update["__interrupt__"]}
        state = {**state, **update}
        path.append(node)
        node = next_node(edges, node, state)
    return {"status": "done", "state": state, "path": path}

def resume(nodes, edges, saved, approved):
    state = {**saved["state"], "approved": approved}
    return run(nodes, edges, state, saved["next"])

import re

def extract_citations(answer):
    result = []
    for cid in re.findall(r"\[(c\d+)\]", answer):
        if cid not in result:
            result.append(cid)
    return result

def extract_quotes(answer):
    found = re.findall(r'["“]([^"”]*)["”]', answer)
    return [q.strip() for q in found if q.strip()]

def norm(s):
    return " ".join(s.split()).lower()

def grounded(answer, chunks):
    cited = extract_citations(answer)
    sources = [norm(c["text"]) for c in chunks if c["id"] in cited]
    unsupported = []
    for q in extract_quotes(answer):
        if not any(norm(q) in src for src in sources):
            unsupported.append(q)
    return unsupported

In your RAG evals, `grounded(answer, chunks)` returns `[]` for an answer (no unsupported quotes found). What can you conclude?
--- options
- Every quoted passage in the answer can be found in a chunk it cites; but whether the conclusion is right, or whether a more important chunk was missed, this check can't tell
- The answer is correct and can go straight to the lawyer
- The model didn't hallucinate at all
- Retrieval found all the relevant chunks
answer: 1
--- explain
Groundedness only checks "is the quote real?". A model can quote the real text and still draw the opposite conclusion (it quotes "sixty (60) days" but says 30 days), or it can make things up without any quotation marks; this check catches neither. Retrieval missing a key chunk is a recall problem, which needs retrieval evals with known correct answers. So it is a cheap first automatic check; it can't replace an eval set and human spot checks.

import re

INSTRUCTIONS = "Answer only from the sources below. Cite every sentence like [c1]. If the sources do not answer the question, say so."

def tokenize(text):
    return re.findall(r"[a-z0-9]+", text.lower())

def top_k(query, chunks, k):
    words = set(tokenize(query))
    scored = [(len(words & set(tokenize(c["text"]))), c) for c in chunks]
    scored = [pair for pair in scored if pair[0] > 0]
    scored.sort(key=lambda pair: -pair[0])
    return [c for _, c in scored[:k]]

def extract_citations(answer):
    result = []
    for cid in re.findall(r"\[(c\d+)\]", answer):
        if cid not in result:
            result.append(cid)
    return result

def check_citations(answer, allowed_ids):
    cited = extract_citations(answer)
    return {"cited": cited, "unknown": [c for c in cited if c not in allowed_ids], "uncited": len(cited) == 0}

def rag_answer(question, chunks, llm, k=2):
    retrieved = top_k(question, chunks, k)
    if not retrieved:
        return {"answer": "", "sources": [], "status": "no_context"}
    ids = [c["id"] for c in retrieved]
    lines = [f"[{c['id']}] {c['text']}" for c in retrieved]
    prompt = INSTRUCTIONS + "\n\n" + "\n".join(lines) + "\n\nQuestion: " + question
    raw = llm(prompt)
    report = check_citations(raw, ids)
    if report["uncited"]:
        status = "unsupported"
    elif report["unknown"]:
        status = "bad_citation"
    else:
        status = "ok"
    return {"answer": raw, "sources": ids, "status": status}

Closed book: write a graph runner with conditional edges in Python, which is what LangGraph does for you behind `graph.py`. When an interviewer asks you to explain the framework, writing it from a blank page is the most convincing answer.
--- prompt
Write `run_graph(nodes, edges, state, start, max_steps=10)`:

- `nodes`: node name → function. The function takes the state dictionary and returns the keys to update (a dictionary)
- `edges`: node name → the name of the next node (a string), or a routing function (it takes the state and returns the name of the next node). `"END"` means the end
- For each node that runs: new state = old state merged with this update (**don't change** the dictionary passed in), and the node's name goes into `path`
- On reaching END: return `{"state": <final state>, "path": path, "stop": "end"}`
- If `max_steps` nodes have already run and END still hasn't been reached: stop and return the same structure, but with `"stop": "max_steps"`
- If the node to run isn't in `nodes`, or the node has no outgoing edge in `edges`: `raise ValueError`
--- solution
def run_graph(nodes, edges, state, start, max_steps=10):
    path = []
    node = start
    while node != "END":
        if len(path) >= max_steps:
            return {"state": state, "path": path, "stop": "max_steps"}
        if node not in nodes or node not in edges:
            raise ValueError(f"bad node {node!r}")
        state = {**state, **nodes[node](state)}
        path.append(node)
        edge = edges[node]
        node = edge(state) if callable(edge) else edge
    return {"state": state, "path": path, "stop": "end"}

--- prompt
In a RAG answer, citations are written as `[c<number>]`, for example `[c2]` or `[c10]`. Write `citation_report(answer, retrieved_ids)` that returns:

- `"cited"`: the citation ids in the answer (without the square brackets), in order of first appearance, duplicates removed
- `"unknown"`: the ids in cited that are not in `retrieved_ids` (in the order of cited)
- `"unused"`: the ids in `retrieved_ids` that are never cited (in the order of `retrieved_ids`)
- `"status"`: no citations at all → `"unsupported"`; any unknown → `"bad_citation"`; otherwise `"ok"`

Example: `citation_report("60 days [c1]. Fees [c2][c1].", ["c1", "c2", "c3"])` → `{"cited": ["c1", "c2"], "unknown": [], "unused": ["c3"], "status": "ok"}`
--- solution
import re

def citation_report(answer, retrieved_ids):
    cited = []
    for cid in re.findall(r"\[(c\d+)\]", answer):
        if cid not in cited:
            cited.append(cid)
    unknown = [c for c in cited if c not in retrieved_ids]
    unused = [c for c in retrieved_ids if c not in cited]
    if not cited:
        status = "unsupported"
    elif unknown:
        status = "bad_citation"
    else:
        status = "ok"
    return {"cited": cited, "unknown": unknown, "unused": unused, "status": status}

--- context
Closed book: write the quote check. Lawyers trust quoted text the most, so every quote must be found in a chunk it cites; the resulting score can go into the eval report, next to the other metrics.
--- prompt
Write `groundedness(answer, chunks)`:

- `chunks`: a dictionary, chunk id → chunk text, like `{"c1": "Either party may ...", "c2": "..."}`
- Quotes: the text in the answer between straight double quotes `"…"`, with spaces at both ends removed; empty ones are ignored
- Citations: the `[c<number>]` in the answer
- A quote is **supported** when, after normalizing (all whitespace collapsed into single spaces, everything lowercase), it is part of some (normalized) chunk **that the answer cites**. Citing an id that isn't in chunks gives no support
- Return `{"quotes": <number of quotes>, "unsupported": [<the unsupported quotes as written, in order of appearance>], "score": <number of supported quotes> / <number of quotes>, rounded to 2 decimal places}`; when there are no quotes, `score` is `1.0`
--- solution
import re

def norm(s):
    return " ".join(s.split()).lower()

def groundedness(answer, chunks):
    cited = re.findall(r"\[(c\d+)\]", answer)
    sources = [norm(chunks[c]) for c in cited if c in chunks]
    quotes = [q.strip() for q in re.findall(r'"([^"]*)"', answer) if q.strip()]
    unsupported = [q for q in quotes if not any(norm(q) in s for s in sources)]
    if not quotes:
        return {"quotes": 0, "unsupported": [], "score": 1.0}
    score = round((len(quotes) - len(unsupported)) / len(quotes), 2)
    return {"quotes": len(quotes), "unsupported": unsupported, "score": score}
