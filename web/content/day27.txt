title: 从脚本到服务：无状态、环境变量、健康检查
--- body
到现在为止，Clause Check 主要是一个命令行工具：在终端里运行，审完一份合同就退出。要让律所的人在网页上用，它得变成一个**服务**：一直在线，通过 HTTP 接收请求。项目里已经有了：`clausecheck/api.py` 是一个 FastAPI 应用，`GET /health` 回答「我还活着」，`POST /review` 接收上传的合同、返回报告 JSON。

上云之前，服务要满足三条：

- **无状态**：云会同时开好几个副本（实例），也会随时关掉一个、换一个新的。所以请求之间不能靠内存传东西：要记住的东西放进桶、数据库或队列
- **配置来自环境变量**：`config.py` 的 `Settings` 全部用 `os.getenv` 读；它调用的 `load_dotenv` 找不到 `.env` 时什么也不做，所以同一份代码在本机读 `.env`，在云上读平台设置的环境变量。模型名也是配置：`config.py` 默认用 `deepseek-flash`，部署时想换成 `deepseek-v4-pro`，设环境变量 `CLAUSECHECK_DEEPSEEK_MODEL` 就行，不用改代码（换了模型，`PRICES` 里要有它的单价，见第 28 天的成本卡片）
- **健康检查**：平台定期访问 `/health` 之类的地址，不健康的实例会被换掉

下面模拟两个实例，看看「记在内存里」在云上为什么会出错。
--- code
class Instance:
    """One copy of the service. The cloud may run several and replace them at any time."""

    def __init__(self, name):
        self.name = name
        self.reviewed = []                       # in memory: gone when the instance goes away

    def handle(self, contract_id, store):
        self.reviewed.append(contract_id)
        store.setdefault("reviewed", []).append(contract_id)   # shared: a bucket or a database
        return f"{self.name} reviewed {contract_id}"

store = {}
a, b = Instance("instance-a"), Instance("instance-b")
print(a.handle(101, store))
print(b.handle(102, store))
print(a.handle(103, store))
print("instance-a remembers:", a.reviewed)
print("instance-b remembers:", b.reviewed)
a = Instance("instance-a2")                      # the platform replaced instance-a
print("after the restart:", a.reviewed)
print("the shared store:", store["reviewed"])

title: Docker：镜像、容器和层缓存
--- body
云平台不关心你用什么语言，它要的是一个**容器镜像**：把代码、Python 和依赖包打成一个包，在哪台机器上跑都一样（「我电脑上是好的」这个问题就没了）。

- **镜像（image）**：打好的包，只读；**容器（container）**：镜像运行起来的一个实例
- **Dockerfile**：打包的步骤清单，每一步生成一**层**（layer）。重新打包时，没变的层直接用缓存；某一层一变，**它后面的所有层都要重做**

Clause Check 的 Dockerfile 大致是这样：

```
FROM python:3.12-slim
ENV PYTHONUNBUFFERED=1
WORKDIR /app
COPY requirements.txt .
RUN pip install --no-cache-dir -r requirements.txt
COPY . .
CMD exec uvicorn clausecheck.api:app --host 0.0.0.0 --port ${PORT:-8080}
```

- 先只复制 `requirements.txt` 并装依赖，**再**复制代码：平时只改代码，装依赖那一层就一直走缓存（运行下面的代码对比）
- `--host 0.0.0.0`：uvicorn 默认只听 `127.0.0.1`，容器外面连不上。`${PORT:-8080}`：用平台给的端口，没有就 8080。`exec` 让 uvicorn 直接接收平台发来的停止信号
- `PYTHONUNBUFFERED=1`：`print` 的日志立刻输出，不在缓冲区里等
- `.dockerignore` 写明哪些文件不进镜像：`.env`（密钥）、`.git`、报告和缓存
- 本机：`docker build -t clausecheck-api .`，然后 `docker run -p 8080:8080 -e PORT=8080 clausecheck-api`
--- code
def rebuild(steps, changed):
    """Docker re-runs the first step whose inputs changed, and every step after it."""
    out, dirty = [], False
    for step, inputs in steps:
        dirty = dirty or any(f in changed for f in inputs)
        out.append(("REBUILD " if dirty else "cached  ") + step)
    return out

CODE = ["requirements.txt", "clausecheck/api.py", "clausecheck/review.py"]
GOOD = [
    ("FROM python:3.12-slim", []),
    ("COPY requirements.txt .", ["requirements.txt"]),
    ("RUN pip install -r requirements.txt   (~2 min)", []),
    ("COPY . .", CODE),
]
BAD = [
    ("FROM python:3.12-slim", []),
    ("COPY . .", CODE),
    ("RUN pip install -r requirements.txt   (~2 min)", []),
]
for name, steps in [("good order", GOOD), ("bad order", BAD)]:
    print(f"{name}, you edited review.py:")
    for line in rebuild(steps, {"clausecheck/review.py"}):
        print("  " + line)

title: Cloud Run：跑你的容器，按请求扩缩
--- body
**Cloud Run**（GCP）运行你的容器镜像，替你管 HTTPS、机器和扩缩容。AWS 上跑容器对应的是 ECS on Fargate（旧资料里常见的 App Runner 从 2026 年 4 月底起不再接受新客户，AWS 建议迁到 ECS 的 Express Mode）；Lambda 是另一种思路（下一张卡片）。你只要遵守一条约定：**监听环境变量 `PORT` 给的端口**（默认 8080），地址用 `0.0.0.0`。

- **扩缩容**：没有请求时可以缩到 0 个实例（不花钱）；请求多了自动加实例。`--max-instances` 设上限，流量暴涨时账单不会跟着暴涨
- **并发**：一个实例同时处理多个请求（1 个 vCPU 时默认 80 个，最多可以调到 1000）。LLM 调用大部分时间在等网络，并发高很划算
- **冷启动**：从 0 到第一个实例启动好，第一批请求要多等几秒（导入 langgraph 这类大包更慢）。`--min-instances 1` 让一个实例一直开着，代价是一直计费
- **请求超时**：默认 5 分钟，最长可以设到 60 分钟（写这课时的数字，以官方文档为准）
- 默认设置下，**只有在处理请求时才给 CPU**：返回响应以后还在后台干活，是靠不住的

部署命令读得懂就行（`--set-secrets` 把 Secret Manager 里的密钥注入成环境变量）：

```
gcloud run deploy clausecheck-api --source . --region europe-north1 \
  --service-account clausecheck-api@clausecheck-dev.iam.gserviceaccount.com \
  --set-secrets DEEPSEEK_API_KEY=deepseek-api-key:latest \
  --max-instances 5 --no-allow-unauthenticated
```
--- code
import math
import os

port = int(os.environ.get("PORT", "8080"))
print(f"uvicorn clausecheck.api:app --host 0.0.0.0 --port {port}")

def instances_needed(requests_per_second, seconds_per_request, concurrency=80):
    in_flight = requests_per_second * seconds_per_request     # requests being handled at the same moment
    return math.ceil(in_flight / concurrency)

print(instances_needed(2, 6))                    # 2 clause reviews per second, 6 s each (mostly waiting for the LLM)
print(instances_needed(50, 6))
print(instances_needed(50, 6, concurrency=1))    # one request per instance: many more instances

title: AWS Lambda：一个事件，调用一次函数
--- body
**Lambda** 运行的不是一个一直在线的服务，而是**一个函数**：来一个事件，调用一次。Python 的入口长这样：

```python
def lambda_handler(event, context):
    return {"statusCode": 200, "headers": {"Content-Type": "application/json"}, "body": json.dumps({...})}
```

- `event` 是一个字典，形状由触发它的服务决定：S3 上传、SQS 消息、API Gateway 转来的 HTTP 请求……
- API Gateway（REST API 的 proxy 集成）给的事件里有 `httpMethod`、`path`、`headers`、`body`。**`body` 是字符串**（也可能是 `None`），要自己 `json.loads`；`isBase64Encoded` 为真时还要先 base64 解码。HTTP API 的新版事件格式字段名不同，以文档为准
- 返回值里的 `body` **也必须是字符串**：`json.dumps(...)`，不能直接放字典
- 超时默认 3 秒，最长 15 分钟；按调用次数和运行时长（乘以内存大小）计费；同样有冷启动
- 经过 API Gateway 的 HTTP 请求还有自己的上限：REST API 默认最多等 **29 秒**（以官方文档为准）。所以 HTTP 入口只做快的事，慢活交给队列（下一张卡片）
- 模块顶层的代码（import、建 client、读密钥）每个实例只运行一次，之后的调用都复用：client 和缓存放在函数外面

TypeScript（Node.js 运行时）的写法是 `export const handler = async (event) => { ... }`，返回同样形状的对象。
--- code
import json

def lambda_handler(event, context):
    body = json.loads(event.get("body") or "{}")
    clause_id = body.get("clause_id", "unknown")
    return {
        "statusCode": 200,
        "headers": {"Content-Type": "application/json"},
        "body": json.dumps({"clause_id": clause_id, "verdict": "flag"}),
    }

event = {
    "httpMethod": "POST",
    "path": "/review",
    "headers": {"Content-Type": "application/json"},
    "body": '{"clause_id": "8.1", "text": "Liability is unlimited."}',
    "isBase64Encoded": False,
}
resp = lambda_handler(event, None)
print(resp["statusCode"], type(resp["body"]).__name__)
print(resp["body"])
print(json.loads(resp["body"])["verdict"])

title: 事件和队列：至少送达一次
cloud: yes
--- body
审一份合同要好几分钟，不能让上传请求一直等着。常见的做法是把工作**交给队列**：

合同上传到桶 → 桶发出「对象已创建」**事件** → 事件变成队列里的一条**消息** → **worker** 取出消息、审查、写报告

- AWS：S3 事件通知 → SQS 队列 → Lambda 或容器里的 worker
- GCP：GCS 通知 → Pub/Sub 主题（或 Eventarc）→ Cloud Run 上的 worker

队列（还有 S3 的事件通知本身）保证的是**至少一次**（at-least-once）：同一条消息可能被送来**不止一次**，SQS 的标准队列也不保证顺序。SQS 的消息被取走后先「隐身」一段时间（visibility timeout，默认 30 秒）；worker 处理成功后**删除**它（Pub/Sub 叫 ack），没删的话，时间一到它会重新出现，交给下一个 worker。这就是免费的自动重试，但也意味着：

- **处理成功之后才删除**。先删后处理，worker 一崩，消息就丢了
- worker 必须**幂等**（第 17 天）：用固定的 key（比如 `job_id`）记下做完的工作，同一条消息再来就跳过
- 一直失败的消息不能无限重来：设最大接收次数，超过就移进**死信队列**（dead-letter queue，DLQ），等人来看
- `receive_message` 默认是**短轮询**：马上返回，队列里明明有消息也可能拿到空的。worker 一般加 `WaitTimeSeconds=20`（**长轮询**：最多等 20 秒，有消息就立刻返回），空响应更少，也更省钱

本页的 boto3 / google-cloud 是模拟的：调用写法和返回结构与真 SDK 一致（只实现了课程用到的部分）；真项目里 `pip install` 后配置凭证即可。`CLOUD.advance(秒数)` 只有模拟里才有，它让模拟的时钟往前走。
--- code
import json
import boto3

sqs = boto3.client("sqs", region_name="eu-north-1")
url = sqs.create_queue(QueueName="review-jobs")["QueueUrl"]
for cid in (103, 104):
    sqs.send_message(QueueUrl=url, MessageBody=json.dumps({"job_id": f"review-{cid}", "contract_id": cid}))

got = sqs.receive_message(QueueUrl=url, MaxNumberOfMessages=10, WaitTimeSeconds=20).get("Messages", [])
print("received:", [json.loads(m["Body"])["job_id"] for m in got])
sqs.delete_message(QueueUrl=url, ReceiptHandle=got[0]["ReceiptHandle"])   # 103 done; the worker crashed on 104
print("right away:", sqs.receive_message(QueueUrl=url).get("Messages", []))

CLOUD.advance(31)                                # 模拟：31 秒过去，隐身时间到了
again = sqs.receive_message(QueueUrl=url, MessageSystemAttributeNames=["ApproximateReceiveCount"]).get("Messages", [])
for m in again:
    print("again:", json.loads(m["Body"])["job_id"], "receive count", m["Attributes"]["ApproximateReceiveCount"])

title: 托管大模型：Bedrock 和 Vertex AI
cloud: yes
--- body
Clause Check 现在直接调 DeepSeek。很多公司（尤其处理合同这种敏感数据时）更愿意用自己云里的**托管大模型**：AWS 的 **Bedrock**、GCP 的 **Vertex AI**（Gemini）。原因：数据留在自己的云账号和选定的区域里；谁能调哪个模型由 IAM 管，不用再保管一把单独的 API 密钥；账单、日志、监控都在一起。

套路和第 4 天一样：发消息、要 JSON、校验、重试、记 token。

- Bedrock 的 `converse` 是统一的对话接口，换模型只换 `modelId`。每条消息的 `content` 是**块的列表** `[{"text": ...}]`；系统提示单独放在 `system=[{"text": ...}]`，不是一条 system 消息；参数在 `inferenceConfig`（驼峰命名：`maxTokens`）。回答在 `resp["output"]["message"]["content"]`，`stopReason` 是 `"max_tokens"` 说明被截断了
- 新模型常常要用**推理配置**（inference profile）的 ID 来调用，比如以 `eu.` 开头的 ID 只在欧盟区域之间路由；以 `global.` 开头的可能把请求发到全世界任何区域，合同数据不要用它
- google-genai：`genai.Client(vertexai=True, project=..., location=...)`。不写 `location` 时默认是 `global`，要在欧盟处理就明确写一个欧盟区域（哪个模型在哪些区域可用，以 Vertex AI 文档为准）。它的错误是自己的 `google.genai.errors.APIError`（`e.code` 是 429、503……），而且**默认不重试**
- 名字会变：Vertex AI 在 2026 年 4 月改名为 Gemini Enterprise Agent Platform（API 没变；新版 google-genai 的文档写 `enterprise=True`，`vertexai=True` 仍然能用）。模型 ID 也会过时：下面的 `eu.amazon.nova-lite-v1:0`、`gemini-2.5-flash` 只是示例（Google 已经公布了 gemini-2.5 系列在 2026 年的退役日期）。写代码前去 Bedrock 控制台、Google Cloud 控制台的模型列表查当前能用的名字，并把它放进配置，不要写死在代码里

本页的 Bedrock 和 Gemini 是模拟的：请求里提到 JSON 时，按和模拟 DeepSeek 类似的关键词规则给出判定（比如 `unlimited` → redline / high）。
--- code
import json
import boto3
from google import genai
from google.genai import types

SYSTEM = "You review contract clauses. Reply with JSON: clause_id, verdict, risk_level."
CLAUSE = "Review clause 8.1: Liability of the Customer is unlimited."

bedrock = boto3.client("bedrock-runtime", region_name="eu-north-1")
resp = bedrock.converse(
    modelId="eu.amazon.nova-lite-v1:0",
    system=[{"text": SYSTEM}],
    messages=[{"role": "user", "content": [{"text": CLAUSE}]}],
    inferenceConfig={"maxTokens": 300, "temperature": 0},
)
print(resp["stopReason"], resp["usage"])
print(json.loads(resp["output"]["message"]["content"][0]["text"]))

gemini = genai.Client(vertexai=True, project="clausecheck-dev", location="europe-north1")
r = gemini.models.generate_content(
    model="gemini-2.5-flash",
    contents=CLAUSE,
    config=types.GenerateContentConfig(system_instruction=SYSTEM, response_mime_type="application/json", temperature=0),
)
print(r.usage_metadata.prompt_token_count, r.usage_metadata.candidates_token_count)
print(json.loads(r.text))

title: 结构化日志和告警
--- body
线上没有人盯着终端。服务把日志写到**标准输出**，平台自动收集：Cloud Run 的进 Cloud Logging，Lambda 的进 CloudWatch Logs。

日志要**一行一个 JSON 对象**（结构化日志），而不是随手 `print("done 8.1")`：这样才能按字段查询和统计，比如「过去一小时 ERROR 有几条」「v2 提示词的平均延迟是多少」。

- 每条都带上 `severity`（INFO / WARNING / ERROR）和 `message`，再加排查要用的字段：`trace_id`、`contract_id`、`clause_id`、`tokens`、`latency_ms`
- Cloud Logging 会认出 JSON 里的 `severity` 和 `message`，当成这条日志的级别和正文；CloudWatch Logs Insights 也能按 JSON 字段查询
- `json.dumps(..., sort_keys=True)` 让字段顺序固定，人看着整齐，也方便比较
- **不要**记合同全文、个人数据、密钥：日志保存得久，能看的人也多

有了日志，再设**告警**：错误率、p95 延迟、每天的 token 花费超过阈值时通知人。
--- code
import json

def log(severity, message, **fields):
    print(json.dumps({"severity": severity, "message": message, **fields}, sort_keys=True))

log("INFO", "clause reviewed", trace_id="t-7f3a", contract_id=103, clause_id="8.1", verdict="redline", tokens=2205, latency_ms=3563)
log("ERROR", "model call failed", trace_id="t-9c1d", contract_id=109, clause_id="8.1", error="ThrottlingException")

lines = [
    '{"severity": "INFO", "latency_ms": 1296}',
    '{"severity": "ERROR", "latency_ms": 30000}',
    '{"severity": "INFO", "latency_ms": 3563}',
    '{"severity": "INFO", "latency_ms": 2149}',
]
records = [json.loads(line) for line in lines]
errors = sum(1 for r in records if r["severity"] == "ERROR")
print(f"error rate {errors / len(records):.0%}, slowest {max(r['latency_ms'] for r in records)} ms")

title: 上线清单和回滚
--- body
上线前过一遍这张单子。面试时被问「你怎么部署它」，也按这个顺序讲：

1. **密钥**不在代码和镜像里，来自 Secret Manager / Secrets Manager
2. **运行身份**是专用的服务账号 / 角色，最小权限（第 26 天）
3. **区域**在欧盟：服务、桶、日志、模型调用都是
4. **上限**：最大实例数、每条条款的步数和 token 上限（第 17 天）、预算告警
5. **可观测**：结构化日志，错误率和延迟的告警，追踪（Langfuse）
6. **回滚**：Cloud Run 每次部署生成一个新的**修订版本**（revision），流量可以先分 10% 给新版本试一试，出问题就切回旧版本，不用重新构建（`gcloud run services update-traffic`）；Lambda 用版本加别名（alias）做同样的事。镜像用固定的标签，不要用 `latest`
7. **健康检查**：`/health` 能回答

两分钟讲清楚一个架构：它做什么 → 请求怎么流动（上传 → 队列 → worker → 报告）→ 数据在哪里、谁能访问 → 失败了怎么办（重试、幂等、死信队列）→ 花多少钱、上限在哪里。
--- code
def route(traffic):
    return ", ".join(f"{rev}: {pct}%" for rev, pct in traffic.items())

traffic = {"clausecheck-api-00012": 100}
print("before:  ", route(traffic))
traffic = {"clausecheck-api-00012": 90, "clausecheck-api-00013": 10}   # canary: 10% try the new revision
print("canary:  ", route(traffic))

error_rate = {"clausecheck-api-00012": 0.004, "clausecheck-api-00013": 0.09}   # from the structured logs
if error_rate["clausecheck-api-00013"] > 2 * error_rate["clausecheck-api-00012"]:
    traffic = {"clausecheck-api-00012": 100}   # roll back: no rebuild, just move the traffic
    print("rollback:", route(traffic))

level: 1

--- context

import json

def review_clause(clause_id, text):
    """The real one calls the LLM. Tests pass their own."""
    return {"clause_id": clause_id, "verdict": "flag", "risk_level": "medium"}

def respond(status, payload):
    return {"statusCode": status, "headers": {"Content-Type": "application/json"}, "body": json.dumps(payload)}

def lambda_handler(event, context, review=review_clause):
    try:
        data = json.loads(event.get("body") or "")
    except json.JSONDecodeError:
        return respond(400, {"error": "body must be a JSON object"})
    if not isinstance(data, dict):
        return respond(400, {"error": "body must be a JSON object"})
    text = data.get("text")
    if not isinstance(text, str) or not text.strip():
        return respond(400, {"error": "text is required"})
    return respond(200, review(data.get("clause_id", "unknown"), text))

from urllib.parse import unquote_plus

def parse_s3_event(event):
    out = []
    for record in event.get("Records", []):
        if not record["eventName"].startswith("ObjectCreated:"):
            continue
        bucket = record["s3"]["bucket"]["name"]
        key = unquote_plus(record["s3"]["object"]["key"])
        out.append((bucket, key))
    return out

import json

def process_batch(sqs, queue_url, handle, seen):
    counts = {"done": 0, "skipped": 0, "failed": 0}
    resp = sqs.receive_message(QueueUrl=queue_url, MaxNumberOfMessages=10)
    for msg in resp.get("Messages", []):
        job = json.loads(msg["Body"])
        if job["job_id"] in seen:
            sqs.delete_message(QueueUrl=queue_url, ReceiptHandle=msg["ReceiptHandle"])
            counts["skipped"] += 1
            continue
        try:
            handle(job)
        except Exception:
            counts["failed"] += 1
            continue
        seen.add(job["job_id"])
        sqs.delete_message(QueueUrl=queue_url, ReceiptHandle=msg["ReceiptHandle"])
        counts["done"] += 1
    return counts

import json

MODEL_ID = "eu.amazon.nova-lite-v1:0"
SYSTEM = "You review contract clauses against a playbook. Reply with JSON only: clause_id, verdict, risk_level."
VERDICTS = ("accept", "flag", "redline")

def review_with_bedrock(client, clause_id, text):
    resp = client.converse(
        modelId=MODEL_ID,
        system=[{"text": SYSTEM}],
        messages=[{"role": "user", "content": [{"text": f"Review clause {clause_id}: {text}"}]}],
        inferenceConfig={"maxTokens": 300, "temperature": 0},
    )
    if resp["stopReason"] == "max_tokens":
        raise ValueError("truncated")
    blocks = resp["output"]["message"]["content"]
    data = json.loads("".join(b["text"] for b in blocks if "text" in b))
    if data["verdict"] not in VERDICTS:
        raise ValueError(f"bad verdict: {data['verdict']}")
    return {"clause_id": data["clause_id"], "verdict": data["verdict"], "risk_level": data["risk_level"],
            "tokens": resp["usage"]["totalTokens"]}

import json
from google.genai import types, errors

SYSTEM = "You review contract clauses against a playbook. Reply with JSON: clause_id, verdict, risk_level."

def review_with_gemini(client, clause_id, text, sleep, model="gemini-2.5-flash"):
    config = types.GenerateContentConfig(system_instruction=SYSTEM, response_mime_type="application/json", temperature=0)
    for attempt in range(3):
        try:
            response = client.models.generate_content(model=model, contents=f"Review clause {clause_id}: {text}", config=config)
            break
        except errors.APIError as e:
            if e.code not in (429, 503) or attempt == 2:
                raise
            sleep(attempt + 1)
    if response.text is None:
        raise ValueError("empty response")
    data = json.loads(response.text)
    usage = response.usage_metadata
    return {"clause_id": data["clause_id"], "verdict": data["verdict"], "risk_level": data["risk_level"],
            "tokens": usage.prompt_token_count + usage.candidates_token_count}

import json

SEVERITIES = ("DEBUG", "INFO", "WARNING", "ERROR")
SECRET_FIELDS = ("text", "contract_text", "api_key")

def log_event(message, severity="INFO", **fields):
    severity = severity.upper()
    if severity not in SEVERITIES:
        raise ValueError(f"bad severity: {severity}")
    record = {"severity": severity, "message": message}
    for name, value in fields.items():
        record[name] = "[redacted]" if name in SECRET_FIELDS else value
    print(json.dumps(record, sort_keys=True, ensure_ascii=False))

import { z } from "zod";

type ApiEvent = { httpMethod: string; path: string; headers: Record<string, string>; body: string | null; isBase64Encoded: boolean };
type ApiResult = { statusCode: number; headers: Record<string, string>; body: string };

const ReviewRequest = z.object({
  clause_id: z.string().default("unknown"),
  text: z.string().min(1),
});

function reviewClause(text: string): "accept" | "flag" | "redline" {
  return /unlimited/i.test(text) ? "redline" : "accept";
}

function respond(statusCode: number, payload: unknown): ApiResult {
  return { statusCode, headers: { "Content-Type": "application/json" }, body: JSON.stringify(payload) };
}

export const handler = async (event: ApiEvent): Promise<ApiResult> => {
  if (event.httpMethod !== "POST") {
    return respond(405, { error: "method not allowed" });
  }
  if (event.body === null) {
    return respond(400, { error: "body must be JSON" });
  }
  let raw: unknown;
  try {
    raw = JSON.parse(event.body);
  } catch {
    return respond(400, { error: "body must be JSON" });

import json

def review_clause(clause_id, text):
    return {"clause_id": clause_id, "verdict": "accept"}

def respond(status, payload):
    return {"statusCode": status, "headers": {"Content-Type": "application/json"}, "body": json.dumps(payload)}

def lambda_handler(event, context, review=review_clause):
    if event.get("path") != "/review":
        return respond(404, {"error": "not found"})
    if event.get("httpMethod") != "POST":
        return respond(405, {"error": "method not allowed"})
    body = event.get("body")
    if body is not None and event.get("isBase64Encoded"):
        body = base64.b64decode(body).decode("utf-8")
    try:
        data = json.loads(body or "")
    except json.JSONDecodeError:

    if not isinstance(data, dict):

    text = data.get("text")

    if not isinstance(text, str) or not text.strip() or not isinstance(clause_id, str):

import json

def drain(sqs, queue_url, handle, done, dead):
    finished = []
    for _ in range(10):
        resp = sqs.receive_message(QueueUrl=queue_url, MaxNumberOfMessages=10, WaitTimeSeconds=20,
                                   MessageSystemAttributeNames=["ApproximateReceiveCount"])
        messages = resp.get("Messages", [])
        if not messages:
            break
        for msg in messages:
            job = json.loads(msg["Body"])
            receipt = msg["ReceiptHandle"]
            if job["job_id"] in done:
                sqs.delete_message(QueueUrl=queue_url, ReceiptHandle=receipt)
                continue
            if int(msg["Attributes"]["ApproximateReceiveCount"]) > 3:
                dead.append(msg["Body"])
                sqs.delete_message(QueueUrl=queue_url, ReceiptHandle=receipt)
                continue
            try:
                handle(job)
            except Exception:
                continue
            done.add(job["job_id"])
            sqs.delete_message(QueueUrl=queue_url, ReceiptHandle=receipt)
            finished.append(job["job_id"])
    return finished

- `botocore.exceptions.ClientError` 的错误码是 `ThrottlingException` 或 `ServiceUnavailableException` 时重试：最多一共调用 4 次，第 `i` 次失败后（`i` 从 0 开始）`sleep(2 ** i)`；第 4 次还失败就把错误抛出去。其他错误马上抛出
- 拿到回答以后：`stopReason` 是 `"max_tokens"`（被截断了，就算文字碰巧能解析也不信）、`content[0]["text"]` 不是合法 JSON、或者 `verdict` 不在 `("accept", "flag", "redline")` 里，都**不要报错**，而是返回兜底结果 `{"clause_id": clause_id, "verdict": "flag", "risk_level": "medium", "fallback": True}`（拿不准就交给人看，这是 Clause Check 的原则）
- 否则返回 `{"clause_id": clause_id, "verdict": ..., "risk_level": ..., "fallback": False}`
--- solution
import json
from botocore.exceptions import ClientError

RETRY_CODES = ("ThrottlingException", "ServiceUnavailableException")
VERDICTS = ("accept", "flag", "redline")

def review_clause_bedrock(client, clause_id, text, sleep):
    for i in range(4):
        try:
            resp = client.converse(
                modelId="eu.amazon.nova-lite-v1:0",
                system=[{"text": "Reply with JSON only: clause_id, verdict, risk_level."}],
                messages=[{"role": "user", "content": [{"text": f"Review clause {clause_id}: {text}"}]}],
                inferenceConfig={"maxTokens": 200, "temperature": 0},
            )
            break
        except ClientError as e:
            if e.response["Error"]["Code"] not in RETRY_CODES or i == 3:
                raise
            sleep(2 ** i)
    fallback = {"clause_id": clause_id, "verdict": "flag", "risk_level": "medium", "fallback": True}
    if resp["stopReason"] == "max_tokens":
        return fallback
    try:
        data = json.loads(resp["output"]["message"]["content"][0]["text"])
    except json.JSONDecodeError:
        return fallback
    if data.get("verdict") not in VERDICTS:
        return fallback
    return {"clause_id": clause_id, "verdict": data["verdict"], "risk_level": data.get("risk_level"), "fallback": False}

import boto3
from botocore.config import Config
from botocore.exceptions import ClientError
BR = boto3.client("bedrock-runtime", region_name="eu-north-1", config=Config(retries={"total_max_attempts": 1}))
def run(fails=0, kind="throttle"):
    CLOUD.queue.clear()
    CLOUD.fail_next("bedrock-runtime", kind, fails)
    delays = []
    try:
        out = review_clause_bedrock(BR, "8.1", "Liability of the Customer is unlimited.", delays.append)
    except ClientError as e:
        out = e.response["Error"]["Code"]
    return out, delays
RED = {"clause_id": "8.1", "verdict": "redline", "risk_level": "high", "fallback": False}
expect("限流 2 次、503 一次后成功", lambda: (run(2), run(1, "unavailable")), ((RED, [1, 2]), (RED, [1])))
expect("一直限流：调用 4 次后抛出", lambda: run(9), ("ThrottlingException", [1, 2, 4]))
