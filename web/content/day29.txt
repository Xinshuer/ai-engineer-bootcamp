title: 为什么要框架（以及什么时候不要）
--- body
第 4 天你亲手写过一次调用：拼 URL、带 `Authorization` 请求头、组 JSON 请求体、从 `choices[0]["message"]["content"]` 取回答。LangChain 把这些包进一个**聊天模型对象**：

```python
model = ChatDeepSeek(model="deepseek-flash")
reply = model.invoke("Review clause 3.1 ...")   # 返回 AIMessage
```

好处：换供应商基本只换这一行（`ChatOpenAI`、`ChatAnthropic` 用法一样）；消息、模板、重试、流式、token 统计、工具、结构化输出都有统一的写法。代价：多了好几层，报错的 Traceback 很长；而且变得快：2025 年 10 月发布 1.0，旧教程里的 `LLMChain`、`langchain.chains` 在 1.x 的 `langchain` 包里已经没有了（1.0 把很多旧模块挪进了 `langchain-classic`）。

Clause Check 的选择（见 README）：审查流程是线性的，plain Python 就够；只有「暂停等人批准、换个进程再继续」才用了 LangGraph。

下面两段代码发出的是同一个请求（LangChain 只多写了一个 `"stream": False`）。`MOCK.calls[-1]["body"]` 就是 LangChain 真正发出去的 JSON，这一周会经常看它。
--- code
import os
import requests
import langchain
import langchain_core
from langchain_deepseek import ChatDeepSeek

question = "Review clause 3.1: Fees are due in 30 days."

# 第 4 天：手写
URL = "https://api.deepseek.com/v1/chat/completions"
headers = {"Authorization": f"Bearer {os.getenv('DEEPSEEK_API_KEY')}"}
body = {"model": "deepseek-flash", "messages": [{"role": "user", "content": question}]}
data = requests.post(URL, headers=headers, json=body).json()

# LangChain：地址、请求头、密钥（读环境变量 DEEPSEEK_API_KEY）、解析，都由它做
model = ChatDeepSeek(model="deepseek-flash")
reply = model.invoke(question)
print("LangChain:", reply.content)
print("它发出的请求体：", MOCK.calls[-1]["body"])

@@ concept
title: AIMessage 和思考模式
--- body
`invoke` 返回 `AIMessage`，常用的几处：

- `.content`：回答文字
- `.usage_metadata`：`input_tokens`、`output_tokens`、`total_tokens`，还有 `input_token_details["cache_read"]`（命中缓存的输入）和 `output_token_details` 里的 `"reasoning"`（思考用掉的 token；没有思考时这个字典可能是空的，所以用 `.get("reasoning", 0)`）
- `.response_metadata["finish_reason"]`：为什么停

DeepSeek V4 的**思考模式默认是开着的**：回答之前先想，想的过程放在 `additional_kwargs["reasoning_content"]`，**按输出 token 收费**，而且这时 `temperature` 不起作用。审查、分类这种短任务通常把它关掉，更快也更便宜：

```python
ChatDeepSeek(model="deepseek-flash", extra_body={"thinking": {"type": "disabled"}})
```

`extra_body` 里的内容会原样放进请求体（本页用的 langchain-deepseek 1.1 没有专门的思考参数）。`temperature=0` 只有关掉思考以后才有意义。

模型名：现在用 `deepseek-flash`（便宜、快）或 `deepseek-v4-pro`。旧教程里的 `deepseek-chat`、`deepseek-reasoner` 官方已经宣布从 2026-07-24 起停用；2026-09 实测还能调用（都由 `deepseek-flash` 回答），但模型列表里已经没有它们，随时可能失效，别再用。模型名写错时返回 400，错误信息是 `The supported API model names are deepseek-flash, deepseek-v4-pro, but you passed ...`。也可以按字符串选供应商：`init_chat_model("deepseek:deepseek-flash")`，得到的同样是 `ChatDeepSeek`。
--- code
from langchain_deepseek import ChatDeepSeek

QUESTION = "Review clause 8.1: Customer's liability shall be unlimited."
default = ChatDeepSeek(model="deepseek-flash")
fast = ChatDeepSeek(model="deepseek-flash", extra_body={"thinking": {"type": "disabled"}}, temperature=0)

msg = default.invoke(QUESTION)
print(type(msg).__name__, "|", msg.content)
print("finish_reason:", msg.response_metadata["finish_reason"])
print("thinking:", msg.additional_kwargs["reasoning_content"])
for name, model in [("thinking on ", default), ("thinking off", fast)]:
    u = model.invoke(QUESTION).usage_metadata
    print(f"{name}: output {u['output_tokens']} tokens, of which reasoning {u['output_token_details'].get('reasoning', 0)}")
print("sent:", {k: v for k, v in MOCK.calls[-1]["body"].items() if k != "messages"})

title: 消息
--- body
第 4 天的 `role` 变成了类：`SystemMessage`（system）、`HumanMessage`（user）、`AIMessage`（assistant），明天还有 `ToolMessage`。`invoke` 也接受简写：`[("system", "..."), ("user", "...")]`，或者第 4 天那样的字典。

**多轮对话**：模型自己什么都不记得，每一轮都要把**整段历史**发过去。做法：把模型回的 `AIMessage` 原样 append 进列表，再 append 下一条 `HumanMessage`。历史越长，每次请求的 token 越多（第 33 天学怎么裁剪）。

模型返回的每条 `AIMessage` 都带一个随机的 `id`（`lc_run--...`），每次运行都不一样（自己新建的消息 `id` 是 `None`）。所以测试里比较 `.content` 和 `type(m).__name__`，不要比较整条消息。
--- code
from langchain_core.messages import HumanMessage, SystemMessage
from langchain_deepseek import ChatDeepSeek

model = ChatDeepSeek(model="deepseek-flash", extra_body={"thinking": {"type": "disabled"}})

history = [
    SystemMessage("You review contract clauses for the Customer."),
    HumanMessage("Review clause 8.1: liability is unlimited."),
]
first = model.invoke(history)
history.append(first)                                   # 模型的回答原样放回去
history.append(HumanMessage("Now clause 9.2: fees are due in 30 days."))
second = model.invoke(history)

for m in history + [second]:
    print(f"{type(m).__name__:<14}{m.content}")
print("roles sent:", [m["role"] for m in MOCK.calls[-1]["body"]["messages"]])
print("shorthand:", model.invoke([("system", "You review contracts."), ("user", "Hi")]).content)
print("id:", first.id[:8] + "...（后面每次都不同）")

@@ concept
title: ChatPromptTemplate
--- body
第 12 天用 `str.format` 写过模板。LangChain 的模板是**一组消息模板**：

```python
prompt = ChatPromptTemplate.from_messages([("system", "You review clauses for the {party}."), ("user", "{text}")])
prompt.invoke({"party": "Customer", "text": "..."}).to_messages()
```

- `.invoke(字典)` 返回 `ChatPromptValue`，`.to_messages()` 取出消息列表
- `input_variables`：需要哪些变量（按字母排好序）。少给一个 → `KeyError`，信息里写着缺哪个
- 模板里要写 JSON 示例时，大括号写两遍 `{{ }}`，和第 12 天一样；**变量的值**里有大括号没关系，值不会再被当成模板
- `MessagesPlaceholder("history")`：在这个位置插进一整段历史消息
- `.partial(party="Customer")`：先填好一部分，返回一个新模板
--- code
from langchain_core.prompts import ChatPromptTemplate, MessagesPlaceholder

review = ChatPromptTemplate.from_messages([
    ("system", 'You review clauses for the {party}. Reply as JSON like {{"verdict": "accept"}}.'),
    ("user", "Review clause {clause_id}: {text}"),
])
print(review.input_variables)
value = review.invoke({"party": "Customer", "clause_id": "8.1", "text": "Pay {net 30}."})
print(type(value).__name__)
for m in value.to_messages():
    print(" ", type(m).__name__, "->", m.content)

try:
    review.invoke({"party": "Customer", "clause_id": "8.1"})
except KeyError as e:
    print("KeyError:", e.args[0].split(".")[0])

print(review.partial(party="Customer").input_variables)

chat = ChatPromptTemplate.from_messages([
    ("system", "You answer questions about one contract."),
    MessagesPlaceholder("history"),
    ("user", "{question}"),
])
msgs = chat.invoke({"history": [("user", "What is clause 8.1?"), ("assistant", "A liability cap.")], "question": "Is it mutual?"}).to_messages()
print([type(m).__name__ for m in msgs])

@@ concept
title: LCEL：用 | 串成一条链
--- body
LangChain 里几乎每个零件都是 **Runnable**：都有 `invoke`（一个输入）、`batch`（一批）、`stream`（流式）。`|` 把它们串成一条链，前一个的输出就是后一个的输入：

```
dict --prompt--> ChatPromptValue --model--> AIMessage --StrOutputParser()--> str
```

管道里放一个普通函数，它会被自动包成 `RunnableLambda`。整条链本身也是 Runnable，所以同样能 batch、stream、带回调。

运行下面的例子会看到 `StrOutputParser` 输出的类型名是 `TextAccessor`：它是 `str` 的子类（1.0 为了兼容旧写法加的），当普通字符串用就行，`==`、`.strip()`、`isinstance(x, str)` 都照常。

经典错误：顺序放反，比如 parser 放到了 model 前面。它收到的是 ChatPromptValue 而不是 AIMessage，报一个看不太懂的 `ValidationError`。**排错时看每一步的输入和输出类型**，下面的例子一步一步走给你看。
--- code
from langchain_core.messages import AIMessage
from langchain_core.output_parsers import StrOutputParser
from langchain_core.prompts import ChatPromptTemplate
from langchain_deepseek import ChatDeepSeek

prompt = ChatPromptTemplate.from_messages([("system", "You summarise clauses in one sentence."), ("user", "{text}")])
model = ChatDeepSeek(model="deepseek-flash", extra_body={"thinking": {"type": "disabled"}})
chain = prompt | model | StrOutputParser() | (lambda s: s.upper())

print(type(chain).__name__, [type(s).__name__ for s in chain.steps])
value = {"text": "Fees are due in 30 days."}
for step in chain.steps:           # 手动走一遍管道，看每一步输出什么类型
    value = step.invoke(value)
    print(f"  {type(step).__name__:<19}-> {type(value).__name__}")
print(chain.invoke({"text": "Fees are due in 30 days."}))

text = StrOutputParser().invoke(AIMessage("accept"))
print(type(text).__name__, isinstance(text, str), text == "accept")

@@ concept
title: stream 和 batch
--- body
- `chain.stream(输入)`：一块一块地给你，界面上就是打字机效果。链的最后是 `StrOutputParser` 时，每块是字符串。有些块是**空字符串**：开头（只带角色）和结尾（只带结束原因、用量）本来就有；思考模式开着时，前面还会多出一长串（思考的内容不属于回答）。显示时要跳过
- `chain.batch([输入1, 输入2, ...])`：结果的顺序和输入一样
- `return_exceptions=True`：出错的那一个位置放异常对象，其他照常返回（第 28 天的「单条失败不拖垮」）。不加的话，一个出错整批都抛异常
- `config={"max_concurrency": 3}`：最多同时 3 个请求。本页浏览器里没有线程，是一个接一个跑的；在本机上是真的并发

真实的 Web 服务里一般用异步版本：`await chain.ainvoke(...)`、`astream`、`abatch`。本页不能运行 asyncio，这里只提一下。
--- code
from langchain_core.output_parsers import StrOutputParser
from langchain_core.prompts import ChatPromptTemplate
from langchain_deepseek import ChatDeepSeek

prompt = ChatPromptTemplate.from_messages([("user", "{text}")])
off = prompt | ChatDeepSeek(model="deepseek-flash", extra_body={"thinking": {"type": "disabled"}}) | StrOutputParser()
on = prompt | ChatDeepSeek(model="deepseek-flash") | StrOutputParser()

print(list(off.stream({"text": "Summarise clause 9.2 on fees"})))
pieces = list(on.stream({"text": "Summarise clause 9.2 on fees"}))
print(len(pieces), "pieces with thinking on,", pieces.count(""), "of them empty")

inputs = [{"text": "Fees are due in 30 days."}, {"text": "Liability is unlimited."}, {"wrong_key": "x"}]
print(off.batch(inputs[:2]))
results = off.batch(inputs, return_exceptions=True, config={"max_concurrency": 2})
print(["ok" if isinstance(r, str) else type(r).__name__ for r in results])

@@ concept
title: Runnable 小积木
--- body
- `RunnableLambda(fn)`：把函数变成 Runnable（管道里的普通函数会自动包）
- `RunnableParallel(summary=链1, risk=链2)`，或者直接写字典 `{"summary": 链1, "risk": 链2}`：**同一个输入**同时交给几条链，结果合成一个字典
- `RunnablePassthrough.assign(words=fn)`：输入的字典原样保留，再加一个键（值可以是函数，也可以是一条链）

典型用法：一条条款同时要摘要和风险等级，两个请求互不依赖，可以并行。

提醒：不要为了用而用。一个普通的 Python 函数能写清楚的事，套三层 Runnable 只会让 Traceback 更长。
--- code
from langchain_core.output_parsers import StrOutputParser
from langchain_core.prompts import ChatPromptTemplate
from langchain_core.runnables import RunnableLambda, RunnableParallel, RunnablePassthrough
from langchain_deepseek import ChatDeepSeek

model = ChatDeepSeek(model="deepseek-flash", extra_body={"thinking": {"type": "disabled"}})
summary = ChatPromptTemplate.from_messages([("user", "Summarise: {text}")]) | model | StrOutputParser()
risk = ChatPromptTemplate.from_messages([("user", "Risk level of: {text}")]) | model | StrOutputParser()

brief = RunnableParallel(summary=summary, risk=risk)
print(brief.invoke({"text": "Liability is unlimited."}))

count = RunnablePassthrough.assign(words=lambda d: len(d["text"].split()))
print(count.invoke({"text": "Liability is unlimited."}))

pipeline = count | RunnableLambda(lambda d: f"{d['words']} words: {d['text']}")
print(pipeline.invoke({"text": "Fees are due in 30 days."}))

title: 测链不联网：假模型
--- body
第 19 天学过依赖注入：**把模型当参数传进来**（`build_chain(model)`），测试时传一个假的：

- `FakeListChatModel(responses=["a", "b"])`：按顺序返回，用完了从头再来
- `GenericFakeChatModel(messages=iter([AIMessage(...)]))`：用完就抛 `StopIteration`；stream 时按空格切块
- 任何 Runnable 都能当模型用：`RunnableLambda(fn)`，`fn` 拿到的是 ChatPromptValue，可以**根据输入决定回答**，还能顺便检查 prompt 对不对

限制：假模型不支持 `bind_tools`（`NotImplementedError`），明天测工具时用模拟服务器。

测什么：链里**你自己写的逻辑**（模板、解析、清洗）。模型答得好不好，是评测（第 13 天）的事。
--- code
from langchain_core.language_models.fake_chat_models import FakeListChatModel, GenericFakeChatModel
from langchain_core.messages import AIMessage
from langchain_core.output_parsers import StrOutputParser
from langchain_core.prompts import ChatPromptTemplate
from langchain_core.runnables import RunnableLambda

def build_chain(model):
    prompt = ChatPromptTemplate.from_messages([("system", "Answer with one word: accept, flag or redline."), ("user", "{text}")])
    return prompt | model | StrOutputParser() | (lambda s: s.strip().lower())

chain = build_chain(FakeListChatModel(responses=[" Redline\n", "accept"]))
print([chain.invoke({"text": "x"}) for _ in range(3)])

def by_rule(prompt_value):
    text = prompt_value.to_messages()[-1].content
    return AIMessage("redline" if "unlimited" in text else "accept")

chain = build_chain(RunnableLambda(by_rule))
print(chain.batch([{"text": "Liability is unlimited."}, {"text": "Fees are due."}]))
print("requests to the server:", len(MOCK.calls))

g = GenericFakeChatModel(messages=iter([AIMessage("flag this clause")]))
print([chunk.content for chunk in g.stream("x")])
try:
    FakeListChatModel(responses=["x"]).bind_tools([])
except NotImplementedError:
    print("bind_tools: NotImplementedError")

title: 思考用了多少 token
level: 2
cards: AIMessage 和思考模式
--- context
Clause Check 每审一条条款，都会记下用了多少 token（模型按它计费），成本统计要靠这些数字。换成 LangChain 以后，这些数字装在返回的消息对象里，要自己去取出来。
--- prompt
写 `token_report(model, question)`：用 `model` 回答一次 `question`，返回字典：

- `"answer"`：回答文字
- `"output"`：输出 token 总数（`usage_metadata["output_tokens"]`）
- `"reasoning"`：其中思考用掉的 token（`usage_metadata["output_token_details"]["reasoning"]`）
- `"thinking"`：回答里有没有思考过程（`additional_kwargs` 里有 `"reasoning_content"` 这个键就是 `True`）

数字不一定都在：思考关掉时回答里可能没有思考的 token 数（本页的模拟服务器这时就不发），`output_token_details` 是空字典；有些模型根本不报用量（比如测试用的假模型），`usage_metadata` 是 `None`。规则：`usage_metadata` 是 `None` 时 `output` 和 `reasoning` 都是 0；没有 `output_token_details` 或其中没有 `"reasoning"` 时，`reasoning` 是 0。

例：思考模式开着时，`token_report(model, "Review clause 3.1: fees.")` → `{"answer": "Mock reply: Review clause 3.1: fees.", "output": 68, "reasoning": 54, "thinking": True}`
--- starter
def token_report(model, question):
    msg = model.invoke(question)
    return {}
--- solution
def token_report(model, question):
    msg = model.invoke(question)
    usage = msg.usage_metadata or {}
    details = usage.get("output_token_details") or {}
    return {
        "answer": msg.content,
        "output": usage.get("output_tokens", 0),
        "reasoning": details.get("reasoning", 0),
        "thinking": "reasoning_content" in msg.additional_kwargs,

from langchain_core.runnables import RunnableLambda

def word_count(clause):
    if not clause.strip():
        raise ValueError("empty clause")
    return len(clause.split())

counter = RunnableLambda(word_count)
print(counter.invoke("Fees are due."))

except ValueError as e:
    print("without return_exceptions:", e)

    results = chain.batch(clauses, config={"max_concurrency": 4}, return_exceptions=True)

        recent = self.history[-self.max_history:] if self.max_history > 0 else []
        answer = self.chain.invoke({"history": recent, "question": question})
        self.history.append(HumanMessage(question))
        self.history.append(AIMessage(answer))
        return answer
