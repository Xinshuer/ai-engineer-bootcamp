title: class 基础
--- body
第 3 天你在 Python 里写过 class，TypeScript 几乎一一对应：

- `__init__` → `constructor`，`self` → `this`。方法里读字段**必须**写 `this.xxx`
- 字段要声明类型：`counts: Record<string, number> = {};`
- 创建对象要写 `new`：`const c = new VerdictCounter();`

构造函数的参数前加 `private readonly` 或 `readonly`，它会自动变成字段（叫**参数属性**），SDK 源码里很常见：

```ts
class Client {
  constructor(private readonly apiKey: string, readonly model = "deepseek-flash") {}
}
```

经典错误：方法里忘了写 `this.`，TypeScript 报 `Cannot find name 'counts'`。
--- code
class VerdictCounter {
  counts: Record<string, number> = {};

  add(verdict: string): void {
    this.counts[verdict] = (this.counts[verdict] ?? 0) + 1;
  }

  total(): number {
    return Object.values(this.counts).reduce((sum, n) => sum + n, 0);
  }
}

class Client {
  constructor(private readonly apiKey: string, readonly model = "deepseek-flash") {}

  describe(): string {
    return `${this.model} with key ${this.apiKey.slice(0, 3)}...`;
  }
}

const counter = new VerdictCounter();
for (const v of ["flag", "accept", "flag"]) {
  counter.add(v);
}
console.log(counter.counts, counter.total());
console.log(new Client("sk-123456").describe());

title: 私有状态和 getter
--- body
类的价值在于**守住规则**，比如「已用的 token 不能超过预算」。如果谁都能直接改 `used`，这条规则就守不住。

- `#used = 0`：真正的私有字段。类外面读写都不行，运行时也看不到（`Object.keys`、`JSON.stringify` 里都没有它）
- `private used = 0`：只在**编译时**禁止，运行时它还是一个普通字段
- getter：`get remaining(): number { ... }`，外面像读字段一样用 `budget.remaining`（不加括号），只能读不能改

新代码推荐用 `#`；读 SDK 源码时两种都会见到。修改状态只通过方法：方法里先检查，再修改。
--- code
class TokenBudget {
  #used = 0;
  constructor(readonly limit: number) {}

  get used(): number {
    return this.#used;
  }
  get remaining(): number {
    return this.limit - this.#used;
  }
  spend(n: number): boolean {
    if (n > this.remaining) {
      return false;
    }
    this.#used += n;
    return true;
  }
}

const budget = new TokenBudget(1000);
console.log(budget.spend(600), budget.spend(600), budget.remaining);
console.log(Object.keys(budget), JSON.stringify(budget));
// budget.remaining = 5; // 去掉注释试试：只有 getter，不能赋值

title: static 和工厂方法
--- body
`static` 方法属于**类本身**，用 `类名.方法()` 调用，不用先 new 一个对象。最常见的用途是**工厂方法**：从外部数据创建对象，创建之前先校验。

```ts
const pb = Playbook.fromJSON(JSON.parse(text)); // 数据不合格就 throw
```

好处：构造函数只接收已经合格的数据，脏数据在门口就被拦下，并且报一个清楚的错误。Clause Check 的 `clausecheck/playbook.py` 里 `Playbook.load(path)` 就是 Python 版的工厂方法（`@classmethod`），它先用 Pydantic 校验每一条规则，再创建 Playbook。

`static` 也可以是常量：`static readonly VERSION = "2026-09";`
--- code
interface Rule {
  id: string;
  topic: string;
}

class Playbook {
  static readonly VERSION = "2026-09";

  constructor(readonly rules: Rule[]) {}

  static fromJSON(raw: unknown): Playbook {
    if (typeof raw !== "object" || raw === null || !("rules" in raw) || !Array.isArray(raw.rules)) {
      throw new Error("playbook JSON needs a 'rules' array");
    }
    return new Playbook(raw.rules);
  }

  topics(): string[] {
    return this.rules.map((r) => r.topic);
  }
}

const pb = Playbook.fromJSON(JSON.parse('{"rules": [{"id": "PB-01", "topic": "liability_cap"}]}'));
console.log(pb.topics(), Playbook.VERSION);
try {
  Playbook.fromJSON({ items: [] });
} catch (e) {
  console.log(e instanceof Error ? e.message : e);
}

@@ concept
title: 自定义错误和 instanceof
--- body
调接口失败的方式很多：429 限流（等一下再试）、401 密钥错（重试没用）、500 服务器错。调用方要**分别处理**，所以给每种失败一个自己的错误类：

```ts
class ApiError extends Error {
  constructor(message: string, readonly status: number) {
    super(message);          // 必须先调用父类的构造函数
    this.name = "ApiError";  // 报错时显示的名字
  }
}
```

处理时用 `instanceof` 区分，**子类要先判断**（RateLimitError 也是一种 ApiError）。不认识的错误要继续 `throw e`，别吞掉。TypeScript 里 `catch (e)` 的 e 是 `unknown`，`instanceof` 检查同时也是收窄。

Clause Check 的 `review.py` 就是这样按类型捕获 Anthropic SDK 的 `RateLimitError`、`APIStatusError`。
--- code
class ApiError extends Error {
  constructor(message: string, readonly status: number) {
    super(message);
    this.name = "ApiError";
  }
}
class RateLimitError extends ApiError {
  constructor(message = "rate limited") {
    super(message, 429);
    this.name = "RateLimitError";
  }
}

function handle(e: unknown): string {
  if (e instanceof RateLimitError) {
    return `wait and retry (${e.status})`;
  }
  if (e instanceof ApiError) {
    return `give up: ${e.name} ${e.status} ${e.message}`;
  }
  throw e;
}

console.log(handle(new RateLimitError()));
console.log(handle(new ApiError("bad key", 401)));
const err = new RateLimitError();
console.log(err instanceof RateLimitError, err instanceof ApiError, err instanceof Error);
try {
  handle(new TypeError("x is undefined"));
} catch (e) {
  console.log("re-thrown:", e instanceof TypeError);
}

@@ concept
title: Result：失败也是一种返回值
--- body
throw 适合**意外**：程序 bug、缺配置、没法继续的情况。但有些失败是**预料之中**的：模型偶尔返回坏 JSON，200 条条款里有 3 条解析失败。这时更好的做法是把失败当成普通的返回值：

```ts
type Result<T> = { ok: true; value: T } | { ok: false; error: string };
```

它就是昨天学的可辨识联合：`if (r.ok)` 之后才能读 `r.value`。好处：函数签名直接告诉调用方「这里会失败」，调用方**忘不了**处理；批量处理时一条失败不会中断整批。

Zod 的 `safeParse` 返回 `{ success: true, data } | { success: false, error }`，是同一个设计。Clause Check 的 `review.py` 接住 SDK 抛出的错误，变成 `Step(stop="error", error=...)` 返回，也是这个思路。
--- code
type Result<T> = { ok: true; value: T } | { ok: false; error: string };

function parseScore(raw: string): Result<number> {
  const n = Number(raw);
  if (raw.trim() === "" || Number.isNaN(n)) {
    return { ok: false, error: `not a number: ${JSON.stringify(raw)}` };
  }
  return { ok: true, value: n };
}

for (const raw of ["0.8", "high", ""]) {
  const r = parseScore(raw);
  if (r.ok) {
    console.log("score", r.value * 100);
  } else {
    console.log("skip:", r.error);
  }
}

title: 依赖注入：把外部世界传进来
--- body
类里直接调用 `fetch`、`Date.now()`，测试时就只能真的联网、真的等时间。**依赖注入**：把这些依赖作为构造函数参数传进来，给一个真实的默认值；测试时传一个假的：

```ts
new DeepSeekClient(key);                  // 生产：用真的 fetch
new DeepSeekClient("sk-test", fakeFetch); // 测试：不联网，结果固定
```

这也是「组合优于继承」：客户端**拥有**一个 fetch 函数，而不是**继承**某个 HTTP 基类，换掉它不影响别的代码。第 13 天给 `measure` 传假时钟 `clock=fake_clock(...)`，就是同一个想法。Clause Check 的 `review.py` 里，审查循环 `model_review(backend, ...)` 只调用 `backend.step(...)` 等几个方法，传进来的是 Anthropic 后端还是 DeepSeek 后端都可以。
--- code
type Clock = () => number;

class Stopwatch {
  #start: number;
  constructor(private readonly now: Clock = () => Date.now()) {
    this.#start = now();
  }
  elapsedMs(): number {
    return this.now() - this.#start;
  }
}

// 测试用的假时钟：每调用一次前进 250 毫秒
let fakeTime = 1000;
const fakeClock: Clock = () => {
  fakeTime += 250;
  return fakeTime;
};
const sw = new Stopwatch(fakeClock);
console.log(sw.elapsedMs(), sw.elapsedMs());

const real = new Stopwatch();
console.log(real.elapsedMs() >= 0);

title: 模块：一个文件一件事
--- body
真实项目按职责拆文件，每个文件只做一件事：

- `types.ts`：类型和错误类（`Verdict`、`Result`、`ApiError`）
- `client.ts`：`DeepSeekClient`，只管 HTTP
- `review.ts`：审查逻辑，只依赖 types 和「客户端接口」
- `main.ts`：把它们组装起来

写法：`export class DeepSeekClient { ... }`，另一个文件 `import { DeepSeekClient } from "./client";`；只导入类型写 `import type { Verdict } from "./types";`。`class X implements ModelClient` 让编译器检查这个类确实有接口要求的方法。

规则：依赖只朝一个方向（main → review → client → types），**不要互相 import**。循环依赖会出现「用到时还是 undefined」这种怪 bug。本页每题只有一个文件，今天的本机任务会真的拆一次。
--- code
// ---- types.ts ----
type Verdict = "accept" | "flag" | "redline";
interface ClauseReview {
  id: string;
  verdict: Verdict;
}

// ---- client.ts ----（只管「怎么问模型」）
interface ModelClient {
  judge(text: string): Verdict;
}
class KeywordClient implements ModelClient {
  judge(text: string): Verdict {
    return text.includes("unlimited") ? "redline" : "accept";
  }
}

// ---- review.ts ----（只依赖 ModelClient 接口，不关心具体是哪个类）
function reviewAll(client: ModelClient, clauses: { id: string; text: string }[]): ClauseReview[] {
  return clauses.map((c) => ({ id: c.id, verdict: client.judge(c.text) }));
}

// ---- main.ts ----（组装）
const reviews = reviewAll(new KeywordClient(), [
  { id: "3.1", text: "Fees are due in 30 days." },
  { id: "8.1", text: "Liability is unlimited." },
]);
console.log(reviews.map((r) => `${r.id}: ${r.verdict}`).join(", "));

title: Map 和 Set
--- body
第 5 天用 `Record<string, T>` 当字典。`Map` 是专门的「键 → 值」容器，这些时候更合适：

- 键会经常增删，需要 `.size`
- 键不是字符串（数字、对象）
- 键来自外部数据：普通对象上 `"constructor"` 这类键会撞上内置属性，Map 不会

```ts
const byId = new Map<string, Rule>();
byId.set("PB-01", rule);
byId.get("PB-01"); // Rule | undefined：注意可能没有
byId.has("PB-02");
for (const [id, rule] of byId) { ... }
const seen = new Map([["8.1", "redline"]]); // 也可以用 [键, 值] 对的数组一次建好
```

`Set` 是「不重复的集合」：`new Set(ids)` 去重，`.has(x)` 查得很快，`.add(x)` 添加，`[...set]` 转回数组。Map 和 Set 都按**插入顺序**遍历。
--- code
interface Rule {
  id: string;
  topic: string;
}
const rules: Rule[] = [
  { id: "PB-01", topic: "liability_cap" },
  { id: "PB-02", topic: "auto_renewal" },
  { id: "PB-07", topic: "liability_cap" },
];
const byId = new Map<string, Rule>();
for (const r of rules) {
  byId.set(r.id, r);
}
console.log(byId.size, byId.has("PB-02"), byId.get("PB-99"));
console.log(byId.get("PB-07")?.topic);

const topics = new Set(rules.map((r) => r.topic));
console.log(topics.size, [...topics]);

const verdicts = new Map([["8.1", "redline"], ["3.1", "accept"]]);
console.log(verdicts.get("8.1"), [...verdicts.keys()]);

const plain: Record<string, number> = {};
console.log("constructor" in plain, new Map<string, number>().has("constructor"));

复习第 15 天。`Step` 是模型一次回复的三种可能（和 `review.py` 里的 `Step.stop` 一样）。写 `finalText(steps)`，按顺序看每一步：

  | { stop: "tool_use"; tool: string }
  | { stop: "error"; error: string };

--- solution
type Step =
  | { stop: "end"; text: string }
  | { stop: "tool_use"; tool: string }
  | { stop: "error"; error: string };

function finalText(steps: Step[]): string {
  let answer = "(no answer)";
  for (const s of steps) {
    if (s.stop === "error") {
      return `failed: ${s.error}`;
    }
    if (s.stop === "end") {
      answer = s.text;
    }
  }
  return answer;
}

--- solution
class Counter {
  counts: Record<string, number> = {};

  add(key: string): void {
    this.counts[key] = (this.counts[key] ?? 0) + 1;
  }

  get(key: string): number {
    return this.counts[key] ?? 0;
  }

  top(n: number): string[] {
    return Object.keys(this.counts)
      .sort((a, b) => this.counts[b] - this.counts[a])
      .slice(0, n);
  }
}
--- tests

}
expect("get", () => c.get("flag"), 3);
expect("没见过的键", () => c.get("maybe"), 0);
expect("top 2", () => c.top(2), ["flag", "accept"]);
expect("n 比键多", () => c.top(10), ["flag", "accept", "redline"]);
expect("每个对象各自计数", () => { const a = new Counter(); a.add("x"); return new Counter().get("x"); }, 0);
--- hints
- 方法里读写字段都要写 `this.counts`。
- `top`：`Object.keys(this.counts)` 按次数从大到小排序（sort 是稳定的，同次数保持先出现的顺序），再 `slice(0, n)`。

--- source
class Playbook:
    def __init__(self, rules: list[Rule]):
        self.rules = rules
        self._by_topic: dict[str, list[Rule]] = {}
        for r in rules:
            self._by_topic.setdefault(r.topic, []).append(r)

    @property
    def topics(self) -> list[str]:
        return sorted(self._by_topic)

    def for_topic(self, topic: str) -> list[Rule]:
        return list(self._by_topic.get(topic, []))

    def get(self, rule_id: str) -> Rule | None:
        return next((r for r in self.rules if r.id == rule_id), None)

--- solution
interface Rule {
  id: string;
  topic: string;
  severity: "low" | "medium" | "high";
}

class Playbook {
  readonly rules: Rule[];
  #byTopic: Record<string, Rule[]> = {};

  constructor(rules: Rule[]) {
    this.rules = rules;
    for (const r of rules) {
      if (this.#byTopic[r.topic] === undefined) {
        this.#byTopic[r.topic] = [];
      }
      this.#byTopic[r.topic].push(r);
    }
  }

  get topics(): string[] {
    return Object.keys(this.#byTopic).sort();
  }

  forTopic(topic: string): Rule[] {
    return [...(this.#byTopic[topic] ?? [])];
  }

  get(ruleId: string): Rule | undefined {
    return this.rules.find((r) => r.id === ruleId);
  }
}

    this.name = "BudgetExceededError";

class TokenBudget {
  #used = 0;

  constructor(readonly limit: number) {}

    return this.#used;

    return this.limit - this.#used;
  }

    if (n < 0) {
      throw new Error(`cannot spend a negative amount: ${n}`);

  }

class PlaybookError extends Error {
  constructor(message: string) {
    super(message);
    this.name = "PlaybookError";
  }
}

interface Rule {
  id: string;
  topic: string;
}

function isRule(x: unknown): x is Rule {
  return typeof x === "object" && x !== null && "id" in x && typeof x.id === "string" && "topic" in x && typeof x.topic === "string";
}

class Playbook {
  constructor(readonly rules: Rule[]) {}

  static fromJSON(raw: unknown): Playbook {
    if (typeof raw !== "object" || raw === null || !("rules" in raw) || !Array.isArray(raw.rules)) {
      throw new PlaybookError("missing rules array");
    }
    const items: unknown[] = raw.rules;
    const rules: Rule[] = [];
    for (let i = 0; i < items.length; i++) {
      const item = items[i];
      if (!isRule(item)) {
        throw new PlaybookError(`bad rule at index ${i}`);
      }
      if (rules.some((r) => r.id === item.id)) {
        throw new PlaybookError(`duplicate rule id ${item.id}`);
      }
      rules.push(item);
    }
    return new Playbook(rules);
  }

  rulesFor(topic: string): string[] {
    return this.rules.filter((r) => r.topic === topic).map((r) => r.id);
  }
}

async function withRetry<T>(fn: () => Promise<T>, tries: number): Promise<T> {
  let lastError: unknown = new Error("tries must be at least 1");
  for (let i = 0; i < tries; i++) {
    try {
      return await fn();
    } catch (e) {
      if (!(e instanceof RateLimitError)) {
        throw e;
      }
      lastError = e;
    }
  }
  throw lastError;
}

interface Rule {
  id: string;
  topic: string;
}

class RuleIndex {
  #byId = new Map<string, Rule>();

  add(rule: Rule): void {
    if (this.#byId.has(rule.id)) {
      throw new Error(`duplicate rule id ${rule.id}`);
    }
    this.#byId.set(rule.id, rule);
  }

  find(id: string): Rule | undefined {
    return this.#byId.get(id);
  }

  get size(): number {
    return this.#byId.size;
  }

  topics(): string[] {
    const unique = new Set<string>();
    for (const rule of this.#byId.values()) {
      unique.add(rule.topic);
    }
    return [...unique].sort();
  }
}

写 `class RateLimiter`：任意连续 `windowMs` 毫秒内最多允许 `max` 次调用。

- 构造函数：`constructor(max: number, windowMs: number, now: () => number = () => Date.now())`
- `tryAcquire(): boolean`：如果最近的窗口内（时间戳 `s` 满足 `now() - s < windowMs`）已经有 `max` 次成功的调用，返回 `false`（这一次不记录）；否则记下这次的时间，返回 `true`

class RateLimiter {
  #stamps: number[] = [];

  constructor(
    private readonly max: number,
    private readonly windowMs: number,
    private readonly now: () => number = () => Date.now(),
  ) {}

  private prune(): void {
    const t = this.now();
    this.#stamps = this.#stamps.filter((s) => t - s < this.windowMs);
  }

  tryAcquire(): boolean {
    this.prune();
    if (this.#stamps.length >= this.max) {
      return false;
    }
    this.#stamps.push(this.now());
    return true;
  }

  get remaining(): number {
    this.prune();
    return this.max - this.#stamps.length;
  }
}

一批条款审完，每条都交回一段 JSON 文字，其中几段可能是坏的。一条坏的不该拖垮整批：好的照常进报告，坏的要记下是第几条、坏在哪里，交给人去看。
--- prompt
模型对一批条款各返回了一段 JSON 文字。不用 Zod，写：

- `type Result<T> = { ok: true; value: T } | { ok: false; error: string }`
- `interface Verdict { clause_id: string; verdict: "accept" | "flag" | "redline" }`
- `parseOne(raw: string): Result<Verdict>`：JSON 坏了 → error `"bad json"`；解析出来不是合格的 Verdict → error `"bad shape"`；否则 ok
- `parseAll(raws: string[]): { verdicts: Verdict[]; errors: string[] }`：errors 里每一项写成 `"#下标: 错误"`，比如 `"#1: bad json"`，都保持原顺序
--- solution
type Result<T> = { ok: true; value: T } | { ok: false; error: string };

interface Verdict {
  clause_id: string;
  verdict: "accept" | "flag" | "redline";
}

const VERDICTS = ["accept", "flag", "redline"];

function isVerdict(x: unknown): x is Verdict {
  return (
    typeof x === "object" &&
    x !== null &&
    "clause_id" in x &&
    typeof x.clause_id === "string" &&
    "verdict" in x &&
    typeof x.verdict === "string" &&
    VERDICTS.includes(x.verdict)
  );
}

function parseOne(raw: string): Result<Verdict> {
  let data: unknown;
  try {
    data = JSON.parse(raw);
  } catch {
    return { ok: false, error: "bad json" };
  }
  if (!isVerdict(data)) {
    return { ok: false, error: "bad shape" };
  }
  return { ok: true, value: data };
}

function parseAll(raws: string[]): { verdicts: Verdict[]; errors: string[] } {
  const verdicts: Verdict[] = [];
  const errors: string[] = [];
  raws.forEach((raw, i) => {
    const r = parseOne(raw);
    if (r.ok) {
      verdicts.push(r.value);
    } else {
      errors.push(`#${i}: ${r.error}`);
    }
  });
  return { verdicts, errors };
}
--- tests
const RAWS = ['{"clause_id": "3.1", "verdict": "accept"}', "Sure! {", '{"clause_id": "8.1", "verdict": "maybe"}', '{"clause_id": "10.1", "verdict": "redline"}'];
expect("parseOne 成功", () => parseOne(RAWS[0]), { ok: true, value: { clause_id: "3.1", verdict: "accept" } });
expect("parseOne 三种失败", () => [parseOne(RAWS[1]), parseOne(RAWS[2]), parseOne("null")], [{ ok: false, error: "bad json" }, { ok: false, error: "bad shape" }, { ok: false, error: "bad shape" }]);
expect("parseAll", () => parseAll(RAWS), { verdicts: [{ clause_id: "3.1", verdict: "accept" }, { clause_id: "10.1", verdict: "redline" }], errors: ["#1: bad json", "#2: bad shape"] });
expect("空", () => parseAll([]), { verdicts: [], errors: [] });
