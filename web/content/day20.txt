@@ concept
title: 读代码的顺序
--- body
拿到陌生代码，不要从第一行硬读到最后一行。按顺序问四个问题：

1. **输入**：参数是什么类型？可能是空的吗？
2. **输出**：返回什么？每条路径都有 return 吗？
3. **循环**：循环几次？什么时候停？有没有可能停不下来？
4. **副作用**：改了传进来的列表或字典吗？写了文件、发了请求吗？

这四问正好对应最常见的四类 bug：空输入、漏了 return、循环不停、偷偷改了别人的数据。下面的例子「看起来只是在挑条款」，运行一下看最后一行。
--- code
def needs_review(reviews, limit=2):
    # 1 输入：reviews 是字典列表，可能为空
    picked = []
    for r in reviews:                 # 3 循环：每条看一次，一定会停
        if r["verdict"] != "accept":
            r["seen"] = True          # 4 副作用：改了调用方的字典！
            picked.append(r["id"])
    return picked[:limit]             # 2 输出：最多 limit 个编号

reviews = [{"id": "8.1", "verdict": "redline"}, {"id": "3.1", "verdict": "accept"}, {"id": "9.1", "verdict": "flag"}]
print(needs_review(reviews))
print(needs_review([]))
print(reviews[0])

@@ concept
title: 找 bug 的清单
lang: ts
--- body
面试官给你一段「有时候不对」的代码时，对照清单一条条过，比盯着看有效得多：

- **边界差一**：`range(n)` 和 `range(n + 1)`、`<` 和 `<=`、切片 `[:k]`
- **边遍历边修改**：在 `for` 里 `remove` 同一个列表
- **忘了 await**（TS）：`forEach(async ...)` 根本不会等
- **忘了 return**：某条路径返回了 `None` / `undefined`
- **键名写错**：`risk` 和 `risk_level`，`.get()` 默默返回 None
- **没有上限的循环**：Agent 没有 `max_steps`，或者计数器没加
- **吞掉错误**：`except Exception: pass`，失败时还默认 `accept`

Agent 循环里最常见的三个：工具结果没放回 messages、assistant 和 tool 消息顺序反了、步数不加。下面演示「忘了 await」：`forEach` 启动了回调就往下走，打印的时候结果还没回来。
--- code
async function review(id: string): Promise<string> {
  await Promise.resolve(); // 假装在等模型
  return `${id}:ok`;
}
async function main() {
  const ids = ["8.1", "4.2"];
  const bad: string[] = [];
  ids.forEach(async (id) => {
    bad.push(await review(id));
  });
  console.log("forEach, right after:", bad);
  const good: string[] = [];
  for (const id of ids) {
    good.push(await review(id));
  }
  console.log("for...of:", good);
  console.log("forEach, later:", bad);
}
main();

@@ concept
title: 重构的原则
--- body
重构 = **行为不变**，结构变好。面试里的重构题通常还会加一个小需求：考你先整理再加，而不是在乱代码上再堆一层 if。

1. **先有测试**：用几个例子把现在的行为锁住
2. **小步改，每步都跑测试**：改名（`x` → `verdict`）、提取函数、提前 return 减少嵌套、去掉重复（三段几乎一样的代码 → 一个循环或一张表）
3. **最后加新需求**，理想情况下只改一个地方

说出来：「我先不改行为，把这三段重复的判断收成一张表，然后新需求只要加一行。」下面的新旧两版，对所有输入结果都一样。
--- code
def label_old(v):
    if v["verdict"] == "redline":
        if v["risk"] == "high":
            return "URGENT"
        else:
            return "REVIEW"
    else:
        if v["verdict"] == "flag":
            return "REVIEW"
        else:
            return "OK"

def label_new(v):
    if v["verdict"] == "redline" and v["risk"] == "high":
        return "URGENT"
    if v["verdict"] in ("redline", "flag"):
        return "REVIEW"
    return "OK"

cases = [{"verdict": a, "risk": b} for a in ["accept", "flag", "redline"] for b in ["low", "high"]]
print(all(label_old(c) == label_new(c) for c in cases))
print([label_new(c) for c in cases])

@@ concept
title: 复杂度直觉
--- body
面试官问「这段代码的复杂度是多少」，要能说出直觉：

- 一层循环走 n 个元素：**O(n)**
- 循环里再套一层循环，或者在循环里对**列表**用 `in`：**O(n²)**。`x in 列表` 要一个个比，`x in 集合` / `x in 字典` 几乎一步到位
- 排序：O(n log n)

一份合同 300 条，n² 也才 9 万次比较，电脑一眨眼就做完。**真正慢的是 300 次模型调用**（每次几秒）。所以要说清楚：「这里 O(n²) 没关系，瓶颈在网络调用，我会先做有上限的并发和缓存。」数据量到几十万（比如跨所有合同去重）时，才需要把列表换成集合或字典。
--- code
ids = [f"{i}.1" for i in range(300)]
cited = ids[::2]             # 150 条被引用过

comparisons = 0
for i in ids:
    for c in cited:           # 列表：一个个比
        comparisons += 1
print("两层循环比较次数:", comparisons)

cited_set = set(cited)       # 集合：直接查
missing = [i for i in ids if i not in cited_set]
print("用集合：查了", len(ids), "次，没被引用的", len(missing), "条")

def add_flag(clause_id, flags=[]):
    flags.append(clause_id)
    return flags

a = add_flag("8.1")
b = add_flag("4.2")
c = add_flag("9.1", [])

--- explain
默认值 `[]` 只在 `def` 执行的那一刻创建一次，之后每次不传 `flags` 都用同一个列表，所以 a 和 b 是同一个对象，两次追加都在里面；自己传了新列表的 c 不受影响。标准写法是 `flags=None`，函数里 `if flags is None: flags = []`。面试时要说出那句关键话：默认参数在定义时求值。

--- context
练习里想按几个不同的门槛生成一批检查函数，用一个循环一次造出来。面试官常用这种写法，考你对函数和变量的理解。
--- prompt
写出输出。`lambda` 里用到的 `limit`，是创建时的值，还是调用时的值？
--- code
checks = []
for limit in [1, 2, 3]:
    checks.append(lambda n: n > limit)
print([check(2) for check in checks])

fixed = []
for limit in [1, 2, 3]:
    fixed.append(lambda n, limit=limit: n > limit)
print([check(2) for check in fixed])
--- explain
lambda 记住的是**变量**，不是当时的值。调用时循环早就结束了，`limit` 是 3，所以三次都是 `2 > 3`，全是 False。第二段用默认参数 `limit=limit` 在创建时把当前值「拍下来」：上一题的坑在这里反而派上了用场。给每条 playbook 规则生成一个检查函数时，就会碰到这个问题。

type: predict
title: 排序的稳定性
level: 2
cards: d8:多键排序; d2:排序和 while
--- context
报告要把高风险的条款排在最前面，让律师先看最要紧的。排序看起来简单，面试里却常考它的细节。
--- prompt
写出输出。Python 的排序是**稳定**的：key 相同的元素保持原来的先后顺序，加了 `reverse=True` 也一样。
--- code
reviews = [
    ("3.2", "medium"), ("8.1", "high"), ("4.2", "medium"),
    ("9.1", "high"), ("1.1", "low"),
]
RANK = {"low": 0, "medium": 1, "high": 2}
by_risk = sorted(reviews, key=lambda r: RANK[r[1]], reverse=True)
print([cid for cid, _ in by_risk])
by_id = sorted(reviews)
print([cid for cid, _ in by_id][:3])
print(sorted(["10.1", "9.1", "8.2"]))
--- explain
按风险倒序时，同为 high 的 8.1、9.1 和同为 medium 的 3.2、4.2 都保持原顺序，所以 `summarise` 里「同风险保持原顺序」不用额外处理。元组排序先比第一个元素，也就是编号字符串。最后一行是老陷阱：字符串逐个字符比较，"1" 比 "8" 小，所以 "10.1" 排在最前。要按数字排，key 用 `tuple(int(p) for p in cid.split("."))`。

--- prompt
写出输出。`var` 是老式的声明，整个函数共用**一个**变量；`let` 在 for 循环里**每一轮都是新的一份**。
--- code
const withVar: (() => number)[] = [];
for (var i = 0; i < 3; i++) {
  withVar.push(() => i);
}
const withLet: (() => number)[] = [];
for (let j = 0; j < 3; j++) {
  withLet.push(() => j);
}
console.log(withVar.map((f) => f()).join(","));
console.log(withLet.map((f) => f()).join(","));
--- explain
三个箭头函数引用的是同一个 `i`，调用时循环已经结束，`i` 是 3。`let j` 每一轮都是新的一份，各自记住 0、1、2。Python 的循环变量更像 `var`，这就是前面闭包题三个 False 的原因。写 TypeScript 一律用 `let` / `const`。

审查代码里到处是 `await`：请求模型、等回答。弄清楚它们实际的执行先后，排查「日志顺序怎么对不上」这类问题时才不会乱猜。
--- prompt
写出输出，一行一个。三条规则：

1. 同步代码先全部跑完
2. `await` 后面的部分、`.then` 的回调排进「微任务」队列，同步代码跑完后按排队顺序执行

--- code

  console.log(`start ${id}`);
  await Promise.resolve();
  console.log(`end ${id}`);
  return id;
}
console.log("A");
setTimeout(() => console.log("timeout"), 0);
review("8.1").then((id) => console.log(`then ${id}`));
review("4.2");
console.log("B");
--- explain

import json
import os
import requests

API_URL = "https://api.deepseek.com/v1/chat/completions"
HEADERS = {"Authorization": f"Bearer {os.getenv('DEEPSEEK_API_KEY')}"}
TOOLS = [{"type": "function", "function": {"name": "lookup_playbook", "description": "Return the customer's rule for a topic. Call it before deciding.", "parameters": {"type": "object", "properties": {"topic": {"type": "string"}}, "required": ["topic"]}}}]

def lookup_playbook(topic):
    return f"rule for {topic}: cap at 12 months of fees"

def agent(question, max_steps=4):
    messages = [{"role": "user", "content": question}]
    for step in range(max_steps):
        body = {"model": "deepseek-flash", "messages": messages, "tools": TOOLS, "thinking": {"type": "disabled"}}
        message = requests.post(API_URL, headers=HEADERS, json=body).json()["choices"][0]["message"]
        if not message.get("tool_calls"):
            return message["content"]
        call = message["tool_calls"][0]
        result = lookup_playbook(**json.loads(call["function"]["arguments"]))
        messages.append(message)
        messages.append({"role": "tool", "tool_call_id": call["id"], "content": result})
    return "STOPPED"

import re

def normalize(text):
    text = re.sub(r"[^a-z0-9\s]", "", text.lower())
    return " ".join(text.split())

def dedupe_clauses(clauses):
    first = {}
    unique = []
    duplicates = {}
    for c in clauses:
        key = normalize(c["text"])
        if key in first:
            duplicates[c["id"]] = first[key]
        else:
            first[key] = c["id"]
            unique.append(c["id"])
    return {"unique": unique, "duplicates": duplicates}

function mergeSpans(spans: [number, number][]): [number, number][] {
  const sorted = [...spans].sort((a, b) => a[0] - b[0]);
  const out: [number, number][] = [];
  for (const [start, end] of sorted) {
    const last = out[out.length - 1];
    if (last && start <= last[1]) {
      last[1] = Math.max(last[1], end);
    } else {
      out.push([start, end]);
    }
  }
  return out;

def plan_batches(clauses, max_requests, max_tokens):
    batches = []
    current = []
    used = 0
    for c in clauses:
        if c["tokens"] > max_tokens:
            raise ValueError(f"clause {c['id']} needs {c['tokens']} tokens, limit is {max_tokens}")
        if current and (len(current) >= max_requests or used + c["tokens"] > max_tokens):
            batches.append(current)
            current, used = [], 0
        current.append(c["id"])
        used += c["tokens"]
    if current:
        batches.append(current)
    return batches

写 `needs_recheck(verdicts, refs)`：

- `verdicts`：条款编号 → 判定，如 `{"8.1": "accept", "12": "redline"}`
- `refs`：条款编号 → 它引用的编号列表，如 `{"8.1": ["12"]}`；没有引用的条款可能不在 `refs` 里
- 返回：判定为 accept、并且**直接**引用了至少一条 redline 条款的编号，按条款号的**数字**顺序排（"9.2" 在 "10.1" 前面，"8.1" 在 "8.10" 前面）

--- solution
def clause_key(cid):
    return tuple(int(p) for p in cid.split("."))

def needs_recheck(verdicts, refs):
    result = []
    for cid, verdict in verdicts.items():
        if verdict != "accept":
            continue
        if any(verdicts.get(r) == "redline" for r in refs.get(cid, [])):
            result.append(cid)
    return sorted(result, key=clause_key)

--- prompt
定义 `type Edit = { start: number; end: number; replacement: string }`，写 `applyRedlines(text: string, edits: Edit[]): string`：把每个 edit 的区间（包含 start，不包含 end）替换成 `replacement`。

- `edits` 的顺序不固定；所有位置都是相对**原文**的（`graph.py` 的做法：从后往前替换，前面的位置就不会被改乱）
- 按 start 排序后，下一个的 start 小于上一个的 end 就是重叠：`throw new Error(...)`；首尾相接可以
- 不要修改传进来的 `edits` 数组；没有 edit 时原样返回
--- solution
type Edit = { start: number; end: number; replacement: string };

function applyRedlines(text: string, edits: Edit[]): string {
  const sorted = [...edits].sort((a, b) => a.start - b.start);
  for (let i = 1; i < sorted.length; i++) {
    if (sorted[i].start < sorted[i - 1].end) {
      throw new Error(`overlapping edits at ${sorted[i].start}`);
    }
  }
  let out = text;
  for (const e of sorted.reverse()) {
    out = out.slice(0, e.start) + e.replacement + out.slice(e.end);
  }
  return out;
}

- 最多调用 `fn` 共 `tries` 次；某一次成功就返回它的结果
- `fn` 失败（Promise 被 reject）就再试
- 全部失败：把**最后一次**的错误抛出去，不能返回 undefined
--- solution
async function withRetry<T>(fn: () => Promise<T>, tries: number): Promise<T> {
  let lastError: unknown = new Error("tries must be at least 1");
  for (let i = 0; i < tries; i++) {
    try {
      return await fn();
    } catch (e) {
      lastError = e;
    }
  }
  throw lastError;
}
