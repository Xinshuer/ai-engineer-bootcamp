@@ concept
title: interface 和 type
--- body
第 5 天你用 `type` 给对象起过名字。`interface` 是另一种写法，描述对象形状时两者几乎一样：

```ts
interface Clause { id: string; text: string }
type Verdict = "accept" | "flag" | "redline";
```

区别只要记两条：

- **联合类型只能用 `type`** 写
- `interface` 可以 `extends` 另一个 interface，在它的基础上加字段

TypeScript 只看**形状**：一个对象只要字段对得上，就符合这个类型，不管它是怎么来的。一个项目选一种风格保持一致就好。本课的约定：对象用 `interface`，联合用 `type`。
--- code
type Verdict = "accept" | "flag" | "redline";

interface Clause {
  id: string;
  text: string;
}
interface ReviewedClause extends Clause {
  verdict: Verdict;
}

const c: ReviewedClause = { id: "8.1", text: "Liability is unlimited.", verdict: "redline" };
const plain: Clause = c; // 多一个 verdict 字段也可以：形状对得上就行
console.log(c.id, c.verdict);
console.log(plain.text);

@@ concept
title: 可选、只读、可选链
--- body
- `heading?: string`：这个字段可以没有，读出来的类型是 `string | undefined`
- `readonly id: string`：创建后不能再改（整个对象只读可以写 `Readonly<Clause>`）
- `c.source?.page`：**可选链**。`?.` 左边是 `null` / `undefined` 时，整个表达式直接得到 `undefined`，而不是报错
- 配合第 5 天的 `??` 给默认值：`c.source?.page ?? "?"`

经典错误：直接写 `c.heading.toUpperCase()`，TypeScript 报 `TS18048: 'c.heading' is possibly 'undefined'`。这不是 TypeScript 找麻烦：模型输出、JSON 文件里的字段真的会缺。数组的 `find` 也一样，找不到时返回 `undefined`。
--- code
interface Clause {
  readonly id: string;
  heading?: string;
  source?: { file: string; page?: number };
}

const a: Clause = { id: "8.1", heading: "Cap on Liability", source: { file: "msa.pdf", page: 3 } };
const b: Clause = { id: "12" };

for (const c of [a, b]) {
  const heading = c.heading ?? "(no heading)";
  console.log(c.id, heading, c.source?.page ?? "?", c.source?.file.toUpperCase());
}
// a.id = "9.9"; // 去掉注释试试：Cannot assign to 'id' because it is a read-only property

@@ concept
title: 联合类型和收窄
--- body
`string | null` 表示「可能是字符串，也可能是 null」。用之前先**检查**，TypeScript 会跟着你的 if 判断，把类型「收窄」：

- `x === null`、`x === undefined`
- `typeof x === "string"`（还有 `"number"`、`"boolean"`、`"object"`）
- `Array.isArray(x)`
- `"verdict" in obj`：对象里有没有这个键

if 里面，TypeScript 知道 x 具体是什么；出了 if，又回到联合类型。在本机 VS Code 里把鼠标放到变量上，能看到每一行它的类型。

经典坑：`typeof null` 和 `typeof []` 的结果都是 `"object"`（JavaScript 的历史包袱）。所以判断数组用 `Array.isArray`，判断对象时要同时排除 `null`。
--- code
function show(x: string | number | string[] | null): string {
  if (x === null) {
    return "nothing";
  }
  if (typeof x === "string") {
    return `text: ${x.toUpperCase()}`;
  }
  if (Array.isArray(x)) {
    return `list of ${x.length}`;
  }
  return `number: ${x.toFixed(1)}`; // 走到这里，x 只可能是 number
}
console.log(show("flag"));
console.log(show(["8.1", "12"]));
console.log(show(0.5));
console.log(show(null));
console.log(typeof null, typeof ["8.1"]);

@@ concept
title: 可辨识联合和穷尽检查
--- body
模型的一次回复可能是「最终回答」「要调工具」或「出错」，每种情况带的字段不同。Clause Check 的 `review.py` 里，`Step` 用一个字符串字段 `stop` 区分它们（`"end"`、`"tool_use"`、`"error"` …）。

TypeScript 把这写成**可辨识联合**：每种情况都有同一个字段（常叫 `kind`、`type`、`stop`），值是不同的字面量。`switch (s.stop)` 的每个 case 里，TypeScript 知道 s 是哪一种，只有 `"tool_use"` 分支能读 `s.tool`。

**穷尽检查**：在 `default` 里写

```ts
const unreachable: never = s;
```

`never` 是「不可能有值」的类型。所有情况都处理了，走到 default 的 s 就是 never，不报错；以后有人加了第四种却忘了处理，这一行立刻报类型错误，bug 在运行前就被抓住。
--- code
type Step =
  | { stop: "end"; text: string }
  | { stop: "tool_use"; tool: string; args: string }
  | { stop: "error"; error: string };

function nextAction(s: Step): string {
  switch (s.stop) {
    case "end":
      return `answer: ${s.text}`;
    case "tool_use":
      return `run ${s.tool}(${s.args})`;
    case "error":
      return `give up: ${s.error}`;
    default: {
      const unreachable: never = s;
      return unreachable;
    }
  }
}

const steps: Step[] = [
  { stop: "tool_use", tool: "lookup_playbook", args: '{"topic": "payment"}' },
  { stop: "end", text: "flag: payment term unclear" },
  { stop: "error", error: "http 429" },
];
for (const s of steps) {
  console.log(nextAction(s));
}

@@ concept
title: 泛型：类型的参数
--- body
写一个「取第一个元素」的函数：给 `string[]` 用时要返回 string，给 `Clause[]` 用时要返回 Clause。写成 `any` 就把类型丢了。**泛型**就是「类型的参数」：

```ts
function first<T>(xs: T[]): T | undefined {
  return xs[0];
}
```

`<T>` 读作「对某个类型 T」。调用时一般不用写 `first<string>(...)`，TypeScript 会从参数推断出 T。你其实早就用过泛型：`Promise<string>`、`Record<string, number>`、`Array<string>`，尖括号里的就是类型参数。type 也可以带参数：`type ApiResult<T> = { ok: true; data: T } | { ok: false; error: string }`。

经典错误：在函数里写 `const x: T = "8.1"`。T 由调用方决定，函数自己不能假设它是 string。
--- code
function first<T>(xs: T[]): T | undefined {
  return xs[0];
}

function countBy<T>(xs: T[], key: (x: T) => string): Record<string, number> {
  const counts: Record<string, number> = {};
  for (const x of xs) {
    const k = key(x);
    counts[k] = (counts[k] ?? 0) + 1;
  }
  return counts;
}

interface Review {
  id: string;
  verdict: string;
}
const reviews: Review[] = [
  { id: "3.1", verdict: "accept" },
  { id: "8.1", verdict: "flag" },
  { id: "10.1", verdict: "flag" },
];
const none: string[] = [];
console.log(first(reviews)?.id, first(none) ?? "empty");
console.log(countBy(reviews, (r) => r.verdict));
console.log(countBy(["low", "high", "low"], (r) => r));

@@ concept
title: 工具类型：从一个类型派生另一个
--- body
不用重写一遍，就能从已有类型「派生」出新类型：

- `Partial<Review>`：所有字段变成可选，适合「补丁」（只改几个字段）
- `Pick<Review, "id" | "verdict">`：只留这几个字段
- `Omit<Review, "cost_usd">`：去掉这几个字段
- `Record<K, V>`：第 5 天就用过
- `ReturnType<typeof fn>`：取函数的返回类型（读别人代码时会见到）

最重要的一点：**这些都只是类型，运行时不存在**。`Omit` 不会帮你删字段；想真的去掉，要用代码生成一个新对象。常用写法是**解构剩余**：

```ts
const { cost_usd, ...rest } = review; // rest = 除 cost_usd 外的所有字段
```
--- code
interface Review {
  id: string;
  verdict: "accept" | "flag" | "redline";
  risk: "low" | "medium" | "high";
  cost_usd: number;
}
type ReviewPatch = Partial<Review>;
type PublicReview = Omit<Review, "cost_usd">;

const r: Review = { id: "8.1", verdict: "flag", risk: "high", cost_usd: 0.0021 };
const patch: ReviewPatch = { verdict: "redline" };
const updated: Review = { ...r, ...patch };
console.log(updated.verdict, r.verdict);

const { cost_usd, ...rest } = r;
const pub: PublicReview = rest;
console.log(Object.keys(pub), cost_usd);

@@ concept
title: unknown 和类型守卫
--- body
`JSON.parse` 返回 `any`：从这里开始 TypeScript 不再检查，字段名拼错也不报错，要到运行时才出事。模型输出、HTTP 响应、文件内容都是**外部数据**，应该当成 `unknown`：「不知道是什么，用之前必须先检查」。

把检查写成**类型守卫**函数，返回类型写成 `x is Verdict`：

```ts
function isVerdict(x: unknown): x is Verdict { ... }
```

`if (isVerdict(data))` 之后，if 里面的 data 就是 Verdict。

两个经典错误：

- `data as Verdict` 只是**告诉**编译器「相信我」，运行时什么也不检查
- 守卫里漏查了一个字段，编译器也发现不了：守卫是你自己的承诺。字段一多，就用第 6 天的 Zod：一份 schema 同时负责检查和类型，不会漏
--- code
const VERDICTS = ["accept", "flag", "redline"];
interface Verdict {
  clause_id: string;
  verdict: "accept" | "flag" | "redline";
}

function isVerdict(x: unknown): x is Verdict {
  return (
    typeof x === "object" &&
    x !== null &&
    "clause_id" in x &&
    typeof x.clause_id === "string" &&
    "verdict" in x &&
    typeof x.verdict === "string" &&
    VERDICTS.includes(x.verdict)
  );
}

const inputs = ['{"clause_id": "8.1", "verdict": "flag"}', '{"clause_id": "8.1", "verdict": "maybe"}', "null"];
for (const raw of inputs) {
  const data: unknown = JSON.parse(raw);
  if (isVerdict(data)) {
    console.log("ok:", data.clause_id, data.verdict);
  } else {
    console.log("rejected:", raw);
  }
}

@@ concept
title: as const：一份列表，两种用途
--- body
同一份列表常常要用两次：运行时要一个数组（遍历、检查），编译时要一个联合类型。分开写两遍，迟早会不一致。`as const` 让一份定义同时给出两样：

```ts
const RISKS = ["low", "medium", "high"] as const;
type Risk = (typeof RISKS)[number]; // "low" | "medium" | "high"
```

- `as const`：数组变成只读，元素的类型是具体的字面量，而不是 string
- `typeof RISKS`：取这个**值**的类型；`[number]`：「用数字下标取到的元素」的类型

经典坑：x 是 `string` 时，`RISKS.includes(x)` 会报错（TypeScript 认为 RISKS 里只可能是那三个词）。查任意字符串要写成 `(RISKS as readonly string[]).includes(x)`。Zod 的 `z.enum(RISKS)` 也可以直接用这份列表。
--- code
const RISKS = ["low", "medium", "high"] as const;
type Risk = (typeof RISKS)[number];

function isRisk(x: string): x is Risk {
  return (RISKS as readonly string[]).includes(x);
}

function rank(r: Risk): number {
  return RISKS.indexOf(r);
}

for (const raw of ["high", "urgent", "low"]) {
  if (isRisk(raw)) {
    console.log(raw, "rank", rank(raw));
  } else {
    console.log(raw, "is not a risk level");
  }
}
console.log(RISKS.length, RISKS[2]);

interface Clause {
  id: string;
  heading?: string;
}

function headingOf(clauses: Clause[], id: string): string {
  const clause = clauses.find((c) => c.id === id);
  if (clause === undefined) {
    return "(missing)";
  }
  return `${clause.id} ${clause.heading?.toUpperCase() ?? "(no heading)"}`;
}

type: predict
title: 收窄的结果
level: 2
cards: 联合类型和收窄
--- context
模型交回来的字段不一定是你想的类型：同一个字段，这次是数字，下次是列表，还可能是空的。用之前，先得弄清它这次到底是什么。
--- prompt
写出输出。最后一行是 JavaScript 的两个老坑，想想为什么要用 `Array.isArray` 和 `=== null`。
--- code
function kindOf(x: string | number | string[] | null | undefined): string {
  if (x === null || x === undefined) {
    return "empty";
  }
  if (typeof x === "number") {
    return x > 0.5 ? "high score" : "low score";
  }
  if (Array.isArray(x)) {
    return `${x.length} ids`;
  }
  return x.trim() === "" ? "blank" : `text ${x}`;
}
console.log(kindOf(0.8), kindOf(0));
console.log(kindOf(["8.1"]), kindOf([]));
console.log(kindOf("  "), kindOf("flag"));
console.log(kindOf(null), kindOf(undefined));
console.log(typeof null, typeof [], Array.isArray([]));
--- explain
每个 if 都排除掉一种可能，走到最后一行时 x 只剩 `string`，所以能直接调用 `x.trim()`。`typeof` 对 `null` 和数组都返回 `"object"`，所以判断数组要用 `Array.isArray`，判断「是个对象」时要加上 `x !== null`。

--- solution
function normalizeIds(input: string | string[] | null): string[] {
  if (input === null) {
    return [];
  }
  const parts = typeof input === "string" ? input.split(",") : input;
  return parts.map((s) => s.trim()).filter((s) => s !== "");
}

function groupBy<T>(xs: T[], key: (x: T) => string): Record<string, T[]> {

  return (
    typeof x === "object" &&
    x !== null &&

const VERDICTS = ["accept", "flag", "redline"] [[as const]];
type Verdict = ([[typeof]] VERDICTS)[number];

function isVerdict(x: string): x [[is]] Verdict {

function toVerdict(x: string): Verdict {
  const v = x.trim().toLowerCase();

}

Agent 运行时会产生一串事件。定义可辨识联合 `ReviewEvent`（用字段 `type` 区分）：

- `{ type: "tool_call"; tool: string }`
- `{ type: "verdict"; clause_id: string; verdict: "accept" | "flag" | "redline" }`

写 `summarize(events: ReviewEvent[])`，返回 `{ toolCalls: 工具调用次数, verdicts: { 判定: 次数 }, errors: [所有 message，保持顺序] }`。用 switch，并加上 `never` 穷尽检查。
--- solution
type ReviewEvent =
  | { type: "tool_call"; tool: string }
  | { type: "verdict"; clause_id: string; verdict: "accept" | "flag" | "redline" }
  | { type: "error"; message: string };

interface Summary {
  toolCalls: number;
  verdicts: Record<string, number>;
  errors: string[];
}

function summarize(events: ReviewEvent[]): Summary {
  const out: Summary = { toolCalls: 0, verdicts: {}, errors: [] };
  for (const e of events) {
    switch (e.type) {
      case "tool_call":
        out.toolCalls += 1;
        break;
      case "verdict":
        out.verdicts[e.verdict] = (out.verdicts[e.verdict] ?? 0) + 1;
        break;
      case "error":
        out.errors.push(e.message);
        break;
      default: {
        const unreachable: never = e;
        throw new Error(`unknown event: ${JSON.stringify(unreachable)}`);
      }
    }
  }
  return out;
}

function topBy<T>(xs: T[], score: (x: T) => number, k: number): T[] {
  if (k <= 0) {
    return [];
  }
  return [...xs].sort((a, b) => score(b) - score(a)).slice(0, k);
}

--- context
playbook 是客户的审查规则，存在一个 JSON 文件里，由人手写手改，难免有写错的规则。加载时要把坏规则挑出来，不能让它悄悄混进审查。
--- prompt
从 JSON 文字里加载 playbook 规则，不用 Zod，手写检查：

- `interface Rule { id: string; topic: string; severity: "low" | "medium" | "high"; keywords?: string[] }`
- `isRule(x: unknown): x is Rule`：`id`、`topic` 是字符串，`severity` 是三档之一；`keywords` 可以没有，有的话必须是字符串数组
- `loadRules(raw: string): { rules: Rule[]; rejected: number }`：`raw` 应该是 `{"rules": [...]}` 这样的 JSON。合格的规则放进 `rules`（保持顺序），不合格的数量记在 `rejected`。`raw` 不是合法 JSON，或者没有 `rules` 数组时，返回 `{ rules: [], rejected: 0 }`
--- solution
const SEVERITIES = ["low", "medium", "high"];

interface Rule {
  id: string;
  topic: string;
  severity: "low" | "medium" | "high";
  keywords?: string[];
}

function isRule(x: unknown): x is Rule {
  if (typeof x !== "object" || x === null) {
    return false;
  }
  if (!("id" in x) || typeof x.id !== "string") {
    return false;
  }
  if (!("topic" in x) || typeof x.topic !== "string") {
    return false;
  }
  if (!("severity" in x) || typeof x.severity !== "string" || !SEVERITIES.includes(x.severity)) {
    return false;
  }
  if ("keywords" in x) {
    const kw = x.keywords;
    if (!Array.isArray(kw) || !kw.every((k) => typeof k === "string")) {
      return false;
    }
  }
  return true;
}

function loadRules(raw: string): { rules: Rule[]; rejected: number } {
  let data: unknown;
  try {
    data = JSON.parse(raw);
  } catch {
    return { rules: [], rejected: 0 };
  }
  if (typeof data !== "object" || data === null || !("rules" in data) || !Array.isArray(data.rules)) {
    return { rules: [], rejected: 0 };
  }
  const items: unknown[] = data.rules;
  const rules = items.filter(isRule);
  return { rules, rejected: items.length - rules.length };
}
