title: 云是什么：租来的电脑，按用量付钱
--- body
云就是**别人的电脑，通过 API 租给你用**：你不买服务器，而是调用 `put_object`、`deploy` 这样的接口，按用量付钱（存了多少 GB、运行了多少秒、调用了多少次）。

三个到处都会见到的词：

- **项目 / 账号**：GCP 叫 project（比如 `clausecheck-dev`），AWS 叫 account。账单和权限都挂在它上面；开发和生产通常分成两个
- **区域（region）**：机房所在的地方，比如 GCP 的 `europe-north1`（芬兰）、AWS 的 `eu-north-1`（斯德哥尔摩）。建资源时就要选定区域，数据存放和处理的地方由它决定，合规（比如「数据不出欧盟」）要看它
- **可用区（zone）**：一个区域里几个互相独立的机房，一个出事，其他的还在

两家的服务几乎一一对应（运行下面的代码）。你将来做的项目可能用任何一家，面试时能说出「GCS 就是 GCP 的 S3」这样的对应关系很加分。名字会变，读资料时留意：旧资料里常见的 AWS App Runner 从 2026 年 4 月底起不再接受新客户，AWS 建议迁到 ECS；GCP 的 Vertex AI 在 2026 年 4 月改名为 Gemini Enterprise Agent Platform（API 没变，文档和面试里还常叫它 Vertex AI）。

@@ concept
title: 对象存储：桶、键和字节
cloud: yes
--- body
合同 PDF、审查报告这类**文件**放在对象存储里：AWS 的 S3、GCP 的 Cloud Storage（GCS）。

- **桶（bucket）**：一个大容器，名字全球唯一，比如 `clausecheck-contracts`
- **键（key）**：对象的完整名字，比如 `contracts/1/103/original.pdf`。**没有真的文件夹**：`/` 只是名字里的一个字符，「列出一个文件夹」其实是「列出以这个前缀开头的键」
- 对象 = 字节 + 元数据：`ContentType`（`application/json`、`application/pdf`）和你自己加的键值对（Metadata；S3 会把它的键名**转成小写**）
- 读出来的是**字节**：S3 是 `resp["Body"].read()`，要 `.decode("utf-8")` 才是文字
- 列出时一次最多返回 1000 个键，更多的要**分页**；一个都没匹配时，S3 的响应里连 `Contents` 键都没有
- 打开版本控制（versioning）后，覆盖和删除都会留下旧版本，删错了能找回

本页的 boto3 / google-cloud 是模拟的：调用写法和返回结构与真 SDK 一致（只实现了课程用到的部分）；真项目里 `pip install boto3 google-cloud-storage` 后配置凭证即可。两个桶 `clausecheck-contracts`、`clausecheck-reports` 已经建好。
--- code
import json
import boto3
from google.cloud import storage

report = {"contract_id": 103, "counts": {"redline": 2, "flag": 1}}

# AWS S3：一个 client，方法名就是 API 的名字，参数全部用关键字传
s3 = boto3.client("s3", region_name="eu-north-1")
s3.put_object(Bucket="clausecheck-reports", Key="reports/103.json",
              Body=json.dumps(report).encode("utf-8"),
              ContentType="application/json", Metadata={"Contract-Id": "103"})
resp = s3.get_object(Bucket="clausecheck-reports", Key="reports/103.json")
print(resp["ContentType"], resp["Metadata"])
print(json.loads(resp["Body"].read().decode("utf-8")))

# GCP Cloud Storage：client → bucket → blob（一个对象）
gcs = storage.Client()
blob = gcs.bucket("clausecheck-reports").blob("reports/103.json")
blob.upload_from_string(json.dumps(report), content_type="application/json")
print(blob.content_type, json.loads(blob.download_as_text()))

# 「文件夹」只是前缀
page = s3.list_objects_v2(Bucket="clausecheck-reports", Prefix="reports/")
print([o["Key"] for o in page["Contents"]], page["IsTruncated"])
print([b.name for b in gcs.list_blobs("clausecheck-reports", prefix="reports/")])
empty = s3.list_objects_v2(Bucket="clausecheck-reports", Prefix="archive/")
print("Contents" in empty, empty.get("Contents", []))

title: 身份和凭证：谁在调用
cloud: yes
--- body
每个 API 调用都要回答「你是谁」。云上有两种身份：

- **人**：你自己的账号，本机开发时用
- **机器**：GCP 的**服务账号**（service account）、AWS 的 **IAM 角色**（role）。Cloud Run 服务、Lambda 函数运行时自带这个身份，代码里不用写任何密钥

SDK 按固定顺序自动找凭证（凭证链），所以同一份代码在本机和线上都不用改：

- AWS：环境变量（`AWS_ACCESS_KEY_ID` 等）→ 本机的 `~/.aws/` 配置（`aws configure` 或 `aws configure sso` 写的）→ 运行环境提供的角色
- GCP：**Application Default Credentials（ADC）**：`GOOGLE_APPLICATION_CREDENTIALS` 指向的文件 → 本机 `gcloud auth application-default login` 登录过的账号 → 运行环境附带的服务账号

**永远不要**把访问密钥、服务账号的 JSON 密钥文件写进代码或提交到 git。

一个细节：`boto3.client(...)` 不检查凭证，**第一次真正调用**时才签名，才报 `NoCredentialsError`；它不是 `ClientError`，`except ClientError` 接不住。Google 的 client 在创建时就找凭证。
--- code
import boto3
import google.auth.exceptions
from botocore.exceptions import ClientError, NoCredentialsError
from google.cloud import storage

# CLOUD 只有本页的模拟才有：假装这台电脑上没有任何凭证
CLOUD.aws_credentials = False
CLOUD.gcp_adc = False

s3 = boto3.client("s3", region_name="eu-north-1")
print("boto3 client created, no credentials checked yet")
try:
    s3.list_objects_v2(Bucket="clausecheck-contracts")
except ClientError as e:
    print("ClientError:", e)
except NoCredentialsError as e:
    print(type(e).__name__, "-", e)
    print("is it a ClientError?", isinstance(e, ClientError))

try:
    storage.Client()
except google.auth.exceptions.DefaultCredentialsError as e:
    print(type(e).__name__, "-", str(e).split(".")[0])

title: IAM：只给需要的权限
--- body
IAM 决定「这个身份能对哪个资源做什么」。原则是**最小权限**：只给完成工作所需的那几个动作，只作用在需要的资源上。

Clause Check 的审查 worker 只需要：读 `clausecheck-contracts` 里的合同，往 `clausecheck-reports` 里写报告，读 DeepSeek 的密钥。它不需要删除合同，也不需要碰别的桶。

- AWS：给 worker 的角色挂一份策略（policy）。`Action` 写具体动作（`s3:GetObject`），`Resource` 写具体的 ARN（`arn:aws:s3:::clausecheck-contracts/*`）
- GCP：在**桶上**给服务账号授予角色，比如 contracts 桶给 `roles/storage.objectViewer`，reports 桶给 `roles/storage.objectCreator`，密钥给 `roles/secretmanager.secretAccessor`。注意 `objectCreator` 只能新建、**不能覆盖**已有的对象；报告要重写的话，得换成权限更大的 `roles/storage.objectUser`（它还能删除）

看到 **403 / AccessDenied / PermissionDenied**：多半不是代码写错了，是身份缺权限。排查三问：这次调用用的是哪个身份（`aws sts get-caller-identity`）？缺的是哪个动作（错误信息里通常写着）？权限加在了哪个资源上？

一个坑：S3 读一个**不存在**的键时，如果身份没有 `s3:ListBucket` 权限，得到的是 403 AccessDenied，而不是 404 NoSuchKey。

下面是一个**极简**的策略检查器，帮你看懂策略的形状。真正的 IAM 还有 Deny（明确拒绝永远优先）、条件、多份策略合并。
--- code
from fnmatch import fnmatch

WORKER_POLICY = {
    "Version": "2012-10-17",
    "Statement": [
        {"Effect": "Allow", "Action": ["s3:GetObject"], "Resource": ["arn:aws:s3:::clausecheck-contracts/*"]},
        {"Effect": "Allow", "Action": ["s3:PutObject"], "Resource": ["arn:aws:s3:::clausecheck-reports/*"]},
        {"Effect": "Allow", "Action": ["secretsmanager:GetSecretValue"],
         "Resource": ["arn:aws:secretsmanager:eu-north-1:123456789012:secret:clausecheck/deepseek-*"]},
    ],
}

def allowed(policy, action, resource):
    for st in policy["Statement"]:
        if st["Effect"] == "Allow" and action in st["Action"] and any(fnmatch(resource, r) for r in st["Resource"]):
            return True
    return False

checks = [
    ("s3:GetObject", "arn:aws:s3:::clausecheck-contracts/contracts/1/103/original.pdf"),
    ("s3:PutObject", "arn:aws:s3:::clausecheck-reports/reports/103.json"),
    ("s3:DeleteObject", "arn:aws:s3:::clausecheck-contracts/contracts/1/103/original.pdf"),
    ("s3:GetObject", "arn:aws:s3:::clausecheck-billing/invoices/2026-09.csv"),
]
for action, resource in checks:
    verdict = "ALLOW" if allowed(WORKER_POLICY, action, resource) else "DENY "
    print(verdict, action.ljust(16), resource.split(":::")[1])

@@ concept
title: 密钥管理：不进代码、不进镜像
cloud: yes
--- body
本机开发时，密钥放在 `.env` 里（第 10 天）。上线以后不这样做：代码仓库、容器镜像、日志里都不能出现密钥。

线上用**密钥管理服务**：GCP 的 Secret Manager、AWS 的 Secrets Manager。密钥加密保存，谁能读由 IAM 控制，读取可以记进审计日志（AWS 是 CloudTrail；GCP 要先打开 Secret Manager 的「数据访问」审计日志，默认是关的），还能**轮换**（换一把新的，旧的作废）。

- GCP：名字是 `projects/项目/secrets/名字/versions/latest`；读出来的 `payload.data` 是**字节**，要 `.decode("utf-8")`
- AWS：`get_secret_value(SecretId=...)["SecretString"]` 是**字符串**；存的是键值对时它是一段 JSON，要 `json.loads`
- 进程启动后读一次，**缓存**起来，别每个请求都读：每次读取都有延迟，也按调用次数计费。代价是轮换以后要重启（或让缓存过期）才用上新密钥
- 另一种常见做法：Cloud Run 可以把 Secret Manager 里的密钥直接注入成环境变量，代码照旧 `os.getenv`

打印密钥时只露出前几个字符，日志里一个完整的密钥都不要有。
--- code
import json
import boto3
from google.cloud import secretmanager

gsm = secretmanager.SecretManagerServiceClient()
name = "projects/clausecheck-dev/secrets/deepseek-api-key/versions/latest"
resp = gsm.access_secret_version(name=name)
print(type(resp.payload.data).__name__, resp.payload.data.decode("utf-8")[:6] + "...")

asm = boto3.client("secretsmanager", region_name="eu-north-1")
secret = asm.get_secret_value(SecretId="clausecheck/deepseek")
print(type(secret["SecretString"]).__name__, secret["SecretString"][:14] + "...")
print(json.loads(secret["SecretString"])["api_key"][:6] + "...")

title: 错误和重试：只重试暂时的错误
cloud: yes
--- body
云 API 的错误分两类，处理方式完全不同：

- **暂时的**：限流（429、`ThrottlingException`、S3 的 `SlowDown`）和服务端 5xx（`ServiceUnavailable`）。等一会儿再试，通常就好了
- **永久的**：404 不存在、403 没权限、400 参数错。重试一百次结果也一样，应该马上报错

好消息：SDK 自己会重试暂时的错误。boto3 默认（legacy 模式）一共试 5 次，standard 模式 3 次，可以用 `Config(retries={"mode": "standard", "total_max_attempts": 3})` 设置；google-cloud-storage 也会重试读取。所以一个限流错误到了你的代码里，意思是「SDK 已经试过好几次了」。

自己写重试时（SDK 不重试的调用，或者整个步骤要重来）：只重试暂时的错误，**指数退避**（0.5 秒、1 秒、2 秒……），再乘一个**随机抖动**（jitter，让很多客户端不在同一瞬间一起重试），并设上限。被重试的操作最好是**幂等**的：同一个键再写一次同样的内容，结果不变。

两家的错误长得不一样：boto3 几乎全是 `ClientError`，看 `e.response["Error"]["Code"]`；Google 按状态码分成不同的异常类（`NotFound`、`TooManyRequests`），看类或者 `e.code`。不要去匹配错误信息的文字，它随时会变。
--- code
import boto3
from botocore.config import Config
from botocore.exceptions import ClientError
from google.cloud import storage
from google.api_core.exceptions import NotFound

s3 = boto3.client("s3", region_name="eu-north-1")
CLOUD.fail_next("s3", "throttle", 2)            # 模拟：接下来两次请求被限流
resp = s3.list_objects_v2(Bucket="clausecheck-reports")
print("succeeded; the SDK retried", resp["ResponseMetadata"]["RetryAttempts"], "times behind the scenes")

no_retry = boto3.client("s3", region_name="eu-north-1", config=Config(retries={"total_max_attempts": 1}))
CLOUD.fail_next("s3", "throttle", 1)
try:
    no_retry.list_objects_v2(Bucket="clausecheck-reports")
except ClientError as e:
    print(e.response["Error"]["Code"], e.response["ResponseMetadata"]["HTTPStatusCode"], "-> transient, retry later")

try:
    s3.get_object(Bucket="clausecheck-reports", Key="reports/999.json")
except ClientError as e:
    print(e.response["Error"]["Code"], "-> permanent, do not retry")

gcs = storage.Client()
try:
    gcs.bucket("clausecheck-reports").blob("reports/999.json").download_as_text()
except NotFound as e:
    print(type(e).__name__, e.code, "-> permanent, do not retry")

title: 数据驻留：合同留在欧盟
cloud: yes
--- body
合同里有姓名、邮箱、签字人，这些都是**个人数据**。欧盟的 **GDPR** 用大白话说：处理个人数据要有正当理由，只收需要的，保护好；把它传到欧盟以外，要有额外的法律保障。所以客户常在合同里写明「数据只能在欧盟存放和处理」。项目 playbook 的 **PB-03**（Data location and DPA）审的就是这种条款，Clause Check 自己当然也要做到：

- 桶、数据库、日志、备份都建在欧盟区域：AWS `eu-north-1`（斯德哥尔摩）、GCP `europe-north1`（芬兰）
- 把合同文字发给大模型也是「处理」：模型的推理位置同样要在欧盟（明天的 Bedrock 和 Vertex AI）
- 两家云默认都做**静态加密**（encryption at rest），但加密不改变数据在哪个国家

建桶时写明区域：S3 在 `us-east-1` 以外建桶，必须带 `CreateBucketConfiguration={"LocationConstraint": 区域}`，否则报 `IllegalLocationConstraintException`；GCS 的 `create_bucket` 不写 `location` 时，默认是 `US`（美国的多区域）。
--- code
import boto3
from botocore.exceptions import ClientError
from google.cloud import storage

s3 = boto3.client("s3", region_name="eu-north-1")
try:
    s3.create_bucket(Bucket="clausecheck-contracts-se")
except ClientError as e:
    print(e.response["Error"]["Code"])
s3.create_bucket(Bucket="clausecheck-contracts-se",
                 CreateBucketConfiguration={"LocationConstraint": "eu-north-1"})
print("S3 bucket created in", s3.meta.region_name)

gcs = storage.Client()
print(gcs.create_bucket("clausecheck-contracts-fi", location="europe-north1").location)
print(gcs.create_bucket("clausecheck-tmp").location, "<- no location given")

title: 成本和命令行
--- body
云的账单主要来自：计算（运行了多少秒）、存储（每 GB 每月）、**出站流量**（egress：数据从云里下载到外面，按 GB 收费，是意外账单的常见来源）和 API 调用次数。对 Clause Check 来说，存合同几乎不花钱，大头是模型的 token（运行下面的估算）。

- **存储类别**：常用的放 Standard；很少读的旧合同可以用生命周期规则自动转到便宜的冷存储（S3 Glacier、GCS Coldline / Archive），但取回要另外收费
- **预算和告警**：两家都能设月度预算，花到 50%、90% 时发邮件提醒。开账号的第一天就设。注意预算**只提醒，不会自动停掉服务**；真要封顶，还得靠最大实例数这类上限（明天讲）
- 价格经常变，代码里的单价只是示例，用来看数量级，以官方价格页为准

命令行在文档和面试里随处可见，读得懂就行：

```
gcloud auth list                          # 现在用的是哪个账号
gcloud auth application-default login     # 本机登录 ADC
gcloud storage cp report.json gs://clausecheck-reports/reports/
aws sts get-caller-identity               # 我现在是谁（排查 403 的第一步）
aws s3 cp report.json s3://clausecheck-reports/reports/
aws s3 ls s3://clausecheck-reports/reports/
```
--- code
# 示例单价（美元），只用来看数量级，以官方价格页为准
STORAGE_PER_GB_MONTH = 0.02
EGRESS_PER_GB = 0.1
TOKENS_PER_CONTRACT = 150_000
USD_PER_MILLION_TOKENS = 0.5

def monthly_cost(contracts, mb_per_contract=2, downloads_per_contract=3):
    gb = contracts * mb_per_contract / 1024
    storage = gb * STORAGE_PER_GB_MONTH
    egress = gb * downloads_per_contract * EGRESS_PER_GB
    llm = contracts * TOKENS_PER_CONTRACT / 1_000_000 * USD_PER_MILLION_TOKENS
    return {"storage": round(storage, 4), "egress": round(egress, 4), "llm": round(llm, 2)}

for n in (100, 1000):
    print(n, "contracts/month:", monthly_cost(n))

--- prompt
复习第 25 天。下面的代码想在查询出错时打印 `query failed`，可是表名 `clausecheck.review` 少写了一个 s（`client` 是 `bigquery.Client()`）。运行时会发生什么？
--- code
from google.api_core.exceptions import GoogleAPICallError

try:
    job = client.query("SELECT verdict FROM clausecheck.review")
except GoogleAPICallError:
    print("query failed")
rows = list(job.result())
--- options
- 打印 `query failed`
- 不会打印：`client.query()` 只是提交了一个查询作业，表不存在的错误要等 `job.result()` 时才抛出，而那一行不在 `try` 里，程序带着 `NotFound` 崩掉
- 不报错，`rows` 是空列表
- `client.query()` 马上抛出 Python 的 `SyntaxError`
answer: 2
--- explain
`client.query()` 立刻返回一个作业对象；SQL 写错、表不存在、超过字节上限，都在 `job.result()` 时才抛出，所以 `try` 要包住 `result()`（或者用一步完成的 `client.query_and_wait()`）。今天还会遇到同样的事：boto3 的 client 建好时不检查凭证，第一次调用才报错；GCS 的 `list_blobs` 开始遍历时才真正发请求、才报错。「错误从哪一步冒出来」决定了 `try` 该放在哪里。

from botocore.exceptions import ClientError

def upload_contract(s3, bucket, key, text, contract_id, prompt_version):
    try:
        resp = s3.put_object(
            Bucket=bucket,
            Key=key,
            Body=text.encode("utf-8"),
            ContentType="text/plain; charset=utf-8",
            Metadata={"contract-id": str(contract_id), "prompt-version": prompt_version},
            IfNoneMatch="*",

            return None
        raise
    return resp["ETag"]

def list_all_keys(s3, bucket, prefix, page_size=1000):
    keys = []
    kwargs = {"Bucket": bucket, "Prefix": prefix, "MaxKeys": page_size}
    while True:
        resp = s3.list_objects_v2(**kwargs)
        keys += [obj["Key"] for obj in resp.get("Contents", [])]
        if not resp.get("IsTruncated"):
            return keys
        kwargs["ContinuationToken"] = resp["NextContinuationToken"]

写 `with_backoff(fn, sleep, attempts=4, base=0.5)`：调用 `fn()`，遇到**可以重试**的错误就等一会儿再试。

- `is_retryable(error)` 已经写好（就是上一题的被测函数）
- 第 1 次失败后等 `base` 秒，第 2 次后等 `base * 2`，第 3 次后 `base * 4`……（指数退避）。等待用传进来的 `sleep(秒数)`：测试传一个只记录、不真睡的假函数
- 最多调用 `fn` 共 `attempts` 次；最后一次还失败，就把**这个错误**抛出去（不再 sleep）
- 不可重试的错误：马上抛出，不 sleep
- 成功就返回 `fn()` 的结果

这里先不加随机抖动，方便测试（闭卷题会加）。测试用的 S3 client 设置了 `total_max_attempts=1`：SDK 自己不重试，每个错误都直接交给你。

from botocore.exceptions import ClientError
from google.api_core.exceptions import TooManyRequests, ServiceUnavailable, InternalServerError

RETRYABLE_AWS_CODES = {"ThrottlingException", "SlowDown", "ServiceUnavailable", "InternalError"}

def is_retryable(error):
    if isinstance(error, ClientError):
        return error.response["Error"]["Code"] in RETRYABLE_AWS_CODES
    return isinstance(error, (TooManyRequests, ServiceUnavailable, InternalServerError))

def with_backoff(fn, sleep, attempts=4, base=0.5):
    for attempt in range(attempts):
        try:
            return fn()
        except Exception as e:
            if not is_retryable(e) or attempt == attempts - 1:
                raise
            sleep(base * 2 ** attempt)

from botocore.exceptions import ClientError

MAX_MINUTES = 7 * 24 * 60

def share_link(s3, bucket, key, minutes):
    if minutes < 1 or minutes > MAX_MINUTES:

        s3.head_object(Bucket=bucket, Key=key)
    except ClientError as e:

            raise FileNotFoundError(key)
        raise
    return s3.generate_presigned_url("get_object", Params={"Bucket": bucket, "Key": key}, ExpiresIn=minutes * 60)

- **先列出全部键，再逐个挪**：`get_object` 读出字节和 `ContentType`，用同一个键、同样的 `ContentType` `put_object` 到归档桶，然后 `delete_object` 删掉原来的
- 返回挪走的键的列表（按列出的顺序）

boto3 的参数全部用关键字传。（真项目里会用 `copy_object` 在 S3 内部复制，不用先下载再上传；本页的模拟没有它，这里用 get + put。）
--- solution
def archive_contracts(s3, customer_id, page_size=1000):
    src, dst = "clausecheck-contracts", "clausecheck-archive"
    kwargs = {"Bucket": src, "Prefix": f"contracts/{customer_id}/", "MaxKeys": page_size}
    keys = []
    while True:
        resp = s3.list_objects_v2(**kwargs)
        keys += [obj["Key"] for obj in resp.get("Contents", [])]
        if not resp.get("IsTruncated"):
            break
        kwargs["ContinuationToken"] = resp["NextContinuationToken"]
    for key in keys:
        obj = s3.get_object(Bucket=src, Key=key)
        s3.put_object(Bucket=dst, Key=key, Body=obj["Body"].read(), ContentType=obj["ContentType"])
        s3.delete_object(Bucket=src, Key=key)
    return keys

import json
from google.api_core.exceptions import NotFound

def add_note(client, contract_id, note):
    blob = client.bucket("clausecheck-reports").blob(f"reports/{contract_id}.json")
    try:
        report = json.loads(blob.download_as_text())
    except NotFound:
        report = {"contract_id": contract_id, "notes": []}
    notes = report.setdefault("notes", [])
    if note not in notes:
        notes.append(note)
    blob.upload_from_string(json.dumps(report, ensure_ascii=False), content_type="application/json")
    return report

exam: yes

--- prompt
写 `call_with_retry(fn, sleep, rand, attempts=5, base=0.2, cap=2.0)`：

- 调用 `fn()`，成功就返回结果
- 失败时先判断能不能重试：`botocore.exceptions.ClientError` 且错误码在 `{"ThrottlingException", "SlowDown", "ServiceUnavailable"}` 里；或者是 `google.api_core.exceptions` 的 `TooManyRequests`、`ServiceUnavailable`。不能重试的错误马上抛出
- 第 `i` 次失败后（`i` 从 0 开始数）等待 `min(cap, base * 2 ** i) * rand()` 秒（指数退避 + 上限 + 随机抖动）。`sleep(秒数)` 和 `rand()`（返回 0 到 1 之间的数）都是传进来的
- 一共最多调用 `fn` `attempts` 次；最后一次失败时把那个错误抛出去，不再等待
--- solution
from botocore.exceptions import ClientError
from google.api_core.exceptions import TooManyRequests, ServiceUnavailable

AWS_RETRYABLE = {"ThrottlingException", "SlowDown", "ServiceUnavailable"}

def _retryable(e):
    if isinstance(e, ClientError):
        return e.response["Error"]["Code"] in AWS_RETRYABLE
    return isinstance(e, (TooManyRequests, ServiceUnavailable))

def call_with_retry(fn, sleep, rand, attempts=5, base=0.2, cap=2.0):
    for i in range(attempts):
        try:
            return fn()
        except Exception as e:
            if not _retryable(e) or i == attempts - 1:
                raise
            sleep(min(cap, base * 2 ** i) * rand())
