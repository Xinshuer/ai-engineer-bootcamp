@@ concept
title: assert：最小的测试
--- body
`assert 条件, "说明"`：条件为真，什么都不发生；条件为假，抛出 `AssertionError`，说明文字就是错误信息。

```python
assert section_of("10.1") == "10", "two-digit section"
```

测试说到底就是**一段调用你的函数、再 assert 结果的代码**。第 7 天你已经用 `assert` 给自己写过例子了。

两个习惯：

- 写上说明，失败时一眼知道是哪条假设错了；不写说明，AssertionError 的信息是空的
- `assert` 用来写测试、检查「不可能发生」的情况；校验外部输入（模型输出、用户的文件）还是用 `if ... raise ValueError`（第 3 天），因为用 `python -O` 运行时所有 assert 都会被跳过
--- code
def section_of(clause_id):
    return clause_id.split(".")[0]

assert section_of("8.1") == "8"
assert section_of("12") == "12", "no dot"
print("two checks passed")

# 故意写错一个期望值，看看失败长什么样
try:
    assert section_of("10.1") == "1", "two-digit section"
except AssertionError as e:
    print("AssertionError:", e)

@@ concept
title: 测试函数和 pytest
--- body
把 assert 放进以 `test_` 开头的函数里，**一个函数只测一件事**，名字写清楚测的是什么：

```python
def test_two_digit_section():
    assert section_of("10.1") == "10"
```

在本机，pytest 会自动找出 `test_*.py` 文件里所有 `test_` 函数，一个个运行，一个失败不影响其他的：`python -m pytest`。Clause Check 的 `tests/test_split.py` 就是这么写的。

本页的「写测试」题：题目给你一个**正确的函数**，同时偷偷藏了几个故意埋了 bug 的版本。你的测试必须**在正确版本上全部通过**，并且**让每个 bug 版本至少失败一个测试**。这叫变异测试（mutation testing）：测试好不好，就看它能不能抓住故意埋的 bug。下面的例子演示的就是这件事。
--- code
def section_of(clause_id):
    return clause_id.split(".")[0]

def test_simple():
    assert section_of("8.1") == "8"

def test_two_digit_section():
    assert section_of("10.1") == "10"

def test_no_dot():
    assert section_of("12") == "12"

# pytest 做的事大致就是这个循环：逐个调用 test_ 函数，抛出异常就算失败
def run_tests():
    for test in [test_simple, test_two_digit_section, test_no_dot]:
        try:
            test()
            print("PASSED", test.__name__)
        except AssertionError:
            print("FAILED", test.__name__)

run_tests()

print("--- a buggy version: clause_id[0] ---")
def section_of(clause_id):
    return clause_id[0]

run_tests()

@@ concept
title: 怎么想测试用例
--- body
对每个函数，按三类想输入，每个想法写一个测试：

1. **正常**：最典型的一两个例子
2. **边界**：空（`""`、`[]`）、0、只有一个元素、**刚好等于**上限、两位数编号 `10.1`、三层编号 `10.2.1`
3. **非法**：坏 JSON、未知判定、负数。函数应该报错还是返回默认值？测试把这个决定写死

bug 最爱藏在边界上：`>` 和 `>=` 只有在「刚好等于」时结果才不同，离边界很远的例子，对的和错的实现都能通过。

测试名写成一句话，比如 `test_exactly_at_limit_is_not_split`。它失败时，名字本身就告诉你坏了什么。
--- code
def needs_split(text, limit=20):
    return len(text) > limit

def needs_split_buggy(text, limit=20):
    return len(text) >= limit

for text in ["", "short clause", "x" * 20, "x" * 21]:
    print(len(text), needs_split(text), needs_split_buggy(text))

@@ concept
title: 测试报错和小数：raises、approx
--- body
**该报错的时候，真的报错了吗？** 用 `pytest.raises`：

```python
import pytest

def test_bad_json_raises():
    with pytest.raises(ValueError, match="not JSON"):
        parse_verdict("Sure! {")
```

`with` 块里的代码必须抛出 `ValueError`，否则这个测试失败（报 `DID NOT RAISE`）。`match=` 是在错误信息里搜索的正则，确认报的正是**这个**错。

最危险的 bug 之一是**吞掉异常**：出错时悄悄返回 None，程序不崩，结果却是错的。`pytest.raises` 专门抓它。

**小数别用 `==` 直接比**：`0.1 + 0.2 == 0.3` 是 False（二进制存不准这些小数）。写 `assert x == pytest.approx(0.3)`，允许极小的误差。
--- code
import pytest

print(0.1 + 0.2, 0.1 + 0.2 == 0.3)
print(0.1 + 0.2 == pytest.approx(0.3))

def parse_risk(text):
    risk = text.strip().lower()
    if risk not in ("low", "medium", "high"):
        raise ValueError(f"unknown risk: {text}")
    return risk

def test_unknown_risk_raises():
    with pytest.raises(ValueError, match="unknown risk"):
        parse_risk("urgent")

test_unknown_risk_raises()
print("test passed")

def parse_risk_swallowing(text):
    try:
        return parse_risk(text)
    except ValueError:
        return None

print("swallowed:", parse_risk_swallowing("urgent"))

@@ concept
title: 调试流程：先复现，再猜，一次只改一处
--- body
遇到 bug 别急着改代码，按这个顺序来：

1. **复现**：找到能稳定出错的**最小**输入（一条条款，而不是整份合同）
2. **读 Traceback**：从最下面一行读起，先看错误类型和信息，再看紧挨着它的那一行代码
3. **看中间值**：用 `repr(x)` 或 f-string 的 `{x=}` 打印。`repr` 会露出看不见的空格、换行，也分得清 `'8.1'` 和 `8.1`
4. **一次一个假设**：「我猜是字段名不对」→ 打印验证 → 对了再改；每次只改一处
5. **补测试**：把刚才那个最小输入写成测试，这个 bug 就再也回不来了
--- code
reply = "flag\n"
print(reply == "flag")
print(repr(reply))
print(f"{reply=}")

cid = 8.1
print(f"{cid=}", type(cid).__name__)

row = {"clause_id": "8.1", "risk_level": "high"}
print(f"{row=}")
print(sorted(row))

@@ concept
title: logging：给程序留下记录
--- body
`print` 适合临时看一眼；长期运行的程序（比如把 Clause Check 做成 `api.py` 那样的服务）要用 `logging`：

- 每条记录有**级别**：DEBUG（细节）< INFO（正常进展）< WARNING（有问题但还能继续）< ERROR（失败了）
- 一行配置决定显示哪些级别、什么格式，调试语句不用删：线上设成 WARNING 就安静了，排查时改成 DEBUG 就能看到全部细节

```python
logging.basicConfig(level=logging.INFO, format="%(levelname)s %(message)s")
logger = logging.getLogger(__name__)
logger.info("clause %s -> %s", cid, verdict)
```

`getLogger(__name__)` 让每个文件有自己名字的 logger。用 `%s` 占位、把值作为参数传进去，而不是自己先拼好字符串：这条记录被过滤掉时，连拼字符串的功夫都省了。
--- code
import logging

logging.basicConfig(level=logging.INFO, format="%(levelname)s %(name)s: %(message)s")
logger = logging.getLogger("clausecheck.review")

for cid, verdict in [("3.1", "accept"), ("8.1", "redline")]:
    logger.debug("raw reply for %s", cid)
    logger.info("clause %s -> %s", cid, verdict)
logger.warning("clause %s: HTTP %d, retrying", "10.1", 429)

@@ concept
title: 常见 bug 模式
--- body
这些 bug 反复出现，面试的「找 bug」题也最爱考它们：

- **差一（off-by-one）**：`range(1, len(xs))` 漏了第一个；`text[:n]` 和 `text[:n - 1]` 差一个字符
- **`>` 和 `>=`**：只在刚好相等时露馅
- **可变默认参数**：`def f(tags=[])`（第 8 天）
- **边遍历边删除**：`for x in xs: xs.remove(x)` 会跳过元素
- **`is` 和 `==`**：`is` 比的是「是不是同一个对象」。比较值永远用 `==`，`is` 只用在 `is None`
- **`//` 和 `/`**：`2 // 3` 是 0
- **忘了 return**：函数悄悄返回 None
- **覆盖内置名字**：写了 `list = [...]` 之后，`list(...)` 就不能用了
--- code
ids = ["3.1", "8.1", "10.1"]
print([ids[i] for i in range(1, len(ids))])
print(2 // 3, 2 / 3)

verdicts = ["accept", "accept", "flag"]
for v in verdicts:
    if v == "accept":
        verdicts.remove(v)
print(verdicts)

def label(risk):
    if risk == "high":
        return "HIGH RISK"
    "normal"

print(label("high"), label("low"))

--- context
写测试离不开 `assert`：它检查一个条件，不成立就报错。这段代码用它挡住不合法的判定，比如模型把风险等级错填进了判定。

    check_verdict("HIGH")

写 `validate_review(d)`，检查模型返回的一条审查结果（字典）：

--- solution
REQUIRED = ("clause_id", "verdict", "risk_level")

def validate_review(d):
    for key in REQUIRED:
        if key not in d:
            raise ValueError(f"missing field: {key}")
    if d["verdict"] not in ("accept", "flag", "redline"):
        raise ValueError(f"bad verdict: {d['verdict']}")
    if d["risk_level"] not in ("low", "medium", "high"):
        raise ValueError(f"bad risk_level: {d['risk_level']}")
    return True
--- tests
def _msg(d):

        validate_review(d)
    except ValueError as e:
        return str(e)
    return "没有报错"

模型返回的 `rule_ids` 经常有重复，还带着空格。写 `dedupe_keep_order(items)`：

- 每项先 `.strip()`
- strip 之后相同的算重复，只保留**第一次出现**的，顺序不变
- strip 之后是空字符串的丢掉

返回一个新列表。

`dedupe_keep_order([" PB-03", "PB-01", "PB-03 ", ""])` → `["PB-03", "PB-01"]`
--- solution
def dedupe_keep_order(items):
    seen = set()
    result = []
    for item in items:
        x = item.strip()
        if x and x not in seen:
            seen.add(x)
            result.append(x)
    return result
--- tests

expect("全是空白", lambda: dedupe_keep_order(["", "  "]), [])
expect("空列表", lambda: dedupe_keep_order([]), [])

审一条条款时，常常要连着看它前后的条款。写 `window(items, size)`：返回所有长度为 `size` 的**连续**片段（每个片段是一个列表），按顺序排列。

- `window(["3.1", "3.2", "3.3", "4.1"], 2)` → `[["3.1", "3.2"], ["3.2", "3.3"], ["3.3", "4.1"]]`
- `size` 比列表还长：返回 `[]`
- `size` 小于 1：`raise ValueError`
--- solution
def window(items, size):
    if size < 1:
        raise ValueError("size must be at least 1")
    return [items[i:i + size] for i in range(len(items) - size + 1)]
--- tests
