title: 从你的执行器到 StateGraph
--- body
第 19 天你写的执行器，每一块在 LangGraph 里都有对应：

- `nodes["review"] = review` → `g.add_node("review", review)`
- `start = "load"` → `g.add_edge(START, "load")`
- `edges["load"] = "review"` → `g.add_edge("load", "review")`
- `edges["summarise"] = route` → `g.add_conditional_edges("summarise", route)`（下下张卡片）
- `"END"` → `END`
- `run_graph(...)` → `app = g.compile()`，然后 `app.invoke(输入)` 返回**最终状态**（一个 dict）
- `max_steps=20` → 调用时传 `{"recursion_limit": 20}`（第 31 天：不传就是 10007）

规矩也一样：节点拿到整个 state，只返回**它改了的键**（一个小字典），合并交给框架。`compile()` 会先检查结构（边指向不存在的节点、没有起点……），返回的 `app` 是一个 Runnable，所以也有 `stream`、`batch`（第 29 天）。

State 用 `TypedDict`（第 19 天学过），`total=False` 表示每个键一开始都可以没有。

值不值得：下面这种直线流程，普通函数一个接一个调用就够了（`pipeline.py` 就是这样）。LangGraph 真正值钱的是检查点、中断等人、并行和流式，`graph.py` 顶部的 docstring 写的就是这个理由。
--- code
from typing import TypedDict
from langgraph.graph import StateGraph, START, END

class State(TypedDict, total=False):
    text: str
    clauses: list[str]
    redlines: list[str]
    summary: str

def load(state: State) -> dict:
    return {"clauses": state["text"].split("\n")}

def review(state: State) -> dict:
    return {"redlines": [c.split()[0] for c in state["clauses"] if "unlimited" in c]}

def summarise(state: State) -> dict:
    return {"summary": f"{len(state['clauses'])} clauses, {len(state['redlines'])} redline(s)"}

g = StateGraph(State)
g.add_node("load", load)
g.add_node("review", review)
g.add_node("summarise", summarise)
g.add_edge(START, "load")
g.add_edge("load", "review")
g.add_edge("review", "summarise")
g.add_edge("summarise", END)
app = g.compile()

final = app.invoke({"text": "3.1 Fees are payable in 30 days.\n8.3 Liability shall be unlimited."})
print(final["summary"], final["redlines"])
print(sorted(final))
print(type(app).__name__)

@@ concept
title: State 和 reducer
--- body
每个键默认是**覆盖**：两个节点先后写 `verdict`，后写的赢，和 `{**state, **update}` 一样。

想「累加」，就给这个键配一个 **reducer**：

```python
class State(TypedDict):
    verdict: str                                  # 覆盖
    notes: Annotated[list[str], operator.add]     # 追加
```

合并时 LangGraph 调用 `operator.add(旧值, 新值)`，对列表就是拼接。reducer 可以是任何「两个参数、返回合并结果」的函数，比如保留更高的风险等级（练习里写）。`invoke` 的输入也要经过 reducer。

为什么重要：节点可以并行（后面的卡片），同一步里好几个节点写同一个键时，只有 reducer 知道怎么合。

经典错误：有 reducer 的键，节点却返回**整个**列表 `{"notes": state["notes"] + ["x"]}`。旧内容会被拼第二遍。节点只返回**新增**的那部分。
--- code
import operator
from typing import Annotated, TypedDict
from langgraph.graph import StateGraph, START, END

class State(TypedDict):
    verdict: str
    notes: Annotated[list[str], operator.add]

def legal(state):
    return {"verdict": "flag", "notes": ["legal: cap is 12 months"]}

def cost(state):
    return {"verdict": "accept", "notes": ["cost: within budget"]}

def wrong(state):
    return {"notes": state["notes"] + ["wrong: returned the whole list"]}

g = StateGraph(State)
g.add_node("legal", legal)
g.add_node("cost", cost)
g.add_node("wrong", wrong)
g.add_edge(START, "legal")
g.add_edge("legal", "cost")
g.add_edge("cost", "wrong")
g.add_edge("wrong", END)
out = g.compile().invoke({"verdict": "", "notes": ["input"]})
print("verdict:", out["verdict"])
for note in out["notes"]:
    print(" -", note)

@@ concept
title: 条件边
--- body
`g.add_conditional_edges("summarise", route)`：`summarise` 跑完后调用 `route(state)`，它返回下一个节点的名字，或者 `END`（直接结束）。和第 19 天的路由函数一模一样。

给路由函数写返回类型 `-> Literal["approve", "export"]`（`graph.py` 的 `route` 就是这样写的）：

- LangGraph 从这个标注知道条件边可能去哪些节点，画图才画得对
- 返回的名字不在里面（比如拼错成 `"Approve"`）时，直接抛 `KeyError: 'Approve'`，马上发现
- 不写标注也能跑，但拼错的名字**不报错**：图记一条警告就停了（后面的卡片专门讲）

也可以用第三个参数说明去向：列表 `["approve", "export"]`，或者映射 `{"yes": "approve", "no": "export"}`（路由返回 yes / no）。效果一样：画图知道去向，拼错也抛 `KeyError`。
--- code
import operator
from typing import Annotated, Literal, TypedDict
from langgraph.graph import StateGraph, START, END

class State(TypedDict, total=False):
    redlines: int
    path: Annotated[list[str], operator.add]

def summarise(state):
    return {"path": ["summarise"]}

def approve(state):
    return {"path": ["approve"]}

def export(state):
    return {"path": ["export"]}

def route(state) -> Literal["approve", "export"]:
    return "approve" if state["redlines"] > 0 else "export"

g = StateGraph(State)
g.add_node("summarise", summarise)
g.add_node("approve", approve)
g.add_node("export", export)
g.add_edge(START, "summarise")
g.add_conditional_edges("summarise", route)
g.add_edge("approve", "export")
g.add_edge("export", END)
app = g.compile()

print(app.invoke({"redlines": 2})["path"])
print(app.invoke({"redlines": 0})["path"])

@@ concept
title: 并行分支和 superstep
--- body
LangGraph 按**步（superstep）**跑：每一步把所有该跑的节点一起跑，跑完再统一合并它们的更新，然后决定下一步。一个节点有两条出边，两个目标就在同一步里并行（普通电脑上是多线程；本页的浏览器里一个接一个跑，结果一样）。

- **汇合**：`g.add_edge(["legal_check", "cost_estimate"], "summarise")`（起点写成列表）表示两边**都完成**后才跑 `summarise`，只跑一次。只写两条单独的边时，两条分支一长一短，`summarise` 会在不同的步里被触发**两次**（下面的例子）
- 同一步里两个节点写同一个**没有 reducer** 的键：`InvalidUpdateError: At key 'verdict': Can receive only one value per step. Use an Annotated key to handle multiple values.` 解决办法就是给它配 reducer
- 合并的顺序是固定的（这一版按节点名排），但不是你加边的顺序，也不是谁先跑完。别依赖它：要稳定的顺序就自己排序
- 不要在并行节点里 `print`：真机上线程先后不定，输出的顺序每次可能不同
--- code
import operator
from typing import Annotated, TypedDict
from langgraph.graph import StateGraph, START, END

class State(TypedDict, total=False):
    findings: Annotated[list[str], operator.add]
    runs: Annotated[list[str], operator.add]

def legal_check(state):
    return {"findings": ["legal: liability is unlimited"]}

def cost_check(state):
    return {"findings": ["cost: fees can rise any time"]}

def cost_estimate(state):
    return {"findings": ["cost: +12% per year"]}

def summarise(state):
    return {"runs": [f"summarise saw {len(state['findings'])} finding(s)"]}

def build(join):
    g = StateGraph(State)
    for name, fn in [("legal_check", legal_check), ("cost_check", cost_check), ("cost_estimate", cost_estimate), ("summarise", summarise)]:
        g.add_node(name, fn)
    g.add_edge(START, "legal_check")
    g.add_edge(START, "cost_check")
    g.add_edge("cost_check", "cost_estimate")
    if join:
        g.add_edge(["legal_check", "cost_estimate"], "summarise")
    else:
        g.add_edge("legal_check", "summarise")
        g.add_edge("cost_estimate", "summarise")
    g.add_edge("summarise", END)
    return g.compile()

print("two edges:", build(join=False).invoke({})["runs"])
out = build(join=True).invoke({})
print("joined:   ", out["runs"])
print(sorted(out["findings"]))

@@ concept
title: 报错的错误和悄悄的错误
--- body
LangGraph 会**报出来**的（好事，马上知道）：

- 边指向不存在的节点：`compile()` 时 `ValueError: Found edge ending at unknown node ...`
- 没有从 `START` 出发的边：`ValueError: Graph must have an entrypoint ...`
- 同名节点加两次：`ValueError: Node ... already present.`
- 节点返回的不是字典：`InvalidUpdateError: Expected dict, got ...`
- 节点读一个没人写过的键：普通的 `KeyError`

**悄悄**发生的（最危险，测试要专门抓）：

- 节点返回了 State 里没有的键（`verdikt`）：直接丢掉
- 路由函数（没有 `Literal` 标注）返回了不存在的节点名：只记一条警告（下面输出里那行 `Task ... wrote to unknown channel ...`），图就停了
- 节点没有出边：图在那里结束
- 节点忘了 `return`（返回 `None`）：当成「什么都没改」

怎么抓：测试断言**最终状态**和**走过的节点**；路由函数写 `Literal`；调试时看 stream（下一张卡片）。
--- code
from typing import TypedDict
from langgraph.graph import StateGraph, START, END

class S(TypedDict, total=False):
    verdict: str

def run(label, node, route=None):
    try:
        g = StateGraph(S)
        g.add_node("review", node)
        g.add_node("export", lambda s: {})
        g.add_edge(START, "review")
        if route:
            g.add_conditional_edges("review", route)
        else:
            g.add_edge("review", "export")
        g.add_edge("export", END)
        print(f"{label:<16} ->", g.compile().invoke({"verdict": "pending"}))
    except Exception as e:
        print(f"{label:<16} -> {type(e).__name__}: {str(e).splitlines()[0]}")

run("returns a str", lambda s: "flag")
run("reads missing", lambda s: {"verdict": s["risk"]})
run("typo in key", lambda s: {"verdikt": "flag"})
run("forgot return", lambda s: None)
run("route typo", lambda s: {"verdict": "flag"}, route=lambda s: "exprot")

@@ concept
title: stream：看每一步做了什么
--- body
`invoke` 只给最终状态。想知道「每一步哪个节点改了什么」，用 `stream`：

- `stream_mode="updates"`：每跑完一个节点给一次 `{节点名: 它的更新}`。一个节点什么都没写进状态（返回 `None`，或者键名写错被丢掉）时，这里是 `None`
- `stream_mode="values"`：每一步之后给一次**完整状态**，第一次是输入本身（某一步什么都没写进状态时，这一步不给）
- 两种都要：`stream_mode=["updates", "values"]`，每次给一个 `(模式, 数据)` 元组

调试「悄悄的错误」时看 updates 一眼就明白：该出现的节点没出现（路由拼错），或者某个节点的更新是 `None`（键名写错）。第 34 天用它给前端推进度。并行分支的 updates 在真机上的顺序可能每次不同，别依赖它。
--- code
from typing import Literal, TypedDict
from langgraph.graph import StateGraph, START, END

class State(TypedDict, total=False):
    text: str
    verdict: str
    exported: bool

def review(state):
    return {"verdict": "redline" if "unlimited" in state["text"] else "accept"}

def route(state) -> Literal["approve", "export"]:
    return "approve" if state["verdict"] == "redline" else "export"

def approve(state):
    return {"verdikt": "approved"}   # 故意拼错：看 updates 里这一步变成了什么

def export(state):
    return {"exported": True}

g = StateGraph(State)
g.add_node("review", review)
g.add_node("approve", approve)
g.add_node("export", export)
g.add_edge(START, "review")
g.add_conditional_edges("review", route)
g.add_edge("approve", "export")
g.add_edge("export", END)
app = g.compile()

for update in app.stream({"text": "Liability shall be unlimited."}, stream_mode="updates"):
    print(update)
print("--- values")
for state in app.stream({"text": "Fees are due in 30 days."}, stream_mode="values"):
    print(state)

@@ concept
title: MessagesState 和 add_messages
--- body
聊天历史是最常见的状态。`MessagesState` 是一个现成的 State，只有一个键 `messages`，reducer 是 `add_messages`：

- 节点返回 `{"messages": [新消息]}`，**接到**历史后面
- `("user", "hi")`、`{"role": "user", "content": "hi"}` 会自动变成 `HumanMessage`，并分配一个 id
- 同一个 id 的新消息**替换**旧的；`RemoveMessage(id=...)` **删除**那一条（用来裁剪历史）
- 要更多键就继承它：`class State(MessagesState): clause_id: str`

经典错误：自己写 `messages: list`（没有 reducer）。节点返回的一条新消息会把整个历史**覆盖**掉，模型下一轮就「失忆」了。

system prompt 通常不存进状态，而是在节点里调模型时临时放在最前面（`create_agent` 也是这样做的）。节点里的 `ChatDeepSeek` 照样关掉 thinking：这里没有工具，开着也不会 400，但简单问答用不着长思考，思考 token 按输出计费；节点一旦给模型绑了工具，就必须关（第 31 天）。
--- code
from langchain_core.messages import SystemMessage, AIMessage, HumanMessage, RemoveMessage
from langchain_deepseek import ChatDeepSeek
from langgraph.graph import StateGraph, START, END, MessagesState
from langgraph.graph.message import add_messages

model = ChatDeepSeek(model="deepseek-flash", extra_body={"thinking": {"type": "disabled"}})

def chat(state: MessagesState):
    reply = model.invoke([SystemMessage("You answer questions about a SaaS contract.")] + state["messages"])
    return {"messages": [reply]}

g = StateGraph(MessagesState)
g.add_node("chat", chat)
g.add_edge(START, "chat")
g.add_edge("chat", END)
app = g.compile()

out = app.invoke({"messages": [("user", "Is clause 8.1 standard?")]})
out = app.invoke({"messages": out["messages"] + [("user", "And clause 9.2?")]})
print([type(m).__name__ for m in out["messages"]])
print([m["role"] for m in MOCK.calls[-1]["body"]["messages"]])

history = [HumanMessage("Review clause 8.1", id="m1"), AIMessage("accept", id="m2")]
history = add_messages(history, [AIMessage("flag: see Section 12", id="m2")])
print([m.content for m in history])
print([m.content for m in add_messages(history, [RemoveMessage(id="m1")])])

title: 看图：draw_mermaid
--- body
`app.get_graph().draw_mermaid()` 输出 Mermaid 文字，贴到 GitHub、Notion 或 mermaid.live 就能看成图。读法：

- `a --> b;` 固定边；`a -.-> b;` 条件边（虚线）
- `__start__`、`__end__` 就是 `START`、`END`

条件边能去哪儿，是从路由函数的 `Literal` 标注（或第三个参数）读出来的。**没有标注时它不知道**：下面第二行里 summarise 直接连到 `__end__`，连 `approve --> export` 这些边也不见了（两个节点还在，成了孤岛），画出来的图是错的（图照样能跑）。这又是一个写 `Literal` 的理由。

对照 `graph.py` 顶部 docstring 里手画的图：`load -> review -> summarise -> (redlines?) -> approve -> export`，另一条是 summarise 直接到 export。给 PR 或面试讲架构时，把 Mermaid 贴出来比口头描述清楚得多。
--- code
from typing import Literal, TypedDict
from langgraph.graph import StateGraph, START, END

class State(TypedDict, total=False):
    redlines: int

def build(route):
    g = StateGraph(State)
    for name in ["load", "review", "summarise", "approve", "export"]:
        g.add_node(name, lambda s: {})
    g.add_edge(START, "load")
    g.add_edge("load", "review")
    g.add_edge("review", "summarise")
    g.add_conditional_edges("summarise", route)
    g.add_edge("approve", "export")
    g.add_edge("export", END)
    return g.compile()

def with_literal(state) -> Literal["approve", "export"]:
    return "approve" if state["redlines"] else "export"

def without(state):
    return "approve" if state["redlines"] else "export"

for route in [with_literal, without]:
    edges = [line.strip() for line in build(route).get_graph().draw_mermaid().splitlines() if "->" in line]
    print(route.__name__, edges)

--- prompt
复习第 31 天。一个 `create_agent` 做的 agent，调用时**没有**传 `recursion_limit`。某次模型卡住了，每一轮都要求再调一次工具。在本课用的 LangGraph 1.2 上会发生什么？
--- options
- 跑 25 步后抛 `GraphRecursionError`
- 一直跑到默认上限 10007 步才抛 `GraphRecursionError`，中间调了约 5000 次模型

answer: 2
--- explain
这一版的默认上限是 10007，老版本和很多教程里写的是 25。每两步（model + tools）就是一次付费的模型调用，所以不设上限几乎等于没有上限。生产代码里永远显式传 `{"recursion_limit": N}`，并在外面接住 `GraphRecursionError`（第 31 天的 `ask_safely`）。

from typing import TypedDict
from langgraph.graph import StateGraph, START, END

class State(TypedDict, total=False):
    text: str
    clauses: list[str]
    redlines: list[str]
    summary: str

def load(state: State) -> dict:
    return {"clauses": [line for line in state["text"].split("\n") if line.strip()]}

def review(state: State) -> dict:
    return {"redlines": [c.split()[0] for c in state["clauses"] if "unlimited" in c or "any country" in c]}

def summarise(state: State) -> dict:
    return {"summary": f"{len(state['clauses'])} clauses, {len(state['redlines'])} redline(s)"}

def build_app():
    g = StateGraph(State)
    g.add_node("load", load)
    g.add_node("review", review)
    g.add_node("summarise", summarise)

from typing import Annotated, TypedDict
from langgraph.graph import StateGraph, START, END

ORDER = {"low": 0, "medium": 1, "high": 2}

def max_risk(old, new):
    if ORDER.get(new, -1) > ORDER.get(old, -1):
        return new
    return old

class State(TypedDict, total=False):
    text: str
    risk: Annotated[str, max_risk]

def liability_check(state):
    return {"risk": "high" if "unlimited" in state["text"] else "low"}

def data_check(state):
    return {"risk": "medium" if "any country" in state["text"] else "low"}

from typing import Literal, TypedDict
from langgraph.graph import StateGraph, START, END

class State(TypedDict, total=False):
    text: str
    clauses: list[str]
    redlines: list[str]
    summary: str
    approved: bool
    exported: str

def load(state):
    return {"clauses": [line for line in state["text"].split("\n") if line.strip()]}

def review(state):
    return {"redlines": [c.split()[0] for c in state["clauses"] if "unlimited" in c or "any country" in c]}

def summarise(state):
    return {"summary": f"{len(state['clauses'])} clauses, {len(state['redlines'])} redline(s)"}

def route(state) -> Literal["approve", "export"]:
    return "approve" if state["redlines"] else "export"

def approve(state):
    return {"approved": True}

def export(state):
    return {"exported": "with redlines" if state.get("approved") else "report only"}

def build_review_graph():
    g = StateGraph(State)
    for name, fn in [("load", load), ("review", review), ("summarise", summarise), ("approve", approve), ("export", export)]:
        g.add_node(name, fn)
    g.add_edge(START, "load")
    g.add_edge("load", "review")
    g.add_edge("review", "summarise")
    g.add_conditional_edges("summarise", route)
    g.add_edge("approve", "export")
    g.add_edge("export", END)
    return g.compile()

- 三个都完成后跑 `decide`，**只跑一次**：`decision` = `"redline"`（risk 是 high）、`"flag"`（medium）、`"accept"`（low）
- `decide → END`
--- solution
import operator
from typing import Annotated, TypedDict
from langgraph.graph import StateGraph, START, END

ORDER = {"low": 0, "medium": 1, "high": 2}

def max_risk(old, new):
    return new if ORDER.get(new, -1) > ORDER.get(old, -1) else old

class State(TypedDict, total=False):
    text: str
    risk: Annotated[str, max_risk]
    findings: Annotated[list[str], operator.add]
    decision: str

def check(keyword, level, name):
    def node(state):
        if keyword in state["text"]:
            return {"risk": level, "findings": [name]}
        return {"risk": "low", "findings": []}
    return node

def decide(state):
    return {"decision": {"high": "redline", "medium": "flag"}.get(state["risk"], "accept")}

def build_checks():
    g = StateGraph(State)
    names = []
    for name, keyword, level in [("liability", "unlimited", "high"), ("data", "any country", "medium"), ("payment", "without notice", "medium")]:
        g.add_node(name, check(keyword, level, name))
        g.add_edge(START, name)
        names.append(name)
    g.add_node("decide", decide)
    g.add_edge(names, "decide")
    g.add_edge("decide", END)
    return g.compile()

- `trim` 节点：只保留最后 `keep` 条消息，更早的每一条都用 `RemoveMessage(id=m.id)` 删掉（`from langchain_core.messages import RemoveMessage`）
- `chat` 节点：调用 `model.invoke(...)`，发给模型的是 `[SystemMessage("You review SaaS contracts.")] + 当前的 messages`（`from langchain_core.messages import SystemMessage`），把回复追加进 messages。system 消息**不**存进状态
- 边：`START → trim → chat → END`
--- solution
from langchain_core.messages import RemoveMessage, SystemMessage
from langgraph.graph import StateGraph, START, END, MessagesState

def build_chat(model, keep):
    def trim(state: MessagesState):
        return {"messages": [RemoveMessage(id=m.id) for m in state["messages"][:-keep]]}

    def chat(state: MessagesState):
        reply = model.invoke([SystemMessage("You review SaaS contracts.")] + state["messages"])
        return {"messages": [reply]}

    g = StateGraph(MessagesState)
    g.add_node("trim", trim)
    g.add_node("chat", chat)
    g.add_edge(START, "trim")
    g.add_edge("trim", "chat")
    g.add_edge("chat", END)
    return g.compile()
