@@ concept
title: 从 Python 到 TypeScript
--- body
概念几乎一样，写法不同：

- 变量：`const x = 1`（不会再改）/ `let x = 1`（会改），不用 `=` 裸写
- 语句末尾一般加 `;`，代码块用 `{ }` 而不是缩进
- `print(...)` → `console.log(...)`
- f-string `f"{a}"` → 模板字符串 `` `${a}` ``（反引号）
- `True` / `False` / `None` → `true` / `false` / `null`、`undefined`
- `and` / `or` / `not` → `&&` / `||` / `!`
- 相等用 `===`，不相等用 `!==`
- 注释 `#` → `//`

本机运行：`npx tsx 文件.ts`；只做类型检查：`npx tsc --noEmit`。本页两件事都会做。
--- code
const clauseId = "8.1";
let count = 3;
count = count + 1;
console.log(clauseId, count);

console.log(count > 3 && clauseId.length > 0, !true);

title: 数组、对象和 type
--- body
- 数组：`const ids: string[] = ["3.1", "8.1"]`，`ids.length`、`ids[0]`、`ids.push("12")`
- 对象（相当于 Python 的字典）：`{ id: "8.1", risk: "high" }`，用 `c.id` 读字段
- 用 `type` 给对象的形状起名字：

```ts
type Clause = { id: string; verdict: Verdict; risk: "low" | "medium" | "high" };
```

- `"low" | "medium" | "high"` 叫**联合字面量类型**，就是 Python 里的 `Literal["low", "medium", "high"]`：只能是这几个值之一

title: 函数和箭头函数
--- body
参数和返回值都标类型：

```ts
function describe(id: string, heading: string): string {
  return `${id} ${heading}`;
```

  return `${prefix} ${id}`;
}

console.log(isHigh("high"), isHigh("low"));
console.log(label("8.1"), label("8.1", "Section"));

@@ concept
title: 数组方法：map、filter、find
--- body
TypeScript 里很少手写「准备空数组 → 循环 → push」，而是用数组方法：

- `filter(c => 条件)` 留下满足条件的，相当于推导式里的 `if`
- `map(c => 新值)` 把每个元素变成新值，相当于推导式的前半部分
- `find(c => 条件)` 找第一个，找不到是 `undefined`
- `includes(x)`、`join(", ")`、`some(...)`、`every(...)`

可以连着写：`clauses.filter(c => c.risk === "high").map(c => c.id)`
--- code
type Clause = { id: string; risk: string };
const clauses: Clause[] = [
  { id: "3.1", risk: "low" },
  { id: "8.1", risk: "high" },
  { id: "10.1", risk: "high" },
];
console.log(clauses.filter((c) => c.risk === "high").map((c) => c.id));
console.log(clauses.find((c) => c.id === "8.1"));
console.log(clauses.find((c) => c.id === "99"));
console.log(clauses.map((c) => c.id).join(", "));

@@ concept
title: Record 和计数
--- body
「键是字符串、值是数字」的对象写成 `Record<string, number>`，就是 Python 的 `dict[str, int]`。

计数的标准写法：

```ts
const counts: Record<string, number> = {};
for (const v of verdicts) {
  counts[v] = (counts[v] ?? 0) + 1;
}
```

`a ?? b`：a 是 `null` 或 `undefined` 时用 b，相当于 Python 的 `dict.get(key, 0)` 那个默认值。
--- code
const verdicts = ["accept", "flag", "accept", "redline"];
const counts: Record<string, number> = {};
for (const v of verdicts) {
  counts[v] = (counts[v] ?? 0) + 1;
}
console.log(counts);
console.log(Object.keys(counts), counts["flag"]);

@@ concept
title: 排序的两个坑
--- body
1. `sort()` **不给比较函数时按字符串排序**：`[10, 9, 1].sort()` 得到 `[1, 10, 9]`
2. `sort()` **会修改原数组**。不想改原数组，先复制：`[...arr].sort(...)`

比较函数返回负数表示 a 排前面：

```ts
[...clauses].sort((a, b) => RISK_ORDER[a.risk] - RISK_ORDER[b.risk])
```

和 Python 的 `sorted` 一样，JavaScript 的 sort 也是稳定的。
--- code
const nums = [10, 9, 1];
console.log([...nums].sort());
console.log([...nums].sort((a, b) => a - b));
console.log(nums);
const RISK_ORDER: Record<string, number> = { high: 0, medium: 1, low: 2 };
const risks = ["low", "high", "medium", "high"];
console.log([...risks].sort((a, b) => RISK_ORDER[a] - RISK_ORDER[b]));

--- prompt
下面哪段代码会被 TypeScript 报错？
--- options
- `let count = 1; count = 2;`
- `const count = 1; count = 2;`
- `const ids = ["3.1"]; ids.push("8.1");`
- `let name = "8.1"; name = "4.2";`

title: == 和 ===
level: 1

--- context
Clause Check 里到处都在比较：判定是不是 `redline`、编号是不是 `8.1`。JavaScript 有两种写「相等」的方式，写 TypeScript 时一般只用其中一种。
--- prompt
为什么 TypeScript / JavaScript 里推荐用 `===` 而不是 `==`？
--- options
- `===` 运行更快
- `==` 会先做类型转换再比较，比如 `"1" == 1` 为 true，容易出意外；`===` 不转换
- `==` 已经被删除了
- 两者完全一样，只是风格
answer: 2
--- explain
`==` 会在比较前偷偷转换类型：`"1" == 1`、`0 == ""`、`null == undefined` 都是 true。`===` 要求类型和值都相同，行为和 Python 的 `==` 一致。一律用 `===` 和 `!==`。
