title: 架构：从上传到看板
cloud: yes
--- body
目标：用户上传合同后马上得到回应；审查在后台慢慢跑，失败了能自动重来；结果能用 SQL 看。括号里是 AWS 上对应的服务：

```
用户上传 .txt
  → GCS 桶 clausecheck-contracts            (S3)
  → 「对象创建」事件 → on_upload 生成任务     (S3 事件通知 → Lambda)
    （GCP 上 on_upload 可以是 Eventarc 触发的一个小 Cloud Run 服务）
  → Pub/Sub 主题 contract-uploaded           (SQS)
  → Cloud Run worker：下载、拆条款、逐条调模型 (Lambda / ECS)
  → BigQuery 表 clausecheck.reviews           (Redshift / Athena)
    + GCS 桶 clausecheck-reports 里的报告     (S3)
  → 看板 SQL：最新判定、成本、失败率
```

桶、worker、BigQuery 都放在欧盟区域（`europe-north1` 芬兰 / `eu-north-1` 斯德哥尔摩）；每个组件一个只拿自己需要权限的服务账号；DeepSeek 密钥在 Secret Manager 里。**注意模型这一步**：调 DeepSeek 时条款原文会发到欧盟以外的服务器。真实客户的合同要么换成欧盟区域的托管模型（第 27 天：Bedrock 的 `eu.` 推理配置文件、Vertex AI 上的 Gemini），要么先确认合同和数据处理协议允许。面试官很可能追问这一点。

**本页的 boto3 / google-cloud 是模拟的**：调用写法和返回结构与真 SDK 一致（只实现了课程用到的部分）；真项目里 `pip install` 后配置凭证即可。

经典错误：在上传的那个 HTTP 请求里同步审完整份合同。一条条款要 2–3 秒，30 条就是一两分钟，用户干等，网关可能先超时；服务一重启，这份合同就丢了。下面的代码走一遍前两步。
--- code
import json
from google.cloud import storage, pubsub_v1

# 第 1 步：合同放进桶。对象名里的 "/" 只是名字的一部分，桶里没有真的文件夹
blob = storage.Client().bucket("clausecheck-contracts").blob("contracts/1/111/msa.txt")
blob.metadata = {"customer_id": "1", "contract_id": "111"}

publisher = pubsub_v1.PublisherClient()
topic = publisher.topic_path("clausecheck-dev", "contract-uploaded")
message_id = publisher.publish(topic, json.dumps(job).encode("utf-8"), contract_id="111").result()
print("发布任务:", job["key"], "message_id =", message_id)

for step, gcp, aws in [("存合同", "Cloud Storage", "S3"), ("队列", "Pub/Sub", "SQS / SNS"),
                       ("worker", "Cloud Run", "Lambda / ECS"), ("结果表", "BigQuery", "Redshift / Athena"),
                       ("密钥", "Secret Manager", "Secrets Manager"), ("日志", "Cloud Logging", "CloudWatch")]:

@@ concept
title: 每一步都可能失败：至少一次和幂等
cloud: yes
--- body
云上没有「一次就成功」。按步骤看它怎么失败、怎么补救：

- **发布任务**：`publish()` 马上返回一个 future，服务器的错误在 `future.result()` 里抛出
- **投递**：Pub/Sub 的 push 订阅和 SQS 标准队列都是**至少一次**（at-least-once）。push 订阅里，worker 返回 200、204 这类成功状态码才算确认；返回 500、超过订阅的确认期限（ack deadline，默认 10 秒，最多能调到 600 秒）还没回应、崩溃，过一会儿会再投一次。所以**同一个任务可能被处理两次**
- **单条条款失败**（模型 429、坏 JSON）：记一行 error，不拖垮整份合同
- **永久错误**（消息坏了、合同里没有条款）：重投也不会好 → 记日志、返回 204 确认掉。**其他错误**（BigQuery 暂时不可用、限流、分不清的）：抛出去 → 返回 500 → 重投；给订阅配一个死信主题，重投到上限（默认 5 次）的消息转过去，不会无限重投
- **幂等**：开头先看报告在不在，在就跳过；报告**最后**写，而且只在不存在时创建（`if_generation_match=0`）。报告就是「做完了」的标记

代价：崩在写完 BigQuery、写报告之前，重投会让表里多出重复的行。所以看板永远按 `(contract_id, clause_id)` 取最新一行。

push 还是 pull：push 由 Pub/Sub 把消息 POST 给 Cloud Run，没消息时服务能缩到 0，最省事；但每个请求都要在确认期限内回应。pull 由 worker 自己去取、自己确认，适合特别长的任务和要控制并发的场合（SQS 就是 pull）。
--- code
import json
from google.cloud import storage
from google.api_core.exceptions import PreconditionFailed

reports = storage.Client().bucket("clausecheck-reports")

def finish(job, report):
    blob = reports.blob(f"reports/{job['contract_id']}/{job['generation']}.json")
    if blob.exists():
        return "duplicate: skipped"
    # ... 这里是下载、审查、写 BigQuery ...
    blob.upload_from_string(json.dumps(report), content_type="application/json", if_generation_match=0)
    return "done"

job = {"contract_id": 111, "generation": "1790000000000001"}
print(finish(job, {"redline": 1}))   # 第一次投递
print(finish(job, {"redline": 1}))   # 同一条消息又投了一次

# 两个 worker 同时拿到同一个任务：都通过了 exists() 检查，但「不存在才创建」只有一个能成功
try:
    reports.blob("reports/111/1790000000000001.json").upload_from_string("{}", if_generation_match=0)
except PreconditionFailed as e:
    print("第二个写入被拒绝:", e.code)

title: 成本估算：钱花在哪
dataset: clausecheck
--- body
面试官常问「这个东西一个月多少钱」。回答的方法：**用自己测到的数据，按用量拆开算，每项说清楚单价的来源**。

- **模型**：每条条款的输入 token（其中多少命中缓存）+ 输出 token，乘以单价。样例库的 `cost_usd` 按 DeepSeek 的**高峰价**算，以官方价格页为准（2026-09）：`deepseek-flash` 每百万 token 输入 0.30、命中缓存 0.006、输出 1.20 美元，大模型 `deepseek-v4-pro` 是 1.32 / 0.044 / 3.96。高峰是工作日 UTC 01:00–04:00 和 06:00–10:00，其余时段半价。项目 `config.py` 的 `PRICES` 记的就是这组高峰价（2026-09）。注意它的查法：表里查不到的模型按单价 0 算，报告里估算的费用就成了 0，所以换模型时要先把单价加进表里
- **思考模式**：DeepSeek 默认先思考再回答，思考的 token 按**输出**计费。给一条条款下判定用不着长时间推理，所以 worker 发请求时带上 `"thinking": {"type": "disabled"}`：更快、更便宜，`temperature` 也重新起作用（思考模式下它不起作用）。样例库的输出 token 就是关掉思考时的量；开着思考，每条都会多出一段推理的输出 token，模型费会高不少
- **BigQuery**：按需查询按扫描字节计费，约 6.25 美元 / TiB，每月前 1 TiB 免费；小表也按每张最低 10 MB 计（以官方价格页为准）。流式写入按量另算，这个规模几乎是零
- **存储、Pub/Sub、Cloud Run**：这个量级基本在免费额度里或只有几分钱（以官方价格页为准）

结论先说：**模型费几乎是全部**。下面直接用样例数据库算。注意最后一行：看板刷得太勤，没有免费额度时，光看板就快赶上 100 份合同的模型费了。

复习第 25、27 天。`sql` 里有一个拼错的列名，`topic_path` 指向一个不存在的主题。这两个错误分别在哪一行抛出？

--- options
- A 和 C：调用的那一刻就会报错
- B 和 D：错误要等拿结果的时候才抛出

--- explain

--- starter
SELECT cu.name, COUNT(co.id) AS contracts, COUNT(r.id) AS reviews
FROM customers AS cu
JOIN contracts AS co ON co.customer_id = cu.id
JOIN reviews AS r ON r.contract_id = co.id
GROUP BY cu.id, cu.name

--- solution
SELECT cu.name, COUNT(DISTINCT co.id) AS contracts, COUNT(r.id) AS reviews
FROM customers AS cu
LEFT JOIN contracts AS co ON co.customer_id = cu.id
LEFT JOIN reviews AS r ON r.contract_id = co.id
GROUP BY cu.id, cu.name
ORDER BY reviews DESC, cu.name
--- hints
- 「没有合同的客户也要列出来」→ 两个 JOIN 都要改成 LEFT JOIN。
- 一份合同接上 reviews 之后变成了很多行（JOIN 放大），`COUNT(co.id)` 数的是行数。数「有几份不同的合同」要写 `COUNT(DISTINCT co.id)`。
- `COUNT(r.id)` 不数 NULL，所以 Amsterdam Data BV 的两列都是 0。

from google.cloud import storage

BUCKET = "clausecheck-contracts"

def upload_contract(client, customer_id, contract_id, filename, text):
    if not filename.endswith(".txt"):
        raise ValueError("only .txt contracts")
    name = f"contracts/{customer_id}/{contract_id}/{filename}"
    blob = client.bucket(BUCKET).blob(name)
    blob.metadata = {"customer_id": str(customer_id), "contract_id": str(contract_id)}
    blob.upload_from_string(text, content_type="text/plain; charset=utf-8")
    return {"bucket": BUCKET, "name": name, "generation": blob.generation}

def on_upload(event, publisher, topic_path):

import re

HEAD = re.compile(r"^(\d+(?:\.\d+)*)\.?\s+([A-Z].*)$")
FAILED = {"verdict": None, "risk_level": None, "topic": "other", "prompt_tokens": 0,

def split_clauses(text):
    clauses = []
    for line in text.split("\n"):
        m = HEAD.match(line.strip())
        if m:
            clauses.append([m.group(1), m.group(2), ""])
        elif clauses:
            clauses[-1][2] += line + "\n"

def review_contract_text(text, review_fn):
    clauses = split_clauses(text)
    if not clauses:
        raise ValueError("no numbered clauses found")
    results = []
    for clause_id, heading, body in clauses:
        try:
            review = review_fn(clause_id, body)
            results.append({"clause_id": clause_id, "heading": heading, **review, "error": None})
        except Exception as e:
            results.append({"clause_id": clause_id, "heading": heading, **FAILED, "error": f"{type(e).__name__}: {e}"})
    return results

import base64
import json

REQUIRED = ("key", "bucket", "name", "generation", "contract_id")

def decode_push(envelope):
    try:
        data = envelope["message"]["data"]
        job = json.loads(base64.b64decode(data).decode("utf-8"))
    except (KeyError, TypeError, ValueError) as e:
        raise ValueError(f"bad message: {e}") from e
    if not isinstance(job, dict) or any(k not in job for k in REQUIRED):
        raise ValueError("bad message: missing fields")
    return job

--- context
worker 处理完一个任务，要用 HTTP 状态码告诉 Pub/Sub 结果，Pub/Sub 据此决定把消息丢掉还是过一会儿再送一次。状态码回错了，要么合同永远没人审，要么一条坏消息被没完没了地重送。
--- prompt
Cloud Run 收到 Pub/Sub 的 push 请求时调用 `handle_push`，它的返回值就是 HTTP 状态码。Pub/Sub 的规则：102、200、201、202、204 表示**确认**（消息从此消失）；其他状态码表示没处理成功，过一会儿**重投**。测试传进来的 `handle_job(job)` 是只收一个参数的替身。

现在的代码出了任何错都回 204。结果：BigQuery 临时出错时，这份合同就永远没人审了，只留下一行日志。运行测试看哪条挂了，然后改成：

- `ValueError`（消息坏了、合同里没有条款：重试也不会好）→ 打印 `dropped: <错误>`，返回 204。确认之后消息就没了，所以生产环境里要先把它记下来（日志，或者存进一个专门放坏消息的桶）

import json

def decode_push(envelope):

        job = json.loads(base64.b64decode(envelope["message"]["data"]).decode("utf-8"))

        job = decode_push(envelope)

  SELECT contract_id, clause_id, verdict, error,
         ROW_NUMBER() OVER (PARTITION BY contract_id, clause_id ORDER BY created_at DESC) AS rn
  FROM `clausecheck-dev.clausecheck.reviews`
)

       COUNT(*) AS clauses,
       COUNTIF(verdict IN ('flag', 'redline')) AS needs_human,
       COUNTIF(error IS NOT NULL) AS failed
FROM ranked
WHERE rn = 1
GROUP BY contract_id
ORDER BY contract_id

from dataclasses import dataclass

MB = 1024 ** 2
TIB = 1024 ** 4
# 示例单价，引用前去官方价格页核对。模型是 deepseek-flash 的高峰价（2026-09），低谷时段半价
PRICES = {
    "input_per_m": 0.30,       # 模型输入（没命中缓存），美元 / 百万 token
    "cache_hit_per_m": 0.006,  # 模型输入（命中缓存）
    "output_per_m": 1.20,      # 模型输出（思考模式的 token 也算输出）
    "bq_per_tib": 6.25,        # BigQuery 按需查询，美元 / TiB
    "bq_free_tib": 1.0,        # 每月免费的查询量
    "gcs_per_gb_month": 0.02,  # 存储，约数
}

@dataclass
class Workload:
    contracts: int                 # 每月合同数
    clauses_per_contract: float = 6.5
    prompt_tokens: int = 2200      # 每条条款的输入 token
    completion_tokens: int = 175   # 每条条款的输出 token
    cache_hit_ratio: float = 0.56  # 输入里命中缓存的比例
    dashboard_queries: int = 2880  # 看板每月的查询次数（每 15 分钟一次）
    tables_per_query: int = 2
    stored_gb: float = 1.0         # 桶里的合同和报告

def estimate_monthly_cost(w, prices=PRICES):
    clauses = w.contracts * w.clauses_per_contract
    hit = w.prompt_tokens * w.cache_hit_ratio
    miss = w.prompt_tokens - hit
    per_clause = (miss * prices["input_per_m"] + hit * prices["cache_hit_per_m"]
                  + w.completion_tokens * prices["output_per_m"]) / 1_000_000
    llm = clauses * per_clause
    tib = w.dashboard_queries * w.tables_per_query * 10 * MB / TIB
    bq = max(0.0, tib - prices["bq_free_tib"]) * prices["bq_per_tib"]
    storage = w.stored_gb * prices["gcs_per_gb_month"]
    return {"llm_usd": round(llm, 2), "bigquery_usd": round(bq, 2), "storage_usd": round(storage, 2),

from google.cloud import bigquery

SQL = """
WITH ranked AS (
  SELECT clause_id, verdict, created_at,
         ROW_NUMBER() OVER (PARTITION BY clause_id ORDER BY created_at DESC) AS rn
  FROM `clausecheck-dev.clausecheck.reviews`
  WHERE contract_id = @contract_id
)
SELECT clause_id, verdict, created_at FROM ranked WHERE rn = 1
"""

def id_key(clause_id):
    return tuple(int(x) for x in clause_id.split("."))

def latest_verdicts(client, contract_id):
    cfg = bigquery.QueryJobConfig(query_parameters=[bigquery.ScalarQueryParameter("contract_id", "INT64", contract_id)])
    rows = client.query(SQL, job_config=cfg).result()
    out = [{"clause_id": r["clause_id"], "verdict": r["verdict"], "reviewed_at": r["created_at"].strftime("%Y-%m-%d %H:%M")}
           for r in rows]
    return sorted(out, key=lambda d: id_key(d["clause_id"]))

--- solution
import json
from botocore.exceptions import ClientError

BUCKET = "clausecheck-reports"

def report_key(contract_id, generation):
    return f"reports/{contract_id}/{generation}.json"

def store_report(s3, contract_id, generation, report):
    try:
        s3.put_object(Bucket=BUCKET, Key=report_key(contract_id, generation), Body=json.dumps(report).encode("utf-8"),
                      ContentType="application/json", Metadata={"contract-id": str(contract_id)}, IfNoneMatch="*")
    except ClientError as e:
        if e.response["Error"]["Code"] == "PreconditionFailed":
            return "duplicate"
        raise
    return "stored"

def load_report(s3, contract_id, generation):
    try:
        resp = s3.get_object(Bucket=BUCKET, Key=report_key(contract_id, generation))
    except ClientError as e:
        if e.response["Error"]["Code"] == "NoSuchKey":
            return None
        raise
    return json.loads(resp["Body"].read().decode("utf-8"))

import json
from botocore.exceptions import ClientError

MODEL_ID = "eu.amazon.nova-lite-v1:0"   # 示例：欧盟的跨区域推理配置文件，以 Bedrock 控制台为准
SYSTEM = 'You review one contract clause. Reply with JSON only: {"verdict": "accept|flag|redline", "risk_level": "low|medium|high"}'

def review(bedrock, clause_id, text):
    resp = bedrock.converse(
        modelId=MODEL_ID,
        system=[{"text": SYSTEM}],
        messages=[{"role": "user", "content": [{"text": f"Review clause {clause_id}: {text}"}]}],
        inferenceConfig={"maxTokens": 200, "temperature": 0},
    )
    return json.loads(resp["output"]["message"]["content"][0]["text"])

def drain(sqs, queue_url, bedrock, done):
    results = []
    while True:
        messages = sqs.receive_message(QueueUrl=queue_url, MaxNumberOfMessages=10).get("Messages", [])
        if not messages:
            return results
        for msg in messages:
            job = json.loads(msg["Body"])
            if job["key"] not in done:
                try:
                    v = review(bedrock, job["clause_id"], job["text"])
                except ClientError:
                    continue
                results.append({"clause_id": job["clause_id"], "verdict": v["verdict"], "risk_level": v["risk_level"]})
                done.add(job["key"])
            sqs.delete_message(QueueUrl=queue_url, ReceiptHandle=msg["ReceiptHandle"])
