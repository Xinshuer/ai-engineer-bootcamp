@@ concept
title: 元组和拆包
--- body
元组 `("8.1", "flag")` 像一个**不能改的小列表**，用来放「固定几样、总是一起出现」的东西：一个编号和它的判定，一个结果和它的原因。

- **拆包**：`cid, verdict = pair`，左边变量的个数要和元组长度一样
- 函数「返回两个值」其实是返回一个元组：`return ok, reason`，调用时 `ok, reason = check(...)`
- `a, b = b, a` 一行交换两个变量
- 你早就用过拆包了：`for k, v in d.items():` 每次拿到的就是一个 `(键, 值)` 元组

常见错误：想改元组里的元素，`pair[1] = "accept"` 会报 `TypeError`。要改就造一个新的元组。
--- code
pair = ("8.1", "flag")
cid, verdict = pair
print(cid, verdict, len(pair))

def check(verdict):
    if verdict in ("accept", "flag", "redline"):
        return True, ""
    return False, f"unknown verdict: {verdict}"

ok, reason = check("maybe")
print(ok, reason)
print(check("flag"))

first, second = "8.1", "3.1"
first, second = second, first
print(first, second)

try:
    pair[1] = "accept"
except TypeError as e:
    print("TypeError:", e)

@@ concept
title: enumerate 和 zip
--- body
- `enumerate(列表)` 每次给你一个 `(下标, 元素)`；`enumerate(列表, 1)` 从 1 开始数。Clause Check 的 `pipeline.py` 里就是 `for i, clause in enumerate(clauses, 1):`，用来显示「第 i 条 / 共 n 条」。以后不用再写 `for i in range(len(xs))` 了
- `zip(a, b)` 把两个列表**按位置配对**：`zip(["8.1", "3.1"], ["flag", "accept"])` 依次给出 `("8.1", "flag")`、`("3.1", "accept")`
- `dict(zip(ids, verdicts))` 一步配成字典

坑：两个列表长度不同时，`zip` 在**短的那个用完时就停**，多出来的悄悄丢掉，不报错。
--- code
ids = ["8.1", "3.1", "10.1"]
verdicts = ["flag", "accept", "redline"]

for i, cid in enumerate(ids, 1):
    print(f"{i}/{len(ids)} reviewing {cid}")

for cid, v in zip(ids, verdicts):
    print(cid, "->", v)

print(dict(zip(ids, verdicts)))
print(list(zip(ids, ["flag"])))

@@ concept
title: 集合 set
--- body
集合 `{"PB-01", "PB-03"}` 是一堆**不重复、没有顺序**的元素。它最擅长两件事：

- **去重**：`set(["PB-01", "PB-01", "PB-03"])` 只剩两个；`s.add(x)` 往里加一个
- **判断在不在**：`"PB-03" in rules`，集合再大也很快

集合之间的运算，正好对应「规则检查」：

- `required - cited`：要求引用、却没引用的（漏了哪些）
- `required & cited`：两边都有的
- `required | cited`：合在一起

两个坑：空集合要写 `set()`，因为 `{}` 是空**字典**；集合没有顺序，需要稳定的输出时用 `sorted(集合)` 变成排好序的列表。
--- code
required = {"PB-01", "PB-03", "PB-07"}
cited = set(["PB-03", "PB-03", "PB-09"])
print(len(cited))
print(sorted(required - cited))
print(sorted(required & cited))
print(sorted(required | cited))
print("PB-07" in required)

seen = set()
for rid in ["PB-02", "PB-01", "PB-02"]:
    seen.add(rid)
print(sorted(seen))
print(type(set()).__name__, type({}).__name__)

@@ concept
title: 字典进阶：推导式、Counter、defaultdict
--- body
- **字典推导式**：`{r["id"]: r["verdict"] for r in reviews}`，和列表推导式一样，只是写成 `键: 值`
- **Counter**：专门计数的字典。`Counter(列表)` 一行完成第 2 天那个计数循环；`.most_common(2)` 返回最多的两个 `(值, 次数)`；查不存在的键返回 0，不报错
- **defaultdict(list)**：取一个不存在的键时，自动先放一个空列表，分组时不用再写 `if key not in groups`。`evals/run_evals.py` 就用 `defaultdict(list)` 收集每条用例的结果

两个都要先导入：`from collections import Counter, defaultdict`。

坑：defaultdict 连「读」一个不存在的键都会把它加进去。交给别人之前，用 `dict(groups)` 转成普通字典。
--- code
from collections import Counter, defaultdict

reviews = [
    {"id": "3.1", "topic": "payment", "verdict": "accept"},
    {"id": "8.1", "topic": "liability_cap", "verdict": "flag"},
    {"id": "3.2", "topic": "payment", "verdict": "flag"},
]
print({r["id"]: r["verdict"] for r in reviews})

counts = Counter([r["verdict"] for r in reviews])
print(counts)
print(counts.most_common(1), counts["redline"])

groups = defaultdict(list)
for r in reviews:
    groups[r["topic"]].append(r["id"])
print(dict(groups))
print(groups["termination"], len(groups))

@@ concept
title: any 和 all
--- body
- `any(...)`：只要**有一个**为真就是 True。「有没有哪条被 redline？」
- `all(...)`：**全部**为真才是 True。「所有判定都合法吗？」

括号里通常写一个**去掉方括号的推导式**（叫生成器表达式）：

```python
any(r["verdict"] == "redline" for r in reviews)
```

它不先造出一整个列表，边算边判断，一有结论就停。`sum(...)`、`max(...)`、`Counter(...)` 的括号里也能这样写。`evals/harness.py` 里就有一句 `any(t.startswith(prefix) for t in ...)`。

边界要记牢：`any([])` 是 False，`all([])` 是 **True**（没有反例，就算「全部合法」）。如果空列表在你的业务里意味着出错，要单独判断。
--- code
reviews = [{"id": "3.1", "verdict": "accept"}, {"id": "8.1", "verdict": "redline"}]
print(any(r["verdict"] == "redline" for r in reviews))
print(all(r["verdict"] in ("accept", "flag", "redline") for r in reviews))
print(sum(1 for r in reviews if r["verdict"] != "accept"))
print(any([]), all([]))

@@ concept
title: 多键排序
--- body
律师要的顺序常常不止一个条件：「先按风险从高到低，风险一样再按编号」。办法是让 `key` 返回一个**元组**。Python 比较元组时先比第一项，一样再比第二项：

```python
RISK = {"high": 0, "medium": 1, "low": 2}
sorted(reviews, key=lambda r: (RISK[r["risk"]], r["id"]))
```

- `reverse=True` 把整个顺序倒过来；想「一项降序、一项升序」时，把数字取负：`key=lambda r: (-r["tokens"], r["id"])`
- `max(xs, key=...)` 找「最大」的那一个元素，`min` 同理；列表可能为空时加 `default=None`

编号的坑：字符串是一个字符一个字符比的，所以 `"10.1" < "8.1"`（因为 `"1" < "8"`）。按编号排，要先转成数字元组：`"10.1"` → `(10, 1)`。Clause Check `split.py` 里的 `_sort_key` 就是做这件事的。
--- code
RISK = {"high": 0, "medium": 1, "low": 2}
reviews = [
    {"id": "10.1", "risk": "high", "tokens": 900},
    {"id": "3.1", "risk": "low", "tokens": 300},
    {"id": "8.1", "risk": "high", "tokens": 1200},
]
print(sorted(["10.1", "8.1", "3.1"]))

def id_key(cid):
    return tuple(int(x) for x in cid.split("."))

print(id_key("10.1"), sorted(["10.1", "8.1", "3.1"], key=id_key))
for r in sorted(reviews, key=lambda r: (RISK[r["risk"]], id_key(r["id"]))):
    print(r["risk"], r["id"])
print(max(reviews, key=lambda r: r["tokens"])["id"])
print(max([], key=len, default=None))

@@ concept
title: dataclass：只装数据的类
--- body
第 3 天写类要手写 `__init__`，一行行 `self.x = x`。如果一个类主要是装数据，用 `@dataclass` 让 Python 替你写：

```python
from dataclasses import dataclass, field

@dataclass
class Clause:
    id: str
    text: str
    risk: str = "low"
    tags: list[str] = field(default_factory=list)
```

自动得到：`__init__`（`Clause("8.1", "...")`）、好读的打印 `Clause(id='8.1', ...)`、按字段比较的 `==`。方法照常写。`asdict(c)` 把它转成字典（方便写 JSON）。

- 列表、字典这种**可变**的默认值必须写 `field(default_factory=list)`，每个对象各有一份新的；写 `= []` 会直接报错。普通函数的 `def f(tags=[])` 也有同样的坑，练习里会遇到
- dataclass **不做校验**：`Clause(8.1, None)` 也能创建成功
--- code
from dataclasses import dataclass, field, asdict

@dataclass
class Clause:
    id: str
    text: str
    risk: str = "low"
    tags: list[str] = field(default_factory=list)

    def is_high(self) -> bool:
        return self.risk == "high"

a = Clause("8.1", "Liability is unlimited.", "high")
b = Clause("3.1", "Fees are due in 30 days.")
print(a)
print(a.is_high(), b.is_high())
b.tags.append("payment")
print(b.tags, a.tags)
print(a == Clause("8.1", "Liability is unlimited.", "high"))
print(asdict(b))

@@ concept
title: *args、**kwargs 和只能按名字传的参数
--- body
读别人的代码（包括 Clause Check）时，经常看到参数前面有星号：

- 定义时 `def log(event, *args, **kwargs):`：多出来的**位置参数**收进元组 `args`，多出来的**名字参数**收进字典 `kwargs`
- 调用时 `f(**d)`：把字典展开成名字参数。第 4 天的 `tools[name](**args)` 就是它；`run_evals.py` 里的 `Settings(**kw)` 也是；`review.py` 的 `_create(self, **kwargs)` 把收到的参数原样转交给 `client.messages.create(**kwargs)`
- `def review(clause_id, *, strict=False):` 中间单独一个 `*`，表示后面的参数**只能按名字传**：`review("8.1", strict=True)` 可以，`review("8.1", True)` 报 `TypeError`。这样调用处一眼就知道那个 `True` 是什么意思

自己写函数时，参数能列清楚就别用 `**kwargs`：它会让拼错的参数名悄悄混过去。
--- code
def log(event, *args, **kwargs):
    print(event, args, kwargs)

log("review")
log("review", "8.1", "flag", risk="high", ms=120)

def review(clause_id, *, strict=False):
    return f"{clause_id} strict={strict}"

options = {"strict": True}
print(review("8.1"), "|", review("8.1", **options))
try:
    review("8.1", True)
except TypeError as e:
    print("TypeError:", e)

title: 返回两个值
level: 1
--- prompt
写 `check_verdict(verdict)`：

- 合法（`accept` / `flag` / `redline` 之一）：返回 `(True, "")`
- 否则：返回 `(False, "unknown verdict: " + verdict)`

```python
ok, reason = check_verdict("maybe")

```

这种「结果 + 原因」的写法，调用方一行就能拆开拿到两样东西。
--- starter
VALID = ("accept", "flag", "redline")

def check_verdict(verdict):
    pass
--- solution
VALID = ("accept", "flag", "redline")

def check_verdict(verdict):
    if verdict in VALID:
        return True, ""
    return False, f"unknown verdict: {verdict}"
--- tests
expect("合法", lambda: check_verdict("flag"), (True, ""))
expect("不合法", lambda: check_verdict("maybe"), (False, "unknown verdict: maybe"))
expect("大写也不合法", lambda: check_verdict("FLAG"), (False, "unknown verdict: FLAG"))
def _unpack():
    ok, reason = check_verdict("redline")
    return ok
expect("可以拆包", _unpack, True)
--- hints
- 两个值之间用逗号：`return True, ""`，Python 会把它们打包成元组。
- 先判断 `verdict in VALID`，是就返回 `(True, "")`；不是就返回 `False` 和用 f-string 拼好的原因。

--- prompt
模型按顺序返回了一串判定，要和条款编号一一配对。写 `verdict_map(ids, verdicts)`，返回 `{编号: 判定}`。

`verdict_map(["8.1", "3.1"], ["flag", "accept"])` → `{"8.1": "flag", "3.1": "accept"}`

两个列表长度不同，说明哪里出了错（少审了一条？），这时不能像 `zip` 那样悄悄丢数据，而要 `raise ValueError(f"length mismatch: {len(ids)} ids, {len(verdicts)} verdicts")`。

（Python 3.10 起 `zip(..., strict=True)` 也会在长度不同时报错，但这里要求自己写出上面这条清楚的错误信息。）
--- starter
def verdict_map(ids, verdicts):
    return dict(zip(ids, verdicts))
--- solution
def verdict_map(ids, verdicts):
    if len(ids) != len(verdicts):
        raise ValueError(f"length mismatch: {len(ids)} ids, {len(verdicts)} verdicts")
    return dict(zip(ids, verdicts))
--- tests
expect("两条", lambda: verdict_map(["8.1", "3.1"], ["flag", "accept"]), {"8.1": "flag", "3.1": "accept"})
expect("空", lambda: verdict_map([], []), {})
expect_raises("判定少了一条", lambda: verdict_map(["8.1", "3.1"], ["flag"]), ValueError)
def _message():
    try:
        verdict_map(["8.1"], ["flag", "accept"])
    except ValueError as e:
        return str(e)
expect("错误信息", _message, "length mismatch: 1 ids, 2 verdicts")
--- hints
- 起始代码对长度一样的情况已经是对的。缺的是：长度不同时要报错。
- 在 `return` 之前加 `if len(ids) != len(verdicts):`，里面 `raise ValueError(...)`。
